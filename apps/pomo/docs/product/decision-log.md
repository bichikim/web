# Pomo 제품 결정 기록

이 문서는 Pomo의 기능·사용자 니즈·수익화·마케팅 방향을 결정할 때 근거와
다음 행동을 남기는 로그다. 의견만 남기지 않고 관찰 사실, 해석, 미결정 항목을
분리한다.

## 기록 규칙

각 항목은 다음 순서로 작성한다.

1. 날짜
2. 결정 또는 보류 내용
3. 근거
4. 영향 범위
5. 다음 행동과 담당 문서

결정이 바뀌면 기존 기록을 지우지 않고 새 날짜의 항목을 추가한다.

## 2026-09-16 — 현재 기능 감사 후 문서 분리

### 결정

현재 구현 감사, 사용자 니즈 조사, 광고 제외 수익화, 마케팅 실행 전략을 각각
독립적인 Markdown 문서로 관리한다.

### 근거

- 기존 [`docs/plan/README.md`](../plan/README.md)는 초기 제품 정의와 기술 방향을
  함께 담고 있다.
- 현재 소스에는 초기 계획 이후 추가된 피드, 기억 보조, 로컬 대화·음성, 상품·
  권한 기반이 존재한다.
- 기능이 존재한다는 사실과 사용자가 돈을 낸다는 사실은 서로 다른 검증 대상이다.

### 영향

- 현재 동작은 [현재 기능 감사](./current-function-audit.md)에 기록한다.
- 사용자에 대한 추정은 [사용자 니즈 조사](./user-needs-research.md)에 기록한다.
- 광고를 제외한 수익 후보와 결제 준비도는 [수익화 기회](./revenue-opportunities.md)에
  기록한다.
- 유입·콘텐츠·전환 실험은 [마케팅 전략](./marketing-strategy.md)에 기록한다.

### 다음 행동

각 문서는 검증이 발생한 시점에 해당 문서와 이 로그를 함께 갱신한다.

## 2026-09-16 — 현재 기능 감사의 증거 경계

### 결정

코드에서 기능이 존재하는 것, 로컬에서 화면이 동작하는 것, 사용자 가치가
검증되는 것을 별도 상태로 기록한다.

### 근거

- 로컬 실행에서 집중 화면, 타이머, 음악, 둘러보기, 설정, 기억 보조, 대화 경로를
  확인했다.
- 상품·오퍼·주문·권한 스키마와 재생 접근 제어는 확인했지만, 구매부터 권한 반영·
  복원까지 이어지는 사용자 흐름은 확인하지 못했다.
- 기능별 전환과 재방문을 판단할 수 있는 제품 이벤트 계약은 이번 조사에서
  확인하지 못했다.

### 영향

수익화 문서에서 “결제 가능”, “사용자가 원한다”, “전환된다”는 표현을 현재
사실처럼 사용하지 않는다.

### 다음 행동

사용자 니즈 조사 후 유료 패키지를 좁히고, 그 다음 거래 흐름을 검증한다.

## 미결정 항목

- 핵심 사용자군
- 무료 핵심 기능과 유료 콘텐츠의 경계
- 일회성 구매·구독·혼합 모델
- 음악·장면·대사·동기화 중 첫 유료 패키지
- 가격, 지역별 판매 조건, 환불 정책
- 기능 이벤트와 개인정보 보관 범위

새로운 근거가 생기면 위 항목을 임의로 지우지 말고 날짜가 있는 결정으로
승격하거나 보류 이유를 추가한다.

## 2026-09-16 — 공개 자료 기반 니즈 우선순위

### 결정

새 기능을 바로 늘리기보다 첫 세션 시작, 조용한 동반감, 반복 사용 가능한
콘텐츠의 순서로 사용자 검증을 진행한다.

### 근거

- 여러 집중 서비스는 타이머와 함께 환경·진행감·동반감 중 하나를 핵심 가치로
  내세운다.
- 공개 사용자 의견에서는 설정과 기능이 많아질수록 집중 앱 자체가 방해가 될 수
  있다는 신호가 있었다.
- 사회적 존재는 사람에 따라 도움이 되거나 방해가 될 수 있다는 연구 결과가 있다.
- Pomo에는 장면·음악·대사·타이머가 이미 있으므로, 기능 추가보다 현재 조합의
  반복 사용 가치를 먼저 확인할 수 있다.

### 영향

- 첫 화면에 모든 기능을 노출하는 방향을 사용자 검증 전의 기본값으로 삼지 않는다.
- 캐릭터 대화는 실시간 챗봇보다 시작·종료 중심의 조용한 동반감으로 먼저 검증한다.
- 수익화 후보는 타이머 잠금보다 테마·음악·대사 확장 팩을 먼저 비교한다.
- 공개 자료는 Pomo 수요의 증거가 아니므로, 실제 인터뷰·과업 테스트가 필요하다.

### 다음 행동

[사용자 니즈 조사](./user-needs-research.md)의 5~8명 인터뷰와 첫 세션 과업
테스트를 진행하고, 결과는 [사용자 니즈 1차 분석](./user-needs-analysis.md)에
근거와 함께 갱신한다.

## 2026-09-16 — 단기 유입 목표 설정

### 결정

광고 없이 2주 동안 Production 웹의 일 고유 방문자 10~20명을 목표로 한다.
목표 달성은 하루의 일시적 상승이 아니라 7일 중 5일 이상 10명 이상인 상태로
판정한다.

### 근거

- 사용자가 현재 방문자가 거의 0명이라고 관찰했다. 정확한 기준선은 Analytics
  대시보드에서 다시 확인해야 한다.
- 현재 Pomo 웹은 [`Analytics.tsx`](../../src/components/vercel/Analytics.tsx)에서
  pageview를 수집하지만, 세션 시작·완료 이벤트는 이번 코드 감사에서 확인하지
  못했다.
- 방문자 수가 충분하지 않은 상태에서는 기능 추가보다 메시지·배포·유입 경로의
  병목을 먼저 구분해야 한다.

### 영향

- 2주 동안 주 대상과 메시지를 하나로 좁힌다.
- 짧은 영상, 허용된 커뮤니티, 직접 초대를 사용하고 유료 광고는 집행하지 않는다.
- 방문자·첫 세션·완료·재방문을 분리해 기록한다.
- 목표를 달성하지 못해도 숫자만 보고 기능을 추가하지 않고 병목을 기록한다.

### 다음 행동

[단기 유입 계획](./short-term-growth-plan.md)의 D0 Production·측정 점검을 먼저
완료하고, [유입 측정 로그](./traffic-log.md)에 매일 수치를 기록한다.

## 2026-09-16 — 전세계 방문자 범위 반영

### 결정

방문자 목표는 특정 국가의 방문자가 아니라 전세계 Production 웹 방문자로 집계한다.
일별 집계는 UTC로 통일하고, 유입 메시지는 영어를 기본 변형으로 하며 한국어를
비교 변형으로 분리한다.

### 근거

- 사용자가 Pomo 방문자가 전세계라고 확인했다.
- 현재 locale 설정은 [`settings.json`](../../.i18n/project.inlang/settings.json)의
  `ko`, `en`으로 확인된다.
- 전세계 방문자와 전세계 언어 지원은 같은 의미가 아니므로, 지원하지 않는 언어를
  제공한다고 홍보하지 않아야 한다.

### 영향

- 국가·지역·랜딩 언어를 유입 로그에 추가한다.
- 영어와 한국어 링크의 성과를 분리한다.
- 특정 국가의 수요가 확인되기 전에는 지역별 기능과 번역을 새로 만들지 않는다.

### 다음 행동

[단기 유입 계획](./short-term-growth-plan.md)의 D0에서 영어·한국어 랜딩 변형,
UTC 집계, 국가·referrer 측정 가능 여부를 확인한다.

## 2026-09-16 — 기존 YouTube 채널을 주 유입 허브로 지정

### 결정

새 YouTube 채널을 개설하지 않고, 사용자가 제공한 [Pomo YouTube 채널](https://www.youtube.com/@pomofi-io)을
전세계 단기 유입 실험의 주 소유 채널로 사용한다.

### 근거

- 사용자가 Pomo 유입 경로로 해당 채널이 있음을 확인했다.
- 채널의 현재 영상 수, 구독자 수, 조회수, 최근 업로드 상태는 이 기록을 작성할
  때 확인하지 않았다.

### 영향

- D1~D3의 영어·한국어 비교 콘텐츠를 해당 채널에 게시한다.
- 영상별 설명란·고정 댓글 링크에 별도 식별자를 부여한다.
- YouTube 지표와 Production 고유 방문자를 분리해 기록한다.

### 다음 행동

[단기 유입 계획](./short-term-growth-plan.md)의 D0에서 채널 접근 권한과 현재 콘텐츠를
확인하고, [유입 측정 로그](./traffic-log.md)에 영상별 링크와 결과를 기록한다.
