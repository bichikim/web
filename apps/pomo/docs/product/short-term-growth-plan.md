# Pomo 단기 유입 계획

기준일: 2026-09-16

상태: 2주 실행 계획

## 0. 목표 정의

### 현재 상태

현재 방문자는 사용자의 관찰상 거의 0명이다. 아직 대시보드에서 같은 기간의
고유 방문자 수를 확인한 근거는 이 문서에 없다. 따라서 첫날에 실제 기준선을
확정한다.

### 2주 목표

광고 없이 Pomo의 **일 고유 방문자 10~20명**을 안정적으로 만든다.

운영 지표는 다음처럼 정의한다.

- 대상: Production 환경의 웹 방문자
- 범위: 전세계 웹 방문자
- 기준: UTC 00:00~23:59 기준 일 단위 방문자
- 목표 구간: 하루 10~20명
- 안정성 조건: 7일 중 5일 이상 목표 하한인 10명 이상
- 제외: 개발자 본인 방문, Preview 환경, 봇·자동화 요청, 같은 사람이 새로고침한 페이지뷰
- 기간: 실행 시작일을 D1로 하는 14일

하루 한 번 발생한 공유나 게시물로 일시적으로 숫자가 오른 것은 목표 달성으로
기록하지 않는다. 7일 이동 평균과 실제 첫 집중 시작을 함께 본다.

### 보조 지표

보조 지표는 방문자 수를 대신하지 않고, 방문자가 왜 다음 단계로 이동하지 않는지
진단하는 데 사용한다.

| 지표                      | 의미                             | 현재 상태                          |
| ------------------------- | -------------------------------- | ---------------------------------- |
| `daily_unique_visitors`   | 하루의 고유 웹 방문자            | 기준선 확인 필요                   |
| `focus_session_started`   | 방문자가 실제 집중 세션을 시작함 | 별도 제품 이벤트 확인 필요         |
| `focus_session_completed` | 집중 세션을 완료함               | 별도 제품 이벤트 확인 필요         |
| `return_visit_next_day`   | 다음 날 다시 방문함              | 별도 제품 이벤트 확인 필요         |
| `referrer`                | 방문자가 들어온 경로             | Vercel Web Analytics에서 확인 대상 |
| `country_or_region`       | 방문자의 국가·지역 분포          | Vercel Web Analytics에서 확인 대상 |
| `landing_locale`          | 방문에 사용한 랜딩 언어          | 링크 식별자와 게시물 기록으로 확인 |

## 1. 먼저 확인할 것: 유입 문제가 아니라 접근 문제인지

방문자가 거의 0명인 상태에서는 콘텐츠를 늘리기 전에 배포와 측정이 실제로
열려 있는지 확인한다.

### D0 배포 점검

- Production URL이 200 응답을 반환하는가
- 첫 화면에서 `시작하기`를 눌러 집중 화면까지 진입하는가
- 모바일·데스크톱에서 화면이 깨지지 않는가
- 페이지 제목과 공유 미리보기에서 Pomo가 어떤 앱인지 이해되는가
- `robots.txt`와 `sitemap.xml`이 의도대로 응답하는가
- Production과 Preview 방문을 구분하고 있는가
- 웹 Analytics가 실제 Production 페이지뷰를 수집하는가

소스의 테스트에는 `https://www.pomofi.io/`가 Production URL로 등장하지만, 이
계획을 작성하는 시점에 실제 외부 접속 상태까지 확인하지 않았다. 배포 점검이
실패하면 마케팅 실험보다 배포·접근성 문제를 먼저 해결한다.

### 측정 기준

현재 [`Analytics.tsx`](../../src/components/vercel/Analytics.tsx)는 웹에서
Vercel Analytics를 주입하고 경로별 pageview를 보낸다. Apps-in-Toss, 데스크톱,
모바일 환경에서는 이 컴포넌트가 반환되지 않는다.

Vercel 공식 문서상 Web Analytics 대시보드에서는 방문자와 referrer를 확인할 수
있고, UTM 파라미터와 custom event는 요금제에 따라 제공 범위가 다르다.
따라서 첫 2주에는 UTM 대시보드가 반드시 있다고 가정하지 않고 다음 순서로
기록한다.

1. 대시보드에서 Production의 `Visitors`와 `Referrers`를 매일 확인한다.
2. 게시물마다 `utm_source`, `utm_medium`, `utm_campaign` 링크를 만든다.
3. UTM 필터가 현재 요금제에서 보이지 않으면 게시물별 링크와 플랫폼 자체 클릭
   수를 함께 기록한다.
4. 세션 시작·완료가 필요하다고 확인된 뒤에만 custom event 추가를 별도 구현 과제로
   만든다.

참고: [Vercel Web Analytics 사용](https://vercel.com/docs/analytics/using-web-analytics),
[custom event](https://vercel.com/docs/analytics/custom-events),
[Analytics 요금·기능 범위](https://vercel.com/docs/analytics/limits-and-pricing)

## 2. 초기 대상과 메시지

### 초기 대상 가설

첫 2주에는 모든 사용자를 대상으로 하지 않는다.

> A quiet focus companion for people who find it hard to start studying, coding,
> writing, or reading alone.

학생, 개발자, 창작자를 모두 별도 시장으로 운영하지 않고, “혼자 시작하기
어려운 책상 작업”이라는 공통 상황으로 묶는다. 방문자 범위는 전세계로 두되,
초기 실험에서는 문제 상황을 좁혀야 메시지별 차이를 확인할 수 있다. 이 대상은
아직 확정 고객군이 아니며, 국가·언어가 다른 5~8명 인터뷰에서 다시 좁힌다.

### 글로벌 메시지와 언어

현재 Pomo의 locale 설정은 [`settings.json`](../../.i18n/project.inlang/settings.json)에
`ko`와 `en`으로 정의되어 있다. 따라서 첫 2주에는 “전세계 방문자”를 측정하되,
모든 언어를 지원한다고 홍보하지 않는다.

- 영어 메시지를 글로벌 기본 변형으로 사용한다.
- 한국어 메시지는 별도 비교 변형으로 운영한다.
- 영어·한국어 이외의 방문자는 국가·referrer·브라우저 언어를 기록하고, 일정한
  수요가 확인된 뒤 번역 우선순위를 정한다.
- 언어 변형마다 링크 식별자를 분리해 전체 방문자 수와 언어별 성과를 구분한다.

외부 기본 문구:

> Start a quiet focus session with Pomo beside you.

한국어 비교 문구:

> 오늘 시작하기 어려운 날, Pomo가 먼저 책상에 앉아 있어요.

주요 행동 요청은 하나만 둔다.

영어 기본 CTA:

> Start focus

한국어 비교 CTA:

> 첫 집중 시작

첫 2주에는 피드, 캘린더, 언어 학습, 결제, AI 생성 기능을 주 메시지로 사용하지
않는다. 기능 수가 많은 제품일수록 첫 방문자의 선택 부담을 줄이는 것이 먼저다.

## 3. 유입 경로 선택

채널을 많이 열지 않는다. 기존에 접근할 수 있는 한 개의 주 채널과 한 개의
보조 채널만 선택한다.

| 경로                                                    | 목적                                             | 2주 운영량                     | 콘텐츠·행동                                                  |
| ------------------------------------------------------- | ------------------------------------------------ | ------------------------------ | ------------------------------------------------------------ |
| [Pomo YouTube 채널](https://www.youtube.com/@pomofi-io) | 기존 소유 채널을 글로벌 주 유입 허브로 사용한다. | D1~D14 주 3편                  | Shorts 2편과 실제 UI 1편, 설명란·고정 댓글에 랜딩 링크와 CTA |
| 기존 스터디·개발·창작 커뮤니티                          | 실제 사용자를 만나고 피드백을 얻는다.            | 주 1~2회, 규칙이 허용하는 범위 | 홍보보다 과업 테스트와 피드백 요청을 우선한다.               |
| 직접 초대                                               | 첫 5~10명의 질적 피드백을 확보한다.              | D1~D7에 10명 안팎              | 대상 상황에 맞는 개인 초대, 반복 발송 금지                   |
| 검색·소개 페이지                                        | 방문자가 앱의 정체성을 즉시 이해하게 한다.       | D0에 1회 정리                  | 제목·설명·공유 이미지·첫 CTA 정리                            |

새 계정을 여러 개 만들거나 모든 커뮤니티에 동시에 게시하지 않는다. 한 경로에서
어떤 메시지가 실제 방문과 세션 시작을 만드는지 알 수 있어야 한다.

## 4. 14일 실행 일정

### D0 — 측정과 진입 경로 준비

- [유입 측정 로그](./traffic-log.md)에 기준선을 `확인 필요`로 기록한다.
- Production URL, 시작 버튼, 모바일·데스크톱, Analytics 수집을 점검한다.
- 영어 기본 메시지와 한국어 비교 메시지가 의도한 locale로 표시되는지 점검한다.
- 사용자가 제공한 [Pomo YouTube 채널](https://www.youtube.com/@pomofi-io)에 접근할
  수 있는지 YouTube Studio에서 확인한다.
- 현재 채널의 영상 수, 구독자 수, 최근 업로드, 시청자 국가·언어는 확인 전까지
  가정하지 않는다.
- 동일한 목적의 링크에 채널별 `utm_source`와 `utm_campaign`을 붙인다.
- YouTube에 게시할 짧은 영상 소재 세 가지와 영상별 링크 식별자를 준비한다.

### D1~D3 — 메시지 세 가지를 작게 시험

기존 Pomo YouTube 채널에 다음 세 소재를 영어 기본 변형으로 각각 한 편씩
공개하고, 같은 내용의 한국어 비교 변형은 별도 링크로 운영한다.

1. **시작이 어려운 날:** Pomo가 먼저 책상에 앉고 25분을 시작하는 장면
2. **실제 사용:** 장면 선택 없이 첫 집중 세션으로 들어가는 실제 화면
3. **개인화:** 사용자가 만든 시작 대사가 재생되고 타이머가 시작되는 화면

각 영상의 설명란과 고정 댓글에는 같은 랜딩 페이지와 하나의 `첫 집중 시작` CTA를
넣는다. 영상 조회수보다 링크 클릭, 고유 방문자, 첫 세션 시작 여부를 기록한다.

### D4~D7 — 첫 사용자와 문제 지점 확인

- 국가·시간대가 한 곳에 몰리지 않도록 대상 가설에 맞는 5~10명에게 직접 초대한다.
- 처음 보는 사람이 설명 없이 첫 세션을 시작하는지 관찰한다.
- 시작 전 중단 지점과 기능을 찾지 못한 지점을 기록한다.
- 세션 후 다시 사용할 이유와 불필요하다고 느낀 기능을 묻는다.
- YouTube Studio에서 영상별 노출·시청·링크 유입 지표를 확인하되, Production
  Analytics의 고유 방문자와 혼동하지 않는다.
- 가장 많은 고유 방문과 실제 시작을 만든 메시지 하나를 고른다.

D7 판단 기준은 “가장 예쁜 콘텐츠”가 아니라 “방문과 첫 시작을 함께 만든
메시지”다.

### D8~D10 — 승자 메시지 반복

- D1~D3의 승자 메시지를 다른 상황으로 두 번 변형한다.
- 한 번은 캐릭터 장면 중심, 한 번은 실제 UI 중심으로 만든다.
- 커뮤니티에는 결과를 과장하지 않고 “첫 세션을 시작해 보고 어디서 막혔는지”를
  묻는 피드백 글을 올린다.
- 방문자는 늘었지만 첫 세션이 없으면 언어별 CTA와 첫 화면을 먼저 점검한다.

### D11~D14 — 목표 구간 안정화

- 가장 반응이 좋은 경로 하나에 게시 빈도를 집중한다.
- 기존 사용자에게 공유를 요청하되, 공유 문구와 링크를 직접 제공한다.
- 7일 이동 평균, 10명 하한 도달 일수, 세션 시작·완료를 확인한다.
- 목표를 달성하지 못해도 어느 단계에서 막혔는지 결정 로그에 남긴다.

## 5. 콘텐츠 제작 규칙

| 규칙              | 적용                                                                   |
| ----------------- | ---------------------------------------------------------------------- |
| 한 콘텐츠 한 문제 | 시작하기 어려움, 늦은 밤 코딩, 독서 중 하나만 선택한다.                |
| 한 콘텐츠 한 기능 | 타이머, 시작 대사, 장면 중 하나만 전면에 둔다.                         |

| 즉시 CTA          | 설명 페이지를 여러 번 거치지 않고 첫 집중 시작으로 연결한다.           |

| 광고 제외         | 유료 광고를 집행하지 않고 콘텐츠·직접 초대·허용된 커뮤니티만 사용한다. |

## 6. 판단 규칙

| 관찰                             | 해석                                  | 다음 행동                                 |
| -------------------------------- | ------------------------------------- | ----------------------------------------- |
| 노출은 있으나 링크 클릭이 없음   | 문제 장면이나 CTA가 약함              | 메시지와 첫 3초를 바꾼다.                 |
| 링크 클릭은 있으나 방문자가 적음 | 링크·배포·Production 접근 문제 가능성 | URL, 배포, referrer를 먼저 점검한다.      |
| 방문은 있으나 세션 시작이 없음   | 랜딩·첫 화면·기능 이해 문제 가능성    | 첫 화면 과업 테스트를 한다.               |
| 세션 시작은 있으나 완료가 없음   | 타이머·오디오·동반감이 방해할 가능성  | 세션 중 이탈 이유를 인터뷰한다.           |
| 완료는 있으나 재방문이 없음      | 반복 가치가 약함                      | 장면·음악·대사 중 재사용 이유를 검증한다. |
| 10~20명 방문이 안정됨            | 1차 유입 목표 달성                    | 어떤 패키지에 돈을 낼지 조사한다.         |

숫자가 낮다는 이유만으로 기능을 계속 추가하지 않는다. 각 단계의 병목을 확인한
뒤 한 번에 하나의 변수를 바꾼다.

## 7. 완료 조건과 다음 계획

2주가 끝났을 때 다음 항목을 채운다.

- Production 일 고유 방문자 7일 기록
- 가장 많은 방문과 세션 시작을 만든 메시지
- 가장 효과적인 주 채널 한 개
- 첫 세션 과업에서 반복된 혼란 지점
- 세션 완료와 재방문의 초기 신호
- 다음 수익화 검증으로 넘어갈지, 유입·활성화 실험을 반복할지에 대한 결정

목표를 달성하면 바로 결제 기능을 만들지 않는다. 먼저 반복 방문자의 공통 상황과
돈을 지불할 확장 가치를 확인한 뒤 [수익화 기회](./revenue-opportunities.md)의
패키지 후보를 좁힌다.
