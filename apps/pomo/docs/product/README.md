# Pomo 제품 문서 허브

이 디렉터리는 Pomo의 현재 기능, 사용자 니즈, 수익화, 마케팅, 제품 결정을
나누어 관리하는 작업 공간이다. 기술 구현의 세부 계약은 소스 코드와
[`docs/plan/development/`](../plan/development/) 문서를 기준으로 하고, 이 디렉터리는
그 기능이 사용자 가치와 사업 가설에 어떻게 연결되는지를 기록한다.

기준일: 2026-09-16

기존의 창작 방향은 [`docs/plan/marketing.md`](../plan/marketing.md), 개발 규칙과

두 문서와 이 허브의 내용이 충돌하면, 현재 동작에 관한 판단은 실제 코드와
실행 확인 결과를 우선하고, 미래 방향에 관한 판단은 최신 결정 기록을 우선한다.

## 증거 상태 표기

문서의 결론을 다음 상태 중 하나로 구분한다.

- `코드에서 확인`: 현재 저장소의 소스·설정·테스트에 해당 근거가 있다.
- `로컬 실행에서 확인`: 이 문서의 기준일에 로컬 앱을 직접 열어 관찰했다.
- `문서상 계획`: 계획 문서에 정의되어 있으나 현재 구현을 뜻하지 않는다.
- `검증 전 가설`: 제품 가치를 추정한 문장으로, 실제 사용자 검증 전에는 결론으로 취급하지 않는다.
- `확인 필요`: 해당 범위를 아직 검증하지 않았거나 현재 근거만으로 판단할 수 없다.

한 문장 안에서 여러 상태를 섞지 않는다. 예를 들어 결제 테이블이 존재한다는
사실만으로 실제 구매가 완료된다고 쓰지 않고, 데이터 구조와 구매 흐름을 각각
기록한다.

## 현재까지의 정리

현재 기능 감사에서 Pomo는 단순 타이머가 아니라 장면, 음악, 캐릭터 대사,
피드, 기억 보조 기능을 한 집중 공간에서 제공하는 앱으로 확인됐다. 첫 화면부터
집중 세션을 시작하는 핵심 흐름은 로컬 실행으로 확인했지만, 사용자 유지율,
지불 의향, 실제 구매 전환은 아직 검증하지 않았다.

음악 앨범의 상품·오퍼·주문·권한을 위한 서버 기반은 일부 존재한다. 그러나
사용자 구매 UI, 결제 완료, 구매 복원까지 이어지는 종단 간 흐름은 이번 감사에서
확인하지 못했다. 따라서 현재 단계의 수익화 문서는 가격 결론이 아니라 검증 순서를
정하는 문서다.

## 앞으로의 관리 순서

1. 기능이 바뀌면 [현재 기능 감사](./current-function-audit.md)에 관찰 사실과 근거를 갱신한다.
2. 실제 사용자에게 질문하거나 테스트하면 [사용자 니즈 조사](./user-needs-research.md)에 원자료와 해석을 분리해 남긴다.
3. 사용자 가치가 확인된 기능만 [수익화 기회](./revenue-opportunities.md)의 패키지 후보로 승격한다.
4. 메시지와 채널은 [마케팅 전략](./marketing-strategy.md)의 실험 단위로 작성하고, 결과를 기록한다.
5. 방향을 결정하거나 보류하면 [결정 기록](./decision-log.md)에 날짜, 근거, 다음 행동을 남긴다.

문서에 기술 세부를 복사해 두지 않는다. 기술 내용이 필요하면 해당 소스나
기술 문서로 링크하고, 이 디렉터리에는 사용자 가치·사업 판단·검증 상태만 남긴다.
