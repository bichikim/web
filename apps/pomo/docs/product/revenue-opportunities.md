# Pomo 수익화 기회

상태: 광고 제외 수익화 가설 초안

이 문서는 광고를 넣지 않는다는 전제에서 Pomo가 만들 수 있는 수익 모델 후보와
검증 순서를 정리한다. 가격, 결제 방식, 목표 매출은 아직 결정하지 않았다.
현재 기능 감사에서 확인한 구현 기반과 사용자 니즈 조사에서 확인해야 할 가치를
분리한다.

## 현재 수익화 준비도

| 항목           | 현재 근거                                                                   | 판단                |
| -------------- | --------------------------------------------------------------------------- | ------------------- |
| 음악 상품 구조 | 상품·오퍼·주문·권한 스키마와 앨범 카탈로그가 있음                           | 기술 기반 일부 확인 |
| 권한 기반 재생 | 권한 보유자는 전체 재생, 그 외에는 미리 듣기 경로                           | 기술 기반 확인      |
| 판매 상태 UI   | 앨범 카드와 공개 카탈로그에 판매 상태 표현                                  | 표현 기반 확인      |
| 구매 UI        | 이번 소스·로컬 UI 감사에서 완결된 구매 버튼과 checkout 흐름을 확인하지 못함 | 확인 필요           |
| 구매 완료·복원 | 완료 주문 반영, 복원, 대기 주문의 사용자 흐름을 확인하지 못함               | 확인 필요           |
| 가격           | 현재 로컬 카탈로그는 무료로 관찰됐고, 판매 상태에는 가격 미정 표현이 있음   | 미결정              |
| 수요           | 사용자 인터뷰·구매 테스트 자료 없음                                         | 미검증              |

관련 근거는 [현재 기능 감사](./current-function-audit.md)의 음악·수익화
절과 [`paid-albums.md`](../plan/development/paid-albums.md)에 연결되어 있다.

## 수익 단위 후보

### 1. 테마 음악·장면 앨범

현재 제품과 가장 직접적으로 연결되는 후보다. 음악, 배경, 활동 장면을 하나의
집중 분위기로 묶어 일회성 콘텐츠로 제공한다.

사용자가 구매하는 결과:

- 특정 작업 시간에 어울리는 분위기
- 반복해서 사용할 수 있는 음악·장면 조합
- 무료 기본 카탈로그와 구별되는 수집 가치

현재 근거는 앨범 카탈로그와 권한 기반 재생이지만, 실제 구매 화면과 가격은
확인하지 않았다. 사용자가 음악보다 장면·캐릭터를 더 중요하게 생각한다면
음악만 판매하는 패키지는 약할 수 있다.

### 2. 캐릭터 대사·음성·이벤트 팩

현재 앱은 사용자가 대사를 직접 작성하고 집중 시작·종료·휴식 이벤트에 연결하며,
음성을 생성할 수 있다. 이 자산을 특정 캐릭터 말투, 상황별 문장, 음성 스타일,
이벤트 세트로 묶는 후보다.

장점:

- 현재의 동료감 경험과 직접 연결된다.
- 사용자가 첫 대사를 만드는 부담을 낮출 수 있다.
- 짧은 콘텐츠 단위로 시험할 수 있다.

주의할 점:

- 사용자가 직접 작성하는 기능을 유료로 막으면 핵심 경험을 약화할 수 있다.
- 음성 모델·자산 라이선스와 생성 비용을 별도로 확인해야 한다.
- 자동 생성 대사에 대한 신뢰와 피로도를 사용자에게 확인해야 한다.

### 3. 장면·행동·캐릭터 컬렉션

현재 장면은 시간대·활동·시선·스타일 조합을 관리한다. 추가 장면, 행동,
캐릭터 의상 또는 계절 테마를 수집하는 모델을 생각할 수 있다.

이는 기능 사용권보다 정서적·수집적 가치에 가깝다. 따라서 “더 많은 장면”이
아니라 어떤 반복 사용 상황을 해결하는지 보여줘야 한다. 캐릭터 생성이나
커스터마이징은 현재 초기 계획에서 제외된 영역이므로, 구현 착수 전에 니즈를
먼저 검증한다.

### 4. 여러 기기에서 이어 쓰는 연속성 기능

현재 로컬 저장과 로그인 UI가 함께 존재한다. 사용자가 데스크톱과 다른 환경에서
설정·대화·기록을 이어 쓰는 가치를 강하게 느낀다면 백업·동기화·복원 기능을
유료 가치로 묶을 수 있다.

다만 서버 저장, 개인정보, 복구, 운영 비용이 추가된다. 현재 구조에 로그인 UI가
있다는 사실만으로 사용자가 동기화에 돈을 낼 것이라고 결론 내리지 않는다.

### 5. 집중 루틴·기억 보조 묶음

언어 학습, 메모, 그림 일기, 캘린더, 리마인더를 특정 사용 목적에 맞춰 묶는
후보다. 예를 들어 시험 준비나 글쓰기 회고처럼 명확한 결과를 제공해야 한다.

기능 수를 늘리는 방식만으로는 가치가 설명되지 않는다. 사용자가 집중 후에
무엇을 기억하거나 다음 행동으로 이어가려는지 먼저 확인한다.

## 우선순위 판단

현재 시점의 우선순위는 매출 예상치가 아니라 검증 비용과 제품 적합성으로 정한다.

| 후보                | 현재 자산과의 거리 | 첫 검증 방법                    | 결제 구현 전 확인할 것         |
| ------------------- | ------------------ | ------------------------------- | ------------------------------ |
| 테마 앨범           | 가까움             | 무료·유료 테마 설명 비교        | 가격, 재생 권한, 구매·복원     |
| 대사·음성 팩        | 가까움             | 상황별 대사 팩 과업 테스트      | 음성 품질, 라이선스, 생성 비용 |
| 장면·캐릭터 컬렉션  | 중간               | 테마 목업 선호 비교             | 반복 사용과 수집 가치          |
| 연속성 기능         | 중간               | 기기 전환 과업과 지불 이유 확인 | 서버·개인정보·운영 비용        |
| 루틴·기억 보조 묶음 | 중간               | 특정 목표 과업 테스트           | 실제 결과와 사용 빈도          |

이 표의 순서는 추천된 가격 순서가 아니다. 사용자 니즈 조사 결과에 따라
순서를 바꾼다.

## 제안하는 실행 순서

### A. 가치 확인

1. [사용자 니즈 조사](./user-needs-research.md)의 맥락 인터뷰로 반복 문제를 찾는다.
2. 후보 패키지를 실제 구매 UI가 아닌 설명·목업으로 비교한다.
3. “좋다”는 반응과 실제 사용할 시점·포기 이유·현재 지출을 구분한다.

### B. 무료 핵심과 유료 경계 설정

다음 경계를 먼저 문서로 고정한다.

- 첫 집중 세션을 시작하는 핵심 타이머와 기본 장면은 진입 장벽으로 남길 것인지
- 사용자가 만든 대사와 기본 음악을 어떤 조건에서 계속 사용할 수 있게 할 것인지
- 유료 콘텐츠가 없어도 Pomo의 핵심 가치가 성립하는지
- 구매하지 않은 사용자가 미리 듣기·미리 보기로 품질을 판단할 수 있는지

유료 기능을 추가하기 전에 무료 핵심 경험이 훼손되지 않는지 확인한다.

### C. 거래 흐름 구현

가치와 패키지가 검증된 뒤에만 다음 흐름을 구현한다.

1. 상품·오퍼·가격 표시
2. 구매 시작과 공급자 응답
3. 주문 검증과 권한 부여
4. 전체 자산 재생
5. 구매 복원·대기 주문·실패 재시도
6. 환불·권한 회수·고객 지원 경로

현재 권한 기반 재생 코드는 거래 흐름의 한 부분이다. 이것만으로 결제 기능이
완료됐다고 기록하지 않는다.

### D. 비용과 반복 수익 확인

실제 가격을 정하기 전에는 다음 비용을 같은 단위로 계산해야 한다.

- 앱스토어·결제 공급자 수수료
- 음성·로컬 모델 배포와 업데이트 비용
- 오디오·장면 저장 및 CDN 전송 비용
- 서버 상품·주문·권한 운영 비용
- 고객 문의·환불·권한 오류 처리 비용

현재 문서에는 최신 공급자 요금이나 시장 가격을 넣지 않았다. 이 숫자는 가격을
결정하는 시점에 공식 요금표와 실제 사용량을 별도로 조사해 갱신한다.

## 아직 결정하지 않은 것

- 일회성 구매, 구독, 혼합 모델 중 선택
- 무료 카탈로그의 규모와 유료 콘텐츠 비율
- 가격과 지역별 가격 정책
- 하나의 큰 컬렉션과 여러 작은 팩 중 선택
- 웹과 Apps-in-Toss의 구매 경험을 동일하게 할지 여부
- 동기화와 백업을 유료 가치에 포함할지 여부

이 항목들은 현재 코드나 기존 계획만으로 결정할 수 없다. 결정할 때는
[결정 기록](./decision-log.md)에 사용자 근거, 비용 근거, 기술 상태를 함께 남긴다.
