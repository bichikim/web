# Pomo 사용자 니즈 조사

상태: 조사 설계 초안

이 문서는 현재 코드와 로컬 실행에서 관찰한 기능을 실제 사용자의 문제와
연결하기 위한 조사 계획이다. 아래 가설은 저장소에서 도출한 후보일 뿐이며,
사용자 인터뷰나 사용성 테스트로 검증하기 전에는 제품 결론으로 취급하지 않는다.

## 조사 목적

수익화를 설계하기 전에 다음 네 가지를 확인한다.

1. 사용자가 어떤 상황에서 집중을 시작하지 못하는가.
2. Pomo의 어떤 기능이 첫 세션 시작과 재방문에 영향을 주는가.
3. 사용자가 무료 기능과 유료 기능의 경계를 어떻게 이해하는가.
4. 한 번의 구매, 콘텐츠 묶음, 반복 결제 중 어떤 제안이 실제 문제와 맞는가.

광고를 넣을지 여부는 조사 범위에 포함하지 않는다. 목표는 광고 외 수익 모델의
가치를 확인하는 것이다.

## 조사 대상 후보

아래는 확정 페르소나가 아니라 인터뷰 표본을 나누기 위한 후보군이다.

- 시험·자격증을 준비하는 학습자
- 개발·문서·기획 업무를 하는 지식 노동자
- 글쓰기·독서·창작 작업을 정기적으로 하는 사람
- 데스크톱에서 배경 장면과 음악을 오래 켜 두는 사람
- 언어 학습과 복습 루틴이 있는 사람

표본을 이 그룹으로 나눈다고 해서 모두 핵심 고객이라고 가정하지 않는다. 조사
후 실제 사용 빈도, 문제의 강도, 현재 대체 수단, 지불 의향을 비교해 우선순위를
다시 정한다.

## 우선 질문

### 문제와 현재 행동

- 최근 집중해야 했지만 시작하지 못한 상황은 무엇이었나?
- 그때 사용한 도구와 루틴은 무엇이었나?
- 집중을 시작한 뒤 중단하게 되는 이유는 무엇인가?
- 타이머, 음악, 배경 영상, 동료감, 기록 중 실제로 다시 찾는 요소는 무엇인가?

### Pomo 경험

- 첫 화면에서 무엇을 먼저 이해했나?
- 장면·캐릭터·음악이 집중을 돕는 순간과 방해하는 순간은 언제인가?
- 직접 쓰는 대사와 자동으로 만들어지는 대사 중 어느 쪽이 더 자연스러운가?
- 피드와 기억 보조 기능은 집중 전, 집중 중, 집중 후 어느 시점에 필요한가?
- 로컬 생성 모델을 설치하거나 기다리는 과정에서 포기할 지점은 어디인가?

### 지불 가치

- 현재 문제를 해결하기 위해 이미 돈을 쓰는 도구가 있는가?
- Pomo에서 없어지면 가장 아쉬울 기능은 무엇인가?
- 음악·장면·캐릭터·대사·동기화 중 무엇을 별도 구매할 수 있다고 느끼는가?
- 한 번 사서 소유하는 콘텐츠와 계속 업데이트되는 기능 중 어느 쪽이 자연스러운가?
- 결제를 망설이게 하는 이유는 가격, 사용 빈도, 개인정보, 품질 중 무엇인가?

## 제안하는 검증 순서

### 1단계: 맥락 인터뷰

제안 표본은 5~8명이다. 각 인터뷰에서는 Pomo를 먼저 설명하기보다 최근의
집중 실패와 현재 대체 행동을 먼저 듣는다. 제품을 보여준 뒤에는 “좋아 보이는가”가
아니라 실제로 언제 다시 사용할지와 무엇을 포기할지를 묻는다.

기록할 항목:

- 문제 상황과 발생 빈도
- 현재 해결 방법과 지불 비용
- 집중 시작·유지·종료 중 가장 큰 마찰
- 캐릭터·음악·대사·기억 보조에 대한 자발적 반응
- 유료 제안에 대한 구체적인 거절·수용 이유

### 2단계: 과업 기반 사용성 테스트

현재 앱에서 다음 과업을 수행하게 하고 관찰한다.

1. 장면을 선택하고 첫 집중 세션을 시작한다.
2. 음악을 바꾸고 다시 세션으로 돌아온다.
3. 시작·종료 대사를 만들어 이벤트에 연결한다.
4. 피드 또는 메모를 추가한다.
5. 다음 세션에서 이전 설정을 다시 사용한다.

측정할 것은 기능을 “좋아한다”는 답변보다 첫 성공까지의 혼란, 도움 요청,
중단 지점, 다시 찾는 기능이다.

### 3단계: 패키지 선호와 지불 의향 확인

구매 기능을 바로 구현하기 전에 다음과 같은 가상 패키지를 같은 조건으로
비교한다.

- 음악·장면을 묶은 테마 팩
- 캐릭터 대사·음성·이벤트를 묶은 동료 팩
- 여러 장면과 음악을 묶은 컬렉션
- 여러 기기에서 설정을 이어가는 연속성 기능

가격 숫자를 먼저 정하지 않는다. 먼저 어떤 결과를 구매한다고 이해하는지,
무엇이 무료여야 한다고 생각하는지, 구매 후 어떤 기대를 하는지를 확인한다.

## 제품 이벤트 측정 초안

분석 이벤트를 추가할 때는 아래 이벤트를 후보로 삼되, 개인정보 범위와 저장
기간을 먼저 결정한다.

| 이벤트 후보               | 의미                                |
| ------------------------- | ----------------------------------- |
| `focus_room_viewed`       | 집중 화면에 진입함                  |
| `focus_session_started`   | 실제 집중 세션을 시작함             |
| `focus_session_completed` | 집중 세션을 정상 종료함             |
| `scene_changed`           | 기본 장면에서 선택을 변경함         |
| `dialogue_saved`          | 대사를 저장함                       |
| `feed_prepared`           | 피드 음성 준비를 완료함             |
| `music_added`             | 앨범 또는 트랙을 재생 목록에 추가함 |
| `account_connected`       | 계정 연결을 완료함                  |
| `offer_viewed`            | 유료 제안 상세를 봄                 |
| `purchase_completed`      | 결제와 권한 반영을 모두 완료함      |

이 표는 구현 요구사항이 아니라 측정 설계 초안이다. 현재 코드에 위 이벤트가
모두 존재한다고 해석하지 않는다.

## 판단 규칙

조사 결과는 다음 형식으로 기록한다.

| 관찰                                                | 해석                           | 다음 행동                       |
| --------------------------------------------------- | ------------------------------ | ------------------------------- |
| 여러 사용자가 같은 상황과 대체 행동을 반복해서 말함 | 문제 후보의 반복성이 있음      | 과업 테스트로 재현              |
| 기능은 인상적이지만 실제 사용 시점이 없음           | 호감과 사용 가치를 구분해야 함 | 반복 사용 과업으로 확인         |
| 유료 패키지의 결과를 구체적으로 설명함              | 패키지 가치 후보가 있음        | 제한된 구매 제안 테스트         |
| 구매보다 성능·설치·개인정보를 먼저 걱정함           | 가치보다 사용 장벽이 큼        | 온보딩·비용·권한 문제 우선 해결 |
| 사용자마다 원하는 기능이 크게 다름                  | 단일 패키지 가설이 약함        | 세그먼트별 패키지 비교          |

인터뷰 한두 명의 강한 표현만으로 기능을 유료화하지 않는다. 반복성, 실제
행동, 대체 비용, 구매 조건이 함께 확인될 때만 수익화 문서의 우선 후보로
승격한다.

## 현재 결론

현재 저장소만으로 확인할 수 있는 것은 기능의 존재와 구현 방향이다. 누가
Pomo를 필요로 하는지, 무엇에 돈을 낼지는 아직 결정할 수 없다. 첫 조사에서는
“Pomo가 좋은가”보다 “어떤 집중 문제를 얼마나 자주 해결하며, 그 해결 결과에
돈을 지불할 이유가 있는가”를 확인한다.
