# 음악 라이브러리와 재생목록

[개발 기술 계획으로 돌아가기](../development.md)

## 목표

DB와 사용자 계정 없이 정적 JSON으로 곡과 앨범을 제공한다. `playlist.json`은 최초 기본
재생목록으로 사용하고, 사용자가 목록을 수정한 뒤에는 플랫폼별 로컬 저장값을 우선한다.

이 문서에서 지속 저장은 앱이나 브라우저를 다시 실행해도 유지된다는 뜻이다. 앱 삭제 또는
브라우저 사이트 데이터 삭제 이후까지 보존하지 않으며 기기 간 동기화도 제공하지 않는다.

## 정적 데이터

- `tracks.json`: 모든 곡의 `id`, 제목, 아티스트, 길이와 음원 URL을 관리한다.
- `albums.json`: 앨범의 `id`, 제목, 설명, 아이콘과 순서가 있는 `trackIds`를 관리한다.
- `playlist.json`: 최초 기본 재생목록의 순서가 있는 `trackIds`를 관리한다.

앨범과 재생목록에는 곡 정보를 복제하지 않는다. 곡 순서는 `trackIds`의 배열 순서로 정한다.
각 파일은 `version`을 포함하며, 중복 ID와 존재하지 않는 곡 참조를 로딩 단계에서 검증한다.

## 사용자 재생목록

사용자가 앨범 추가, 곡 삭제 또는 순서 변경을 처음 수행하기 전에는 `playlist.json`을 사용한다.
수정 이후에는 다음 형식의 사용자 재생목록을 저장한다.

```ts
interface StoredPlaylist {
  readonly savedAt: number
  readonly trackIds: readonly string[]
  readonly version: 1
}
```

저장 키는 `pomo:focus-room-playlist:v1`을 사용한다. 웹에서는 `localStorage`, 앱인토스에서는
`Storage`를 사용한다. 재생목록은 현재 곡과 재생 위치를 저장하는 playback 상태와 분리한다.

## 복원 규칙

1. 전체 곡과 앨범, 기본 재생목록 JSON을 읽고 검증한다.
2. 유효한 사용자 재생목록이 있으면 해당 `trackIds`를 우선한다.
3. 저장값이 없거나 손상되었으면 `playlist.json`을 사용한다.
4. 카탈로그에 없는 곡 ID는 건너뛰고 나머지 순서를 유지한다.
5. 해석된 목록이 비면 기본 재생목록으로 복구한다.
6. 기본값 초기화 시 사용자 저장값만 삭제하고 최신 `playlist.json`을 다시 적용한다.

앱 업데이트로 기본 재생목록이 바뀌어도 기존 사용자 목록은 유지한다. 사용자가 새 기본값을
원할 때 명시적으로 초기화할 수 있도록 한다.

## 구현 순서

1. `PTrack`, `PAlbum`, 기본 재생목록과 저장 스냅샷 타입을 확정한다.
2. 기존 곡 데이터를 `tracks.json`으로 옮기고 `albums.json`, `playlist.json`을 작성한다.
3. 각 JSON의 런타임 검증과 ID 참조 해석을 구현한다.
4. 브라우저와 앱인토스용 사용자 재생목록 저장 어댑터를 구현한다.
5. 초기 로딩에서 사용자 저장값과 기본 재생목록의 우선순위를 적용한다.
6. 앨범 모달을 임시 곡 분할 방식에서 `albums.json` 기반으로 교체한다.
7. 앨범 추가, 곡 삭제, 순서 변경과 기본값 초기화를 저장 동작에 연결한다.
8. 손상 데이터, 누락된 곡, 저장 실패와 비동기 쓰기 경합을 테스트한다.

## 완료 조건

- 저장값이 없는 사용자는 `playlist.json`의 곡을 지정된 순서로 본다.
- 사용자 수정 사항은 앱이나 브라우저를 다시 실행해도 유지된다.
- 앱인토스 저장소를 사용할 수 없으면 브라우저 저장소 또는 현재 세션으로 안전하게 대체한다.
- 앱 삭제나 사이트 데이터 삭제 후에는 기본 재생목록으로 돌아간다.
- 잘못된 JSON이나 오래된 곡 ID가 있어도 플레이어를 사용할 수 있다.
