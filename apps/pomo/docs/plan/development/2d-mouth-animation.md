# 2D 입모양과 턱 전환 개선

[개발 기술 계획으로 돌아가기](../development.md)

## 목적

Pomo의 2D 캐릭터가 대사를 말할 때 종점 입모양만 즉시 교체하지 않고, 입술의 해제와 턱의 이동을
연속된 동작으로 보여 준다. 특히 `closed(ㅁ/ㅂ/ㅍ) → open(ㅏ/ㅓ)`에서 닫힌 입이 한 프레임 만에
크게 열리는 느낌을 없애는 것이 첫 번째 목표다.

현재 런타임에는 `rest`, `closed`, `open`, `wide`, `round`, `narrow` 여섯 비짐이 있고, 발음 선행
판단 50ms와 별도로 시각 전환을 100ms 동안 재생하며 입모양별 턱 진행률을 보간한다. 여섯 비짐은 발음
분류용 종점으로 유지하고 렌더링 단계에서 세 개의 실제 중간 프레임과 턱 포즈를 함께 적용한다.

## 전이 모델

모든 비짐 쌍을 개별 제작하지 않는다. 입의 벌어짐과 모양 변화를 다음 두 축으로 나누고, 자주 쓰거나
차이가 큰 경로에만 재사용 가능한 브리지 프레임을 둔다.

- 벌어짐 축: `closed → release → small-open → half-open → open`
- 모양 축: `narrow ↔ wide`, `narrow ↔ round`, `open ↔ wide`, `open ↔ round`
- `rest`는 무음 종점이며 작은 움직임에서는 `narrow`를 공통 브리지로 사용할 수 있다.
- 역방향은 정방향 프레임을 역순으로 재사용하되, 닫힐 때 부자연스러운 프레임은 별도로 제작한다.

`closed → open`의 최초 후보는 다음 다섯 단계다. 숫자는 고정 타이밍이 아니라 시각적 진행률이며 실제
유지 시간은 음성 구간 길이와 발화 강도에 맞춘다.

| 단계 | 이름         | 입술과 입안                            | 턱 진행률 후보 |
| ---- | ------------ | -------------------------------------- | -------------- |
| 0    | `closed`     | 입술이 완전히 닫힌 상태                | 0              |
| 1    | `release`    | 입술 접촉이 풀리고 가는 틈이 생긴 상태 | 0.15~0.25      |
| 2    | `small-open` | 목표 모양을 향해 작게 열린 상태        | 0.3~0.45       |
| 3    | `half-open`  | 목표 모양의 절반 정도까지 열린 상태    | 0.5~0.7        |
| 4    | `open`       | `ㅏ/ㅓ` 발음에 맞게 완전히 열린 상태   | 1              |

턱은 입과 별도의 장식 애니메이션이 아니라 각 전이 프레임의 일부다. 프레임마다 승인된 `jawProgress`를
기록하고 같은 진행 곡선으로 재생한다. 닫힌 입에서 턱이 먼저 크게 내려가거나, 입이 다 열린 뒤 턱이
뒤늦게 이동하는 결과는 사용하지 않는다.

## 에셋 제작

### 1. 기준 얼굴 고정

- 장면별 승인된 원본 전체 이미지를 구도, 색, 얼굴 정체성과 목표 해상도의 기준으로 사용한다.
- 원본 레이어를 합성해 `closed`와 목표 입모양의 전체 캔버스 종점 이미지를 만든다.
- 입 중심, 양쪽 입꼬리, 아래입술, 턱 끝과 목 접합부 좌표를 기록한다.
- H3와 ChatGPT 이미지 생성 전에는 얼굴이나 입 주변을 자르지 않는다.
- 생성 프롬프트에서 입술, 입안과 필요한 최소 범위의 아래턱만 변경 대상으로 지정하고 나머지 장면은
  원본과 같게 유지한다.

### 2. MiniMax H3 전이 영상

ComfyUI에서 원본 전체 장면의 `closed` 이미지를 시작 프레임, 목표 입모양 이미지를 종료 프레임으로
사용해 전이별 짧은 영상을 만든다. 먼저 `day-reading-user`의 `closed → open` 한 경로를 파일럿으로
제작한다.

ComfyUI는 H3 영상 생성에만 사용한다. 이후 프레임 추출, 전체 이미지 보관과 사각 크롭에는 사용하지
않으며 모서리 블러나 페더를 추가하지 않는다.

- 카메라, 머리 위치, 눈, 코, 조명과 팔레트를 고정한다.
- 입술이 닫힘에서 목표 모양으로 한 번만 점진적으로 변하게 한다.
- 아래턱과 턱선은 입의 벌어짐을 따라 조금씩 내려가게 한다.
- 고개 회전, 눈 깜박임, 표정 교체, 모션 블러와 새 치아·혀 생성을 금지한다.
- 같은 조건으로 2개 이상 후보를 만들고 가장 연속적인 한 영상만 선택한다.

핵심 비짐은 `rest`에서 각 종점으로 가는 영상을 만들고, `closed → open`처럼 차이가 커서 팝이
보이는 경로는 별도 전이 영상을 추가한다. 모든 방향 조합을 미리 생성하지 않고 실제 대사 미리보기에서
불연속이 확인된 경로만 확장한다.

### 3. 프레임 추출과 정리

- 영상을 원본 프레임레이트의 무손실 PNG로 추출한다.
- 균일한 시간 간격이 아니라 입술 간격과 턱 위치가 고르게 진행하는 `release`, `small-open`,
  `half-open` 프레임을 선택한다.
- 추출한 프레임은 최종 에셋으로 사용하지 않고 입 벌어짐, 입꼬리와 턱 하강 정도를 판단하는 동작
  참고자료로 사용한다.
- ChatGPT 이미지 편집에는 원본 전체 이미지를 편집 대상, 선택한 H3 프레임을 입·턱 포즈 참고자료로
  함께 입력한다.
- 원본과 같은 전체 캔버스 크기로 생성하며 카메라, 구도, 배경, 조명, 팔레트, 캐릭터 위치와 얼굴
  정체성을 변경하지 않는다.
- 업스케일링이 필요하면 잘라낸 입 이미지가 아니라 전체 캔버스에 적용한다. 결과는 원본 해상도로 한
  번만 맞추고 원본과 색상 차이가 생기지 않았는지 확인한다.
- 생성 결과를 원본과 비교해 입·아래턱 밖의 변화, 머리 위치 이동과 색상 차이가 있는 후보는
  제외한다.

### 4. 입·턱 에셋 추출

- 승인된 전체 이미지에서 입술, 볼 아래쪽, 턱 끝과 목 접합부를 포함하도록 충분히 넓게 추출한다.
- 세부 마스크를 확정하기 전까지 전체 캔버스 원본과 생성 결과를 함께 보관한다.
- 수동 마스크 작업 전 전달본은 `x=930`, `y=285`, `260×180`의 완전 불투명 RGBA 사각 PNG로
  추출한다. 블러, 페더와 자동 배경 제거는 적용하지 않는다.
- 최종 합성에서는 마스크 밖을 원본 픽셀로 유지해 배경과 캐릭터의 나머지 부분이 바뀌지 않게 한다.
- 인접 단계의 입 중심, 입꼬리와 턱 끝이 한 방향으로 이동하는지 다시 확인한다.

최종 PNG는 장면과 같은 전체 캔버스 좌표를 유지한다. 런타임 WebP는 기존 자산 압축 절차로 만들며
원본 PNG와 선택 근거는 `asset-library/focus-room-source/`에 보관한다.

## 턱 처리

`day-reading-user`의 얼굴 각도에 맞는 턱 변위 마스크를 파일럿에서 확정한다. 기존
`night-reading-user` 마스크는 범위와 진행 방향을 정하는 참고자료로만 사용하며 다음을 검수한다.

- 변위는 아래입술 아래에서 시작해 턱 끝으로 갈수록 커져야 한다.
- 코, 눈, 광대와 머리카락은 변위 마스크에 포함하지 않는다.
- 턱선, 목과 옷깃의 접합부가 최대 열림에서도 찢어지거나 이중으로 보이지 않아야 한다.
- 입 패치와 머리 변위가 같은 아래입술 픽셀을 서로 다른 방향으로 중복 이동하지 않아야 한다.
- 장면별 얼굴 각도가 다르므로 한 장면의 마스크와 최대 이동량을 다른 장면에 그대로 복사하지 않는다.

픽셀 변위만으로 턱선이 늘어나거나 뭉개지면 더 강한 변위를 적용하지 않는다. 해당 단계의 아래턱이
포함된 전이 패치를 만들고, 기준 얼굴과의 접합 범위를 넓혀 해결한다.

## 런타임 연결

1. 발음 타임라인은 기존 여섯 `PViseme` 종점을 계속 반환한다.
2. 렌더러는 `from`, `to`, 전이 진행률로 전이 경로와 표시할 브리지 프레임을 결정한다.
3. 각 브리지 프레임의 `jawProgress`를 턱 채널에 함께 적용한다.
4. 인접 프레임 사이에 이중 입술이 보이면 긴 알파 크로스페이드를 사용하지 않고 프레임 선택 시점을
   조정한다.
5. 전환 도중 새 비짐이 들어오면 종점부터 다시 시작하지 않고 현재 표시 중인 단계에서 가장 가까운
   새 경로로 이어 간다.
6. 짧은 음절은 중간 단계를 일부 건너뛸 수 있지만 `closed → open`의 입술 해제 프레임은 우선
   보존한다.
7. `prefers-reduced-motion`에서는 중간 전환 애니메이션을 생략하고 승인된 종점 입모양과 턱 포즈를
   즉시 적용한다.

초기 시각 전이 시간은 100ms로 적용한다. 발음 선행 판단 50ms와 분리해 중간 프레임을 볼 수 있게 하고,
실제 합성 음성에서 80~140ms 범위를 비교한 뒤 필요하면 시각 전환 상수만 조정한다.

## 검수

`/dev/focus-room-layer-review`의 종점 선택 변경을 실제 런타임 전환 컨트롤러에 연결해 한 번 재생한다.
`마`, `마마`, `아마`, `음아`처럼 닫힘과 열림이 연속되는 짧은 대사와 실제 저장된 TTS 음성을 함께
검수한다.

완료 조건은 다음과 같다.

- `closed → open → closed`에서 입술, 입안과 턱이 한 방향으로 연속 이동한다.
- 중간 프레임에 이중 입술, 잔상, 새 치아·혀와 얼굴 정체성 변화가 없다.
- 마스크 밖 픽셀은 기준 얼굴과 동일하다.
- 입 중심과 머리 기준점은 최종 표시 크기에서 1px보다 크게 튀지 않는다.
- 턱 끝은 열리는 동안 단조롭게 내려가고 닫히는 동안 단조롭게 돌아온다.
- 최대 열림에서 턱선, 목과 옷깃의 접합부가 끊기지 않는다.
- 실제 재생 속도와 원본 크기에서 종점만 교체할 때보다 팝이 명확히 줄어든다.
- 전환 도중 다른 비짐으로 바뀌어도 처음 프레임으로 되돌아가는 점프가 없다.
- 2D 장면 애니메이션, 눈 깜박임과 머리 움직임을 함께 켰을 때 입과 턱이 머리를 정확히 따라간다.

## 구현 순서

1. 현재 `closed → open` 재생을 녹화해 팝과 턱 위치의 기준 자료를 남긴다.
2. `day-reading-user`의 원본 전체 장면과 `closed/open` 종점 이미지를 확정한다.
3. H3 파일럿 영상을 만들고 `release`, `small-open`, `half-open` 참고 프레임을 추출한다.
4. 원본 전체 장면과 각 참고 프레임으로 원본 해상도의 중간 단계 이미지를 생성한다.
5. 입·턱 밖의 장면 변화, 색상 차이와 얼굴 위치 이동을 비교해 후보를 승인한다.
6. 승인된 전체 이미지에서 입·턱 에셋을 추출하고 전체 캔버스 좌표로 합성해 접합부를 검수한다.
7. 전이 경로·프레임·`jawProgress` 메타데이터와 중단 후 재지정 가능한 런타임을 구현한다.
8. 리뷰 화면, 단위 테스트와 실제 TTS 미리보기로 `closed ↔ open`을 승인한다.
9. `closed ↔ wide/round`와 모양 축 전환을 우선순위대로 추가한다.
10. 장면별 턱 마스크와 입 좌표를 검수한 뒤 낮·밤 사용자 장면으로 확장한다.

`closed ↔ open` 파일럿 승인 후 `closed ↔ wide`, `closed ↔ round`, `open ↔ wide`, `open ↔ round`,
`narrow ↔ wide`, `narrow ↔ round`의 H3 영상과 3개 중간 전체 이미지를 제작하고 낮 사용자 장면의
런타임·리뷰에 연결했다. 수동 마스크가 끝나면 각 경로의 `lower-face-crops/*.png`를 같은 이름으로
교체하고 무손실 WebP로 다시 변환한다.
