### P2-1. 브라우저 오류 때문에 정상 Toss 자동 음성 설정을 복원하지 못함

- 위험: Apps in Toss에서 정상 native 설정이 남아 있어도 브라우저 복사본이 손상되거나 읽기가 불가능하면 자동 음성 모델·목소리 복원이 실패한다.
- 계약: [이슈 #2233](https://github.com/bichikim/web/issues/2233)은 Toss/web에서 같은 키로 복원·저장을 요구한다. 기존 브라우저 오류 표시는 유지해야 한다.
- 원인: 수정 전 [automatic-dialogue-settings.ts](/Users/bichi/.codex/worktrees/aa4c/web/apps/pomo/src/features/focus-room-dialogue/automatic-dialogue-settings.ts:60)의 `readWeb`가 엄격한 브라우저 codec의 예외를 그대로 전달했다. - 반증 가능한 검사: 실제 repository에 정상 native JSON을 제공하고, 브라우저의 malformed JSON 및 주입한 `getItem` 예외를 각각 제공한다. 두 경우 모두 정상 설정 복원을 기대한다.
- 수정 전 관찰: Wallaby 7개 중 기존 5개 통과, 새 2개 실패. 각각 한국어 decode 오류와 `browser storage unavailable`로 reject했다. 로그: `/private/tmp/aa4c-review-native-before.log`.

## 검증 범위와 이전 한계

1. 실제 Apps in Toss 기기·브리지는 실행하지 못했다. 저장소 복원과 실패 경로의 검증은 native Storage mock을 사용한다.
2. 3100에서 HTTP 200 및 실제 인앱 브라우저의 캐릭터 장면·포모도로·음악 플레이어 렌더링을 확인했다. 첫 화면 확인 시점의 error-level console log는 비어 있었다. 이후 관찰한 오류는 6번에 별도로 기록했다. 기존 SSR 해석 오류는 현재 재현되지 않았다. 이 관찰은 모든 UI 상태·센서·실제 음성 생성 및 배포 검증을 대신하지 않는다.
3. 수정 전 기본 400ms 실행에서는 시간 초과가 남았고, 진단 과정에서 명령에만 2초 제한을 지정해 8,482개 검사를 완료했다. 후속 시간 초과 수정 후에는 timeout 400ms·Worker 3개 기본 설정으로 전체 1,283개 파일·8,495개 테스트가 통과했다. 설정 override 없이 실행한 결과이며 CI 실행을 뜻하지 않는다.
4. 수정 전 Lunar의 기본 제한 분리 실행도 시간 초과했고 변경 전 HEAD 운영 코드를 주입한 실행은 334ms로 통과했다. 다른 실행의 시간 차이는 환경 부하와 함께 달라질 수 있어 브라우저 성능 회귀를 증명하지 않는다. 직접 관찰한 다른 프로세스의 CPU 사용과 긴 transform/import 비용을 기록했다. History의 분리 계측은 import 207ms·실제 함수 호출 및 검사 4ms였다. 실제 브라우저의 달력 상호작용 성능을 비교 측정하지 않았다.
5. Wallaby 최초 관련 테스트 63개 중 62개 통과, sound-joining 1개가 400ms 제한을 초과했다. 일반 Vitest 전체 단위 실행에서 동일 sound-joining 파일 9개는 통과했다. 후속 수정 뒤 관련 38개와 추가 UI 4개 Wallaby 검사가 모두 기본 400ms에서 통과했다. Wallaby 제한은 바꾸지 않았으며 전체 instrumented suite를 재실행한 것은 아니다. 시간 초과 자체를 제품 결함으로 분류하지 않는다.

6. 마지막 개발 서버/브라우저 로그에서 `ResizeObserver loop completed with undelivered notifications`가 4회 기록된 것을 확인했다. 현재 화면의 타이머·음악 플레이어는 렌더링되지만 오류의 재현 조건·사용자 영향·이번 변경과의 연관성은 확인하지 못했다. HMR 뒤의 Solid owner 및 Pixi texture binding 경고도 관찰했다. 경고나 로그만으로 별도 P2 또는 성능 회귀를 판정하지 않는다.
