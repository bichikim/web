# 열린 Pomo 리팩터링 이슈 통합 계획

기준: 2026-09-23, `origin/dev` (`6c250ef42`), GitHub `Refactor` 라벨의 열린 이슈 38건. 완료 이력은 [refactoring.md](./refactoring.md)에 있다. 이 문서는 작업 순서와 검증 범위를 기록한다. 이슈의 과거 `dev` 링크와 현재 코드를 대조한 뒤 각 항목을 수정한다.

## 작업 원칙

1. 각 묶음의 기존 테스트를 먼저 실행하고, 빠진 성공·실패·취소·정리·경합 동작을 테스트로 보강한다. 현재 동작을 보존해야 하는 테스트는 수정 전 통과시킨다.
2. 공유 계약을 바꾸는 경우 `graft callers`로 소비자를 확인하고, 가장 작은 공통 연산을 만든 다음 호출부를 전환한다.
3. 저장소의 읽기 우선순위, 실패 전파, 시각 비교, 비동기 순서, Blob URL 소유권은 각 호출부의 계약으로 유지한다.
4. 변경 묶음마다 관련 테스트, Pomo 타입 검사, oxlint, `pnpm format`을 실행한다. 마지막에는 영향 범위 전체를 재검증한다.
5. 변경하지 않는 항목은 이유와 증거를 기록한다. 유사한 문법만으로 의미가 다른 연산을 합치지 않는다.

## 완료 기준

- 각 이슈의 현재 코드 경로와 관련 테스트를 확인하고, 해당하는 수정 또는 변경하지 않는 근거를 기록한다.
- 단위 테스트에서 제외한 통합 테스트를 별도 실행 경로로 검증한다.
- 변경 경로의 테스트, 타입 검사, oxlint, 포맷이 통과한다.
- GitHub 이슈 상태와 배포 상태는 로컬 코드 검증과 별도로 보고한다.
