# mapInBatches

입력을 고정 크기의 묶음으로 나누고, 각 묶음의 작업이 모두 끝난 뒤 다음 묶음을 시작합니다. 작업이 하나 끝날 때마다 다음 항목을 시작하는 동시 실행 제한과 구분됩니다.

- 전체 입력은 첫 작업을 호출하기 전에 복사해 묶음으로 나눕니다. 항목 객체 자체는 복사하지 않습니다.
- 빈 입력에서는 작업을 호출하지 않습니다. 마지막 묶음은 `batchSize`보다 작을 수 있습니다.
- 중복 항목도 각각 처리하고, 완료 순서와 관계없이 입력 순서로 결과를 반환합니다. `null`이나 `undefined`를 제거하지 않습니다.
- `batchSize`는 양의 정수여야 합니다. 검증은 기존 `es-toolkit`의 `chunk`에 맡깁니다.
- 동기 예외는 Promise 거부처럼 처리하므로 해당 묶음의 모든 작업을 시작합니다. `Promise.all`이 먼저 관찰한 거부 사유로 거부하고, 이후 묶음을 시작하지 않습니다. 이미 시작한 작업은 취소하지 않습니다.
- 호출마다 독립적으로 실행합니다. 호출 사이의 전역 동시 실행 제한이나 잠금을 제공하지 않습니다.

AI 복구와 파일 정리 서비스가 사용합니다. 묶음 크기, 오류 기록과 복구, 결과 제외 정책은 소비자가 소유합니다. `Promise.all`과 기존 `chunk`를 재사용하며 새 의존성을 추가하지 않습니다. 내부 직렬 큐와 `settleSequentially`는 한 번에 한 작업을 실행하고, `limitAsync`는 빈 슬롯을 바로 채우므로 이 묶음 경계를 대신하지 않습니다.
