# createPendingTasks

이미 시작한 Promise의 완료를 추적합니다. 저장소 조정기의 병렬 쓰기 대기에 사용하며, 쓰기를 시작하거나 직렬화하지 않습니다.

- `track`은 입력 Promise를 그대로 반환합니다. 성공 값과 원래 거부 사유도 유지합니다.
- 성공·실패 후 등록을 해제합니다. 별도의 cleanup Promise 분기에서 생기는 거부만 처리합니다.
- `hasPending`은 아직 완료 정리가 실행되지 않은 등록 작업이 있는지 반환합니다. 이미 완료된 Promise도 등록 직후에는 추적하며, Promise 반응이 실행되면 해제합니다.
- `settle`은 호출 시 등록된 작업의 스냅샷만 기다리고, 개별 작업이 실패해도 성공합니다. 이후 추가되거나 완료 관찰자에서 등록한 작업은 그 대기에 포함하지 않습니다.
- 인스턴스마다 독립적으로 추적합니다. 중복 등록은 동일 Promise를 반환하며, 취소·재시도·결과 캐시·프로세스 간 조정을 제공하지 않습니다.

내장 `Set`과 기존 `Promise.finally`·`Promise.all` 조합을 사용합니다. 직렬 큐는 실행 순서를 제어하고 single-flight는 키별 중복 실행을 공유하므로 이 대기 계약과 다릅니다. revision·timestamp·저장소 권위와 쓰기 오류 정책은 소비자가 담당합니다.
