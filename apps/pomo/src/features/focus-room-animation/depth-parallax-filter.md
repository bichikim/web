# 모바일 장면 픽셀화 개선 계획

## 목표와 현재 근거

휴대폰에서 캐릭터의 피부·머리카락·옷이 블록처럼 보이는 현상을 조사한다. 원본 재제작이나 샤프닝보다 렌더링 과정의 결함 여부를 먼저 확인한다.

- 첨부 화면에서 확인한 문제는 단순한 선의 흐림이 아니라 픽셀처럼 뭉개지는 현상이다.
- 데스크톱에서 같은 머리 이미지를 같은 크기로 표시했을 때, 일반 이미지와 필터 없는 Pixi 캔버스 사이에 뚜렷한 차이는 관찰하지 못했다.
- 정지 장면과 움직임 중간 상태의 비교에서 추가적인 흐림은 관찰했지만, 이것으로 모바일의 블록 현상을 입증하지는 못했다.
- PixiJS의 기본 fragment 정밀도는 `mediump`이며, 변경 전 깊이 필터는 이를 별도로 지정하지 않았다. 테스트한 데스크톱에서는 `mediump`와 `highp` 모두 23비트였으므로 모바일 정밀도 문제의 재현 환경이 아니다.
- 발생 시점은 미상이다. 정밀도 기본값은 이전 버전에도 있어, 이번 변경을 최근 회귀의 원인에 대한 결론으로 취급하지 않는다.

근거: [깊이 필터 구현](./depth-parallax-filter.ts), [장면 렌더러](./scene-renderer.ts), [MDN의 WebGL 정밀도 지침](https://developer.mozilla.org/en-US/docs/Web/API/WebGL_API/WebGL_best_practices#be_precise_with_glsl_precision_annotations).

## 이번 PR의 범위

1. 깊이 필터의 `GlProgram.from` 옵션에 `preferredFragmentPrecision: 'highp'`만 추가한다.
2. 기존 테스트에서 이 옵션 전달을 검증한다.
3. 관련 테스트, lint, 포맷을 확인하고 실제 WebGL에서 셰이더 컴파일과 렌더링을 검증한다.

원본 이미지, 캔버스 크기와 해상도, 샘플링 방식, 다른 필터, 애니메이션, 의존성은 변경하지 않는다. 웹·모바일 웹·PWA·Apps in Toss·데스크톱에 공통으로 쓰는 필터의 옵션만 변경하되, 플랫폼별 시각적 개선은 각각 확인해야 한다.

## 실기기 확인과 완료 기준

동일한 휴대폰과 삼성 브라우저에서 변경 전후의 밤 독서 장면을 비교한다. 화면 크기, 확대 배율, 장면과 구도를 맞추고 정지 상태와 움직임 중의 화면을 각각 확인한다.

- 피부·머리카락·옷의 블록 현상이 줄어드는지 확인한다.
- 눈·입, 머리 움직임, 깊이 이동과 장면 전환이 정상인지 확인한다.
- 셰이더 오류와 눈에 띄는 성능 저하가 없는지 확인한다.

관련 테스트와 데스크톱 렌더링 통과는 코드 변경의 검증이며, 모바일 문제 해결의 증거가 아니다. 실기기 비교 전에는 개선 여부를 미확인으로 기록한다.

## 이번 변경의 검증 결과

- Wallaby로 깊이 필터와 장면 초기화·전환 관련 테스트 18개가 통과했다.
- 변경한 TypeScript 파일의 oxlint 검사와 저장소 포맷이 통과했다.
- 실제 WebGL 렌더링에서 깊이 필터의 fragment 정밀도는 `highp`, 다른 두 필터는 기존 `mediump`로 확인했다. WebGL 오류 값은 0이었으며 브라우저 콘솔 오류는 없었다.
- 휴대폰에서 픽셀화가 줄어드는지는 미확인이다.

## 개선되지 않을 때

1. 실기기의 WebGL 버전, fragment 정밀도, 캔버스 실제 크기와 텍스처 샘플링 상태를 수집한다.
2. 깊이·머리카락·호흡 필터를 각각 분리하여 블록 현상이 발생하는 단계를 좁힌다. 다른 필터의 정밀도 변경은 별도 비교로 검증한다.
3. 9월 21일 얼굴 레이어 교체와 9월 23일 PixiJS 8.19.0 → 8.21.0 변경을 같은 에셋·설정으로 비교한다. 변경 날짜를 발생 날짜로 단정하지 않는다.
4. 확인된 원인에 한해 후속 수정한다. 원인과 무관한 확대 보정이나 샤프닝을 먼저 추가하지 않는다.

이번 옵션 변경으로 문제가 생기면 해당 옵션만 제거하여 되돌린다.
