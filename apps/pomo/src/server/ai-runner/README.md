# Pomo AI runner

**현재 상태: 의도적인 출시 보류.** [출시 플래그](../../features/ai-job/release.ts)는 `false`다. 서버 AI 선택·결과 UI, 권한 조회·저장 작업 복원, API와 cron 호출, runner 기동을 막는다. 기기 내 Gemma는 유지한다. 아래 실행 예와 과거 검증 기록은 출시 준비용이며 현재 공개·가동 상태를 뜻하지 않는다. 이 차단은 버그나 미완성 연결이 아니므로 자동 수정·리팩터링으로 해제하지 않는다.

4단계의 두 runner 중 SQLite 구현을 통합 기준으로 삼았다. 기존 작업 디렉터리는 보존하고, 이 디렉터리의 runner와 5단계 UI를 하나의 checkout에 모았다. JSON 저장소 기반의 다른 runner는 함께 배포하지 않는다.

## 실행

저장소 루트에서 Node 24 이상으로 실행한다. 모델 다운로드와 추론은 별도 Worker에서 수행한다.

```sh
POMO_AI_RUNNER_TOKEN="$RUNNER_TOKEN" \
POMO_AI_RUNNER_STORAGE_PATH="$PWD/.data/ai-artifacts" \
node apps/pomo/src/server/ai-runner/index.ts
```

환경 변수는 [설정 코드](index.ts)와 [앱 환경 변수 예시](../../../.env.example)를 따른다. 앱의 `POMO_AI_RUNNER_URL`은 runner 주소를, 양쪽의 `POMO_AI_RUNNER_TOKEN`은 같은 인증값을 사용한다. 개발 중에는 `POMO_AI_RUNNER_STORAGE_PATH`로 로컬 저장 폴더를 지정할 수 있다. 로컬 파일 저장은 R2 연동 검증을 대신하지 않는다.

SQLite DB 파일당 프로세스를 하나만 운영한다. 시작 시 running 작업을 복구하므로 같은 DB를 사용하는 복수 프로세스를 띄우지 않는다. 동시 추론은 하나이며, 취소·시간 초과 때 Worker 종료를 기다린 뒤 슬롯을 반환한다. 프로세스별 복구 소유권을 관리하는 다중 replica 배포는 지원 범위가 아니다.

## 통합 검증

2026-09-21 로컬 환경에서 다음을 확인했다.

- AI 서비스·HTTP runner·SQLite·결과 계약·UI 관련 Wallaby 테스트 223개 통과. 실제 HTTP 클라이언트에서 파일 결과를 받아 UI 스키마로 해석하는 테스트와 취소 후 SQLite 재조회 테스트를 포함한다. 이 계약 테스트의 추론만 대체 구현을 사용한다.
- 종료 중 대기 작업 실행, 업로드 중 시간 초과의 성공 처리, SQLite 실행 슬롯 경쟁, 재시작 시 취소 요청 유실을 테스트로 재현하고 수정했다.
- 실제 Gemma q4 텍스트 생성 성공: 출력 상한 8토큰, 전체 약 7.05초. 짧은 출력의 동작 확인이며 품질 평가가 아니다.
- 실제 Supertonic int8 음성 생성·파일 저장 성공: 전체 약 8.04초, WAV 132,918바이트, ffprobe로 재생 길이 약 1.51초 확인.
- 실제 추론 측정은 기존 모델 캐시를 사용했다. 최초 다운로드 시간, 운영 부하, provider 청구 비용을 나타내지 않는다.

- Pomo typecheck와 web production build 통과. 포맷 적용 및 diff 공백 검사 통과. Pomo lint 오류 없음(변경하지 않은 기존 파일의 경고 2개는 남아 있음).
- 웹과 Apps-in-Toss 개발 시뮬레이션에서 대화 표시 설정을 켜고, 구독/API 응답을 테스트 데이터로 제공하여 서버 Luna 기본 선택 → 요청 1회 제출 → 취소 1회 호출 → 취소 안내 표시를 확인했다. 실제 결제 권한·provider 실행·네이티브 기기 검증을 대신하지 않는다.
- 브라우저의 전체 장면 로딩은 완료되지 않았으며, 개발용 가상 자격 증명에서 account 503·weather 500을 관찰했다. 이번 UI 검증은 대화 입력·서버 job 제어 범위에 한정한다.

## 6단계: 배포 전 기동 검증

시작 시 HTTP 포트를 확보한 뒤 작업을 복구한다. 포트 충돌에서는 복구하지 않으며, 초기화·복구 실패 시 열린 자원을 정리한다. 종료는 새 연결 수신을 멈추고 진행 중 HTTP 요청을 마친 뒤 추론과 SQLite를 닫는다. 반복 종료 호출은 같은 완료 결과를 기다린다. HTTP 종료 동작은 [Node 24의 server.close 계약](https://nodejs.org/docs/latest-v24.x/api/http.html#serverclosecallback)을 따른다.

`GET /v1/health`는 기존 job API와 같은 Bearer 인증을 사용하고 `{"protocolVersion":1,"status":"ok"}`를 반환한다. 모델 로딩, 외부 DB, R2 쓰기 또는 추론 준비 상태를 보증하지 않는 프로세스 응답 확인용 API다.

2026-09-21 실제 Node CLI를 환경 파일로 실행해 인증 없는 조회 401, 인증된 조회 200, 같은 포트의 중복 기동 실패, 기존 프로세스의 응답 유지, SIGTERM 정상 종료와 같은 DB 경로에서의 재기동을 확인했다. 이 실행에서는 추론 요청이나 외부 서비스 호출을 하지 않았다.

추가 회귀 테스트를 포함한 관련 테스트 228개, Pomo 타입 검사와 린트를 통과했고 포맷을 적용했다.

### 배포할 때 필요한 설정

1. runner를 실행할 서버와 HTTPS 주소를 정한다. 현 구현은 서버 한 대·SQLite 파일당 프로세스 하나를 전제로 한다. 다른 포트로 같은 DB를 열면 포트 충돌 방지가 적용되지 않으므로 복수 실행을 금지한다.
2. 서버에 저장소 의존성을 설치하고, 지속되는 DB·모델 캐시 디렉터리를 마련한다. 경로와 인증 토큰은 [환경 변수 예시](../../../.env.example)의 runner 항목을 따른다.
3. 실제 미디어 저장을 검증할 때는 runner와 Pomo 앱에 동일한 R2 bucket·prefix를 설정한다. runner의 `POMO_AI_RUNNER_STORAGE_PATH`는 비워 로컬 파일 저장이 선택되지 않도록 한다.
4. 서버의 비공개 환경 파일을 지정해 실행한다. 아래 경로는 운영자가 준비할 예시이며 자동으로 생성되거나 배포되지 않는다.

```sh
node --env-file=/etc/pomo-ai-runner/runner.env apps/pomo/src/server/ai-runner/index.ts
```

5. 앱에 runner HTTPS 주소와 같은 인증 토큰을 설정한다. `/v1/health`를 먼저 조회한 뒤 아래 실제 연결 검증을 수행한다. 앱 DB migration과 구독·quota 설정은 [운영 계약](../../../docs/ai-runner.md)을 따른다.

### 실제 연결 검증의 완료 조건

- 개발·스테이징 계정으로 구독 권한과 월 quota 예약/반환을 검증한다.
- 실제 provider에 제출한 job의 성공·취소·재조회와 앱 재시작 후 복원을 확인한다.
- 음성 결과가 R2에 저장되고, 소유자만 결과를 받아 재생·저장·삭제할 수 있는지 확인한다.
- cron의 복구·만료 처리와 실제 provider 사용량을 확인한다.

현재 통합 checkout에는 개발용 가상 환경 설정만 있다. 이번 점검에서는 runner URL·토큰, DB 연결, R2 자격 증명 및 대상 배포가 확인되지 않았으므로 위 실제 연결 검증은 미완료다. 실행 서버와 개발·스테이징 환경이 정해지면 이 순서로 진행한다. 비밀값은 채팅이나 저장소에 넣지 않고 해당 환경에 설정한다.

## 남은 운영 검증

실제 Neon·OpenAI·R2·cron을 연결한 전체 경로, 운영 구독/결제 데이터, 장시간 부하, 비용 정산, 모든 catalog 모델의 가중치·라이선스·품질 검증은 완료하지 않았다. 이번 성공만으로 local 모델의 production allowlist를 활성화하지 않는다. 운영 계약은 [AI job 운영 경계](../../../docs/ai-runner.md)를 따른다.

## 글로벌 배포 계획 — 미확정

한국 전용 서비스가 아니라 글로벌 서비스를 목표로 한다. 서울 배포를 전제로 한 이전 추천은 확정안으로 사용하지 않는다. 서버 구매나 실제 배포는 아직 진행하지 않는다.

1. 현재 Pomo API·DB의 실제 실행 지역과 예상 사용자 분포를 확인한다.
2. 미국·유럽 후보와 API 인접 지역의 전용 CPU 가격·가용성·API 왕복 지연을 비교한다. 한국과의 거리만으로 선택하지 않는다.
3. 현재 CPU 실행 모델을 기준으로 전용 4 vCPU·RAM 16GB·SSD 80GB 이상, runner 한 프로세스·동시 추론 하나를 초기 검증 사양으로 삼는다. 보장된 처리량이나 최종 운영 사양은 아니다.
4. Supertonic 다운로드 캐시와 작업마다 다시 로딩하는 모델의 재사용 방식을 검토한다. 대상 서버에서 메모리·응답 시간·대기 시간을 반복 측정한 뒤 증설 여부를 결정한다.
5. 이미지·음악 모델은 아직 runtime이 없으므로 별도 GPU 실행 경로와 비용을 검토한다. 현재 CPU 서버로 모든 모델을 운영할 수 있다고 가정하지 않는다.
6. 스테이징에서 provider·DB·R2·구독 권한·quota·cron·복구를 검증하고, 사용자가 공개를 지시한 후 출시 플래그와 cron 예약을 함께 활성화한다. 플래그 해제만으로 운영 검증이 완료되는 것은 아니다.

출시 재개 시 `vercel.json`에서 제거한 `/api/cron/ai-jobs`의 주기와 비용을 다시 결정한다. 환경 변수나 자격 증명을 채우는 것만으로 기능이 열리도록 변경하지 않는다. 구현 테스트에서만 출시 플래그를 mock으로 켜며, 비공개 상태 테스트는 실제 `false` 값을 검증한다.

### 비공개 상태 검증

2026-09-21 관련 테스트 327개, 타입 검사, 웹 빌드를 통과했다. 린트 오류는 없고 기존 다른 파일의 경고 2개는 남아 있다. 웹·Apps-in-Toss 개발 시뮬레이션에서 서버 실행 선택 UI와 자동 AI 요청이 없으며, 이전 job 기록이 있어도 복원하지 않는 것을 확인했다. 앱 서버의 권한·제출·상태·결과·취소·저장·삭제·cron 경로는 모두 404를 반환했다. 독립 runner CLI도 자원을 만들기 전에 출시 보류 오류로 종료했다. 이는 로컬 코드 검증이며 운영 배포나 토스 실기기 검증을 의미하지 않는다.
