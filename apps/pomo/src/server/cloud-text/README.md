# 클라우드 텍스트 사용 한도

한도 결정은 [read-user-limits.ts](./read-user-limits.ts)와 [resolve-limit.ts](./resolve-limit.ts)가 소유한다. 생성 API와 관리자 조회가 같은 계산을 사용한다.

## 유료 상품 정책

구매 처리는 아직 연결하지 않는다. 기존 commerce 상품과 구매 권한 기록을 재사용할 수 있도록 상품별 정책 저장 구조와 조회만 준비한다. 상품 등록 화면, 결제 요청, 결제 알림 검증, 구매 권한 발급은 이 기능의 범위에 포함하지 않는다. 어떤 유료 상품도 자동으로 등록하거나 무제한으로 전환하지 않는다.

상품별 정책은 [cloudTextProductLimits](../database/schema/cloud-text.ts)에 저장한다. 정책 행이 없는 상품은 클라우드 혜택을 주지 않는다. 정책의 숫자는 일일 횟수이고, `null`은 무제한이다. 실제 상품과 구체적인 유료 횟수는 상품 정책을 결정한 뒤 등록한다.

한도 우선순위는 관리자 지정, 유효한 상품 정책, 기본 무료 한도 순서다. 구매 권한은 시작 시각 이후이고 만료 전이며 취소되지 않아야 한다. 여러 권한은 횟수를 합산하지 않고 가장 큰 한도를 적용한다. 하나라도 무제한이면 상품 한도는 무제한이다. 구매가 만료·취소되면 다음 조회·예약부터 다른 유효 상품 또는 무료 기본 한도로 돌아간다.

결제 연동 시 서버가 확인한 구매만 기존 `commerce_entitlement_grants`에 발급한다. 사용자 입력이나 클라이언트의 유료 여부를 한도 판단에 사용하지 않는다. 취소·환불로 권한을 철회할 때에도 서버가 확인한 이벤트를 사용한다.

## 관리자 지정과 무제한

[update-limit.ts](./admin/update-limit.ts)는 사용자의 상품 정책보다 우선하는 예외를 저장한다. API의 숫자는 지정 횟수, `"unlimited"`는 무제한, `null`은 예외 삭제다. ‘기본값 복원’은 사용자 예외를 삭제하므로 구매 권한이 있으면 상품 정책으로 복원된다. 무료 한도 3회를 강제하려면 숫자 3을 저장한다.

DB에서는 사용자 예외 행의 부재와 무제한 행의 `daily_limit = null`을 구분한다. 응답의 `limit`과 `remaining`이 모두 `null`이면 무제한이다. 제한 계정은 두 필드가 모두 숫자여야 한다. 무제한을 임의의 큰 숫자나 `Infinity`로 표현하지 않는다.

무제한은 일일 횟수 제한에만 적용한다. 요청 크기, 출력 토큰 제한과 생성 제한 시간은 그대로 적용한다. 생성 기록·중복 요청 판단·실패 처리·오늘 사용 초기화도 유지한다. 유료 정책 변경이나 만료가 오늘의 사용 기록을 지우지는 않는다.

## 후속 연결 지점

상품 정책 등록 UI와 결제 연결이 추가되면 이 저장·조회 계약을 재사용한다. 권한 발급·철회와 사용자 예외 변경은 생성 예약과 동일한 사용자 행 잠금 순서로 처리해 정책 변경과 생성 시작을 조정한다. 이미 예약한 생성은 완료하도록 두고, 이후 예약부터 새 정책을 적용한다.
