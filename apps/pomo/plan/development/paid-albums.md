# 유료 음악과 앨범 관리

[개발 기술 계획으로 돌아가기](../development.md)

## 목표

관리자가 웹에서 앨범과 곡을 등록하고, 사용자가 구매한 앨범만 재생할 수 있도록 한다. 음원은
별도의 비공개 Cloudflare R2 버킷에 저장하고, 앨범·곡·구매 권한은 Neon DB에서 관리한다.

관리 화면은 일반 웹 SSR에만 제공한다. 공개 카탈로그, 구매와 재생은 일반 웹과 앱인토스가 같은
서버 API를 사용한다. 앱인토스 일회성 구매와 웹 외부 체크아웃이 같은 앨범 권한을 지급하도록
결제 제공자와 콘텐츠 권한을 분리한다. 월 결제는 도입 여부만 검토하고 최초 구현에는 포함하지
않는다.

## 기존 구조와 전환

현재 무료 음악은 `tracks.json`, `albums.json`, `playlist.json`을 정적 데이터로 사용한다. 유료
앨범은 공개 URL과 정적 JSON만으로 구매 권한을 보호할 수 없으므로 DB 카탈로그와 인증된 재생
흐름을 추가한다.

무료 기본 카탈로그는 DB로 이전하지 않고 JSON을 계속 기준으로 사용한다. `playlist.json`에는 무료
기본 곡만 넣는다. DB에는 관리자 화면에서 등록한 유료 앨범과 곡만 저장한다.

1. 무료 JSON 카탈로그와 유료 DB 카탈로그를 각각 검증해 읽는다.
2. 무료 slug ID를 보존하고 유료 앨범·곡은 UUID를 사용한다.
3. 두 카탈로그를 합칠 때 전체 범위의 ID 충돌을 검사한다.
4. 유료 API가 실패해도 무료 JSON 음악과 기본 재생목록은 계속 사용할 수 있게 한다.
5. 구매한 유료 앨범은 사용자가 명시적으로 재생목록에 추가한다.

사용자 재생목록의 로컬 저장과 복원 규칙은 유지하고, 저장된 곡 ID가 최신 카탈로그에 없으면
기존 복원 규칙대로 건너뛴다.

### 공통 카탈로그 모델

현재 JSON의 공개 `source`와 유료 곡의 만료되는 재생 접근 정보를 같은 고정 문자열로 취급하지
않는다.
무료 JSON 로더와 유료 API 로더는 다음 공통 소스 형태로 변환한다.

```ts
type TrackSource =
  | {readonly kind: 'public'; readonly url: string}
  | {readonly kind: 'entitled'; readonly trackId: string}
```

`public`은 현재 `storage.pomofi.io` 주소를 그대로 사용한다. `entitled`는 재생 직전에 사용자 권한을
확인하고 짧은 재생 토큰이 포함된 오디오 게이트웨이 URL을 발급하며, 만료 전에 갱신한다. 재생목록과
재생 위치에는 URL이 아니라 안정적인 곡 ID만 저장한다.

앨범은 동적 CSS 아이콘 클래스 대신 다음 표지 모델을 사용한다.

```ts
interface AlbumArtwork {
  readonly coverFallback: 'lp' | 'cd' | 'music'
  readonly coverImageUrl?: string
}
```

`coverImageUrl`이 있으면 앨범 커버로 표시한다. 주소가 없거나 이미지 로딩이 실패하면
`coverFallback`에 따라 LP판, CD 또는 기본 음악 아이콘을 표시한다. 새 앨범의 기본값은 `lp`로
한다. 기존 `albums.json` v1의 `icon`은 전환 호환을 위해 읽되 공통 모델의 `music` 대체 표현으로
변환한다. 기존 JSON을 새 스키마로 갱신할 때 `icon`을 제거하고 `coverImageUrl`과
`coverFallback`을 사용한다.

현재 코드는 `PTrack.source`를 문자열, `PAlbum.icon`을 필수 문자열로 검사하므로 새 모델과 바로
호환되지는 않는다. 구현 10단계 전까지 v1 JSON은 수정하지 않는다. 이후 무료 v1 로더의 결과를
공통 모델로 변환하고, 유료 `entitled` 소스를 재생 URL로 해석하는 계층을 플레이어 앞에 둔다.
기존 재생 복원은 이미 `trackId`를 저장하므로 그대로 호환된다. JSON 자체를 v2로 바꾸는 일은
로더와 테스트가 v1·v2를 함께 지원한 뒤 별도 전환으로 진행한다.

## 결제와 권한 모델

앨범, 판매 상품, 판매 채널, 주문과 재생 권한을 서로 분리한다. 앱인토스 SKU나 웹 결제 Price ID를
앨범 행에 직접 저장하지 않는다.

```text
앨범 ← 내부 상품 ← 판매 채널별 오퍼 ← 주문·주문 항목 → 권한 지급
```

- 내부 상품은 사용자가 무엇을 얻는지를 정의한다. 한 상품이 앨범 하나나 묶음 앨범을 지급할 수
  있다.
- 오퍼는 어디서 어떤 방식으로 파는지를 정의한다. 같은 상품에 앱인토스 SKU와 웹 Checkout
  Price를 각각 연결할 수 있다.
- 주문은 결제 제공자의 주문을 내부 사용자와 연결하고 결제 당시 금액과 통화를 보존한다.
- 권한 지급은 주문 항목이 사용자에게 제공한 접근 기간을 기록한다. `endsAt`이 없으면 영구
  권한이고, 값이 있으면 그 시각까지만 유효하다.
- 사용자는 같은 앨범에 여러 권한 지급을 가질 수 있다. 하나라도 유효하면 재생할 수 있으므로 웹과
  앱인토스에서 중복 구매하거나 나중에 구독을 추가해도 기존 영구 권한을 덮어쓰지 않는다.

모든 주문과 권한은 결제 제공자의 사용자 ID나 이메일이 아니라 내부 `pomo_users.id`에 연결한다.
웹과 앱인토스의 계정이 같은 Pomo 사용자로 연결된 경우에만 두 채널의 구매 권한을 공유한다.

`Link`가 Stripe Link를 뜻하면 별도 제공자가 아니라 Stripe Checkout 안의 결제수단으로 기록한다.
Stripe Payment Link처럼 공유 URL을 뜻해도 오퍼와 주문 구조는 같다. 다만 디지털 권한은 로그인한
Pomo 사용자에게 귀속해야 하므로, 웹 구매는 서버가 인증된 사용자를 연결한 Checkout Session을
만들거나 제공자가 검증한 동일 수준의 참조값을 사용한다. 성공 화면이나 클라이언트 응답만으로
권한을 지급하지 않고 서명이 검증된 webhook과 제공자 주문 조회를 기준으로 처리한다.

참고:

- [Stripe Link with Checkout](https://docs.stripe.com/payments/link/checkout-link)
- [Stripe Payment Links](https://docs.stripe.com/payment-links)
- [Stripe Checkout fulfillment](https://docs.stripe.com/checkout/fulfillment)

## R2 저장소

새 버킷 이름은 `pomofi-paid-audio`로 한다. 버킷은 비공개로 유지하고 `r2.dev`와 공개 사용자 지정
도메인을 연결하지 않는다. Vercel에는 이 버킷의 객체만 읽고 쓸 수 있는 최소 권한 자격 증명을
등록한다.

R2와 DB는 따로 설계하지 않는다. R2는 MP3 원본 바이트의 기준이고 DB는 어떤 R2 객체가 현재
재생 가능한 자산인지 판단하는 기준이다. MP3 자산 행에는 Presigned URL이나 공개 URL을 저장하지
않고, 서버가 생성한 객체 키와 검증된 객체 메타데이터만 저장한다. 버킷 이름은 환경 설정으로
선택하고 DB에는 운영·개발 버킷 이름 대신 `paid-private` 같은 저장소 역할을 기록한다. 공개
앨범 커버의 `coverImageUrl`은 이 규칙의 대상이 아니다.

객체 키는 교체와 롤백이 가능하도록 덮어쓰지 않는 자산 경로를 사용한다. `assetId`는 업로드
예약 전에 DB에서 만든 UUID이므로 같은 곡의 동시 업로드도 서로 다른 키를 사용한다.

```text
tracks/{trackId}/{assetId}/source.mp3
```

앨범 커버는 구매 전 사용자도 볼 수 있는 공개 카탈로그 자산이므로 비공개 유료 MP3 버킷에 넣지
않는다. 관리자가 업로드한 커버는 기존 `pomofi-audio` 공개 자산 저장소의 버전 경로에 저장하고
`storage.pomofi.io` 사용자 지정 도메인의 HTTPS 주소를 `coverImageUrl`로 기록한다. 외부 이미지
장애가 앨범 목록을 막지 않도록 항상 로컬 대체 표현을 함께 둔다. 선택한 JPG·PNG·WebP 원본은
관리자 브라우저에서 중앙 정사각형으로 자르고 1200×1200, 품질 0.85 WebP로 변환한 결과만
미리보기와 R2 업로드에 사용한다. 서버는 변환 결과의 형식과 크기 제한을 다시 검증한다.

같은 키를 덮어쓰지 않는다. MP3 교체 시 새 자산 버전을 업로드하고 검증한 뒤 DB의 현재 자산
참조만 원자적으로 바꾼다. 이전 자산은 즉시 삭제하지 않고 `retired`로 전환해 진행 중인 재생과
롤백을 보호한 뒤 유예 기간 후 정리한다.

공개 커버는 변환된 4MiB 이하 WebP를 Pomo API가 받아 크기를 강제한 뒤 R2에 저장한다. 브라우저에
R2 쓰기 권한을 주는 URL은 반환하지 않는다. 이후 비공개 MP3 업로드에는 R2 S3 API의 Presigned
PUT URL과 업로드 완료 검증을 사용한다. 사용자 재생에는 Presigned GET을 사용하지 않는다. Pomo
API가 구매 권한과 현재 `active` 자산을 확인한 뒤 자산 ID, 불변 객체 키와
만료 시각을 HMAC으로 서명한 짧은 재생 토큰을 발급한다. 토큰은 전달받은 사람이 만료 전까지 사용할
수 있는 bearer 권한이므로 로그에 전체 URL과 토큰을 남기지 않는다.

오디오 요청은 `audio.pomofi.io/tracks/{assetId}/source.mp3?token=...` 형태로 Cloudflare Worker에
전달한다. Worker는 R2 바인딩으로 비공개 버킷을 읽으며 다음 순서를 지킨다.

1. 캐시를 조회하기 전에 토큰 서명, 만료, URL의 자산 ID와 서명된 불변 객체 키의 일치를 검증한다.
2. 토큰과 쿼리 문자열을 제외한 불변 객체 키를 CDN 캐시 키로 사용한다.
3. 전체 `200` 응답을 캐시에 저장하고 `Range` 요청은 캐시된 `Content-Length`를 기준으로 `206`으로
   처리한다. 전체 요청의 첫 캐시 미스에서는 객체를 스트리밍해 캐시를 채운다. `Range` 요청의 첫
   미스에서는 R2 범위 읽기로 `206`을 즉시 반환하고 전체 객체는 백그라운드에서 캐시에 저장한다.
4. 캐시 미스일 때만 R2 `GetObject`를 실행한다. 객체가 없거나 토큰이 잘못되면 캐시하지 않는다.
5. 자산 키를 덮어쓰지 않으므로 긴 edge TTL을 사용하고, 교체는 새 `assetId` URL로 자연스럽게
   캐시를 분리한다.

Cloudflare Cache API는 데이터센터별 캐시이므로 Worker 요청은 매번 실행되지만 DB와 R2 조회는
대부분 생략할 수 있다. 권한 판정은 토큰 발급 시 한 번만 수행하고 Worker는 DB에 연결하지 않는다.
전역 Tiered Cache가 필요해질 때만 별도 공개 원본·WAF 또는 상위 캐시 계층을 검토한다.

브라우저 직접 업로드를 위해 R2에는 운영 웹, Vercel Preview와 로컬 개발 출처의 `PUT`, `HEAD`만
허용한다. 사용자 재생의 `GET`, `HEAD`, `Range` CORS는 오디오 Worker가 운영 웹과 앱인토스 출처에
대해 처리한다. 만료된 토큰은 재생 전에 갱신한다.

### DB–R2 자산 생명주기

Neon 트랜잭션과 R2 객체 작업은 하나의 원자적 트랜잭션으로 묶을 수 없으므로 다음 상태 전이를
사용한다.

```text
pending → uploaded → ready → active → retired → deleted
pending/uploaded → failed
```

1. 서버가 `pending` 자산 행과 충돌하지 않는 객체 키를 먼저 만든다.
2. 관리자에게 해당 키와 `audio/mpeg`으로 제한한 Presigned PUT URL을 발급한다.
3. 업로드 완료 요청에서 R2 `HEAD`로 객체 존재, 크기, 콘텐츠 형식과 ETag를 읽고 `uploaded`로
   전환한다. `HEAD` 값은 실제 파일 바이트가 MP3라는 증거로 사용하지 않는다.
4. 신뢰할 수 있는 서버 작업이 파일 헤더와 디코딩 가능 여부, 실제 재생 시간과 허용 크기를
   검사한다. 통과하면 검증값을 기록하고 `ready`, 실패하면 오류 코드와 함께 `failed`로 전환한다.
5. 교체 트랜잭션은 트랙을 잠근 뒤 기존 `active` 자산을 `retired`, 새 `ready` 자산을 `active`로
   전환한다. 트랙별 `active` 자산은 최대 하나라는 부분 고유 제약을 둔다.
6. `retired` 자산은 유예 기간과 참조 재검사를 거쳐 R2에서 삭제한다.
7. R2 삭제 성공 후 `deleted`와 삭제 시각을 기록한다. 실패하면 같은 작업을 다시 시도한다.

업로드 후 DB 갱신이 실패한 객체, DB에는 있지만 R2에 없는 객체와 오래된 `pending` 자산을 찾는
재조정 작업을 둔다. 재조정은 `active` 객체를 자동 삭제하지 않고 오류로 보고한다. 완료된 음원은
DB 상태를 확인해야 삭제할 수 있으므로 R2 만료 규칙을 적용하지 않는다. R2 생명주기 규칙은
미완료 multipart 업로드 정리에만 사용하고, 자산 삭제는 애플리케이션 작업이 담당한다. 삭제와
교체 작업은 재시도해도 같은 결과가 되도록 만든다.

| `music_track_assets`       | UUID, 곡 UUID, 저장소 역할, 고유 객체 키, 상태, 형식, 바이트 크기, 불투명 ETag, 검증된 재생 밀리초, 상태별 시각과 실패 코드 |

`music_track_assets`의 형식은 `audio/mpeg`, 크기와 검증된 재생 시간은 양수여야 한다. ETag는 변경 감지와
감사 값으로만 보존하며 파일 해시라고 가정하지 않는다. 트랙 길이는 현재 `active` 자산의 검증된
밀리초를 API에서 `durationSeconds`로 변환한다. 앨범은 수록곡과 판매 오퍼가 없어도 공개할 수 있다.
단, 수록곡이 하나라도 등록됐다면 모든 곡에 정확히 하나의 `active` 자산이 있어야 `published`를
허용한다.

이 DB 테이블에는 무료 JSON 카탈로그를 복제하지 않는다. 유료 앨범 상태는 `draft`, `published`,
`archived`로 관리하고 음원 생명주기는 자산 행에서만 관리한다. 최초 출시의 `commerce_offers`에는
`one_time` 오퍼만 생성하고 `subscription`은 월 결제를 승인한 뒤 활성화한다.

관리자 화면은 한국어 원문과 영어·일본어·간체 중국어 제목·설명을 모두 편집할 수 있게 한다.
한국어 제목·설명은 필수이며 나머지 언어의 제목·설명은 선택 입력이다.
Gemma 4 E2B 번역은 관리자 브라우저의 WebGPU에서 요청할 때만 실행하고 세 대상 언어를 편집 가능한
초안으로 채운다. 번역 결과는 자동 공개하지 않으며 고유명사와 문체를 검토한 뒤 앨범 초안과 함께
저장한다. 표시 언어가 없으면 한국어, 그마저 없으면 첫 번째 등록 언어로 대체한다.

주문 상태는 `pending`, `paid`, `partially_refunded`, `refunded`, `canceled`, `failed`로 정규화한다.
결제 제공자가 최소 화폐 단위와 소수 자릿수를 다르게 표현해도 제공자 어댑터가 이 형태로 바꾸며,
원래 통화와 금액 스냅샷은 변경하지 않는다. 전액 환불만 해당 주문의 권한을 회수하고 부분 환불의
권한 정책은 웹 제공자 확정 시 별도로 결정한다.

`commerce_orders`의 `(provider, providerOrderId)`와 `commerce_provider_events`의
`(provider, providerEventId)`에는 각각 고유 제약을 둔다. 같은 주문이나 이벤트가 다시 도착해도
권한 지급이나 회수가 한 번만 반영되도록 한다. 환불된 주문과 권한은 삭제하지 않고 상태와 처리
시각을 보존한다. 앱인토스 상태 조회처럼 제공자 이벤트 ID가 없는 동기화 응답은 검증된
`orderId`, 상태와 상태 시각으로 결정적인 처리 키를 만들어 중복을 막는다.

권한 판정은 요청 사용자에게 연결된 상품 중 `startsAt <= now`, `endsAt`이 없거나 미래이고
`revokedAt`이 없는 지급이 하나라도 있는지 확인한 뒤 그 상품의 앨범 포함 관계를 조회한다. 전액
환불은 해당 주문 항목의 지급만 회수한다. 다른 채널에서 받은 영구 또는 기간 권한은 변경하지
않는다.

### 쓰기 원칙

- 외부 요청과 R2 작업은 DB 트랜잭션 안에서 기다리지 않는다. 제공자 주문·이벤트 ID와 자산 상태를
  멱등성 키로 사용해 짧은 DB 트랜잭션으로 결과만 반영한다.
- 상태 갱신은 예상 이전 상태를 조건에 포함한다. 이미 처리된 동일 결과는 성공으로 반환하고,
  다른 결과와 충돌하면 운영 검토 대상으로 남긴다.
- 주문의 금액·통화·상품 스냅샷과 권한 이력은 수정하거나 삭제하지 않는다. 환불과 회수는 새 상태와
  시각으로 기록한다.
- `pomo_users.deleted_at`이 설정된 사용자는 새 구매와 재생 토큰 발급을 거부하되 회계·권한 이력은
  보존한다.

월 결제를 도입하면 `commerce_subscriptions`를 추가해 제공자 구독 ID, 상태와 현재 이용 기간을
관리한다. 갱신 결제마다 기존 `commerce_orders`와 기간이 있는 권한 지급을 생성하므로, 일회성
구매 경로와 재생 권한 판정은 바꾸지 않는다. 구독 테이블과 결제 UI는 월 결제를 결정하기 전에는
구현하지 않는다.

`/admin` 대시보드에 `음악 / 앨범 관리` 카드를 추가한다. 카드 전체를 키보드로 선택할 수 있는
링크로 만들고 선택하면 `/admin/music`으로 이동한다.

`/admin/music`은 다음 기능을 제공한다.

- 앨범 초안 생성과 기본 정보 수정

- 커버가 없을 때 사용할 LP판·CD·음악 아이콘 선택

- 음원 업로드 진행률, 실패와 재시도 표시
- 앨범에 곡 추가, 제거와 순서 변경
- 내부 상품과 앱인토스·웹 판매 오퍼 연결

- 초안 저장, 공개와 보관

## 업로드 흐름

1. 관리자가 앨범 초안과 곡 메타데이터를 생성한다.
2. 서버가 파일 형식과 크기를 확인하고 서버가 결정한 객체 키로 Presigned PUT URL을 발급한다.
3. 브라우저가 파일을 R2로 직접 업로드하며 진행률을 표시한다.
4. 업로드 완료 API가 R2 `HEAD`로 객체 존재와 메타데이터를 확인해 `uploaded`로 전환한다.
5. 서버 미디어 검사가 실제 MP3와 재생 시간을 검증해 `ready` 또는 `failed`로 전환한다.
6. 관리자가 `ready` 자산을 활성화하면 기존 자산과 원자적으로 교체한다.
7. 앨범 공개 시 곡 상태, 순서, 커버와 판매 상품 연결을 다시 검증한다.

브라우저가 보낸 객체 키, 업로드 성공 여부와 재생 시간을 그대로 신뢰하지 않는다. 실패하거나
중단된 업로드는 재시도할 수 있게 하고, 참조되지 않은 객체는 유예 기간 후 별도 정리한다.

## 카탈로그와 재생

공개 카탈로그 API는 공개된 앨범과 곡 메타데이터만 반환하며 R2 객체 키와 자격 증명을 노출하지
않는다. 유료 곡을 선택하면 서버는 다음 순서로 재생 접근 정보를 발급한다.

1. 웹 또는 앱인토스 사용자 세션을 확인한다.
2. 앨범의 공개 상태와 사용자의 유효한 권한을 확인한다.
3. 현재 `active` 자산의 ID와 불변 객체 키를 담은 짧은 HMAC 재생 토큰을 발급한다.
4. 토큰을 쿼리에 포함한 안정적인 오디오 게이트웨이 URL과 만료 시각을 반환한다.
5. 플레이어는 만료 전에 토큰을 갱신하고 다음 곡에서도 새 접근 정보를 요청한다.

권한이 없는 사용자는 카탈로그와 미리보기 정보만 볼 수 있고 원본 음원 URL은 받을 수 없다.
오디오 탐색을 위한 Range 요청은 브라우저와 실제 토스 WebView에서 검증한다.

서버 API 경계는 다음과 같이 고정한다. 경로 이름은 구현 시 SolidStart 라우트 규칙에 맞추되 책임을
합치지 않는다.

| 경계                | 책임                                                                                 |
| ------------------- | ------------------------------------------------------------------------------------ |
| 관리자 카탈로그 API | 앨범·곡 초안, 곡 순서, 커버, 상품·오퍼와 공개 상태 관리                              |
| 자산 API            | 자산 예약과 Presigned PUT 발급, 업로드 완료 확인, 미디어 검증 상태 조회, 활성화·폐기 |
| 사용자 카탈로그 API | 공개 유료 메타데이터와 현재 사용자의 `owned`\|`locked` 상태 반환                     |
| 재생 API            | 세션·앨범·권한·`active` 자산을 확인하고 한 곡의 서명 토큰·게이트웨이 URL·만료 반환   |
| 오디오 Worker       | 토큰을 검증하고 안정적인 자산 키로 CDN 캐시 조회 후 미스에서만 비공개 R2 읽기        |
| 결제 어댑터         | 제공자 응답을 내부 주문 상태로 정규화하고 주문·권한 트랜잭션 호출                    |

앨범 목록은 무료 JSON 결과와 유료 API 결과를 합쳐 표시한다. 유료 API 오류는 유료 영역에만
표시하고 무료 앨범 로딩을 실패시키지 않는다. 권한이 없는 유료 앨범은 커버와 구매 정보만
표시하며 플레이어 추가 동작은 구매 흐름으로 연결한다.

## 앱인토스 일회성 결제

앨범은 한 번 구매하면 계속 이용하는 비소모성 인앱 상품으로 등록한다. `processProductGrant`에서
클라이언트가 보낸 성공 여부를 신뢰하지 않고 `orderId`를 서버로 전달한다. 서버는 mTLS 주문 상태
조회로 주문과 SKU를 확인하고 주문·주문 항목·종료 시각이 없는 권한을 한 트랜잭션으로 기록한 뒤
지급 성공을 반환한다. 이후 `completeProductGrant`를 호출한다. `getPendingOrders`로 미지급 주문을
복구하고 `getCompletedOrRefundedOrders` 또는 서버 API로 완료·환불을 동기화한다.

결제 화면이 열린 동안 음악을 일시 정지하고 결제가 끝나면 기존 재생 상태를 복원한다.

참고: [앱인토스 일회성 인앱 결제](https://developers-apps-in-toss.toss.im/bedrock/reference/framework/%EC%9D%B8%EC%95%B1%20%EA%B2%B0%EC%A0%9C/IAP.html)

## 웹 결제

웹 결제 제공자는 아직 확정하지 않는다. Stripe Checkout·Link·Payment Links 또는 같은 방식의
호스팅 체크아웃을 후보로 두되 다음 계약을 만족해야 한다.

- 로그인한 Pomo 사용자와 Checkout을 서버에서 안전하게 연결할 수 있다.
- 일회성 결제 완료와 환불을 서명된 webhook 또는 서버 간 조회로 확인할 수 있다.
- 제공자 이벤트의 고유 ID로 중복 처리를 막을 수 있다.
- 내부 상품 ID와 제공자 Price·상품 ID를 분리할 수 있다.

웹 결제수단이 카드, Stripe Link나 다른 지갑으로 바뀌어도 `provider`는 결제 계약 주체를 나타내고
세부 결제수단은 주문의 선택적 감사 정보로만 보존한다. 결제수단에 따라 앨범 권한 모델을 나누지
않는다.

## 월 결제 검토

월 결제는 최초 범위에서 제외한다. 도입 결정 전에 단일 앨범 구독인지 전체 카탈로그 구독인지,
웹과 앱인토스 간 구독 권한을 합칠지, 유예 기간·해지·환불 시 권한 종료 규칙을 먼저 결정한다.
현재 주문과 권한 지급 구조는 `endsAt`이 있는 기간 권한을 지원하므로 이 검토 결과를 수용할 수
있다.

## 구현 순서

1. **자동 검증 완료, 실기기 검증 대기** — 토스 Sandbox에서 `TossAuth.login()`의 `SANDBOX`
   인가 코드를 서버가 교환하고,
   `pomo_users`와 `pomo_identities(provider = 'toss')`가 생성되는지 검증한다. 자동 테스트는 항상
   실행하고, mTLS 환경 변수와 Sandbox 앱이 준비되면 실기기 왕복 검증까지 완료한다.
2. **완료** — 음악·자산 카탈로그와 결제·권한 DB 마이그레이션을 개발 DB에 적용하고 새 테이블과
   제약을 확인한다.
3. **버킷 생성 완료** — `pomofi-paid-audio` R2 버킷을 비공개로 만들고 `r2.dev`와 공개 사용자 지정
   도메인이 연결되지 않았는지 확인한다. 이후 업로드 구현 전에 최소 권한 자격 증명과 허용 출처
   CORS를 설정한다.
4. **초기 등록 기능 완료** — 관리자 API가 Neon Auth `admin` 역할을 직접 검사하도록 만들고,
   `/admin`의 `음악 / 앨범 관리` 카드와 `/admin/music`의 앨범·곡 등록 및 서버 검증형 공개 R2
   커버 이미지 업로드 기능을 구현한다.
5. **완료** — R2 자산 예약, Presigned PUT, 업로드 확인, 서버 MP3 검사와 활성화·교체 흐름을
   연결한다.
6. 앨범 수정·곡 순서·상품·판매 오퍼·공개 검증과 보관 기능을 완성한다.
7. 공개 카탈로그, 권한 기반 재생 토큰 API와 캐시형 Cloudflare 오디오 Worker를 구현한다.
8. 앱인토스 비소모성 일회성 결제, 복구와 환불 흐름을 연결한다.
9. 선택한 웹 Checkout의 일회성 결제와 환불 흐름을 연결한다.
10. 무료 JSON과 유료 API를 합성하는 카탈로그 어댑터와 플레이어 소스 해석기를 연결한다.

## 검증

- 일반 사용자와 비로그인 사용자가 관리자 화면과 API를 사용할 수 없는지 확인한다.
- 허용하지 않은 파일 형식, 크기, 객체 키와 완료되지 않은 업로드를 거부한다.
- DB–R2 불일치, 중단된 업로드, 교체 실패와 삭제 재시도를 안전하게 복구한다.
- 수록곡이 없는 앨범의 공개를 허용하고, 수록곡이 있다면 활성 음원이 없는 곡이 하나라도 있을 때
  공개를 거부한다.
- 유료 API가 실패해도 무료 JSON 카탈로그와 기본 재생목록을 사용할 수 있게 한다.
- 무료 slug와 유료 UUID의 충돌을 거부하고 저장된 곡 ID 복원을 유지한다.
- 커버 주소 누락과 이미지 로딩 실패에서 선택한 LP판·CD·음악 아이콘을 표시한다.
- 미구매 사용자는 유료 재생 토큰을 받지 못하고 구매 사용자는 재생과 탐색을 할 수 있게 한다.
- 사용자별 토큰과 쿼리 문자열이 CDN 캐시 키를 분할하지 않고, 캐시 히트에서 R2 읽기가 발생하지
  않게 한다.
- Worker가 토큰을 검증하기 전 캐시 응답을 반환하지 않고 다른 자산 URL에 토큰을 재사용할 수 없게
  한다.
- 만료된 URL을 갱신하고 로그나 카탈로그 응답에 서명된 URL이 남지 않게 한다.
- 앱인토스와 웹의 결제 이벤트 중복, 중단 후 복구와 환불을 멱등하게 처리한다.
- 같은 사용자가 서로 다른 판매 채널에서 산 권한이 충돌하거나 기존 영구 권한을 줄이지 않게 한다.
- 성공 URL만 호출하거나 위조한 제공자 이벤트로 권한을 만들 수 없게 한다.
- 관리자 로그인부터 카드 이동, 앨범 생성, 업로드와 공개까지 브라우저 E2E로 검증한다.
- 구매, 백그라운드 전환과 재생 복원을 실제 토스 WebView에서 검증한다.

## 완료 조건

- 관리자가 `/admin`의 카드에서 음악 관리 화면으로 이동할 수 있다.
- 관리자가 앨범과 곡을 등록하고 업로드 상태를 확인한 뒤 공개할 수 있다.
- MP3 교체와 삭제 중에도 DB가 검증된 현재 R2 객체만 가리킨다.
- 비공개 R2 객체는 구매 권한 없이 직접 읽을 수 없다.
- 무료 JSON 음악은 DB와 구매 상태에 의존하지 않고 기존처럼 재생된다.
- 유료 음악은 유효한 구매자만 재생할 수 있다.
- 커버가 없는 앨범도 일관된 LP판·CD·음악 아이콘 대체 표현으로 표시된다.
- 앱인토스 일회성 구매와 웹 구매가 같은 내부 상품 권한을 지급한다.
- 결제 완료, 복구와 환불 결과가 판매 채널과 관계없이 사용자 권한에 일관되게 반영된다.
