# 구독 피드 대화

[개발 기술 계획으로 돌아가기](../development.md)

## 목표

사용자가 2D 집중룸에 입장하면 즉시 구독 피드를 확인하고, 머무는 동안 1분마다 다시 확인해 새
항목의 원문 전체를 Pomo의 음성 대화로 만든다. 숨겨졌던 탭이 다시 활성화되거나 피드 연결이
변경될 때도 즉시 확인한다. 생성은 집중룸 사용을 막지 않고 진행하며, 완성 후 알림을 받은 사용자가
`듣기`를 선택했을 때만 대화창과 음성을 재생한다.

```text
2D 집중룸 입장 또는 체류 중 주기 확인
  → 구독 피드 동기화
  → 새 항목 발견
  → 피드 대화 생성 상태 표시
  → 원문 전체의 음성과 말풍선 타임라인 저장
  → 새 피드 대화 알림
  → 사용자가 듣기 선택
  → 대화창과 음성 재생
```

브라우저가 닫힌 뒤에도 생성이 계속된다고 보장하지 않는다. 여기서 백그라운드 생성은 2D 집중룸을
열어 둔 동안 다른 조작과 화면 렌더링을 막지 않는 작업을 뜻한다.

## 피드 연결 설정

집중룸 설정에 `피드` 탭을 두고 사용자가 여러 피드 주소를 리스트로 추가한다. 각 연결에는 해당
피드를 읽을 Supertonic 음성을 함께 선택하며, 저장된 목록에서도 음성을 변경하거나 연결을 삭제할
수 있다.

```ts
interface FeedConnection {
  readonly createdAt: string
  readonly id: string
  readonly updatedAt: string
  readonly url: string
  readonly version: 1
  readonly voiceId: SupertonicVoiceId
}
```

- HTTP와 HTTPS 주소만 허용하고 정규화된 같은 주소의 중복 추가를 막는다.
- 실제 피드 형식 확인은 피드 동기화가 구현될 때 연결한다. 현재 설정은 주소 형식만 검증한다.
- 연결 목록은 버전된 로컬 설정으로 저장해 집중룸 이탈, 새로고침과 앱 업데이트 후에도 복원한다.
- 첫 연결을 저장할 때 지원 브라우저에는 영속 저장을 요청한다.
- 사용자가 연결을 삭제하거나 앱 데이터를 제거하기 전까지 주소와 선택 음성을 유지한다.
- 피드 음성의 48시간 만료는 연결 설정을 삭제하지 않는다.
- 피드 연결은 작은 사용자 설정으로 보관하고, 향후 늘어나는 피드 항목·생성 작업·음성 메타데이터는
  Dexie와 바이너리 저장소에 분리한다.

## 개발 테스트 피드

Pomo Vite 개발 서버는 RSS와 Atom 동기화를 검증할 수 있는 로컬 피드를 제공한다. 프로덕션 및
앱인토스 정적 빌드에는 이 경로를 포함하지 않는다.

```text
RSS  http://localhost:<port>/__dev/feeds/rss.xml
Atom http://localhost:<port>/__dev/feeds/atom.xml
```

- 최근 12개 항목을 제공하며 5분 경계마다 새 항목 하나가 추가된다.
- 각 항목의 제목과 본문은 `안녕하세요 YYYY-MM-DD HH:mm:ss KST` 형식이다.
- 같은 5분 구간에서는 항목 ID와 문서 내용이 유지되어 중복 감지 테스트가 가능하다.
- 응답은 캐시하지 않아 매 요청에서 현재 5분 구간을 바로 반영한다.
- 개발 환경의 빈 피드 목록에는 RSS와 Atom을 추천 피드로 표시한다. 각 추천 항목에서 음성을
  선택하고 `추가`하면 일반 저장 피드 항목으로 전환되며, 추가하지 않은 추천 항목은 계속 표시한다.

## 원문 정책

- 제목과 정제된 본문 전체를 읽으며 요약, 중간 생략이나 임의 절단을 하지 않는다.
- HTML 태그, 메뉴, 광고, 반복 공백과 음성으로 읽을 필요가 없는 장식 문구를 제거한 뒤 길이를 계산한다.
- 실제로 읽는 제목도 길이에 포함하며 최대 길이는 3,000자다.
- 3,000자를 초과한 항목은 음성을 만들지 않고, 최대 길이를 초과했다는 상태와 `원문 보기`를 제공한다.
- 피드가 본문 일부만 제공하면 연결된 원문에서 전체 본문을 가져온다. 전체 본문을 확보하지 못하면
  일부 내용으로 음성을 만들지 않고 실패 사유와 `원문 보기`를 제공한다.
- 피드 항목은 안정적인 원본 식별자를 우선 사용하고, 없으면 링크와 발행 정보를 조합해 중복 생성을 막는다.

## 저장 모델과 기존 데이터 호환

피드 음성도 기존 `FocusRoomDialogue` version 1 형식과 기존 WAV 저장 경로로 저장한다. 기존 음성
생성기, 말풍선 타임라인, 재생기와 삭제 흐름을 재사용하며 기존 대화 스키마에 피드 전용 필드를
추가하지 않는다.

피드 출처와 만료 정보는 `dialogueId`로 기존 대화를 참조하는 별도 메타데이터에 저장한다.

```ts
interface FeedDialogueMetadata {
  readonly createdAt: string
  readonly dialogueId: string
  readonly expiresAt: string
  readonly feedConnectionId: string
  readonly feedItemId: string
  readonly publishedAt: string
  readonly sourceTitle: string
  readonly sourceUrl: string
  readonly version: 1
}
```

미완성 작업에는 다시 생성하는 데 필요한 입력만 저장한다. 생성 중 만들어진 부분 음성은 영속
저장하거나 재사용하지 않는다.

```ts
interface FeedDialogueJob {
  readonly createdAt: string
  readonly errorMessage: string | null
  readonly feedConnectionId: string
  readonly feedItemId: string
  readonly id: string
  readonly modelId: SupertonicModelId
  readonly script: string
  readonly sourceTitle: string
  readonly sourceUrl: string
  readonly status: 'queued' | 'generating' | 'interrupted' | 'failed'
  readonly updatedAt: string
  readonly voiceId: SupertonicVoiceId
}
```

Dexie 마이그레이션은 기존 테이블과 레코드를 유지한 채 피드 메타데이터와 작업 테이블만 추가한다.
메타데이터가 없는 기존 대화는 수동 대화로 취급하며 자동 삭제하지 않는다.

## 생성과 중단 복구

1. 새 항목의 전체 원문을 확보하고 3,000자 정책을 검증한다.
2. 음성 생성 전에 읽을 원문, 모델과 목소리를 `FeedDialogueJob`으로 저장한다.
3. 작업을 `generating`으로 바꾸고 기존 Supertonic 생성 흐름으로 전체 음성과 타임라인을 만든다.
4. 기존 저장소 계약으로 `FocusRoomDialogue`와 WAV를 저장한다.
5. `FeedDialogueMetadata`를 저장하고 미완성 작업을 제거한다.
6. 사용자에게 새 피드 대화가 준비됐다고 알린다.

페이지 이탈, 새로고침이나 앱 종료로 생성이 끊기면 부분 결과를 버린다. 다음 실행에서 남아 있는
`generating` 작업은 중단된 작업으로 간주하고 다음 선택을 한 번 제공한다.

- `다시 만들기`: 저장된 원문으로 음성을 처음부터 다시 만든다.
- `나중에`: 작업을 유지하고 이번 입장에서는 다시 묻지 않는다.
- `삭제`: 작업을 제거하고 해당 항목의 생성을 취소한다.

여러 미완성 작업이 있으면 개별 확인창을 연속으로 표시하지 않고 하나의 복구 안내에서 묶어 보여준다.

## 상태와 재생 UX

이미지와 모델 로딩 상태를 알리는 기존 집중룸 표현을 따라 다음 상태를 미디어 도크 근처에 표시한다.

```text
피드를 확인하고 있어요…
새 피드 대화를 만들고 있어요…
새 피드 대화가 준비됐어요  [듣기]
```

- 생성 중에도 장면, 타이머, 음악과 설정을 계속 조작할 수 있다.
- 완성 전에는 대화 목록이나 재생 대상으로 노출하지 않는다.
- 자동 재생하지 않으며 사용자가 `듣기`를 선택했을 때 기존 대화창과 음성 재생기를 연다.
- 피드 대화 목록에는 제목, 출처, 발행 시각과 남은 보관 기간을 표시한다.
- 피드 동기화나 음성 생성 실패는 입장 대사, 장면과 음악 실행을 막지 않는다.

## 만료와 정리

- 피드 대화의 `expiresAt`은 음성 생성 완료 시각부터 48시간으로 계산한다.
- 피드 동기화가 성공해 다음 항목을 확인할 때 만료된 피드 대화를 정리한다.
- 브라우저가 닫혀 있으면 정확한 만료 시각의 삭제를 보장하지 않는다. 48시간이 지나면 삭제 대상이
  되고 다음 동기화가 실제 정리 트리거가 된다.
- 현재 재생 중인 대화는 해당 동기화의 정리에서 제외하고 재생 종료 후 다시 정리한다.
- 정리는 기존 대화 삭제 계약을 사용해 대화 레코드와 WAV를 제거한 뒤 피드 메타데이터를 제거한다.
- 미완성 작업은 완성 대화와 별도의 보존 기간을 사용하며, 오래된 작업을 정리할 때 사용자에게 알린다.
- 음성이 만료되어도 피드 항목의 발견 기록은 유지해 같은 항목을 새 피드로 다시 만들지 않는다.

## 구현 단계

1. 피드 연결 목록, 주소·음성 영속 설정과 주소 검증
2. 피드 항목 식별과 전체 본문 정제 계약
3. 피드 메타데이터·미완성 작업 저장소와 기존 Dexie 데이터의 additive migration
4. 3,000자 전체 읽기 검증과 초과·본문 확보 실패 상태
5. 입장·체류·탭 활성화 시 피드 동기화와 기존 음성 생성기로 작업 실행
6. 생성 상태, 중단 복구와 완성 알림 UI
7. 피드 대화 목록, 기존 대화창 재생과 원문 이동
8. 48시간 만료 판정과 다음 동기화 기반 정리
9. 기존 수동 대화 호환, 중복 방지, 중단·재입장과 만료 정리 테스트

## 제외 범위

- 3,000자를 넘는 원문 분할 재생
- 원문 요약이나 일부 발췌 음성
- 앱이 닫힌 동안의 음성 생성과 정확한 시각의 백그라운드 삭제
- 피드 음성의 기기 간 동기화
