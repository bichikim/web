# Pomo 제품 계획

마케팅과 애니메이션 스토리텔링 계획은 [마케팅 계획](./marketing.md)에서 관리한다.

합의한 개발 규칙은 [개발 기술 계획](./development.md)에서 관리한다.

## 1. 제품 정의

**Pomo — Focus for more.**

Pomo는 책상에서 함께 공부하는 3D 캐릭터, 집중 음악, 뽀모도로 타이머를 결합한 집중 앱이다. 사용자는 공부, 코딩, 글쓰기, 독서에 맞는 장면을 선택하고, 직접 작성한 대사를 집중 세션의 시작과 종료에 캐릭터의 목소리로 들을 수 있다.

핵심 가치는 타이머 기능 자체가 아니라 **다시 돌아오고 싶은 집중 공간과 동료감**이다.

## 2. 주요 사용자와 사용 순간

- 혼자 오래 공부하거나 작업할 때 적당한 동료감이 필요한 사람
- 영상형 로파이 콘텐츠보다 타이머와 환경을 직접 제어하고 싶은 사람
- 정해진 루틴과 응원 문구로 집중 시작의 마찰을 줄이고 싶은 사람

첫 목표 플랫폼은 데스크톱 웹이다. 넓은 화면에서 작업 앱 옆에 두거나 전체 화면으로 사용하는 상황을 우선한다. 모바일과 설치형 앱은 핵심 경험이 검증된 뒤 결정한다.

## 3. 핵심 경험

```text
장면과 활동 선택
      ↓
시간·음악·시작/종료 대사 설정
      ↓
캐릭터의 시작 대사와 함께 집중
      ↓
캐릭터 행동과 음악으로 세션 유지
      ↓
종료 대사, 휴식, 다음 세션
```

캐릭터는 사용자의 활동에 맞춰 다음 행동을 반복한다.

- 글쓰기: 노트에 글을 쓰고 잠시 생각하기
- 코딩: 키보드를 치고 모니터 확인하기
- 독서: 책을 읽고 페이지 넘기기
- 휴식: 스트레칭, 차 마시기, 창밖 보기

행동은 집중을 방해하지 않도록 느리고 예측 가능해야 한다. 중요한 타이머 상태는 색상이나 캐릭터 애니메이션에만 의존하지 않고 텍스트와 소리로도 전달한다.

## 4. MVP 범위

### 포함

- 한 개의 3D 캐릭터와 책상 장면
- 글쓰기, 코딩, 독서 애니메이션
- 집중·짧은 휴식 타이머와 시작, 일시정지, 재개, 종료
- 집중 시간과 휴식 시간 설정
- 로파이 음악 3개 이상과 음량, 음소거
- 사용자가 작성하는 시작·종료 대사
- 세션 시작·종료 시 음성 재생
- 설정과 대사의 로컬 저장
- 키보드 조작, 명확한 포커스 표시, `prefers-reduced-motion` 대응

### 제외

- 로그인과 기기 간 동기화
- 캐릭터 생성 및 의상 커스터마이징
- 여러 캐릭터와 호감도 시스템
- 생성형 AI 대화
- 멀티플레이 집중방
- 결제와 상점
- 모바일 네이티브 앱

## 5. 화면 구조

집중 화면 하나를 중심으로 하고 설정은 보조 패널로 연다.

```text
기본 상태
┌─────────────────────────────────────────────────────────┐
│                                                         │
│                 3D 캐릭터와 책상 장면                    │
│                       [24:37]                            │
│                  책상 위 3D 뽀모도로                     │
│                                                         │
├─────────────────────────────────────────────────────────┤
│ ♫ Evening Lo-fi                            ━━━━━  60%  │
└─────────────────────────────────────────────────────────┘

뽀모도로 선택
[책상 위 3D 뽀모도로]
          ↓ 오브젝트가 화면 중앙의 정면 구도로 이동
[2D 인터페이스처럼 보이는 3D 뽀모도로]
          ↓
[타이머 조작]
```

- 남은 시간과 현재 세션 상태는 책상 위 뽀모도로에 3D로 자연스럽게 렌더링한다.
- 별도의 고정 2D 타이머 패널은 두지 않는다.
- 책상 위 뽀모도로를 선택하면 카메라는 고정한 채 뽀모도로 오브젝트가 화면 중앙으로 이동한다.
- 중앙에 놓인 뽀모도로는 정면의 2D 인터페이스 같은 구도가 되며 사용자가 타이머를 조작할 수 있다.
- 시작 전에는 `집중 시작`을 유일한 주요 행동으로 둔다.
- 실행 중에는 일시정지를 주요 행동, 종료를 보조 행동으로 구분한다.
- 대사 편집, 시간, 음악 선택은 시작 전 설정 패널에 묶는다.

## 6. 음성 대사 규칙

MVP는 사용자가 미리 작성한 텍스트만 읽는다. 대사는 다음 시점에 각각 지정할 수 있다.

- 집중 시작
- 집중 종료
- 휴식 시작
- 휴식 종료

기본 대사를 제공하되 빈 값도 허용한다. 음성 재생이 실패해도 타이머는 정상 진행하며 텍스트 자막을 함께 표시한다. 브라우저 음성 합성은 빠른 검증에 적합하지만 기기별 음질과 음성 차이가 있으므로 구현 전에 별도 기술 검증을 거친다.

## 7. 기술 방향과 결정 체크포인트

| 영역       | 초기 방향                             | 구현 전 확인할 것                            |
| ---------- | ------------------------------------- | -------------------------------------------- |
| 앱         | 저장소 표준에 맞춘 SolidJS 계열 웹 앱 | SolidStart SSG와 Vite SPA 중 배포 요구 비교  |
| 3D         | WebGL 기반 GLTF/VRM 캐릭터            | 모델 라이선스, 번들 크기, 저사양 성능        |
| 애니메이션 | 상태 기반 애니메이션 전환             | 전환 품질, 루프 이음새, reduced motion 대안  |
| 음성       | Web Speech API 우선 검증              | 한국어·일본어 음질, 브라우저 지원, 재생 권한 |
| 음악       | 앱에 포함한 라이선스 확인 음원        | 배포·상업 이용 범위, 반복 재생 이음새        |
| 저장       | 브라우저 로컬 저장소                  | 설정 스키마 버전과 손상 시 초기화            |
| 타이머     | 경과 시각 기반 상태 계산              | 백그라운드 탭 throttling과 절전 복귀         |

타이머는 `setInterval` 횟수를 진실의 원천으로 삼지 않고 목표 종료 시각과 현재 시각의 차이로 남은 시간을 계산한다. 이는 백그라운드 탭과 절전 모드 이후에도 시간이 크게 어긋나지 않게 하는 작은 비용의 미래 대비다.

## 8. 구현 단계

### Phase 0 — 경험 검증

1. 저해상도 3D 장면 하나로 데스크톱 성능을 측정한다.
2. 활동별 애니메이션 전환을 검증한다.
3. 브라우저 음성 합성의 음질과 자동 재생 제약을 확인한다.
4. 후보 음악의 라이선스를 기록한다.

완료 조건: 지원 브라우저와 최소 성능 기준을 정하고, 3D·음성 기술 선택을 기록한다.

### Phase 1 — 집중 루프

1. 앱 골격과 집중 화면을 만든다.
2. 정확한 타이머 상태 모델을 구현한다.
3. 집중과 휴식 전환, 알림, 오류 복구를 구현한다.
4. 키보드와 스크린 리더로 핵심 조작을 검증한다.

완료 조건: 3D와 음악 없이도 한 번의 집중·휴식 루프를 안정적으로 끝낼 수 있다.

### Phase 2 — Pomo 경험

1. 3D 장면과 활동별 행동을 연결한다.
2. 음악 선택, 반복 재생, 음량을 추가한다.
3. 사용자 대사 편집과 음성·자막 재생을 연결한다.
4. 새로고침 후 설정과 진행 상태를 복구한다.

완료 조건: 코딩, 글쓰기, 독서 중 하나를 선택해 캐릭터·음악·대사와 함께 세션을 완료할 수 있다.

### Phase 3 — 품질과 배포

1. 저사양 품질 옵션과 사용자가 직접 선택할 수 있는 2D 화면 모드를 제공한다.
2. 브라우저별 음성·오디오·백그라운드 동작을 검증한다.
3. 자산 로딩, 접근성, 반응형 레이아웃을 개선한다.
4. 정적 배포와 오류 관측을 구성한다.

완료 조건: 지원 환경에서 첫 화면과 핵심 조작이 안정적으로 동작하고, 음성이나 3D 실패 시에도 타이머를 사용할 수 있다.

## 9. 성공 지표

초기에는 계정이나 분석 인프라보다 직접 사용성 검증을 우선한다.

- 첫 방문자가 도움 없이 집중 세션을 시작할 수 있는가
- 시작한 세션 중 정상 종료한 비율
- 사용자가 다음 날 다시 세션을 시작하는가
- 캐릭터, 음악, 대사 중 재방문 이유가 무엇인가
- 3D 장면이 집중을 돕는가, 방해하는가

## 10. 다음 결정

구현을 시작하기 전에 다음 세 가지를 먼저 확정한다.

1. 목표 분위기: 현실적인 방, 애니메이션풍 방, 미니어처 디오라마 중 하나
2. 캐릭터 자산: 직접 제작, 라이선스 모델 구매, 임시 모델 사용 중 하나
3. 음성 방식: 브라우저 기본 음성으로 MVP 검증 또는 외부 TTS 도입
