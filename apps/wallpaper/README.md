# Wallpaper

## 기본 제공 콘텐츠

위젯에서 애시를 바로 선택할 수 있다. 앨범에는 음악 커버를 가로형으로 확장한 배경화면과 웹사이트의 기존 배경을 제공한다. 파일을 가져오거나 네트워크에서 내려받을 필요가 없으며, 저장된 선택은 유지한다. 구성과 원본 경로는 [기본 제공 에셋](./builtin-assets.md)을 참고한다.

## 앨범 표시 방식

사진·동영상의 **표시 방식**에서 **전체 보기**와 **화면 채우기**를 고른다. 전체 보기는 원본 전체를 보여주고, 화면 채우기는 비율을 유지해 화면을 채우며 넘치는 가장자리를 잘라낸다. 기존 설정은 전체 보기로 유지한다. 모니터마다 선택을 저장하며, 재생 중 바꿔도 파일이나 재생 위치를 초기화하지 않는다.

## 앨범 폴더 가져오기

앨범의 `폴더`에서 사진 폴더를 선택하면 하위 폴더의 사진도 함께 가져온다. `하위 폴더 모두 포함`을 끄면 최대 깊이를 지정할 수 있으며, 선택한 폴더는 깊이 0이다. 사진이 아닌 파일과 빈 파일은 건너뛴다. 가져온 사진은 현재 화면의 기존 앨범에 추가하며, 이후 원본 폴더의 변경을 자동으로 반영하지 않는다.

## Poffo 불러오기

위젯·Poffo 배경의 불러오기 영역은 선택한 캐릭터 이름과 불러오기 버튼만 표시한다. 불러오기 화면에서 저장된 캐릭터 선택과 Poffo 파일 가져오기를 수행하며, 위젯에서는 하단에 ‘위젯으로 띄우기’를 제공한다. 편집 중인 미리보기는 바깥에 유지하고 기존 저장·선택 동작을 그대로 사용한다. 모달 안의 공용 드롭다운은 해당 모달에 목록을 생성해 플랫폼의 입력 차단 영역에 포함되지 않도록 한다.

## 개별 위젯 설정

**Poffo → 연결 → 립싱크**에서 끄기·음성·말풍선을 고르고 입 열림 파라미터를 자동 또는 직접 연결한다. 방향 반전·움직임 배율은 위젯별로 저장한다. 음성 입력은 실제 재생 시각과 PCM 크기를 따라가며, 생성·대기 중인 청크는 입을 움직이지 않는다. 로컬 및 ChatGPT 설정 음성에 같은 재생 경로를 사용한다. 말풍선 입력은 선택한 말풍선의 새 텍스트를 기반으로 입 열림을 근사하며, 공백·문장부호에서 닫는다. 음소별 입 모양 인식은 포함하지 않는다. 선택 변경·읽기 취소·표시 끄기는 이전 입력을 즉시 중단한다. 미리보기와 위젯은 같은 연결을 사용하고 플레이어를 다시 만들지 않는다.

시선·립싱크·에이전트 상태는 각자 지정한 파라미터만 부분 갱신하며 다른 입력이나 기본 애니메이션을 지우지 않는다. 립싱크 수신이 몰리면 화면 프레임마다 최신 값 하나만 적용하고 같은 값은 다시 그리지 않는다. 2026-10-19에 관련 Wallaby 27개와 Chromium·WebKit 14개를 통과했다. 맥 앱에서는 실제 음성의 립싱크 이벤트 1,336개·최대 입력 약 0.96과 미리보기의 연속 24개 서로 다른 렌더 프레임을 확인했다. 진단 수신기는 확인 뒤 제거했고 기존 음성·트래킹·idle 설정을 유지했다.

위젯 헤더를 누르면 설정을 접거나 펼친다. 한 번에 하나만 펼치며 모두 접을 수도 있다. 접힌 헤더에는 번호·캐릭터 이름과 트래킹·말풍선·읽어주기 상태를 표시한다. 설정 접기는 실제 위젯을 닫지 않으며, 공유 미리보기와 편집 상태를 DOM에 유지한다. 접힌 내용은 `inert`로 입력을 차단하고, 접힘 높이와 화살표는 CSS 전환으로 움직인다. 동작 줄이기 설정에서는 전환을 생략한다.

펼친 위젯의 **Poffo / 말풍선**에서 편집 항목을 고른다. Poffo에는 트래킹 입력·기본 애니메이션·보정만, 말풍선에는 위치·표시·본문·읽어주기만 표시한다. 캐릭터 미리보기는 하나를 유지하며 항목 전환이나 위젯 선택으로 플레이어를 다시 만들지 않는다. 말풍선 위치 버튼은 말풍선 편집에서만 보인다. 위젯 닫기는 내용 안에서 분리한 헤더의 독립 버튼이다. 열린 위젯이 없으면 말풍선 편집 선택을 표시하지 않는다.

말풍선 본문 보기는 자동 줄바꿈·가로 스크롤을 바로 선택한다. 읽어주기는 음성·언어, 로컬 모델·목소리·GPU, 속도·음량 순으로 묶고 ChatGPT 설정 음성에서는 로컬 항목을 숨긴다. 표시를 꺼도 설정은 편집할 수 있으며 말풍선 위치·읽기·모델·음량 등 기존 값을 보존한다. 미리듣기와 기존 음성 실행 수명은 그대로 유지한다.

2026-10-19 설정 정리 검증: 관련 Wallaby 21개, Chromium·WebKit 8개, 타입·oxlint·포맷 및 맥 앱 빌드를 통과했다. 320·496px 컨테이너에서 키보드 전환·실제 플레이어 하나 유지·말풍선 위치 버튼의 미리보기 경계·입력란 가로 넘침·로컬/ChatGPT 전환 시 값 유지·접기와 포커스·마지막 위젯 닫기를 검증했다. 텍스트 대비는 파란 선택 글자/흰 배경 6.7:1, 보조 글자/로컬 모델 배경 6.99:1, 꺼진 스위치/흰 손잡이 4.8:1을 확인했다. 최신 맥 앱에서 Poffo/말풍선 전환, 위치 버튼, 본문 선택, 로컬 모델·GPU·재생 옵션·미리듣기의 배치를 직접 확인했다. 기존 Codex 연결과 Full·Mina·GPU 켜짐·한국어·속도 1·음량 100은 유지했다. 실제 맥에서 위치 드래그나 음성 생성을 다시 실행한 것은 아니며, 위치 저장과 음성 설정 변경은 자동 검사로 확인했다.

각 위젯의 `기본 애니메이션`에서 자동·재생 안 함·모델에 포함된 동작을 고른다. 자동은 기존처럼 모델의 첫 동작을 반복한다. 선택은 위젯별로 저장하며 실제 위젯과 미리보기에 반영한다. 선택 변경과 위치·음성·트래킹 설정 갱신은 모델이나 플레이어를 다시 만들지 않는다. 존재하지 않는 저장 동작은 ‘사용 불가’로 표시하고 자동으로 다른 동작을 재생하지 않는다. 음성 설정의 상시 설명 두 문구는 제거하고 진행 상태와 오류 피드백은 유지한다.

2026-10-18 검증: 관련 Wallaby 33개와 Chromium·WebKit 4개를 통과했다. 브라우저의 실제 Poffo 플레이어에서 선택 동작의 파라미터 변화·정지·자동 복귀와 동일 플레이어 유지를 확인했다. 맥 앱에서 실제 모델의 동작 목록·선택·재생 안 함 저장과 재실행 후 복원을 확인했으며, 검증 후 기존 `자동 · idle`로 돌려두었다. ChatGPT 음성·한국어·속도 1·음량 80과 다른 위젯 설정은 유지했다.

각 위젯의 **Poffo → 연결 → 에이전트 상태**에서 연결됨·작업 중·도구 처리 중·질문·승인 대기·응답 도착·중단·도구 오류를 모델 파라미터에 연결한다. ON/OFF 값을 따로 지정하며 기본값은 모델의 최댓값/기본값이다. 전체 채팅 중 하나라도 해당 상태이면 ON이며, 같은 파라미터에 여러 상태를 연결하면 활성 상태가 비활성 상태보다 우선한다. 말풍선 표시를 꺼도 연결은 유지한다. 트래킹·립싱크·상태 연결의 파라미터 목록은 한 번 준비해 공유한다.

**위젯 → Poffo → 연결 → 감정·내용**에서 설명을 직접 등록하고 모델 파라미터에 연결한다. 토글은 OFF/ON 값, 연속값은 시작/끝 범위를 지정하며 매칭 기준은 별도로 조정한다. 문장 테스트로 매칭 점수와 실제 모델 반응을 확인한다. 새로 선택한 말풍선의 텍스트도 같은 연결에 자동 적용한다. 같은 파라미터는 기준을 통과한 연결 중 가장 높은 점수를 우선한다. 유사도 점수는 감정의 확률이 아니다.

EmbeddingGemma 2와 ONNX 런타임은 앱에 내장한다. 빌드 시 [고정 모델 목록](./semantic-model.json)의 파일을 검증해 리소스로 묶으며, 사용자 실행 중 모델 다운로드나 외부 추론을 하지 않는다. 설정 창의 Worker 하나를 위젯들이 공유한다. 텍스트 모델만 포함하고 GPU용 양자화 모델과 CPU/WASM용 모델을 제공한다.

질문은 기존 Poffo MCP로 받은 질문이다. 도구 오류는 기존 `PostToolUse`가 전달한 명시적인 실패 메타데이터나 Bash 종료 코드만 판별한다. 도구 출력의 단어를 추측하지 않으며 원문은 상태 이벤트에 포함하지 않는다. 같은 도구가 성공하거나 새 턴·응답 종료·중단으로 전환하면 오류를 해제한다. 모델·네트워크 오류 전체를 수신하는 기능은 포함하지 않는다. 기존 훅 정의와 사용자 신뢰 설정은 변경하지 않는다.

## AI 에이전트 연결

- 위젯 공용 영역에는 Codex의 연결 상태와 연결·관리 버튼만 표시한다. 관리 화면에서 작업·응답 수신, 승인 요청 처리, 질문 답변, 음성 로그인 상태를 확인하고 연결 진단·해제를 수행한다. 관리 화면을 열거나 닫는 동작은 기존 등록을 변경하지 않는다.
- 새 연결은 알림·승인 훅 등록 뒤 질문 답변 MCP 등록까지 이어서 진행한다. 이미 연결된 경우 사용자가 해제한 질문 연결을 자동으로 다시 켜지 않는다. 훅 등록·실제 수신·MCP 등록 상태를 구분하고, Codex의 검토·승인이나 도구 로딩을 대신 완료했다고 표시하지 않는다.
- 음성 로그인 확인은 로컬 인증 파일을 읽고 상태만 반환하며 인증 정보나 음성 요청을 전달하지 않는다. 관리 화면의 ChatGPT 설정 음성 미리듣기는, 위젯별 읽어주기·서비스·모델·목소리·속도·음량을 저장하거나 변경하지 않는다. 미리듣기를 누르면 기존 음성 경로로 예시 문장을 생성한다.
- 2026-10-18 검증: 관련 Wallaby 21개·Chromium/WebKit 2개·네이티브 인증/음성 검사 3개와 타입·린트·clippy·형식 검사를 통과했다. 최신 맥 앱에서 연결 카드, 관리·진단, 로컬 로그인 확인, Codex 음성 미리듣기의 오류 없는 종료와 Esc 닫기를 확인했다. 기존 위젯의 ChatGPT 설정 음성·한국어·속도 1·음량 80을 유지했고, 검증 전후 `hooks.json`과 `config.toml`의 SHA-256이 일치했다. 실제 연결을 해제하거나 재등록하지 않았으며 새 연결·부분 실패·해제 흐름은 포트를 모의한 검사로 확인했다.

- 공식 [Hooks](https://learn.chatgpt.com/docs/hooks)의 command 훅을 사용한다. 일반 알림은 비동기, 사용자 승인 응답은 동기로 처리한다. 사용자 프롬프트, 도구 실행, 승인 요청, 응답 종료와 중단을 로컬에서 받는다.
- 공용 위젯 설정에서 등록·연결 상태·해제를 제공한다. Codex의 훅 검토와 신뢰 승인은 사용자가 Codex에서 진행하며, 앱은 신뢰 기록을 변경하지 않는다.
- 기존 훅과 설정을 보존하고 앱이 등록한 핸들러만 해제한다. 앱이 꺼져 있으면 릴레이는 성공으로 종료하며 Codex 작업을 막지 않는다.
- 각 위젯의 말풍선 표시 여부와 위치를 저장한다. 설정의 실제 캐릭터 미리보기에서 `Codex 알림` 말풍선을 끌어 위치를 정한다. 놓으면 저장하고 방향키로 미세 조정하거나 Esc로 취소한다. 말풍선은 캐릭터와 분리된 투명 창에 표시해 기존 캐릭터 크기·클릭 통과·드래그를 유지한다.
- 기록 경로가 있는 채팅의 세션 ID마다 별도의 말풍선을 쌓고 실제 채팅 제목과 세션별 고정 파스텔 색상으로 구분한다. 제목은 공식 App Server의 읽기 전용 `thread/read(includeTurns: false)`로 조회하며 채팅을 재개하거나 대화 파일을 해석하지 않는다. 기록 경로가 없는 임시 세션은 릴레이에서 제외한다. 다른 채팅의 도구 실행이 응답 도착 알림을 덮지 않는다. 긴 목록은 스크롤하며, 네이티브 창은 모니터 작업 영역 크기로 유지하고 내부 기준선과 본문 높이만 조정한다.
- 제목을 한 번 누르면 말풍선을 선택하며, 더블클릭하거나 `Codex에서 열기` 버튼을 누르면 해당 대화를 연다. 본문 선택과 닫기는 독립적으로 동작한다. 본체와 꼬리는 불투명한 파스텔 배경을 사용하며, 음성 준비·버퍼링의 로딩 아이콘과 재생 중 스피커는 한 자리에서 교체한다.
- 말풍선을 같은 가로 위치에 포개 뒤쪽 제목만 드러낸다. 선택은 앞에서부터의 실제 순서를 갱신하며 나머지 순서를 유지한다. 그리는 DOM은 뒤에서 앞으로 배치해 WebKit에서도 표시와 클릭 순서를 일치시킨다. 뒤쪽은 제목 밖의 그리기만 제한하며, 본문을 접거나 펼치지 않고 기존 선택 애니메이션과 겹침을 유지한다.
- 말풍선 바깥의 투명 여백·그림자·조작하지 않는 꼬리는 뒤쪽 앱으로 입력을 통과시킨다. 프레임의 실제 크기·둥근 모서리·클리핑을 마스크로 읽어 캐릭터와 같은 네이티브 포인터 판정을 사용한다. 레이아웃 변경과 이동 애니메이션 동안 갱신하고, 누른 채 드래그할 때는 기존 입력 대상을 유지한다.
- 스택은 앞쪽 카드 높이와 뒤쪽 제목 간격을 기준으로 배치한다. 선택 중에는 묶음 높이의 별도 전환을 끄고, 공통 기준점이 달라진 만큼 카드 좌표를 옮겨 화면상의 현재 위치를 유지한다. 이동 거리는 새 기준점에서 계산한다. 이동 중 내용 높이가 바뀌면 현재 위치·그림자에서 다시 이어간다. 네이티브 창은 이동 중 필요한 최대 공간을 유지하고 모두 안착한 뒤 줄인다. 뒤쪽 본문은 DOM에 유지하며 스크롤 위치와 입력 초안을 보존한다.
- 선택 시 8px·200ms 상승 후 실제 이동 거리 / 160px/s로 하강한다. 그림자는 상승 중 깊어지고 하강 중 유지한 뒤 안착 시 복귀한다. 재선택은 현재 렌더링된 위치·그림자 진행 값을 읽어 즉시 이어지며, 이전 완료 콜백은 새 선택을 변경하지 않는다. 애니메이션 완료 신호를 사용하고 타이머와 z-index는 추가하지 않는다.
- 제목만 남기는 카드 바깥 클리핑은 안착한 뒤 뒤쪽 카드에만 적용한다. 이동 중에는 프레임 자체의 높이와 내부 본문 클리핑으로 크기를 표현해, 확대·축소하는 테두리와 깊어진 그림자를 사각형이나 계단 모양으로 자르지 않는다. 2026-10-19에 Chromium·WebKit 74개와 Wallaby 8개를 통과했고, 맥 앱의 크기가 다른 임시 말풍선 전환 프레임에서 그림자 경계가 잘리지 않는 것을 확인했다. 확인 후 임시 말풍선은 닫았다.
- 꼬리는 화면 가장자리 보정 후의 실제 말풍선 위치와 캐릭터 위치를 비교해 위·아래·왼쪽·오른쪽에 붙인다. 둥근 모서리를 피하고, 캐릭터 기준점이 말풍선 안에 겹치면 꼬리를 숨긴다. 미리보기의 위치 조정 핸들에는 꼬리를 표시하지 않는다.
- 캐릭터 위쪽의 말풍선은 DOM도 아래쪽 끝에 붙여 위로 확장한다. 아래쪽 배치는 위쪽 끝을 기준으로 아래로 확장한다. 내용 측정·네이티브 응답 전후에 같은 기준을 유지하며, macOS는 크기와 위치를 하나의 NSWindow 프레임으로 적용한다. 모니터 작업 영역의 공간을 먼저 사용하고 부족할 때만 최소 조작 영역을 확보하기 위해 겹침을 허용한다.
- 화면 경계에서는 최소 320px의 조작 높이와 실제 정렬 기준점을 분리한다. 말풍선 전체가 들어갈 자리가 없으면 실제 높이로 반대쪽 경계에 붙이고, 바깥쪽에는 8px 선택 상승을 위한 12px 여백을 둔다. 목록이 화면 사용 영역보다 길 때만 원래 방향의 바깥 스크롤을 사용한다. 최소 높이를 위한 가상 영역 안에 짧은 말풍선을 정렬해 빈 공간을 남기지 않는다.
- 2026-10-18 경계 검증: Chromium·WebKit 말풍선·크기·입력 통과 검사 78개, 관련 Wallaby 3개와 Rust 배치 검사 13개를 통과했다. 상·하단의 짧은/긴 본문, 서로 다른 크기 선택 중 프레임별 잘림, 전체 화면보다 긴 목록의 스크롤을 확인했다. 실제 맥 앱을 상단 배치 조건으로 실행해 프레임 위쪽 12px을 측정했고, 검증 후 캐릭터의 원래 좌표를 복원했다. 이는 저장 좌표로 재현한 결과이며 실제 마우스 드래그를 자동 조작한 결과와 구분한다.
- 다음 요청 입력란과 보내기, 승인·거절·Codex에서 처리, 질문 답변 보내기는 스크롤 밖 하단에 유지한다. 응답·승인 요청 내용·질문 항목만 사용 가능한 높이 안에서 스크롤한다. 위젯의 `본문 보기`에서 자동 줄바꿈과 가로 스크롤을 선택한다. 기본 보기는 자동 줄바꿈이며 본문·코드 블록이 너비에 맞춰 줄바꿈된다. 표는 독립된 영역에서 가로 스크롤한다. 설정 미리보기에도 같은 위·아래 배치 방향을 적용한다.
- 공개 진행 메시지와 응답은 Markdown의 굵은 글씨·인라인 코드·코드 블록·GFM 표를 표시한다. 같은 파서로 제목·목록·인용도 표시하며, HTML은 실행하지 않고 문자로 보여준다. 보기 옵션은 위젯별로 저장하고 열린 말풍선에 바로 반영한다. 표시 서식과 읽어주기 전처리는 별개로 유지한다.
- 2026-10-18 서식·보기 검증: 관련 Wallaby 검사 52개와 Chromium·WebKit 말풍선 검사 66개를 통과했다. 실제 맥 앱에서 테스트 채팅의 굵은 글씨·인라인 코드·코드 블록·표를 확인했다. 설정을 가로 스크롤에서 자동 줄바꿈으로 바꾸자 응답의 표시 폭/내용 폭이 `216/713px → 216/216px`, 코드가 `214/214px`이 됐고, 표는 `214/1010px`의 독립 영역을 유지했다. 표를 가로 100px, 본문을 세로 100px 스크롤해도 입력란 위치는 같았다. 기존 ChatGPT 음성·언어·속도·음량 설정을 유지했다.
- 승인 릴레이는 해당 턴의 `approvals_reviewer`가 `user`일 때만 Poffo 결정을 기다린다. `auto_review`·기존 별칭·알 수 없는 모드는 결정 없는 `{}`를 즉시 반환해 Codex의 원래 심사로 넘기며, 승인 대기 알림도 만들지 않는다. 전역 설정으로 현재 채팅의 모드를 추정하지 않는다. Hooks에는 reviewer 필드가 없어 로컬 transcript의 마지막 4MiB 안에서 일치하는 `turn_context.turn_id`의 모드만 읽는다. transcript 형식은 고정 인터페이스가 아니므로 누락·변경·읽기 실패 시에도 Codex로 넘긴다. 경로와 기록 내용은 앱으로 전달하거나 저장하지 않는다.
- 공식 Hooks에는 자동 심사 거절 후에만 호출되는 이벤트가 없다. 자동 심사 거절을 Poffo 승인 버튼으로 재처리하지 않는다. 거절 이후 Codex가 명시적으로 질문할 때 Poffo MCP 질문 도구를 사용하면 말풍선에서 답할 수 있다. 원래 Codex 심사·거절·재승인 절차는 유지한다.
- 응답 종료는 응답 도착으로만 표시한다. 전체 작업 완료를 추론하지 않는다. 실제 응답은 스크롤 가능한 영역에 텍스트로 표시한다.
- 작업 중 본문은 공식 App Server의 읽기 전용 `thread/items/list`에서 같은 턴의 최신 공개 `agentMessage(phase: commentary)`를 조회해 표시한다. 도구 시작·종료 훅이 조회를 유발하며 타이머·채팅 재개·새 턴 생성은 하지 않는다. 도구 이름은 작은 보조 정보로 유지한다. 조회가 없거나 실패하면 같은 턴의 기존 진행 문구를 유지하고, 아직 받은 문구가 없을 때만 기본 상태 문구를 사용한다. 종료·다음 턴 이후 늦게 도착한 조회는 반영하지 않는다. 내부 추론·사용자 메시지·다른 턴 본문은 표시하지 않는다.
- 닫기는 해당 위젯·채팅의 현재 알림에만 적용한다. 같은 알림의 도구 실행 갱신에는 숨김을 유지하고, 다음 프롬프트·승인 요청·응답 도착에는 다시 표시한다. 다른 위젯의 말풍선은 유지한다.
- 승인 요청은 공식 동기 `PermissionRequest` 훅으로 연결한다. 요청별 원문·작업 폴더와 `이번만 승인 / 거절 / Codex에서 처리`를 표시한다. 일회성 결정만 지원하며 세션 전체 승인이나 자동 승인은 제공하지 않는다. 기존 연결은 설정의 `승인 버튼 연결`로 갱신하고, 변경된 훅 정의를 Codex에서 다시 검토·신뢰해야 한다.
- 앱이 없으면 헬퍼는 즉시 `{}`로 종료한다. 표시할 위젯이 없거나 모든 관련 말풍선을 닫았을 때, 연결 해제·턴 종료·앱 종료·120초 경과 때도 원래 Codex 승인 흐름으로 돌려준다. 승인 요청 내용은 메모리에만 두며 수신 기록에서 제외한다.
- 질문 답변은 로컬 `poffo_questions` MCP의 `ask_question`으로 구현한다. 공용 설정에서 등록·해제하며 선택지와 직접 입력을 해당 채팅의 도구 결과로 돌려준다. Codex 기본 질문 창의 기존 요청을 가로채는 방식은 아니다. 응답 도착·중단 말풍선의 다음 요청은 공식 `codex queue`로 해당 채팅 UUID에 전송한다. 별도 실행기로 원본 채팅을 중복 실행하거나 새 채팅으로 대체하지 않는다.
- 다음 요청을 보내면 입력창을 즉시 숨긴다. 전송 접수 후에도 새 응답이 도착할 때까지 숨김을 유지하며, 전송 실패 시에는 작성한 내용과 오류를 다시 표시한다.

### MCP 질문 답변

- 공용 위젯 설정의 `질문 답변 연결`은 `~/.codex/config.toml`에 앱 소유 `mcp_servers.poffo_questions`만 등록한다. 기존 설정과 주석은 보존하고, 같은 이름의 다른 서버가 있으면 덮어쓰지 않는다. 질문 연결 해제와 전체 Codex 연결 해제는 이 항목만 제거한다. 등록 후 Codex 설정 → MCP 서버에서 재시작하고, 채팅의 `/mcp`에서 연결을 확인한다. 새 서버가 목록에 없으면 Codex를 완전히 종료한 뒤 다시 실행해 설정을 불러온다. 화면의 `MCP 등록됨`은 파일 등록 상태이며 실제 채팅의 도구 로딩을 뜻하지 않는다.
- `ask_question`은 질문 1–3개, 선택지와 직접 입력을 지원한다. executor가 전달한 채팅·턴 메타데이터로만 연결하고, 메타데이터가 없으면 Codex에서 질문하도록 오류를 반환한다. 다른 채팅으로 추정해 보내거나 모델 인수로 채팅을 바꾸지 않는다. 질문과 답변은 메모리에만 보관한다.

### 말풍선 음성

위젯 항목의 **말풍선 읽어주기**에서 음성 서비스·언어·속도·음량을 설정하고 미리 들을 수 있다. 새 위젯에서는 꺼져 있다. 기본값인 **로컬 음성**은 Pomo와 공유하는 엔진으로 기기 안에서 생성한다. 모델은 최초 사용 시 내려받아 로컬 IndexedDB에 캐시하며, 대화 내용은 전송하지 않는다. ChatGPT 설정 음성으로 전환해도 기존 로컬 모델·목소리 설정은 유지한다.

실제 말풍선 읽기는 창 안에서 로컬 실행기 하나를 공유하며 첫 생성 때 모델을 준비한다. 읽기가 끝나거나 채팅을 바꾸거나 읽기 컴포넌트를 다시 생성해도 해당 창이 살아 있는 동안 모델 세션과 목소리를 메모리에 유지한다. 문장·언어·속도·음량 변경은 모델을 다시 로드하지 않는다. 모델 또는 GPU 설정 변경, GPU 오류 후 CPU 전환, 워커 오류, 창/앱 재실행에는 준비가 필요하다. 소유자별 취소와 재생 큐는 구분하고 공유 실행 요청은 순서대로 처리한다. 기다리는 요청도 취소 즉시 끝나며 다른 읽기는 취소하지 않는다. **미리듣기 버튼과 기존 수명은 유지**하고, 미리듣기에는 별도 실행기를 사용한다. 미리듣기를 위해 말풍선용 모델을 미리 준비하거나 계속 유지하지 않는다.

로컬 음성의 **GPU 가속**은 위젯마다 저장하며 기본값은 켜짐이다. 끄면 WebGPU를 조회하지 않고 CPU(WASM)로만 실행한다. 켜면 Full 모델에서 WebGPU를 우선 사용하고, 현재 CPU 실행용 INT8 프로필은 WASM을 유지한다. ONNX Runtime의 [WebGPU 실행 방식](https://onnxruntime.ai/docs/tutorials/web/ep-webgpu.html)을 사용한다. GPU API 유무는 워커 안에서 처음 필요한 때 한 번 확인하며, 별도 어댑터 탐색 없이 실제 모델 세션 생성으로 실행 가능 여부를 확인한다. 런타임 모듈·모델 세션·목소리를 재사용하고, GPU 초기화 실패나 실행 오류가 난 모델은 해당 워커가 살아 있는 동안 CPU로 유지한다. 다운로드 오류와 사용자의 취소는 GPU 실패로 기록하지 않는다. 모델이나 GPU 설정을 바꿀 때만 세션을 다시 준비하며, GPU 실행 오류는 현재 문장을 CPU로 한 번 재생성한다. 앱 재실행 시에는 최신 실행 환경을 다시 판단한다.

**ChatGPT 설정 음성**은 Codex 파일 기반 로그인으로 연결한다. 합성 요청마다 계정의 현재 `settings.voice_name`을 조회해 사용하므로 햇살 등 특정 목소리를 고정하지 않는다. 설정을 확인하지 못하면 다른 목소리로 대체하지 않고 오류를 표시한다. 기존 `haetsal`·`codex` 선택은 `chatgpt`로 이관한다. 설정에는 **로컬 음성 / ChatGPT 설정 음성**만 표시하며, 로컬 모델·목소리와 위젯별 읽기·언어·속도·음량 설정을 유지한다. 기존 기본 합성 경로 코드는 남겨 두지만 자동 대체하지 않는다. 읽을 텍스트를 OpenAI로 전송하며 인증 정보는 네이티브 프로세스 안에서만 사용한다. 같은 Codex 로그인으로 내부 실시간 경로에 연결하며, 읽을 문장은 세션 시작 때 전달하되 자동 시작을 요구하지 않는다. SDP 적용 후 제어 연결의 준비 완료를 확인하고, 포함된 Supertonic 안내 파형을 입력 트랙에 한 번 보낸다. 안내 자체는 스피커로 재생하지 않으며 실제 읽기는 ChatGPT 설정 목소리로 생성한다. 매 요청에 로컬 모델을 준비하지 않는다. 무음 제한 시간도 준비 완료 뒤에 시작한다. 마이크는 사용하지 않는다. 첫 유효 음성부터 0.2초를 모아 기존 재생 큐로 스트리밍하고, 발화 종료와 재생 완료를 모두 확인한 뒤 읽은 위치를 저장한다. 연결 지연·무음은 새 연결로 최대 두 번 재요청하며, 이미 재생한 발화의 연결이 끊기면 중복 재생하지 않고 다시 읽기를 제공한다. 로그인·사용량 오류는 반복하지 않는다. 마지막 실패는 **다시 읽기**, 설정 미리듣기는 **다시 듣기**로 재요청할 수 있다. 실패한 문장은 읽은 것으로 기록하지 않는다. 이 경로도 비공식 연동이다.

- 실제 명령을 실행하지 않는 별도 UI 검증 요청으로 맥의 요청 원문·폴더·세 버튼 표시와 `이번만 승인` 클릭을 확인했다. 실행 파일이 공식 `hookSpecificOutput.decision.behavior = allow`를 반환했다. 이는 실제 Codex 작업의 승인 검증과 구분한다.
- 등록 직후 공식 `hooks/list`에서는 `enabled: true`, `trustStatus: modified`였다. 이후 사용자의 검토·신뢰 작업 후 실제 Codex 읽기 전용 확인 요청이 `사용자가 Poffo에서 거절했습니다.`로 실행 전에 거부되어 거절 경로가 작동하는 것을 확인했다. 거절된 확인 명령은 우회하거나 재실행하지 않았다.
- 사용자가 허용한 `현재 폴더 이름 확인` 채팅에 `require_escalated`의 `pwd` 검증 요청을 보냈다. 맥 말풍선에서 실제 명령 `pwd`, 설명 `Poffo 승인 연동 검증: 현재 폴더 경로만 확인`, 실제 작업 폴더와 세 버튼이 표시됐다. 이후 해당 턴의 `/bin/zsh -lc pwd`가 exit 0으로 완료되고 같은 말풍선에 응답 본문 `web`이 도착했다. 실제 턴은 약 47.2초에 종료되어 120초 타임아웃 복귀와 구분된다.
- 이 승인 검증 당시에는 기존 데스크톱 채팅의 프롬프트 전송·질문 답변을 구현하지 않았다.

### 채팅 제목·응답 본문·닫기 검증

- 2026-10-17: Wallaby 20개, 실제 Chromium·WebKit 6개, Rust 24개를 통과했다. 기존 겹침·중간 재선택 회귀와 함께 제목 비동기 조회의 오래된 결과 무시, 닫기 요청 중 다른 채팅·새 알림 도착, UTF-8 응답 전달, 색상 유지, 본문 스크롤·닫기 독립 동작을 확인했다.
- 최신 맥 앱에서 실제 `현재 폴더 이름 확인`과 `Pomo 데스크톱 배경 계획 수립` 제목, 서로 다른 색상, 허용된 테스트 채팅의 실제 `web` 응답을 확인했다. 테스트 채팅을 닫으면 그 말풍선만 사라지고 새 요청·응답 때 다시 표시됐다. 30줄 응답에서 실제 마우스 스크롤로 `응답 줄 20–30`이 보이는 것을 확인했다. 작업 중인 말풍선도 닫은 뒤 도구 진행 이벤트에는 다시 나타나지 않았다.
- 앱 재실행 전후 `hooks.json`·`config.toml`의 SHA-256은 동일하며, 자동 갱신된 릴레이와 앱 실행 파일의 SHA-256이 일치했다. 이 검증 시점에는 직접 프롬프트 전송·승인·질문 답변을 구현하지 않았으며, 동기 승인 연결은 후속 변경이다.

### 2026-10-17 Codex 연결 검증

- 겹침 선택: Wallaby 12개, 실제 Chromium·WebKit 브라우저 테스트 4개, Rust 19개를 통과했다. 네 카드의 제목 클릭 판정, C → A → B → D 순서, DOM 노드 유지, 상승·하강 중 재선택의 위치·그림자 연속성, 거리별 시간, 안착 후 그림자 복귀와 크기 유지, 키보드 선택·동작 줄이기를 검증했다. 기본 말풍선 폭은 유지하고 네이티브 투명 여백을 늘려 그림자 공간을 확보한다. 배율별 저장 위치 기준 유지는 Rust 테스트로 검증했다.
- 최종 맥 앱에서 실제 현재 채팅과 허용된 테스트 채팅의 겹침을 확인했다. 뒤쪽 제목을 눌러 선택이 전환되고, 응답 말풍선이 원래 높이로 맨 앞에 안착하며 뒤쪽 본문이 비치지 않는 화면을 확인했다. 최신 앱을 실행해 둔 상태다.
- 말풍선 과다 표시 조사에서 실제 채팅 목록에 없는 ID의 `SessionStart(source=fork)`·`UserPromptSubmit`·`Stop`을 확인했다. 이 입력의 `transcript_path`는 없고, 실제 현재 채팅과 테스트 채팅은 기록 경로가 있었다. 릴레이가 경로의 존재 여부만 판별해 누락·null·빈 문자열인 임시 세션을 전달하지 않도록 수정했다. 경로 문자열은 수신기로 전달하지 않고 파일도 열지 않는다. 응답 본문 전달은 아래의 후속 변경을 따른다. Hooks 문서에서 경로는 선택 사항이므로, 이 필터는 기록 없는 세션의 알림을 의도적으로 제외한다.
- 연결된 앱의 시작 시 헬퍼를 원자적으로 갱신한다. 실제 재실행 후 헬퍼와 앱 실행 파일의 SHA-256이 일치했고, `hooks.json`·`config.toml`은 변경되지 않았다. 최신 맥 알림 창에서 현재 채팅과 테스트 채팅의 두 말풍선만 표시됐으며, 같은 테스트 채팅에 두 번 요청해도 말풍선이 늘지 않았다. 실제 승인 대기와 별도 채팅의 응답 도착이 함께 표시된 접근성 트리도 확인했다.
- 최근 변경 관련 Wallaby 테스트 23개와 Rust 테스트 18개를 통과했다. 타입 검사, oxlint, Rust clippy, macOS 앱 빌드도 통과했다.
- 사용자가 Codex 데스크톱에서 현재 등록한 7개 훅을 검토·승인했다. 현재 정의의 승인 기록과 실제 자동 수신을 확인했으며, 앱은 신뢰 기록을 쓰지 않는다.
- 실제 `UserPromptSubmit`·`PreToolUse`·`PermissionRequest`·`PostToolUse`·`Stop`을 설정의 수신 기록에서 확인했다. 사용자가 허용한 별도 채팅에 파일 수정 없는 `pwd` 요청을 보내 실제 도구 승인 요청·실행·응답 종료 수신과 해당 채팅의 `응답 도착` 상태를 확인했다.
- 실제 맥 알림 창에서 여러 채팅의 독립된 말풍선을 확인했다. 허용된 테스트 채팅(`ead3fb21`)의 `응답 도착`이 현재 채팅의 도구 실행과 동시에 유지되는 것을 접근성 트리와 화면에서 확인했다. 승인 대기 말풍선의 렌더링은 별도 테스트 이벤트로 검증했으며, 실제 `PermissionRequest` 수신과 구분해 기록한다.
- macOS에서 새 자식 창이 생성 직후 `is_visible = true`로 보고되는 것을 확인했다. 새 창은 이 값과 관계없이 최초 위치·표시를 초기화한다. 도착 시 포커스를 가져오지 않고, 내용 갱신마다 창을 다시 올리지 않는다. 사용자가 맥 창 메뉴나 클릭으로 알림 창에 접근해 스크롤할 수 있다.
- 실제 미리보기의 오른쪽 꼬리와 맥 알림 창의 꼬리·채팅별 스택 표시를 확인했다. 네 방향 선택·모서리 제한·겹침 시 숨김, Retina 배율 및 음수 좌표 모니터의 위치 계산을 테스트했다. 창 이동·크기 변경·스크롤 이벤트로 좌표를 갱신하며 타이머를 추가하지 않는다.
- 실제 맥 설정에서 개별 위젯의 표시 토글과 위치 핸들 드래그를 확인했다. 두 위젯의 독립 저장과 선택한 위젯에만 적용되는 동작은 저장소·설정 화면 테스트로 검증했다.
- 위치 조절판을 실제 캐릭터 미리보기의 드래그 말풍선으로 교체했다. 관련 Wallaby 테스트 17개가 통과했으며, 맥 앱에서 드래그·방향키 이동·앱 재실행 후 위치 유지를 확인했다. 미리보기 좌표는 실제 위젯 비율을 기준으로 계산하고, 저장한 말풍선이 위젯 밖에 있어도 보이도록 범위를 맞춘다. 위젯을 바꾸거나 입력 방식을 변경할 때 기존 캐릭터 캔버스를 유지하는 테스트도 통과했다.
- 앱을 종료한 뒤 등록된 헬퍼를 실행했을 때 약 793ms 안에 exit 0과 빈 결정 `{}`로 종료했다. 모든 등록은 비동기이며 수신기가 없어도 Codex 결정을 바꾸지 않는다.
- 실제 연결 해제 후 `hooks.json`이 기존 `{ "hooks": {} }`로 복원됐고, `config.toml`의 SHA-256은 해제 전후 동일했다. 기존·나중에 추가된 타사 훅 보존은 병합 테스트로 별도 검증했다. 재연결 후 재승인 없이 실제 수신이 재개됐다.
- 연결 해제 후에도 이미 훅을 로드한 Codex 세션이 명령을 실행할 수 있어 로컬 헬퍼 파일은 유지한다. 등록 항목과 수신 상태만 해제하며 늦은 이벤트는 무시한다.
- 수신 기록은 메모리의 최근 32건으로 제한하며 이벤트 종류·세션/턴 ID·도구 이름을 기록한다. `Stop.last_assistant_message`는 채팅별 최신 응답 말풍선에만 메모리로 보관하며 수신 기록이나 디스크에 쓰지 않는다. 최대 65,536자이며 초과분은 생략을 표시한다. 프롬프트·명령 내용은 전달하지 않고 대화 파일도 열지 않는다.
- Windows 실제 데스크톱 검증은 수행하지 않았다.

Pomo에서 공용 배경 기능을 추출해 만드는 로컬 데스크톱 배경 유틸이다. macOS와 Windows를 함께 지원한다. `wallpaper`는 내부 작업명이며, 음악·포모도로·기타 위젯과 Cubism → Puppet 변환기 개발은 이번 범위에 포함하지 않는다.

## 확정한 동작

- 로그인과 서버 없이 로컬 파일·설정을 사용한다.
- 모니터마다 Poffo, 웹사이트, 사진·동영상 앨범 중 하나를 지정한다.
- Poffo는 기존 `packages/puppet` 플레이어를 연결한다. 저장 형식과 내부 패키지 이름은 호환성을 위해 유지한다.
- Poffo 배경 캐릭터는 미리보기 드래그·방향키·위치 설정으로 이동한다. 별도 위젯은 배경 종류와 관계없이 일반 앱 위에 표시하며 드래그 위치와 열린 캐릭터를 기억한다.
- 위젯 닫기는 설정에서 관리한다. 캐릭터 우클릭 → `크기 조정`에서 8개 핸들로 조절하고 `조정 완료`로 저장한다. 조정 중에는 캐릭터 몸체를 드래그해 위치를 옮길 수 있고, 방향키로 크기를 조절하거나 Esc로 취소할 수 있다. 저장한 크기는 재실행 후 유지한다.
- 위젯의 렌더링 투명도로 입력 영역을 구분한다. 투명한 부분은 뒤쪽 창으로 입력을 통과시키며, 메뉴·크기 조정 중에는 전체 위젯이 입력을 받는다. 누른 채 드래그할 때는 입력 상태를 유지한다.
- Poffo 배경·위젯마다 따라가기를 `끄기 / 커서 / 카메라` 중 선택한다. 얼굴·눈동자의 좌우·상하 연결 파라미터를 직접 고르거나 사용하지 않을 수 있고, 방향도 반전할 수 있다. 자동 연결은 알려진 ID가 하나만 일치할 때 적용하며 실제 연결 이름을 표시한다.
- `시선 보정`에서 얼굴 회전·눈동자 배율과 축별 최대 이동 범위를 각각 조절한다. 카메라 모드는 캐릭터가 있는 모니터 기준 카메라 위치와 사용자 거리로 바라볼 방향을 추정한다. 카메라 위치는 모니터 그림의 아이콘을, 캐릭터 얼굴 기준은 실제 캐릭터 미리보기의 십자를 끌어 맞춘다. `화면 밖 보기`로 다른 화면 쪽에 설치된 카메라도 배치할 수 있다. 드래그는 놓을 때 저장하고 Esc로 취소하며 방향키로 미세 조정할 수 있다. 평소 자세에서 `현재 얼굴을 기준으로`를 누르면 영상 속 얼굴 중심의 기준을 저장한다. `세부 기준`에서는 모니터 대각선·카메라 화각을 맞춘다. 실제 거리나 카메라 설치 각도를 자동 측정하는 기능은 아니다.
- 카메라 따라가기는 기기 안에서 얼굴 위치만 계산한다. 카메라를 사용하는 배경·위젯들이 한 스트림을 공유하며, 마지막 사용을 끄거나 앱을 종료하면 카메라를 해제한다. 영상은 저장·전송하지 않는다.
- 웹사이트는 모니터별 마지막 주소와 최근 방문 내역을 기억한다. 내역은 하나씩 삭제하며 현재 주소와 저장된 마지막 주소는 유지한다. 네이티브 내역은 페이지 로드 완료 시 기록하며 SPA의 페이지 로드 없는 주소 변경은 포함하지 않는다.
- 앨범은 사진·동영상을 순차 또는 랜덤으로 재생한다.
- 웹사이트는 쿠키·웹 저장소를 유지한다. 같은 사이트를 여러 모니터에서 열면 로그인 상태를 공유하고, 사이트 데이터 삭제를 제공한다. 사이트가 만료시킨 세션의 유지는 보장하지 않는다.
- 기본 입력은 바탕화면으로 통과한다. 설정의 조작 탭에서 모니터별로 `입력 통과 / 조작 허용`을 선택하며, 다시 변경할 때까지 유지한다. 길게 누르기·보조키·카운트다운·무입력 자동 해제는 제공하지 않는다.
- 모니터 연결 해제·재연결과 앱 재시작 후 설정을 복원한다.
- macOS 메뉴 막대와 Windows 시스템 트레이의 아이콘을 누르면 `설정…`과 `Wallpaper 종료` 메뉴가 열린다. 앱을 직접 실행하면 설정 창을 표시하고, 닫기 버튼은 창만 숨긴다. macOS에서 실행 중인 앱을 다시 열어도 설정 창을 복원한다. 앱 종료는 트레이 메뉴에서 한다.

## 책임과 의존 방향

| 위치                       | 책임                                                             |
| -------------------------- | ---------------------------------------------------------------- |
| `packages/desktop-surface` | 기존 Tauri 네이티브 배경 창, 배치, 입력, 창 복원                 |
| `packages/wallpaper`       | 공용 배경 모델, 앨범 재생, 저장소 계약, 모니터별 설정, 입력 정책 |

공용 패키지는 앱의 `src`를 참조하지 않는다. Pomo 저장소 이름과 기존 데이터 형식은 유지하며, 앱 전용 캐시·오류 보고·파일 선택은 어댑터로 연결한다. 배경 콘텐츠 종류와 창의 입력 상태는 별도로 모델링한다.

### 배경 입력 설정 단순화

- 2026-10-17: 사용자 요청으로 길게 누르기·보조키·무입력 해제 설정과 사용되지 않던 상태 계산을 제거했다. 기존 `hold`·`modifierHold` 데이터는 `입력 통과`로 읽고, `always`는 `조작 허용`으로 유지한다. 저장할 때는 선택한 상태만 기록한다.
- 관련 Wallaby 테스트 31개로 기존 데이터 재개방·변환, 모니터별 저장, 낙관적 업데이트 및 렌더러를 재시작하지 않는 네이티브 입력 전환을 확인했다. 이 테스트의 네이티브 경계는 모킹했다.
- macOS 최신 앱의 조작 탭에서 두 선택지만 표시되는 것을 확인했다. `조작 허용` 선택 후 네이티브 조회 결과는 `interactive`, `입력 통과`로 복원한 뒤에는 `passThrough`였다. 실제 IndexedDB에도 `{activation: 'passThrough'}`만 저장됐다. 앱 타입 검사·변경 경로 oxlint·macOS 앱 빌드가 통과했고 `pnpm format`을 실행했다. Windows 실행과 웹사이트에서의 실제 입력 전달은 이번 변경에서 별도 확인하지 않았다.

## 개발 실행

의존성 설치 후 기존 Puppet 패키지를 먼저 빌드한다.

```sh
pnpm --filter @winter-love/puppet build
pnpm --filter @apps/wallpaper dev
```

`pnpm --filter @apps/wallpaper desktop`은 Vite와 Tauri 앱을 실행한다. 이미 Vite를 실행 중이면 종료한 뒤 사용한다. 앱을 직접 실행하거나 메뉴 막대·시스템 트레이의 Wallpaper 아이콘 → `설정…`에서 설정 창을 연다. 브라우저 미리보기에서는 관리 화면을 바로 표시하며, 배경 창 적용은 네이티브 앱에서 실행한다. 앨범에서 기본 제공 배경화면을 선택하거나 파일·웹사이트를 추가한다. Poffo에서는 애시·기본 배경·내장 샘플을 선택할 수 있다.

개발 서버가 필요 없는 로컬 검증용 macOS 앱은 다음 명령으로 빌드한다.

```sh
pnpm --filter @apps/wallpaper exec tauri build --debug --bundles app --no-sign
```

네이티브 설정은 [Tauri Vite 연동](https://v2.tauri.app/start/frontend/vite/)을 따른다. 웹사이트 데이터 저장소 연결은 [Tauri WebView API](https://v2.tauri.app/reference/javascript/api/namespacewebview/)의 OS별 저장소 차이를 확인하며 구현한다.
