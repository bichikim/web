# Poffo 앱 분리와 배포 계획

상태: 구현 진행 중. 사용자가 구현 시작을 승인했다. 미정인 제품·호환성 정책은 확인 후 반영하며, 배포는 GitHub Actions 수동 실행으로 진행한다. `dev`는 Preview, `main`은 Production으로 분리한다.

## 목표와 확정한 경계

서비스의 실행·라우팅·페이지 구성은 `apps/poffo`가 담당한다. **공유 문서와 문서별 undo/redo도 Poffo의 모델 세션이 단독으로 소유한다.** Editor·Studio·Viewer는 같은 세션의 문서를 사용하며, 각 화면이나 Puppet 편집기에 별도의 현재 문서 저장소를 두지 않는다. `packages/puppet`은 편집 UI·명령 계산·검증·렌더링 등 재사용 기능을 제공한다. 의존 방향은 `apps/poffo → packages/puppet`으로 유지한다.

**헤더 UI는 모두 Poffo에서 구현한다.** 모델링·애니메이션 전환 UI, 패널 버튼, 에디터 메뉴 UI도 Poffo 소유다. Puppet에는 이 조작부를 헤더용 컴포넌트로 남기지 않고, 필요한 상태와 명령을 제공한다. 캔버스, 편집 패널, 타임라인과 그 안의 편집 UI는 Puppet에 남긴다.

| 구분                                     | 소유   | 의미                                              |
| ---------------------------------------- | ------ | ------------------------------------------------- |
| Editor·Studio·Viewer·Converter           | Poffo  | 앱 페이지와 URL, 페이지 간 이동                   |
| 공유 문서·revision·undo/redo             | Poffo  | 세 화면이 참조하는 단일 모델 세션                 |
| 모델링·애니메이션                        | Puppet | 같은 문서와 편집 이력을 사용하는 에디터 내부 모드 |
| 좌측·우측·하단 패널                      | Puppet | 열림 상태, 크기, 리사이즈와 실제 패널 렌더링      |
| 헤더의 모드 선택·패널 버튼·에디터 메뉴   | Poffo  | Puppet 상태를 표시하고 명령을 호출하는 UI         |
| Studio의 입력 연결·보정·그래프·설정 파일 | Poffo  | 모델 구동을 위한 앱 기능                          |
| Viewer의 모델 선택·재생·보기 설정        | Poffo  | 모델을 확인하는 앱 기능                           |
| 모델 포맷·검증·변형·렌더링·변환          | Puppet | 재사용 가능한 도구 기능                           |

기존 키폼 편집의 **임시 변경**은 에디터 내부 상태다. 공유 문서의 별도 종류나 Studio·Viewer 공용 문서 저장소로 확대하지 않는다.

모델링·애니메이션은 앱 라우트와 별개다. 브라우저 API를 사용하는지, 화면을 렌더링하는지보다 서비스의 경로·세션·화면 정책을 알고 있는지를 소속 판단 기준으로 삼는다.

첫 배포에서 Editor·Studio·Viewer·Converter를 모두 공개한다. `/`는 `/editor`로 연결한다.

## 분리해서 처리할 파일

### 헤더와 에디터 명령

`EditorToolbar.tsx`의 JSX·메뉴 표시·헤더 배치는 Poffo로 옮긴다. 편집 계산과 도구 제어는 Puppet에 남기고, 실제 문서·이력 반영은 Poffo 세션에 요청한다. undo/redo 메뉴는 Poffo 세션의 상태와 명령을 사용한다.

| 헤더 UI                          | 각 소유자가 제공할 상태·명령                              |
| -------------------------------- | --------------------------------------------------------- |
| 모델링·애니메이션 전환           | 현재 모드, 전환 가능 상태, 기존 전환 절차를 수행하는 명령 |
| 좌측·우측·하단 패널 버튼         | 패널별 열림 상태와 토글 명령                              |
| undo/redo 메뉴                   | Poffo 세션의 가능 여부·표시용 이력 정보·실행 명령         |
| 가져오기·불러오기·PSD 재가져오기 | 파일을 받아 기존 편집 절차를 실행하는 명령과 진행 상태    |
| JSON·아틀라스 내보내기           | 내보낼 문서·아틀라스를 생성하는 명령과 결과·진행 상태     |
| 복구 메뉴                        | 복구 기능의 상태·명령. 실제 저장소는 앱에서 연결          |
| 상태 표시·브러시 설정 영역       | 필요한 상태와 도구별 연결 계약                            |

실제 공개 이름과 자료형은 [control](../../../packages/puppet/src/editor/control.ts#L1)과 [model 계약](../../../packages/puppet/src/editor/model/types.ts#L1)을 따른다. 내부 signal·history 객체 전체를 공개하지 않고 실제 UI에 필요한 읽기 상태와 명령만 제공한다.

- 모드 변경은 현재 [전환 명령](../../../packages/puppet/src/editor/internal/EditorBody.tsx#L1)을 거쳐야 한다. 앱이 모드 상태를 직접 수정하지 않는다.
- 패널·편집 모드·선택은 Puppet의 에디터 내부 상태이고, 문서와 편집 이력은 Poffo 세션 상태다. 헤더는 각 소유자의 읽기 상태와 명령을 연결하며 복사본을 저장하지 않는다.
- 메뉴와 키보드 단축키는 같은 명령을 사용한다. 앱이 활성 여부를 전달하고, 패키지는 페이지 이름 대신 그 계약으로 입력 처리를 제한한다.
- 브러시 설정의 기존 내용과 동작을 유지한다. 헤더 위치로 옮길 수 있도록 필요한 렌더링·마운트 계약을 정하고, 관련 편집 기능까지 앱으로 옮기지는 않는다.

### 상태·명령 API 연결 방식

Poffo는 Shadow DOM 없이 Solid `PuppetEditor`를 직접 렌더링한다. Shadow DOM은 독립 `editor-element` 호스트에만 적용한다. 에디터는 외부 문서와 변경 요청 계약에 연결된다. Poffo의 모델 세션이 문서와 undo/redo를 보유하며, `EditorController`는 편집기 내부 상태와 도구 수명만 관리한다. 공개 계약은 `ModelBinding`과 `EditorController`로 구현했다.

| 구성               | 소유·책임                                                                 |
| ------------------ | ------------------------------------------------------------------------- |
| Poffo 모델 세션    | 공유 문서, revision, undo/redo, 편집 트랜잭션, 저장·복구 상태             |
| `EditorToolbar`    | 헤더 UI와 세션·편집기 명령 연결                                           |
| `EditorController` | 모드·선택·패널·기존 임시 변경·편집 입력과 도구 상태                       |
| `PuppetEditor`     | 외부 문서와 controller를 사용하는 편집 패널·타임라인·오버레이             |
| Studio·Viewer      | 같은 모델 세션을 사용하는 Poffo 페이지. 입력·재생·보기 상태는 모델과 구분 |
| `ViewportSurface`  | 전달받은 모델을 그리는 캔버스·플레이어 자원의 생성과 정리                 |

Poffo는 라우트 위에서 모델 세션을 유지하고 편집기를 해당 세션에 연결한다. Editor 화면이 비활성화되거나 편집기 controller가 정리돼도 모델 세션의 문서·이력을 함께 파기하지 않는다. 여러 세션을 지원할 경우 서로 다른 문서·이력·편집 상태를 공유하지 않는다. 지금은 한 작업 공간의 모델 세션 하나를 기준으로 하며 탭 UI는 추가하지 않는다.

#### 문서 연결과 변경 요청

Puppet이 정의하는 호스트 중립적인 문서 연결 계약을 Poffo가 구현한다. 패키지는 Poffo의 파일·context·라우터를 import하지 않는다.

승인에 따라 기존 `initialDocument`·`replacementDocument` props를 필수 [model 바인딩](../../../packages/puppet/src/editor/types.ts#L1)으로 교체하고 저장소 소비처·테스트·Storybook을 이전했다. 초기값용 prop을 상시 제어 문서로 몰래 재정의하거나, 기존 내부 저장소를 유지한 채 앱과 양방향 동기화하는 방식으로 바꾸지 않는다.

| 연결 기능 | 계약                                                                                 |
| --------- | ------------------------------------------------------------------------------------ |
| 문서 조회 | Poffo 세션의 문서·세션 식별자·revision을 읽음. 패키지 내부 원본 저장소를 만들지 않음 |
| 변경 요청 | 기준 세션·revision과 편집 결과 또는 연산을 호스트에 전달                             |
| 트랜잭션  | 드래그 등 같은 조작의 변경을 Poffo가 undo 한 단계로 묶음                             |
| undo/redo | Poffo의 이력 상태 조회와 실행 요청. 편집기 내부 이력을 따로 만들지 않음              |
| 변경 완료 | Poffo가 검증·반영한 결과와 새 revision을 반환. 수락만으로 적용 완료를 알리지 않음    |

흐름은 `Poffo 문서 → 세 화면 → 편집 변경 요청 → Poffo 반영 → 세 화면 갱신`이다. 에디터가 자신의 원본을 먼저 확정한 뒤 앱과 동기화하는 흐름은 사용하지 않는다. 요청 전후에 필요한 드래그·계산 결과는 일시적인 조작 상태로 두고 공유 문서 원본으로 취급하지 않는다.

- 트랜잭션의 시작·갱신·완료·취소와 undo 단위는 Poffo 세션이 관리한다. 자동 복구 저장은 완료된 편집 단위를 기준으로 한다.
- 패키지는 이력 계산·명령 변환을 재사용 함수로 제공할 수 있지만 현재 문서·이력 인스턴스를 별도로 소유하지 않는다.
- 같은 변경을 변경 알림과 외부 문서 교체 양쪽으로 재반영하지 않는다. 호스트 거절·문서 교체·세션 종료 시 오래된 편집 결과를 적용하지 않는다.

#### 편집 트랜잭션의 소유와 종료

트랜잭션 상태와 종료 결정은 Poffo 모델 세션이 소유한다. 에디터는 문서 연결 시 받은 소유자 식별자로 조작을 요청하며, 요청자가 소유자 안에서 고유한 `transactionId`를 보내며, 세션이 이를 검증·보관하고 시작 문서·이력 위치를 소유한다.

- 한 세션에는 문서를 변경하는 트랜잭션을 하나만 연다. 갱신·완료·취소는 소유자와 `transactionId`가 모두 일치해야 한다. 다른 화면의 교체·undo/redo·반영 요청은 진행 중이면 `busy`로 거절하고 임의로 합치지 않는다.
- 드래그 갱신은 공유 문서에 표시하되 아직 이력에 추가하지 않는다. 정상 완료 때 변경 전체를 undo 한 단계로 확정하고 복구 저장 대상으로 알린다. 내용 변화가 없으면 이력·커밋 알림을 추가하지 않는다.
- 취소는 시작 문서와 이력 위치로 되돌리고 트랜잭션을 닫는다. redo 기록을 포함한 기존 이력을 보존하며 새 undo 단계·자동 저장 커밋을 만들지 않는다. 되돌림도 문서 revision을 갱신해 이전 작업 결과를 무효화한다.
- 정상 화면 이동·비활성화는 미완료 트랜잭션이 있으면 `busy`로 중단한다. 조작을 정상 종료하거나 명시적으로 취소한 뒤 다시 전환하며, 이동만으로 커밋·취소하지 않는다.
- 에디터 강제 해제·요소 제거 등에서는 호스트 연결의 소유자 해제를 알린다. 호스트는 해당 소유자의 미완료 트랜잭션을 취소·복원한 뒤 연결을 해제한다. 모델 세션이나 다른 소유자의 완료된 이력을 파기하지 않는다.
- 완료와 해제가 경합하면 호스트에서 먼저 확정한 종료 하나만 유효하다. 이미 완료된 작업의 해제는 롤백하지 않고, 이미 취소된 작업의 늦은 갱신·완료는 거절한다. 반복 해제·취소는 추가 변경을 만들지 않는다.
- 명시적인 문서 초기화는 미완료 트랜잭션을 먼저 취소·종료한 뒤 새 문서·이력 기준을 적용한다. 이 두 처리는 호스트에서 한 번에 확정하고 외부에는 최종 `reset`만 알린다. 중간 롤백 문서를 별도 발행해 초기화 알림을 중복시키지 않는다. 일반적인 undo 가능한 교체는 진행 중 조작을 강제로 취소하지 않는다.
- 트랜잭션 중 실제 파일 내보내기·새 복구 스냅샷 생성은 `busy`로 거절한다. 기존 완료 시점의 복구 저장 작업은 계속할 수 있고, 저장 결과를 해당 revision에만 연결한다.

#### 문서 변경 알림과 내부 상태 정리

문서 객체의 참조 변경만으로 편집 상태를 초기화하지 않는다. 호스트는 `sessionId`, 단조 증가하는 `revision`, 변경 종류 `kind`, 단계 `phase`와 요청·조작 식별자를 함께 전달한다. `kind`는 `edit/replace/reset/undo/redo`, 트랜잭션 단계는 `update/commit/rollback`으로 구분한다. 별도의 범용 이벤트 시스템은 만들지 않는다.

이력 항목에는 일반 편집과 모델 교체를 구분하는 의미를 보관한다. undo/redo 알림에도 어느 종류의 항목을 통과했는지 전달해, 모델 교체의 취소·재적용을 일반 편집과 구분한다.

| 알림                                                               | 에디터 내부 상태 처리                                                                                                    |
| ------------------------------------------------------------------ | ------------------------------------------------------------------------------------------------------------------------ |
| 일반 `edit`의 갱신·완료                                            | 모드·패널·유효한 선택·임시 변경 유지. 자신의 완료 알림을 새 변경 요청으로 되돌리지 않음                                  |
| `replace`·`reset` 또는 모델 교체를 되돌리거나 재적용하는 undo/redo | 기존 임시 변경과 이전 모델 대상의 대기 작업 해제. 레이어·키폼·정점 선택을 새 모델 기준으로 초기화. 모드·패널 설정은 유지 |
| 일반 편집의 undo/redo                                              | 존재하는 선택은 유지하고 사라진 대상 선택은 해제. 임시 변경은 보관하되 표시·저장 전에 대상·키폼·형상 호환성을 재검증     |
| 트랜잭션 `rollback`                                                | 취소된 조작의 표시 상태를 정리하고 호스트가 복원한 문서 사용. 관련 없는 임시 변경·모드·패널은 유지                       |
| 다른 세션 연결                                                     | 이전 연결의 대기 작업과 문서 대상 편집 상태 해제. 이전 세션의 임시 변경을 새 세션에 재사용하지 않음                      |

일반 undo/redo 후 임시 변경이 더 이상 유효하지 않으면 내용을 자동 적용·삭제하지 않는다. 해당 미리보기·저장을 막고 기존 임시 변경 조작부에서 적용 불가를 알리며 사용자가 정리할 수 있게 한다. 새 공유 문서나 임시 변경 자동 저장 기능을 추가하지 않는다.

#### 읽기 상태

`control.getState()`는 에디터 내부 상태의 읽기 전용 반응형 조회 함수다. 문서·이력 정보는 바인딩한 Poffo 세션에서 읽는다. controller에 해당 정보가 필요하면 파생 조회로 제공하며 상태 복제본을 만들지 않는다.

| 상태                    | 소유·제공 내용                                                    |
| ----------------------- | ----------------------------------------------------------------- |
| `lifecycle`             | 에디터 controller의 `inactive`, `active`, `suspended`, `disposed` |
| `mode`                  | 에디터의 `appliedMode`, `mode`, `modePending`                     |
| `panels`·선택           | 에디터 내부 상태                                                  |
| 기존 임시 변경          | 키폼에 아직 적용하지 않은 에디터 내부 상태                        |
| 문서·revision·undo/redo | Poffo 세션의 읽기 상태                                            |
| 진행 상태               | 파일·세션 작업은 Poffo, 도구 내부 작업은 에디터가 소유            |
| 실행 가능 여부          | 세션과 에디터 상태에서 파생                                       |
| 렌더러 상태             | 공유 viewport에서 제공. 문서·이력의 수명과 구분                   |

현재 [선택 피드백과 실제 적용의 구분](../../../packages/puppet/src/editor/internal/use-editor-selection.ts#L1)을 유지한다. 모드 선택은 즉시 표시하고 취소·실패 시 실제 적용 상태에 맞춘다. 렌더러 오류만으로 Poffo의 문서 조회·복구·내보내기를 막지 않는다.

#### 명령 경계와 허용 범위

| 명령·동작                    | 책임                                                                                      |
| ---------------------------- | ----------------------------------------------------------------------------------------- |
| `selectMode(mode)`           | 에디터의 기존 전환 절차 실행. 마지막 요청 적용, 이전 미완료 요청 취소                     |
| `setPanelOpen`·`togglePanel` | 에디터 내부 패널 상태 변경                                                                |
| undo/redo                    | Poffo 세션에서 실행. 메뉴·단축키가 같은 명령을 사용                                       |
| 파일 추가·불러오기           | Poffo가 파일 입력을 받고 Puppet의 해석·검증 기능을 호출한 뒤 세션에 반영                  |
| PSD 재가져오기               | Puppet이 비교·변환을 수행하고 선택 결과를 Poffo의 한 편집 트랜잭션으로 요청               |
| 모델 교체                    | 어느 화면에서 시작하든 Poffo 세션의 동일한 교체 명령 사용                                 |
| 내보내기                     | Poffo가 세션 문서를 읽고 Puppet의 직렬화·아틀라스 생성 기능 호출                          |
| 기존 임시 변경 저장          | 선택 키폼 변경을 Poffo에 요청. 호스트 반영 완료와 요청 일치 확인 후 해당 임시 변경만 정리 |

에디터가 `inactive`·`suspended`일 때는 해당 에디터의 변경 입력을 제한한다. 이를 세션 전체의 잠금으로 확대하지 않는다. Studio·Viewer의 호스트 문서 교체는 에디터 활성 여부가 아니라 Poffo의 트랜잭션·충돌 규칙으로 판단한다. 진행 중 조작과 충돌하는 변경은 명시적으로 거절·취소 처리하며 임의로 덮어쓰지 않는다.

#### 비동기 수락·완료·취소

문서 변경은 동기 `ModelCommandResult`로 실제 호스트 반영 완료 또는 거절을 반환한다. 수락만 반환하는 문서 쓰기 큐는 없다. `ok: true`일 때만 임시 변경 정리·PSD 검토 닫기·파일 성공 처리를 진행한다.

모드 전환만 `accepted(operation)`과 `operation.finished`를 사용한다. 완료는 `completed`, 이전 요청·비활성화·해제·명시적 취소는 `cancelled`로 구분한다. 이미 완료된 변경은 취소로 되돌리지 않고 undo로 처리한다. 명령별 결과와 오류 코드는 [공개 타입](../../../packages/puppet/src/editor/control.ts#L1)을 따른다.

파일 읽기·PSD 비교·메시 계산은 결과를 반영하기 전 기준 문서·revision을 재검증한다. 외부 제어 객체의 비동기 문서 교체 호출은 시작 시 캡처한 `{sessionId, revision}`을 `replaceDocument`의 두 번째 인수로 보낼 수 있다. 이전 연결·revision 결과를 새 문서에 전달하지 않는다.

### 파일 작업과 피드백

파일 선택·다운로드·문서 반영·저장 정책은 Poffo가, 파일 해석·검증·편집 연산·내보낼 데이터 생성은 Puppet이 담당한다.

- Poffo가 `openModel(file)` 같은 앱 진입점에서 파일을 준비하고, 성공한 결과만 현재 모델 세션에 반영한다. 실패하면 기존 문서를 유지한다.
- 파일 불러오기와 일반 모델 교체는 현재 세션에서 undo 가능한 한 작업으로 처리한다. 새 작업 생성·문서 초기화는 이력 재설정과 연결되는 별도 동작으로 구분한다.
- 파일 추가·PSD 재가져오기·일반 교체는 서로 다른 편집 의미를 유지한다. [기존 교체 후 선택·도구 초기화](../../../packages/puppet/src/editor/internal/EditorBody.tsx#L1)는 새 문서 반영 알림에 연결한다.
- 현재 [useDocumentExport](../src/editor/use-document-export.ts#L1)의 계산과 다운로드 처리를 분리한다. Poffo가 다운로드 이름·브라우저 저장 동작·객체 URL 정리를 맡는다.
- 복구 저장 성공과 파일 내보내기를 구분한다. 다운로드 실행만으로 실제 파일 저장 완료를 확정하지 않는다.
- 헤더에서 시작한 명령의 피드백은 Poffo가 표시한다. 편집 패널 내부 안내까지 전부 앱으로 이동하지 않으며 같은 오류를 중복 표시하지 않는다.

### 공유 모델 세션과 기존 임시 변경

Editor·Studio·Viewer는 라우트 위의 같은 Poffo 모델 세션을 참조한다. 각 화면에 문서 복사본을 두고 동기화하지 않는다. 세션 ID·문서·undo/redo·복구 저장 상태는 Poffo가 관리한다. 파일명·다중 문서 탭 관리 기능은 이번 이전에 추가하지 않는다. 화면 이동은 세션 ID나 문서 이력을 바꾸지 않는다.

```text
Poffo 모델 세션의 공유 문서·undo/redo
  → Editor·Studio·Viewer가 같은 문서 사용
  → Editor 또는 앱 기능에서 변경 요청
  → Poffo가 검증·문서·이력 반영
  → 세 화면과 공유 플레이어 갱신
```

#### 모델과 화면 상태

- Studio의 연결·보정·그래프 설정은 모델 세션에 연결된 별도 앱 상태다. 수동 파라미터·추적값·재생 위치가 모델 문서의 기본값이나 키폼을 자동으로 덮어쓰지 않는다.
- 모델 수정·교체 시 Studio 설정을 현재 모델과 검증한다. 세션 식별과 구조 호환성 판단을 혼동하지 않도록 현재 [signature 기반 설정 복원](../src/runtime/use-runtime-profile.ts#L1)을 정리한다. 유효하지 않은 연결을 다른 파라미터에 임의로 재적용하지 않는다.
- 문서 revision은 비동기 충돌 검사용이다. undo로 기준 내용에 돌아갈 수 있으므로 revision 차이만으로 수정 여부를 판단하지 않는다. 저장 기준 스냅샷·이력 체크포인트와 복구 저장 상태를 구분한다.

#### 기존 임시 변경

[useTemporaryForm](../../../packages/puppet/src/editor/internal/use-temporary-form.ts#L1)의 키폼 편집용 임시 변경은 에디터 내부에 남긴다. 파츠별 변경을 보관하고, [임시 변경 버튼의 hover·focus](../../../packages/puppet/src/editor/internal/TemporaryFormButton.tsx#L1)로 확인하며, [선택 키폼에 저장](../../../packages/puppet/src/editor/internal/use-temporary-form.ts#L1)할 때 공유 문서 변경을 요청한다.

- 별도의 공유 미리보기 문서·저장소·revision 종류를 만들지 않는다. 렌더링을 위한 계산 결과는 원본과 구분된 파생값이며 다른 문서 소유자가 아니다.
- 선택 키폼에 반영하기 전에는 Poffo 문서·undo/redo·자동 복구 저장에 추가하지 않는다. 요청 수락은 완료가 아니며, 거절·실패·취소 시 임시 변경을 유지한다.
- 저장 요청은 대상·revision·선택 키폼과 제출한 임시 변경 버전을 캡처한다. 동기 호스트 반영이 `ok: true`로 완료된 뒤에도 제출한 버전이 그대로인지 확인하고 해당 버전만 정리한다. 호스트 알림의 동기 재진입으로 새 버전이 생겼다면 보존한다.
- 대기 중 사용자가 임시 변경을 더 수정했다면 이전 요청이 완료돼도 새 버전을 삭제하지 않는다. 이미 대기 중인 동일 버전의 저장 요청은 `busy`로 거절해 중복 이력 반영을 막는다. 호스트가 대상의 유효성과 동일한 적용 값을 확인해 변경 없는 완료를 반환한 경우도 완료로 처리하되 새 이력은 만들지 않는다.
- 문서 교체·초기화로 대상이 바뀌면 이전 요청 결과로 새 대상의 임시 변경을 정리하지 않는다. 대기 요청 취소와 변경 종류별 내부 상태 정리 규칙을 적용한다.
- 화면 전환만으로 임시 변경을 커밋·삭제하지 않는다. 문서 교체·undo/redo 시에는 위 변경 종류별 내부 상태 정리 규칙을 적용하고 기존 조작부·접근성을 검증한다.
- 이전 runtime 실행의 `temporary.document` 전달은 제거했다. Studio·Viewer는 Poffo 공유 문서를 사용한다. 내부 임시 변경의 별도 확인 기능이 필요하면 표시 정책으로 따로 결정하며 공유 문서 소유권 설계에 포함하지 않는다.
- 내보내기는 Poffo 세션 문서를 사용한다. 기존 임시 변경이 제외됐다는 안내가 필요하면 에디터가 그 존재를 알려 Poffo가 표시한다. 임시 변경 자동 저장·화면 간 적용 같은 새 기능은 추가하지 않는다.

#### 이전 설계에서 대체하는 내용

Puppet controller의 문서·이력 소유, 작업·커밋·미리보기 문서를 각각 공유 상태로 취급한 구분, 모든 화면 이동 전 문서 복사·저장 완료를 요구한 흐름은 이 계약으로 대체한다. 복구용 스냅샷과 undo 이력은 같은 모델 세션의 기록이며 독립적인 현재 문서가 아니다.

### Workspace와 공유 뷰포트

`workspace` 폴더를 통째로 앱으로 이동하거나 그대로 공개 API로 만들지 않는다.

- `WorkspaceProvider`, `WorkspacePages`, `context`, `use-workspace-session`, `use-workspace-navigation`의 앱 조율 책임은 Poffo로 옮긴다.
- `BaseHeader`, `HeaderSurface`와 현재 헤더·뷰포트 등록을 조율하는 `create-surface-registry`의 사용부는 앱이 소유한다.
- [Viewport](../../../packages/puppet/src/editor/viewport/Viewport.tsx#L1)는 앱 context를 참조하는 연결부와 재사용 뷰포트로 분리한다.
- [workspace/types.ts](../../../packages/puppet/src/editor/viewport/types.ts#L1)는 앱 페이지·화면 소유권 타입과 패키지의 뷰포트 계약으로 나눈다.
- [tracking의 RuntimeView](../src/tracking/types.ts#L1)는 카메라·화면 맞춤 상태만 표현하는 패키지 계약으로 분리한다. 앱의 추적 프로필이 그 타입을 사용한다.
- 각 책임을 옮긴 뒤 기존 `workspace/index.ts`와 폴더를 정리한다.

공유 캔버스와 유지된 화면 컨트롤러는 동작을 확인하며 이전한다. 단순히 화면을 재마운트하거나 공유 캔버스를 여러 개로 바꾸는 것으로 대체하지 않는다.

공유 `ViewportSurface`는 헤더·활성 화면이 바뀌어도 유지하는 구조로 설계한다.

- 활성 화면은 문서·모션·파라미터·편집 오버레이·프레임 연결을 포함하는 공개 뷰포트 설정을 제공한다. Poffo는 소스를 선택해 전달하며 편집 오버레이를 재구현하지 않는다.
- 캔버스·플레이어를 생성한 `ViewportSurface`만 해당 자원을 파기한다. Editor·Studio·Viewer controller는 공유 플레이어를 빌려 사용하고 직접 파기하지 않는다.
- 소스 교체 세대를 확인해 이전 화면의 늦은 콜백을 새 화면에 반영하지 않는다. 헤더 마운트·언마운트는 뷰포트 수명에 영향을 주지 않는다.
- 현재 [공유 뷰포트의 Portal 유지 구조](../src/workspace/WorkspaceProvider.tsx#L1)와 [플레이어 정리 책임](../../../packages/puppet/src/editor/PlayerCanvas.tsx#L1)을 분리해 이어간다. 구체적인 뷰포트 자료형은 기존 기능을 담을 수 있는지 확인한 뒤 정한다.

#### 인스턴스와 자원의 생명주기

모델 세션과 편집기 controller의 수명을 구분한다. Poffo가 공유 문서·이력의 수명을 관리하고, 에디터는 세션을 빌려 내부 조작 상태와 입력 자원을 관리한다.

| 동작           | 에디터 계약                                                                                                 |
| -------------- | ----------------------------------------------------------------------------------------------------------- |
| `activate()`   | 연결된 편집 화면의 입력 허용                                                                                |
| `suspend()`    | 에디터의 변경 입력을 일시 차단. 세션 전체 잠금이나 저장 요구가 아님                                         |
| `resume()`     | 일시 정지한 에디터 입력 복구                                                                                |
| `deactivate()` | 편집기 내부 상태를 유지하고 입력·단축키·편집 재생 비활성화                                                  |
| `dispose()`    | 호스트에 소유자 해제를 알리고 미완료 조작 취소 후 에디터 자원 정리. 빌린 세션·이력·플레이어는 파기하지 않음 |

에디터 controller는 `inactive → active → suspended`와 복귀를 지원하고 최종적으로 `disposed`가 된다. 정리된 controller로 새 요청을 보내지 않는다. 정상적인 전환은 진행 중 조작이 있으면 `busy`로 중단한다. 강제 해제는 위 트랜잭션 취소·복원 계약으로 종료하므로 완료된 편집을 버리거나 미완료 조작을 임의로 커밋하지 않는다.

- 헤더 교체·라우트 이동이 모델 세션이나 공유 viewport를 다시 만드는 이유가 되지 않는다.
- controller를 유지해 모드·선택·패널·기존 임시 변경을 보존하되, 화면별 문서·이력 저장소는 만들지 않는다.
- 앱으로 옮긴 카메라·추적 Worker·입력 이벤트는 Poffo가 소유한다. Studio·Viewer 같은 runtime 세션에서 유지할 상태와 Editor 복귀·세션 종료 시 정리할 자원을 확인한다.
- 모델 세션 종료·초기화는 Poffo가 결정한다. 이전 세션·revision을 대상으로 한 작업은 결과 반영 전 검증하고 무효화한다.

#### 같은 모델의 화면 이동

1. Poffo가 같은 모델 세션을 유지한 채 대상 페이지를 준비한다.
2. 미완료 편집 트랜잭션이 있으면 `busy`로 전환을 중단한다. 정상 완료 또는 사용자의 명시적 취소 후 재시도하며, 필요한 경우에만 에디터 입력을 일시 정지한다.
3. 기존 공유 문서를 사용하는 대상 화면과 뷰포트 입력으로 전환한다. 문서를 복사하거나 runtime 전용 저장소에서 다시 불러오지 않는다.
4. 활성 화면·단축키·입력·추적을 조정한다. 실패·취소 시 유효한 기존 화면으로 복귀한다.

자동 복구 저장은 Poffo 세션의 완료된 편집 단위에 따라 독립적으로 진행한다. 같은 세션 안의 화면 이동에 저장 완료를 필수로 요구하지 않으며, 저장 실패만으로 세 화면의 메모리상 공유 문서 사용을 막지 않는다.

세션 닫기·새 작업으로 교체·실제 브라우저 이탈은 화면 이동과 별개로 저장·복구 정책을 정한다. 지연된 저장·화면 준비 결과는 모델 세션·편집기 인스턴스·revision 중 해당 작업에 필요한 식별자를 재확인한 뒤 반영한다.

### Custom Element 호환성

`editor-element`는 외부 문서 연결 계약과 `EditorController`를 사용하는 DOM 어댑터로 한정한다. 아래 계약을 구현했으며, 자동화 검증과 외부 소비처 호환성의 범위는 구분한다.

Poffo 서비스에서는 앱의 모델 세션이 문서·이력을 소유하고 `editor`를 직접 사용한다. 독립 Custom Element에서는 기존 `.document` API를 유지하기 위해 요소 어댑터가 호스트 역할로 문서·이력을 관리하고 편집기에 연결한다. 이 호스트 역할을 편집기 controller의 내부 문서 저장소로 되돌리지 않으며 Poffo를 패키지에서 import하지 않는다. 이번 이전에서는 독립 요소가 호스트 역할을 제공하며, Custom Element에 별도 외부 공유 세션 연결 옵션은 추가하지 않는다. Poffo의 외부 문서 연결은 `editor` 공개 계약을 사용한다. 사용 예와 호스트 이전 절차는 [Custom Element 연결](editor-element.md#L1)을 따른다.

현재 [PuppetEditorElement](../../../packages/puppet/src/editor-element/PuppetEditorElement.tsx#L1)는 `PuppetEditor`를 직접 렌더링한다. 저장소에서 확인한 직접 소비처는 [단독 태그 데모](../../../packages/puppet/element.html#L1)와 [어댑터 테스트](../../../packages/puppet/src/editor-element/__tests__/PuppetEditorElement.spec.tsx#L1)다. 외부 소비처는 확인되지 않았으며, 헤더 제거로 달라지는 사용 경로를 별도 이전 항목으로 다룬다.

#### 인스턴스별 제어 객체

DOM 호스트에는 인스턴스에 묶인 제어 객체 하나와 일반 JavaScript 상태 조회를 제공한다. Solid accessor·owner나 내부 controller 자체를 노출하지 않는다.

| 접근 경로            | 계약                                                                      |
| -------------------- | ------------------------------------------------------------------------- |
| `element.control`    | 현재 연결된 인스턴스의 읽기 전용 제어 객체. 연결 전·연결 해제 후에는 없음 |
| `control.getState()` | 현재 표시용 상태의 읽기 전용 스냅샷 조회                                  |
| `control.commands`   | 해당 인스턴스에 묶인 편집·문서 명령                                       |
| `control.lifecycle`  | 해당 인스턴스의 `activate/deactivate/suspend/resume` 제어                 |

연결 전·해제 후 `control`은 `undefined`다. `element.state`는 `{editor, error}`이며 연결 전·해제 후에도 입력 오류를 조회할 수 있다. 연결되지 않은 상태에 호출을 무제한 대기시키는 큐는 만들지 않는다.

- 재연결 등으로 인스턴스가 교체되면 새 제어 객체를 제공한다. 이전 객체의 명령은 `disposed` 또는 `stale-instance`로 거절하고, 이전 비동기 작업도 새 인스턴스를 변경하지 않는다.
- 고정된 `commands` 객체가 현재 controller를 자동으로 따라가는 중계 계층은 추가하지 않는다. 호스트는 연결 상태 변경 시 현재 제어 객체를 다시 얻는다.
- 별도의 `active` setter와 요소 최상위 `suspend()/resume()`를 함께 추가하지 않는다. 활성화와 일시 정지는 `control.lifecycle` 한 경로로 제어한다.
- 최종 해제는 요소 어댑터가 소유한다. 제어 객체를 통해 호스트가 controller만 파기한 채 연결된 요소를 남기는 별도 경로는 우선 추가하지 않는다.

#### 기존 API와 문서 초기화

호환성 보존 대상은 소비자가 관찰하는 문서·이벤트·초기화 의미다. DOM이나 controller의 재생성 횟수는 공개 보장 대상에 포함하지 않는다.

| 기존 표면                     | 유지할 범위와 확인할 내용                                                                                                                                                                 |
| ----------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `<puppet-editor>`와 등록 함수 | 태그 이름, [import 시 자동 등록](../../../packages/puppet/src/editor-element/index.ts#L1), [명시적 등록·중복 방지](../../../packages/puppet/src/editor-element/define-element.ts#L1) 유지 |
| `.document` getter            | 현재 작업 문서의 방어적 복사본을 반환. 반환 객체 수정은 내부 문서에 영향을 주지 않음                                                                                                      |
| `.document = value`           | 문서와 편집 상태의 초기화 의미를 보존하는 방향. undo 가능한 일반 교체와 구분                                                                                                              |
| `.exportDocument()`           | [문서를 동기적으로 반환](../../../packages/puppet/src/editor-element/PuppetEditorElement.tsx#L1)하는 동작 유지. 매번 방어적 복사본을 반환                                                 |
| `puppet-document-change`      | [이벤트 이름·문서 payload·bubbles·composed](../../../packages/puppet/src/editor-element/PuppetEditorElement.tsx#L1) 유지. payload를 다른 객체로 감싸지 않음                               |
| Shadow DOM과 Portal           | [기존 내부 Portal 검사](../../../packages/puppet/src/editor-element/__tests__/PuppetEditorElement.spec.tsx#L1)를 실제 메뉴·포커스 검증과 함께 보강                                        |

이전 setter의 전체 재생성에 관한 [대체 구현](../../../packages/puppet/src/editor-element/PuppetEditorElement.tsx#L1)과 [이벤트·이력 검사](../../../packages/puppet/src/editor-element/__tests__/PuppetEditorElement.spec.tsx#L1)를 기준으로 초기화 의미를 검증한다. 전체 재생성은 공개 보장 대상이 아니다. 필요한 초기화 의미는 호스트가 소유한 이력의 초기화와 에디터의 선택·임시 변경 정리를 조합해 보존한다. 현재 [이력 초기화 기능](../../../packages/puppet/src/editor/model/reduce-model.ts#L1)은 의미를 확인할 참고 구현이며, 이 함수를 패키지 controller에 남겨 소유권을 유지하거나 단독 호출만으로 호환성을 확보하는 계획은 아니다.

```text
element.document = nextDocument
  → 호스트 문서·이력과 에디터 내부 상태 초기화

control.commands.replaceDocument(nextDocument, ...)
  → 호스트 세션에 undo 가능한 한 번의 교체 요청
```

명시적인 호스트 문서 초기화는 이전 문서를 대상으로 한 비동기 요청과 화면 준비 결과를 무효화한다. 모델 세션·revision과 에디터 인스턴스는 다른 식별 범위다. controller를 유지해 문서를 초기화해도 이전 모델 revision의 결과를 반영하지 않고, controller가 교체되면 이전 제어 객체도 거절한다. 에디터의 일시 정지를 문서 세션 전체의 잠금으로 사용하지 않는다.

#### 최소 이벤트와 알림 규칙

기존 변경 이벤트와 표시용 상태 변경·자동 저장용 커밋 이벤트로 한정한다. 별도의 `ready` 이벤트는 추가하지 않는다. 내부 변경 종류·단계는 어댑터에서 변환하고, 기존 변경 이벤트의 `detail`은 문서 자체로 유지한다.

| 이벤트 제안                   | 발행 계약                                                                            |
| ----------------------------- | ------------------------------------------------------------------------------------ |
| 기존 `puppet-document-change` | 호스트의 실제 문서 갱신·롤백과 초기 연결·명시적 초기화 알림                          |
| `puppet-state-change`         | `element.state`와 같은 `{editor, error}`. 연결·모드·패널·실행 가능 여부와 오류       |
| `puppet-document-commit`      | 호스트가 완료한 편집·교체·undo/redo의 문서·세션·revision. 이력 변화 없는 호출은 제외 |

- 최초 연결·재연결은 초기 문서 알림을 한 번 발행하고, 연결된 제어 객체를 조회할 수 있는 상태를 알린다. 문서를 연결한 것만으로 커밋 이벤트를 발행하지 않는다.
- `.document` 대입은 같은 유효 문서 객체여도 명시적 초기화로 처리한다. 연결 중이면 초기화 문서 알림을 한 번 발행하고 이력을 비우지만, 사용자 편집 커밋 이벤트는 발행하지 않는다. 연결 전 대입은 보관만 하고 연결 시 초기 알림을 발행한다.
- 트랜잭션 갱신은 문서 변경을 알리고, 정상 완료는 커밋을 한 번 알린다. 완료 시 내용이 다시 바뀌지 않았다면 문서 변경 이벤트를 중복 발행하지 않는다. 롤백은 복원된 문서 변경만 알리고 커밋은 발행하지 않는다.
- 한 처리 단계에서는 캐시와 읽기 상태를 먼저 갱신하고, 필요한 문서 변경 이벤트, 커밋 이벤트, 상태 이벤트 순으로 발행한다. 렌더러 준비는 별도 상태 변화다.
- 이벤트 핸들러에서 초기화·제거·재연결이 발생하면 이전 단계의 나머지 알림을 중단한다. 새 인스턴스·새 문서 알림과 이전 작업의 결과를 섞지 않는다.
- 상태 이벤트에 문서 전체를 반복해서 담거나 애니메이션 프레임마다 헤더 상태를 발행하지 않는다. 이벤트를 놓친 호스트도 현재 연결·상태를 조회해 UI를 구성할 수 있어야 한다.

이는 새 연결 계약의 발행 순서다. 기존 공개 이벤트의 payload·전파 옵션은 유지하고, 실제 소비자의 초기 알림·재진입 동작과 대조해 이전 영향을 기록한다.

#### 연결·해제와 자원 소유

단독 요소의 호스트와 편집기·렌더러 수명을 다음처럼 정한다. 내부 controller의 재생성 횟수는 보장하지 않으며 문서 조회·이력 의미와 이벤트 계약을 보장한다.

| 상황                     | 문서·이력·제어 객체                                                                                                    |
| ------------------------ | ---------------------------------------------------------------------------------------------------------------------- |
| 연결 전 `.document` 대입 | 문서를 초기 입력으로 보관. controller·viewport·이력 세션은 생성하지 않음                                               |
| 연결                     | 보관 문서로 요소 소유 호스트 세션과 편집기·전용 viewport 구성. 초기 이력은 비어 있고 UI 연결 후 편집 입력 활성화       |
| 비활성화·일시 정지       | 같은 호스트 문서·이력·제어 객체 유지. 에디터 입력만 제한                                                               |
| 연결 중 `.document` 대입 | 호스트 문서·이력 초기화, 기존 조작 취소와 에디터 내부 상태 정리. 재생성 여부와 무관하게 이전 요청 무효화               |
| DOM 연결 해제            | 소유자 해제로 미완료 트랜잭션 복원, 마지막 확정 문서 보관, 편집기·구독·작업·전용 viewport와 요소 소유 호스트 이력 정리 |
| 해제 후 문서 조회        | `.document`와 `exportDocument()`는 보관한 마지막 확정 문서를 동기 반환. `element.control`은 없음                       |
| 해제 후 문서 대입        | 보관 문서를 교체하고 다음 연결의 초기 입력으로 사용                                                                    |
| 같은 요소 재연결         | 보관 문서로 새 호스트 세션·제어 객체 구성. 이전 undo/redo·선택·미확정 임시 변경은 복원하지 않음                        |

- 해제는 먼저 이전 연결을 닫는 상태로 만들고, 캡처한 소유자·자원에 대해 수행한다. 호스트 트랜잭션을 취소·복원한 다음 문서 캐시를 갱신하고 자원을 정리한다. 늦은 결과가 캐시나 다음 연결을 바꾸지 않게 한다.
- 롤백으로 문서가 바뀌었다면 기존 문서 변경 이벤트를 알린다. 최종적으로 `element.control`이 없는 연결 해제 상태를 알리며 커밋 이벤트는 발행하지 않는다. 재진입으로 새 연결이 시작되면 이전 연결의 나머지 정리·알림이 새 자원을 대상으로 실행되지 않게 한다.
- 일반 DOM 제거·재삽입도 이 해제·재연결 계약을 따른다. 유지해야 할 편집 상태가 있으면 요소를 제거하지 않고 같은 연결에서 비활성화한다. DOM 이동을 위한 별도 지연 해제·상태 유지 옵션은 추가하지 않는다.
- 이 해제 정책은 단독 요소가 소유한 호스트 이력에 적용한다. Poffo가 `editor`에 빌려준 공유 문서·이력은 편집기 정리로 파기하지 않는다.
- 강제 해제 중 미완료 조작은 취소돼 마지막 확정 문서로 돌아간다. 정상 완료된 문서의 제거·재연결 호환성과 구분해, 새 트랜잭션 계약에 따른 중단 동작으로 검증한다.

#### 기존 API 경계와 검증 범위

| 항목        | 확인·결정할 내용                                                                           |
| ----------- | ------------------------------------------------------------------------------------------ |
| 반환 객체   | getter·`exportDocument()`는 각각 방어적 복사본을 반환. 입력 문서도 복사해 외부 변경과 분리 |
| 잘못된 입력 | setter 경계에서 검증. 잘못된 입력은 예외 없이 실패 상태·이벤트로 알리고 기존 문서를 보존   |
| 대입 시점   | 연결 전·후 대입이 조회·편집 화면·이벤트에 반영되는 시점                                    |
| 초기화      | 동일 객체도 초기화하는 위 계약과 이력·선택·임시 변경 정리 검증                             |
| 이벤트      | 위 발행 순서·횟수·payload와 초기화·제거·재연결 재진입 검증                                 |
| 접근성      | 헤더 외부 이전 후 메뉴·팝오버·키보드·포커스 복귀 연결                                      |

헤더 UI를 Puppet에 남기거나 패키지에서 Poffo를 import하는 방식으로 호환성을 해결하지 않는다. 기존 단독 태그는 별도 헤더가 없으므로, 헤더 외부 이전은 호스트 변경이 필요한 UI 변경으로 명시한다. Poffo에 호스트 연결 예제·이전 절차를 두고, API와 기본 UI의 호환 범위를 구분해 검증한다. 외부 소비처까지 전체 호환성이 유지된다고 단정하거나, 호스트 이전 경로 없이 기능이 사라지는 변경을 완료 처리하지 않는다.

## 서비스 앱 구성과 빌드

Poffo는 SolidJS·Vite 기반 앱으로 구성하고, `@winter-love/puppet`을 workspace 의존성으로 사용한다. 앱은 패키지의 공개 진입점만 사용한다.

- 패키지의 기존 라이브러리 빌드를 유지한다. 서비스 HTML 빌드를 패키지에 추가하지 않는다.
- Puppet 배포 결과물·타입을 만든 뒤 Poffo 앱을 빌드한다. [Turbo의 의존 패키지 선행 빌드](../../../turbo.json#L1)를 활용한다.
- 앱의 출력 디렉터리는 `apps/poffo/dist`로 계획한다.
- 편집기용 UnoCSS와 앱의 UnoCSS가 각각 필요한 스타일을 포함하는지 확인한다. 앱에서 패키지의 비공개 스타일 모듈을 직접 import하지 않는다.
- 앱 생성에 필요한 `package.json` 스크립트 추가는 저장소 규칙에 따라 구현 전에 명시적 승인을 받는다.

### Studio와 라이브러리 빌드 대상

[BUILD_TARGETS](../../../packages/puppet/vite.config.ts#L1)는 페이지 목록이 아니라 라이브러리 출력 진입점 목록이다. 현재 Studio는 독립 공개 진입점 없이 [RuntimePage를 Studio 모드로 렌더링](../src/workspace/WorkspacePages.tsx#L1)하는 앱 화면이다.

- Studio 페이지·헤더·입력 연결·매핑은 Poffo로 옮겨 앱 빌드에 포함한다. 패키지의 `BUILD_TARGETS`에 별도 `studio` 진입점을 추가하는 계획은 포함하지 않는다.
- Studio·Viewer의 공통 렌더링·모션·파라미터 제어에는 Puppet의 `player` 공개 진입점을 사용한다.
- Editor의 편집 기능·상태·명령에는 `editor` 공개 진입점을 사용한다. Poffo가 이를 조합하는 데 필요한 계약을 먼저 정리한다.
- [editor](../../../packages/puppet/src/editor/index.ts#L1)는 Solid 컴포넌트와 편집 API를 제공한다. [editor-element](../../../packages/puppet/src/editor-element/index.ts#L1)는 같은 편집기를 `<puppet-editor>` Custom Element로 감싸 등록하는 별도 통합 방식이다.
- Poffo는 Solid 앱이므로 `editor`를 직접 사용한다. `editor-element`는 다른 호스트에서 사용할 통합 경로로 유지하며, 상태·명령 연결은 앞의 호환성 항목에 따라 정리한다.

## GitHub Actions와 Vercel 배포

워크플로를 구현했다. 실제 원격 실행·배포·도메인 연결은 별도 검증 항목이다.

- 개발용 [poffo-deploy.yml](../../../.github/workflows/poffo-deploy.yml#L1)과 운영용 [poffo-production-deploy.yml](../../../.github/workflows/poffo-production-deploy.yml#L1)을 분리한다.
- PR에서는 앱·패키지의 lint, 포맷, 타입, 관련 테스트·서비스 빌드·브라우저 동작을 검증한다.
- 자동 배포는 실행하지 않는다. 개발 배포는 `dev`의 수동 실행만 허용하고 Vercel Preview 설정·산출물·배포를 사용한다. 운영 배포는 `main`의 수동 실행만 허용한다. 개발 액션에는 `--prod`·운영 승격 경로가 없다.
- 변경 감지에 앱, Puppet, 실제 공용 의존 패키지, 잠금 파일과 빌드·워크플로 설정을 포함한다.
- 프로덕션 배포를 직렬화하고 Vercel Git 자동 배포와 중복 실행되지 않도록 구성한다.
- [Pomo 운영 워크플로](../../../.github/workflows/pomo-production-deploy.yml#L1)의 `main` 제한과 [Pomo 개발 워크플로](../../../.github/workflows/pomo-audio-gateway-deploy.yml#L1)의 `dev`·Preview 분리를 따른다. Node·pnpm·Vercel CLI 구성과 인증 방식도 기존 구성을 참고한다. 토큰의 실제 사용 가능 여부는 구현할 때 확인한다.
- Vercel 프로젝트의 Root Directory는 `apps/poffo`로 맞춘다. 앞서 생성한 `poffo` 프로젝트의 설정을 다시 확인하며, 기존 로그인 보호 설정을 임의로 변경하지 않는다.

운영 배포 순서는 다음과 같다. 개발 배포는 Preview 설정을 가져와 `build --target=preview`·`deploy --prebuilt --target=preview`를 사용하고, 응답 검사 후 운영 승격 없이 끝낸다. CLI 옵션과 프로젝트 설정은 구현 시 공식 문서로 재확인한다.

```text
체크아웃·환경 준비·의존성 설치
  → 코드 검사·관련 테스트
  → Vercel 프로덕션 설정 가져오기
  → Puppet 선행 빌드를 포함한 vercel build --prod
  → 산출물·브라우저 동작 검증
  → deploy --prebuilt --prod --skip-domain
  → 배포 URL·정적 자산 응답 검증
  → promote로 프로덕션 도메인 반영
```

기존 [Pomo의 배포 후 검증·승격 흐름](../../../.github/workflows/pomo-production-deploy.yml#L1)을 참고한다. 실패한 배포는 승격하지 않는다. 배포 URL과 커밋 SHA를 Actions 요약에 남기고, 이전 정상 배포가 있는 경우 되돌릴 수 있도록 기록한다.

첫 Actions 배포를 확인한 뒤 `poffo.io`의 DNS·HTTPS 연결을 진행한다. DNS는 당시 Vercel이 반환하는 값을 사용하고, 기존 메일 등 관련 없는 레코드는 보존한다.

공식 참고 문서:

- [Vercel CLI 배포와 prebuilt·skip-domain](https://vercel.com/docs/cli/deploy)
- [Vercel CLI build](https://vercel.com/docs/cli/build)
- [Vercel Git 자동 배포 설정](https://vercel.com/docs/project-configuration/git-configuration)

## 진행 순서와 완료 기준

1. **공유 모델 세션·API 설계**: Poffo 문서·undo/redo 소유권과 외부 문서 연결·변경 요청 계약을 먼저 정한다. 헤더 명령·파일 처리·Custom Element 호스트 역할을 이에 맞춘다.
2. **생명주기·기존 임시 변경 정리**: 모델 세션과 에디터·공유 캔버스·추적 자원의 수명을 구분한다. 기존 임시 변경을 내부 상태로 보존하고, 이 두 단계의 계약을 정리한 뒤 파일 이동을 시작한다.
3. **Poffo 앱·헤더 구성**: 공통 헤더와 Editor 전용 헤더 UI를 앱에서 구현한다. 패키지에 앱 context 의존을 추가하지 않는다.
4. **라우트·페이지·세션 이전**: Studio·Viewer·Converter와 관련 테스트·자산을 이동한다. 화면별 조합을 나누고 공통 부분만 공유한다.
5. **뷰포트·타입 의존 정리**: 외부 문서 바인딩·변경 요청, 단축키 활성화, 공유 캔버스·뷰 타입을 공개 계약으로 연결한다. 패키지가 앱 구현을 import하지 않도록 한다.
6. **이전 결과 검증**: 공개 API만으로 앱이 빌드되고 아래 시나리오의 작업 흐름이 유지되는지 확인한다.
7. **배포 조건 확정**: 공개 경로, 배포 브랜치, 기존 저장 데이터의 호환·이전 범위를 확정한다.
8. **Actions 배포·도메인 연결**: 검증된 앱을 워크플로로 배포하고 `poffo.io`에서 확인한다.

### 배포 전에 확정할 항목

| 항목                     | 결정할 내용                                                                                           |
| ------------------------ | ----------------------------------------------------------------------------------------------------- |
| 공개 경로                | 확정: 네 화면 모두 공개, `/`는 `/editor`로 연결                                                       |
| 배포 브랜치              | 확정: 자동 배포 없음. `dev` 수동 → Preview, `main` 수동 → Production                                  |
| 저장 데이터 호환         | 확정: Editor 복구 기록 유지. Viewer 문서는 자동 병합하지 않음. Studio 설정은 모델 호환성 검사 후 유지 |
| 환경·도메인 간 문서 이전 | 개발·preview·프로덕션에서 작업한 문서를 이전해야 하는지와 필요할 경우 명시적인 내보내기·불러오기 절차 |

기존 저장 데이터의 호환 범위는 세션 이전 전에 정한다. 단순한 파일·이름 변경 때문에 기존 복구 기록을 초기화하지 않는다. 세부 파일명과 폴더명은 구현 중 판단할 수 있지만, 상태 소유권·생명주기·호환성 결정을 그 과정에서 임의로 바꾸지는 않는다.

### 검증 시나리오

구현 시 자동화할 검사와 실제 배포에서 확인할 검사를 구분한다. CI 산출물의 브라우저 검증, 원격 HTTP·자산 응답 검사, 프로덕션 작업 흐름 확인을 서로의 증거로 대체하지 않는다.

| 시나리오                                              | 확인할 결과                                                               |
| ----------------------------------------------------- | ------------------------------------------------------------------------- |
| 모델링 변경 → 애니메이션 전환 → undo                  | 선택·적용 모드 표시가 일치하고, 기존 편집 이력과 undo 범위를 유지         |
| 패널 닫기 → Studio 이동 → Editor 복귀                 | 패널 상태·문서·선택·뷰포트 상태 유지, 불필요한 인스턴스 재생성 없음       |
| Viewer에서 모델 교체 → Editor 확인 → undo             | 교체 문서가 한 번만 반영되고 정한 undo 단위로 복원                        |
| 빠른 모드·페이지 전환 또는 이동 취소                  | 오래된 결과가 현재 화면·문서를 덮어쓰지 않고 UI와 실제 상태가 일치        |
| 저장 실패 후 이동·재시도                              | 공유 문서 유지·화면 이동 가능, 중복 오류 안내 없음, 복구 저장 재시도 유지 |
| Studio·Viewer 활성 중 Editor 단축키·메뉴 조작         | 숨겨진 Editor가 활성 화면의 입력을 처리하지 않음                          |
| 파일 선택 취소·변환 실패·내보내기 완료                | 취소·실패·완료 결과를 구분하고 다운로드 자원·진행 표시 정리               |
| 헤더 교체·화면 종료·인스턴스 파기                     | 정한 수명에 따라 연결·이벤트·플레이어·추적 자원 해제                      |
| 공개 API만으로 Poffo 빌드, Custom Element 소비자 연결 | 패키지 내부 import 없음, 합의한 공개 계약과 기존 소비자 호환 범위 유지    |

상태·명령 계약은 다음 경우도 확인한다.

- 빠른 모드 선택에서 마지막 요청만 적용하고, 이전 요청의 결과는 취소로 구분한다.
- 파일 읽기 중 문서가 바뀌면 `document-changed`로 끝나며 현재 문서를 덮어쓰지 않는다.
- Poffo 세션이 완료한 편집 단위만 복구 저장하고, 화면 이동·모드 전환·임시 변경 확인은 undo 단계를 만들지 않는다.
- 에디터 미마운트·비활성화·정리 후에도 같은 세션의 문서와 이력을 Studio·Viewer가 사용할 수 있다.
- 파일 추가·교체·임시 변경 저장·undo/redo가 모두 같은 Poffo 세션을 통해 한 번만 반영된다.
- 드래그의 여러 갱신을 한 undo 단계로 묶고, 호스트 거절·원본 교체 시 오래된 에디터 결과를 반영하지 않는다.
- 기존 임시 변경을 내부에서 확인·보관하고, 선택 키폼 저장의 호스트 반영 완료 후 제출 버전만 정리한다. 요청 수락만으로 정리하지 않는다.
- 수락 후 실패·취소·문서 교체에서는 임시 변경을 잘못 삭제하지 않고, 대기 중 새로 수정한 버전은 이전 완료로 지워지지 않는다.
- 드래그 중 강제 해제하면 시작 문서·이력을 복원하고, 정상 완료와 해제의 경합은 한 종료만 반영한다. 다음 조작이 미완료 트랜잭션에 합쳐지지 않는다.
- 문서 알림 종류에 따라 일반 편집은 유효한 선택·임시 변경을 유지하고, 모델 교체·초기화는 이전 모델 대상 상태를 정리한다. 모델 교체를 undo/redo할 때도 같은 구분을 적용한다.
- 헤더 재마운트 후에도 동일 controller를 사용하고 공유 캔버스를 중복 생성·파기하지 않는다.
- `dispose()` 이후 늦게 완료된 작업은 상태를 바꾸지 않으며 반복 정리로 빌린 플레이어를 파기하지 않는다.
- 렌더러 오류 중에도 문서 조회·복구·내보내기 경로를 사용할 수 있다.

Custom Element는 다음 소비자 관점의 검증을 추가한다. 재생성 횟수만 확인하는 mock 검사를 실제 문서·이력·이벤트 동작의 증거로 대체하지 않는다.

- 재연결 후 이전 제어 객체의 명령을 거절하며 새 문서에 전달하지 않는다.
- 일시 정지는 에디터 입력만 제어하고, 호스트 문서 변경·초기화는 해당 호스트의 트랜잭션·충돌 규칙과 이전 결과 무효화 계약을 따른다.
- 문서 초기화와 undo 가능한 교체를 구분하고, 동일 객체 대입의 합의한 의미를 보존한다.
- 이벤트 핸들러에서 초기화·제거·재연결해도 이전 인스턴스의 후속 알림·작업을 반영하지 않는다.
- 연결 전·후 입력, 잘못된 입력, 반환 객체 참조와 초기·재연결 알림을 정한 계약대로 처리한다. 요소 제거 후 문서 getter·export는 보관 문서를 반환하고, 재연결은 새 이력으로 시작한다.
- 초기화·초기 연결은 커밋을 만들지 않고, 변경·커밋·상태 이벤트의 순서와 재진입 시 중단 규칙을 확인한다.
- 반복 연결·제거 및 여러 요소 사용 시 controller·viewport·구독을 서로 공유하거나 중복 정리하지 않는다.
- 외부 헤더를 연결한 실제 화면에서 키보드·포커스·Shadow DOM 팝오버를 확인한다.

각 단계의 완료 여부는 구현과 실행 증거를 구분해 기록한다. 아래 항목을 모두 확인하기 전에는 전체 작업을 완료 처리하지 않는다.

- [ ] Poffo 세션이 공유 문서·revision·undo/redo·편집 트랜잭션의 단일 소유자이며 화면별 원본 저장소가 없다.
- [ ] 에디터는 외부 문서를 읽고 호스트에 변경을 요청한다. 빌린 문서·이력을 에디터 정리로 파기하지 않는다.
- [ ] 기존 임시 변경은 에디터 내부 상태이고 별도 공유 문서나 새 미리보기 기능으로 확장되지 않는다.
- [ ] 임시 변경은 호스트 반영 완료·요청 일치 확인 후 제출 버전만 정리된다. 실패·새 수정·이전 연결의 늦은 결과가 현재 버전을 지우지 않는다.
- [ ] 트랜잭션 소유자·종료가 명확하고, 강제 해제는 미완료 변경만 복원하며 다음 편집과 이력을 섞지 않는다.
- [ ] 일반 편집·교체·초기화·undo/redo·롤백 알림별 내부 상태 유지·정리가 검증된다.
- [ ] 헤더 UI와 서비스 라우팅은 Poffo에 있고, Puppet은 앱 경로·context를 참조하지 않는다.
- [ ] 모델링·애니메이션 전환과 패널 버튼이 Puppet의 단일 상태·명령에 연결된다.
- [ ] 선택 모드·적용 모드·전환 상태와 비동기 명령의 완료·실패·취소 결과가 헤더에 올바르게 반영된다.
- [ ] 헤더 연결·해제와 화면 활성화·비활성화가 편집기·플레이어의 유지·파기와 구분된다.
- [ ] 파일 가져오기·열기·PSD 재가져오기·내보내기·복구와 undo/redo가 유지된다.
- [ ] 파일 선택·다운로드·헤더 피드백과 패키지의 데이터 처리 경계가 분리된다.
- [ ] 변경 요청·호스트 반영·화면 갱신이 순환 적용을 만들지 않으며 모델 교체의 undo 범위가 검증된다.
- [ ] 화면을 오가도 문서·편집 이력·선택·뷰포트 상태가 유지된다.
- [ ] 숨겨진 화면의 메뉴·단축키가 활성 화면에 간섭하지 않는다.
- [ ] 메뉴·팝오버·브러시 설정의 배치, 겹침, 클리핑, 포인터 조작, 포커스 복귀와 접근성 의미가 유지된다.
- [ ] 같은 세션의 화면 이동은 문서 복사·재로드·저장 완료를 요구하지 않는다. 저장 실패 중에도 공유 문서를 사용할 수 있다.
- [ ] 세션 닫기·초기화·실제 이탈의 저장·복구 정책과 추적·자원 정리가 검증된다.
- [ ] Custom Element의 상태·명령 연결과 기존 소비자의 이전 경로가 검증된다.
- [ ] 단독 요소의 제거 후 문서 조회·재연결 시 이력 재시작·이벤트 순서가 검증되고 Poffo의 빌린 세션 수명과 구분된다.
- [ ] 이전 Custom Element 제어 객체가 새 인스턴스로 호출을 전달하지 않으며, 초기화·일시 정지·이벤트 재진입 계약이 검증된다.
- [ ] Custom Element의 API 호환 범위와 호스트 이전이 필요한 헤더 UI 변경이 구분돼 기록된다.
- [ ] 기존 복구·세션 데이터의 호환 범위와 필요한 환경 간 문서 이전 절차가 검증된다.

- [ ] Actions에서 대상 커밋을 배포하고 배포 URL·커밋 SHA를 기록한다.
- [ ] 공개하기로 정한 경로의 직접 접속·새로고침·정적 자산 로딩이 정상 동작한다.
- [ ] `https://poffo.io`에서 배포 결과와 에디터 작업 흐름을 확인한다.

## 구현 단계에서 확정한 사항

- Solid `PuppetEditor`는 외부 문서 바인딩을 필수로 받는다. 기존 `initialDocument` 사용처·테스트를 함께 이전한다.
- `editor-element`의 잘못된 `.document` 대입은 예외 없이 실패 상태·이벤트로 알린다. 유효한 대입의 초기화 의미는 유지한다.
- `.document`·`exportDocument()`는 방어적 복사본을 반환한다. 기존 참조 동일성은 호환 대상에서 제외한다.
- 앱 스크립트 네 개의 추가를 승인받았다: `dev: vite`, `build: vite build`, `lint: oxlint src vite.config.ts uno.config.ts`, `typecheck: tsc --noEmit`.

- `.document`·`exportDocument()`는 트랜잭션 중에도 현재 작업 문서의 동기 복사본 조회를 허용한다. 실제 다운로드·새 복구 스냅샷 생성만 `busy`로 제한한다.
- `element.state`와 `puppet-state-change`는 같은 `{editor, error}`를 제공한다. 잘못된 대입은 연결 전에도 조회할 수 있다.
- 기존 `session` 쿼리는 문서 선택에 사용하지 않고 URL에서 제거한다. Editor 복구 기록을 사용하며 Viewer 문서 DB는 읽거나 병합하지 않는다.
- 아틀라스 문서의 최초 입력·초기화 자체는 커밋을 만들지 않는다. **뒤따르는 아틀라스 준비 완료는 별도 교체·커밋·undo 한 단계로 기록하는 기존 예외를 유지한다.** 준비 중 편집·초기화·해제가 발생하면 이전 결과를 무시한다. 실패 시 입력 문서를 보존하고 오류를 알린다.
- 단독 요소의 `control.lifecycle`에는 `dispose`를 노출하지 않는다. 최종 해제는 DOM 제거를 통한 어댑터 소유이며, Solid 직접 호스트의 controller에는 `dispose`가 있다.
- 저장소는 기존 Editor DB·탭 키를 유지한다. 브라우저 탭 종료의 저장 보장은 확대하지 않는다. 완료된 커밋의 비동기 복구 저장이 끝나기 전에 종료하면 마지막 변경은 복원되지 않을 수 있다. 다른 origin으로의 자동 데이터 이전은 없으며 JSON 내보내기·불러오기를 사용한다.

- 독립 요소의 실제 브라우저에서 외부 모드·패널 명령, 복사본 조회, 재연결·이전 제어 객체 거절, Shadow DOM 팝오버·메뉴의 마우스·내부 포커스·Escape·포커스 복귀를 확인했다. 동일한 Custom Element 소스 서버를 사용하는 호환성 브라우저 검사 1개도 통과했으며 워크플로에 포함했다.
- 개발 서버의 기존 예제 응답은 HTTP 200, 122개 파츠·6개 모션을 포함한 문서로 확인했다. 예제는 프로덕션 산출물에 포함하지 않는다.

원격 Actions 실행·배포 URL·프로덕션 도메인 확인은 아직 남아 있다. Vercel 프로젝트 설정은 조회로 확인했지만 GitHub secret의 실제 배포 권한은 원격 실행에서 확인해야 한다. `poffo.io`는 등록·소유 확인 상태이며 DNS는 아직 다른 서버를 가리킨다. Porkbun DNS 변경은 첫 Actions 배포 확인 뒤 진행한다. 실제 웹캠 표정 정확도·방송 출력과 큰 모델의 성능 측정도 이 검사로 대체하지 않는다.

[로컬·Actions 실행 절차](../README.md#L1), [DOM 호스트 이전](editor-element.md#L1)을 따른다. 전체 완료 체크리스트 중 원격 배포·도메인 항목을 완료 처리하지 않는다.

### 배포 브랜치 정정

이전의 `dev → Production` 설명은 폐기한다. Pomo의 배포 구성을 확인한 뒤 `dev → Preview`, `main → Production` 수동 실행으로 바로잡았다. 개발 액션은 Preview 환경만 사용하고 `promote`를 호출하지 않는다. 운영 액션은 `main`만 허용하고 검증한 운영 산출물만 승격한다. 이 수정은 워크플로·문서 변경이며 실제 원격 배포는 실행하지 않았다.
