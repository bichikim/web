# Poffo CLI·MCP와 제작 워크플로

2026-11-09 갱신. Node/브라우저 공통 백엔드, 로컬 CLI·MCP, 제작 레시피와 Poffo 제작 스킬을 구현했다. 설치 앱의 Node·CLI 동봉과 사용자 명령 등록도 구현했다. Windows x64·Intel Mac·ARM Mac 실행기에서 실제 설치물의 제작·MCP·저장/재열기 검증과 여섯 포즈의 PNG RGBA 완전 일치가 확인됐다. Windows 네이티브 창·시스템 대화상자·저장·복구·호스트 수명 16단계도 CI에서 통과했다. macOS arm64의 이전 네이티브 검증에서는 시스템 저장 창의 취소·파일 쓰기·새 프로세스 재열기, 미저장 종료의 취소·확인·문서 복구, 독립 CLI 호스트의 창 종료 후 유지를 확인했다.

## 목표와 구조

Node 모드는 **공통 백엔드 → GUI+CLI/MCP**, 웹 단독 모드는 **브라우저 클라이언트 백엔드 → GUI**다. 두 모드가 같은 Puppet 문서·reducer·이력·PSD 변환기를 사용하고, 파일·PNG·렌더 I/O만 어댑터로 연결한다. Node 모드의 GUI는 원격 바인딩을 사용하며 별도 이력을 만들지 않는다.

개발과 프로덕션 CLI는 각각 `dev`와 `start`로 시작한다. 기본은 GUI를 함께 열고 `--cli`는 자동 열기를 생략한다. CLI 모드가 GPU 없는 렌더를 의미하지는 않는다. PNG는 연결된 GUI의 독립 플레이어가 완성한 프레임을 캡처한다.

미래의 MCP 연결은 처음부터 예상할 수 있어 입력 스키마·명령 카탈로그·dispatcher를 공유했다. CLI와 MCP를 위한 편집 엔진을 따로 만드는 비용 없이 같은 오류·revision·undo 단위를 사용한다. 전역 플러그인 시스템이나 분산 작업 큐는 추가하지 않았다.

현재 실행 명령·레시피·MCP 설정은 [CLI 설명](../src/cli/README.md), 코드 책임은 [백엔드 설명](../src/backend/README.md), 제작 판단은 [Poffo 제작 스킬](../skills/poffo-authoring/SKILL.md)이 원본이다. 명령별 입력은 실행 중인 `operations`와 `recipe-schema`에서 조회한다.

## 구현과 검증

| 목표                    | 구현 상태와 증거                                                                                                                                                                                     |
| ----------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 공통 처리와 환경별 입력 | 같은 PSD 변환기에 Node 경로/PNG 인코더와 브라우저 File/Worker를 연결했다. Node 통합과 실제 Chromium Worker 검사가 있다.                                                                              |

| 명령·원자적 쓰기        | 카탈로그·스키마·preview/apply·revision 검사·제한된 재전송 기록을 구현했다. 잘못된 후보·원형 객체 변경·중복 요청·오래된 revision을 검사한다.                                                          |
| 저장·복구·수명          | PSD/JSON/Poffo 열기, 원본 보존 저장, 직렬 복구 저장, 미저장 종료 거절, 소유 클라이언트 단절 시 트랜잭션 해제를 구현했다. native 파일의 새 프로세스 재로드를 확인했다.                                |
| 설치 앱 런타임          | 공식 Node와 의존성·CLI·스킬을 동봉한다. 절대 실행 경로와 부모 EOF 수명, 기존 세션 연결, 사용자 명령 등록을 제공한다. 세 OS 설치물에서 최소 PATH와 잘못된 NODE_OPTIONS를 넣어도 동봉 Node로 실행됐다. |
| 실제 프레임 캡처        | 중립과 모션 시점 PNG가 실제로 생성되고 픽셀이 있으며 서로 다름을 Chromium과 WebKit에서 검사한다. 모델 revision을 바꾸지 않는다. 정지 캡처에는 물리를 적용하지 않는다.                                |
| 재현 가능한 제작 흐름   | patch/render 레시피, 단계별 체크포인트·report·입력/출력/엔진 해시, 실패 후 재개를 구현했다. 파일 변조와 도중 GUI 편집은 거절한다.                                                                    |
| 에이전트 연결           | 표준 SDK stdio MCP와 번들 제작 스킬을 제공한다. 실제 MCP 클라이언트가 CLI와 같은 sessionId·revision을 읽는다. 스킬 형식 검사를 통과했다.                                                             |

2026-11-08 초기 CLI 구현에서 관련 단위 회귀 513파일·3,228테스트, 네이티브 저장 추가 회귀, Node 통합 34테스트, CLI·GUI E2E 2테스트, 데스크톱 개발 hook 2테스트를 통과했다. 실제 설치물과 캐릭터 검증의 범위·남은 확인은 [캐릭터 검증 기록](../validation/character/README.md)에 구분한다. 실행 명령은 백엔드와 설치 앱 설명에 있다.

이전 텍스처 업로드 수정에서는 WebKit의 RGB 차이를 명시적인 RGBA·알파 변환으로 해결했다. 당시 macOS arm64 설치물의 Editor·Viewer·재시작 RGBA가 일치했고, Chromium 여섯 포즈는 수정 전후 픽셀이 같았다. 플레이어 단위 1,175테스트·브라우저 렌더링 33테스트와 두 패키지의 타입 검사도 통과했다. 추가 실행과 자원 해제 증거는 캐릭터 검증 기록에 있다.

그 뒤 남았던 OS 간 차이는 MSAA canvas 읽기와 PNG 알파 변환에서 확인했다. 명시적인 RGBA8 resolve와 공통 PNG 인코더를 적용한 새 설치본의 [최종 CI](https://github.com/bichikim/web/actions/runs/42488520236)에서 세 OS의 여섯 포즈가 정확히 일치했다. 같은 새 Mac 설치본의 WebKit 제작 검증도 통과했다. [진단 절차](../browser/pixels/README.md)와 캐릭터 검증 기록에 범위를 구분한다.

## 제작 워크플로

1. 승인된 디자인·원본·기존 리그와 수정 범위·목표 동작을 정한다.
2. 실행 중인 능력·문서·식별자를 읽고 저장·재로드·렌더 경로를 확인한다.
3. 파츠의 역할·가림·좌표·부착점과 드러날 숨은 면을 준비한다.
4. 메시·계층·파라미터·키폼을 작은 preview/apply 단위로 작성한다.
5. 물리·표정·모션을 연결하고 중립·중간·끝각·복합 포즈와 연속 재생을 확인한다.
6. 최종 문서를 새 세션에서 재로드하고 원본·편집 파일·recipe·report·실제 검증 화면과 해시를 인계한다.

이미지 생성·파츠 추출과 기존 리그의 품질 판단은 제작 스킬의 관련 reference를 따른다. 정상인 원본을 보존하며 Poffo를 대상으로 한 작업에 Cubism 변환을 필수 중간 단계로 넣지 않는다. 구조 검사·실제 적용·검증한 동작 범위·사용자 수용을 따로 기록한다.

## 남은 단계

- **네이티브 UI**: Windows는 실제 설치물의 창·대화상자·저장·재열기·복구·독립 호스트 검증을 통과했다. Intel Mac은 저장 상태 반영 실패를 조사 중이다. 다른 물리 GPU 전체의 검증은 별도다.
- **제작 연산 확장**: 현재 JSON Patch로 파츠·키폼·물리 문서를 수정할 수 있다. 자주 쓰는 제작 의도를 기존 순수 연산으로 조합하는 명령, 영향 diff, 대형 문서 부분 조회와 장기 작업의 취소 API는 사용 수요에 맞춰 추가한다.
- **추가 제작 범위**: 실제 122파츠 캐릭터에서 모션 제작·기존 리그 보존·복합 포즈·연속 재생·저장/재열기를 검사한다. 새 그림 생성, 파츠 교체, 새 메시·리그의 품질이나 독립 에이전트의 제작 완주까지 검증한 것은 아니다.
- **외부 어댑터**: Cubism 편집·MOC3 출력·VTube Studio는 현재 Poffo CLI 기능이 아니다. 요청된 최종 대상일 때 도구 버전·라이선스·실제 파일 호환을 확인한 뒤 선택적으로 연결한다.
