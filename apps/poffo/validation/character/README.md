# 실캐릭터 제작 검증

2026-11-08, macOS arm64 설치물에서 저장소의 `packages/puppet/examples/development-model.json`을 별도 작업 폴더로 복사해 검사했다. 원본은 122파츠·20,297정점·72파라미터·82바인딩·6모션이다. 새 디자인을 생성한 검사가 아니라 기존 캐릭터에 새 모션을 제작하는 검증이다.

[제작 레시피](recipe.json)는 기존 메시·텍스처·계층·키폼·물리를 보존하면서 얼굴·몸통 회전, 깜빡임, 입, 꼬리를 묶은 모션을 추가한다. patch 한 단계와 실제 GPU PNG 여섯 단계로 구성한다.

## 검증 계약

- 실제 DMG에서 앱을 꺼내 저장소 밖의 공백·한글 경로에 둔다. 시스템 Node를 제외한 PATH와 잘못된 NODE_OPTIONS에서도 동봉 Node를 실행한다.
- 사용자 bin 폴더에 명령을 등록하고 그 경로로 다시 실행한다. 기존 다른 명령은 보존한다.
- 표준 stdio MCP 클라이언트가 같은 호스트의 sessionId와 캐릭터 상태를 읽는다.
- 중립·좌우·깜빡임·미소·얼굴/몸통 복합 포즈를 1280px PNG로 캡처한다. 여섯 이미지가 유효하고 서로 다른지 검사한다.
- 실제 Viewer에서 새 모션을 두 번 연속 재생하고 시간 갱신을 관측한다. 정지 PNG는 물리를 끄므로 연속 물리 재생 검증의 근거로 사용하지 않는다.
- 출력 `.poffo`를 새 Node 프로세스에서 읽는다. 원본 파일 해시, 기존 모션, 모션을 제외한 전체 리그 해시가 보존되는지 확인한다.
- 저장 전후를 같은 Viewer 조건에서 캡처한다. Chromium은 실제 SwiftShader renderer를 확인하고 RGBA 픽셀을 정확히 비교한다. WebKit은 문서와 알파의 정확한 보존을 검사하며 RGB 해시 일치 여부를 진단으로 기록한다. 허용 오차를 높이거나 픽셀을 반올림해 통과시키지 않는다.

실행 명령은 [설치 앱 설명](../../src-tauri/README.md)에 있다. 출력 폴더에는 모델·recipe·여섯 포즈·저장 전후 PNG·재생 화면·report를 보관한다. Playwright의 실제 재생 녹화도 별도 보관할 수 있다. report에는 입력·리그·이미지·레시피 산출물 해시와 관측한 프레임 시간이 들어가며 인증 토큰은 넣지 않는다.

## 실행 결과

최종 DMG의 실제 CLI로 Chromium/SwiftShader와 WebKit의 제작 E2E가 각각 통과했다. 원본·리그 보존, 7단계 레시피, MCP 연결, 모션 두 사이클, 새 호스트 재열기를 확인했다. Chromium은 저장 전후 RGBA가 일치했다. WebKit의 RGB 일치 여부는 진단값이며 통과 기준으로 바꾸어 보고하지 않는다.

로컬 산출물은 Git에서 제외한 `output/`에 있다. `output/manifest.json`은 DMG와 엔진 해시·검사 결과·미확인 범위를, 브라우저별 `report.json`은 세부 증거를 담는다. 두 report의 엔진 해시가 최종 DMG 안의 CLI와 GUI 엔트리로 계산한 해시와 일치함을 확인했다.

## 관측과 한계

여섯 포즈를 직접 검토했으며 해당 범위에서 큰 파츠 누락이나 찢어짐은 보이지 않았다. 이 관측은 새 그림·파츠 교체·새 메시/리깅 제작의 품질, 모든 파라미터 조합, 모든 GPU를 보증하지 않는다.

WebKit의 Apple GPU에서는 같은 모델 해시로 Editor에서 두 번 캡처하면 픽셀이 같지만, 저장 없이 Viewer로 전환하면 RGB 차이가 생겼다. 알파 차이는 없었고 합성 후 최대 채널 차이는 2였다. 같은 Viewer 조건의 작은 재시작 프로브에서는 일치했지만 전체 제작 E2E에서는 재생 후 컨텍스트 교체에도 RGB 차이가 관측됐다. 엄격한 RGB 회귀 기준은 SwiftShader이며 WebKit의 RGB 완전 일치는 미통과 상태로 남긴다. 내부 렌더 원인은 미확정이며 이 차이를 픽셀 완전 일치로 보고하지 않는다.

네이티브 앱은 실제 캐릭터 표시·GUI 편집의 Node 반영·PNG 캡처를 확인했다. 시스템 저장 창에서 취소하면 파일이 생기지 않고 미저장 상태가 유지됐다. 실제 저장한 `.poffo`를 새 내장 Node 프로세스에서 열어 GUI 문서 전체와 일치하고 122파츠·7모션이 보존됨을 확인했다. 최종 DMG의 앱에서도 한글 이름 파일을 저장하고 새 프로세스로 전체 문서 일치를 확인했다. 저장 뒤 창을 닫으면 추가 확인 없이 앱과 소유 호스트가 종료돼 저장 상태 반영도 확인했다. 독립 CLI 호스트는 연결된 창을 닫은 뒤에도 같은 sessionId·revision으로 유지됐다. 이 결과와 저장 파일은 `output/native/`에 보관한다.

미저장 종료 확인 창은 편집 창에 연결했다. 실제 창 닫기에서 취소하면 같은 호스트·revision·문서를 유지했고, 앱 메뉴에서 종료를 확인하면 창과 앱이 소유한 호스트가 종료됐다. 새 DMG의 앱으로 같은 workspace를 다시 열어 미저장 문서 전체가 복구됨을 확인했다. Windows·Intel Mac의 runner 실행은 미검증이다.
