# SideBuy 기획 및 인프라 계획

## 1. 제품 목표

SideBuy는 사용자가 온라인 쇼핑에서 빠르게 결정을 내리도록 돕는 구매 의사결정 서비스다.

1. 필요한 조건을 결정한다.
2. 구매할 제품과 모델을 결정한다.
3. 선택한 제품의 최적 구매처를 결정한다.

추천 상품을 많이 나열하기보다 사용자가 상위 1~2개 후보에서 결정하도록 돕는 것을 목표로 한다.

## 2. 사용자 흐름

### 2.1 구매 조건 결정

사용자가 “젖병을 사고 싶다”처럼 입력하면 AI가 고객 맥락과 상품 카테고리 스킬을 불러와 추가 질문을 JSON으로 생성한다.

- 필수 조건: 맞지 않으면 후보에서 제외
- 선호 조건: 추천 순위에 반영
- 도움말: 어려운 용어와 선택지의 차이 설명
- 추가 요청: 자연어로 제약이나 선호 입력
- 판단 전략: 감당할 수 없는 리뷰 문제, 최소 리뷰 수, 긍정 리뷰 비율 등
- 과거 선택: 유사 구매 이력이 있으면 출처를 표시하고 미리 선택

다음 단계로 이동할 때 원래 요청, 질문 버전, 답변, 자동 선택과 사용자 변경, 판단 전략을 하나의 구매 세션으로 저장한다.

### 2.2 구매 제품 결정

조건과 리뷰를 바탕으로 최대 3개를 우선 노출하고 필요할 때 더 볼 수 있게 한다. 상단에는 해당 카테고리의 구매 요령을 요약한다.

각 상품 카드에는 다음을 표시한다.

- 추천 순위와 한 줄 결론
- 사용자 조건에 맞는 이유
- 충족하지 못한 조건과 감수할 단점
- 핵심 사양과 리뷰 위험 요약
- 리뷰 신뢰도와 예상 가격대
- `실제 판매 페이지에서 보기`
- `최적가격으로 구매처 결정`

`실제 판매 페이지에서 보기`는 정확한 모델, 상세 정보와 리뷰가 충분한 대표 판매 페이지를 새 창으로 연다. 사용자가 창을 닫고 돌아와도 2단계 상태를 유지하며, 이 동작만으로 가격 최적화를 실행하지 않는다.

`최적가격으로 구매처 결정`을 누르면 해당 제품과 정확한 옵션을 선택 상태로 저장하고 3단계 가격 탐색을 시작한다.

### 2.3 최적 구매처 결정

사용자가 명시적으로 선택한 제품에 한해서 실시간 또는 최신 가격 탐색을 실행한다.

동일 상품 여부를 다음 기준으로 검증한다.

- 브랜드와 모델 번호
- 용량, 사이즈, 색상, 구성 수량
- 세대 또는 출시 버전
- 포함 액세서리
- 정품, 병행수입, 리퍼, 중고 여부

판매처별 상품 가격, 배송비, 수량, 단위 가격, 도착 예정일, 멤버십, 확실히 적용 가능한 쿠폰과 혜택, 판매자 신뢰도와 반품 조건을 비교한다.

결과에는 다음을 구분해 보여준다.

- AI 최종 추천 구매처
- 배송비 포함 최저가
- 멤버십 반영 최저가
- 가장 빠른 배송

모든 가격에는 수집 시점과 결제 단계에서 달라질 수 있다는 안내를 표시한다.

## 3. 추천 원칙

LLM이 임의로 순위를 정하지 않는다.

1. 규칙 엔진이 필수 조건에 맞지 않는 상품을 제거한다.
2. 사양 적합도, 가격, 리뷰 수, 긍정 비율과 배송 조건을 점수화한다.
3. AI가 리뷰에서 사용자가 감당할 수 없는 문제의 빈도와 최근성을 분류한다.
4. 사용자의 명시적 선호와 구매 이력을 반영한다.
5. AI가 계산 결과와 근거를 이해하기 쉬운 설명으로 변환한다.

안전성이 중요한 카테고리의 검증 규칙은 AI가 생성한 질문이나 설명보다 우선한다. 광고와 제휴 수익은 추천 순위에서 분리하고 사용자에게 표시한다.

## 4. 핵심 데이터 모델

- `PurchaseSession`: 원래 요청, 대상 사용자, 질문과 답변, 판단 전략, 단계와 버전
- `CategorySkill`: 필수 질문, 사양, 도움말, 안전 규칙, 리뷰 위험과 점수 기준
- `Product`: 브랜드와 모델로 식별되는 논리적 제품
- `ProductVariant`: 용량, 색상, 크기와 구성 수량 등 선택 규격
- `Offer`: 특정 판매처가 특정 옵션으로 판매하는 항목
- `ReviewInsight`: 리뷰 출처, 기준 시점, 문제 유형, 빈도, 최근성과 신뢰도
- `Recommendation`: 후보, 점수 구성, 제외 이유와 사용자용 설명
- `PriceSearch`: 선택 제품, 검색 상태, 수집 시점과 비교 결과
- `PurchaseDecision`: 제품 선택, 구매처 선택과 구매 확인 상태

구매 상태는 구분해서 기록한다.

- `PRODUCT_VIEWED`: 대표 판매 페이지를 열어봄
- `PRODUCT_SELECTED_FOR_PRICE_SEARCH`: 가격 탐색 대상으로 제품을 선택함
- `MERCHANT_SELECTED`: 최종 구매처를 결정함
- `PURCHASE_SELF_REPORTED`: 사용자가 구매했다고 표시함
- `PURCHASE_VERIFIED`: 외부 데이터로 실제 구매가 확인됨

## 5. 인프라 구성

초기에는 배포 제품보다 책임 경계를 먼저 확정한다.

- Node.js API: 프론트 요청, 인증, 구매 세션과 단계 전환
- 추천 오케스트레이터: 스킬 선택, 상품 수집, 리뷰 분석과 추천 작업 실행
- 규칙 및 순위 엔진: 필터, 정량 점수와 추천 근거 계산
- 스킬 레지스트리: 고객 맥락 및 상품 카테고리별 질문과 검증 규칙 관리
- 상품 정규화 계층: 외부 상품을 Product, Variant와 Offer로 통합
- 판매처 커넥터: 허용된 API와 제휴 피드로 상품, 리뷰, 가격과 재고 수집
- 작업 큐와 워커: 리뷰 분석, 가격 탐색과 재시도 처리
- 관계형 저장소: 사용자, 세션, 상품, 추천과 구매 결정
- 검색 색인: 상품과 리뷰 검색
- 캐시: 가격, 재고와 사전 분석 결과의 단기 재사용
- 원본 저장소: 수집 데이터와 분석 재현을 위한 원본 보관
- 관측 및 감사 로그: 모델, 프롬프트, 스킬, 데이터와 점수 버전 기록
- 운영 도구: 상품 매칭 오류, 추천 근거와 데이터 신선도 검수

초기에는 모듈형 단일 Node.js 서비스와 하나의 관계형 데이터베이스를 중심으로 시작한다. 검색, 캐시, 비동기 워커는 필요에 따라 분리하고 서비스 분리는 실제 부하가 확인된 뒤 진행한다.

## 6. 주요 API 경계

- 구매 세션 생성
- 카테고리 분류 및 질문 JSON 생성
- 조건 답변 저장
- 추천 작업 시작 및 결과 조회
- 대표 판매 페이지 열람 기록
- 가격 탐색 대상 제품과 옵션 확정
- 가격 탐색 시작 및 진행 상태 조회
- 최적 구매처 결과 조회
- 구매처 선택 및 구매 여부 기록

질문과 AI 출력은 자유 형식이 아닌 버전이 있는 JSON 스키마로 검증한다. 오래 걸리는 추천과 가격 탐색은 작업 ID를 발급하고 진행 상태를 전달한다.

## 7. 개인정보와 개인화

- 전체 인구통계보다 해당 구매에 필요한 정보만 수집한다.
- 구매자와 실제 사용 대상자(자녀, 부모, 반려동물, 선물 대상)를 분리한다.
- 과거 이력으로 미리 선택한 값은 출처를 표시하고 사용자가 수정할 수 있게 한다.
- 자동 선택값과 사용자가 직접 입력한 값을 구분해 잘못된 개인화의 누적을 방지한다.
- 민감 정보의 저장 기간, 삭제와 개인화 사용 동의를 제공한다.

## 8. MVP 범위

### 포함

- 안전 위험이 낮은 2~3개 카테고리와 고난도 검증용 1개 카테고리
- 자연어 요청과 카테고리별 질문 JSON
- 필수 및 선호 조건 저장
- 상위 3개 상품 추천과 리뷰 위험 요약
- 대표 판매 페이지 새 창 열기
- 사용자 클릭 후 시작되는 정확한 옵션별 가격 탐색
- 2~3개 판매처의 총비용 비교
- 제품 및 구매처 결정 상태 기록
- 추천 근거와 상품 매칭을 검수하는 운영 화면

### 제외

- 모든 쇼핑몰의 완전한 실시간 최저가
- 모든 쿠폰과 카드 혜택의 자동 적용
- 모든 카테고리 자유 추천
- 실제 구매 완료의 전면 자동 확인
- 광고비에 따른 추천 순위 변경

## 9. 품질 지표

- 추천 1~2위 제품 선택률
- 조건 입력부터 제품 결정까지 걸린 시간
- 대표 판매 페이지 확인 후 복귀율
- 제품 선택 후 가격 탐색 완료율
- 최종 구매처 링크 진입률
- 필수 조건 위반 추천률
- 동일 상품 및 옵션 매칭 오류율
- 리뷰 요약과 근거의 일치율
- 가격 데이터의 신선도와 결제 가격 오차

## 10. 구현 순서

1. 질문 JSON과 단계별 상태 전이 규격 확정
2. Product, Variant, Offer와 구매 세션 모델 확정
3. 한 카테고리의 질문부터 제품 결정까지 구현
4. 대표 판매 페이지 새 창 흐름과 상태 보존 구현
5. 정확한 옵션을 기준으로 한 가격 탐색 구현
6. 규칙 기반 필터와 순위 엔진 구현
7. 리뷰 분석과 AI 설명 생성 추가
8. 개인화, 운영 검수와 자동 평가 추가
9. 카테고리와 판매처 확대

첫 구현 전에 질문 JSON 스키마, 상품·옵션·오퍼 모델, 추천 점수와 근거 규격을 우선 확정한다.
