# Scaling, amplification, and work timing

- Define supported scales and measurable performance budgets for every growth path. Require reproducible, executed performance tests at multiple meaningful scales; reuse tests only if they cover the path and its growth conditions. Small-data functional tests do not establish scaling behavior.
- Distinguish prerequisites for the next usable result or interaction from work consumer contracts permit to finish later. Evaluate deferring execution, transfer, or presentation to remove unnecessary critical-path work while preserving required results, consistency, ordering, error/cancellation handling, and cleanup.
- When rendering blocks interaction, identify the blocking work, keep urgent input feedback responsive, and separate nonurgent updates using supported scheduling or transitions. Check the installed runtime's yielding/interruption semantics; async deferral alone does not make synchronous computation non-blocking. Reduce or split remaining blocking work while preserving focus, state consistency, and completion of deferred updates.
- Measure time to a usable result, input responsiveness, and rendering stalls separately from full completion, including repeated interaction while deferred work is active. Verify benefits against timing budgets and resource use; an earlier initial display alone does not establish improvement.
- Trace initial input through derived work and subsequent state changes, including interacting growth factors, multiplying work, feedback loops, and concentrated load on shared dependencies.
- Test factors independently and in combinations supported by code and dependency relationships, including relevant execution orders and sustained operation. Isolated results do not establish performance under interacting factors.
- Measure internal work, retained resources, backlog, latency, and throughput. Test near enforced limits and beyond them; verify amplification and accumulation stop and resources recover after input or load subsides.
- Record environment, scales, combinations, order, duration, acceptance criteria, and results. Use comparable conditions for regression claims; report unexecuted or uncovered checks as verification gaps.
