# 사용자와 함께 리팩터링

## 검토 단위 정하기

- 대상 폴더를 사용자가 지정하지 않았다면 검토를 시작하지 말고 대상 폴더를 물어본다. 현재 작업 디렉터리나 이전 대화에서 대상을 임의로 추정하지 않는다.
- 사용자가 지정한 폴더만 대상으로 한다. 폴더 내부에 역할과 사용 계약이 독립적인 항목이 있으면 각각 검토 단위로 나누고, 함께 이해해야 하는 구현과 테스트는 같은 단위로 묶는다.
- 먼저 검토 단위 목록과 진행 순서를 간단히 안내한다. 이미 사용자 검토가 완료된 항목은 기본적으로 건너뛴다.

## 하나씩 설명하고 논의하기

- 한 번에 하나의 검토 단위만 설명한다.
- 실제 구현과 사용처를 확인하고 역할과 사용 목적, 입력·출력, 중요한 동작 조건, 이름과 동작의 일치 여부를 쉬운 말로 설명한다. 수정이 필요하면 이유와 제안을 덧붙인다.
- 기존 코드를 설명할 때는 정확한 파일과 줄 번호를 링크한다.
- 설명 후 사용자의 질문·수정 요청·검토 완료 응답을 기다린다. 다음 항목으로 임의로 넘어가지 않는다.
- 사용자가 이미 검토했다고 지정한 항목은 설명을 반복하지 않고 완료 기록을 남긴다. 여러 항목을 함께 확인했다면 지정한 항목 모두 기록할 수 있다.

## 리팩터링하기

- 설명이나 질문만으로 코드 변경에 동의했다고 해석하지 않는다.
- 사용자가 요청하거나 동의한 변경을 구현하고, 변경에 맞는 검증을 수행한다.
- 결과와 검증 범위를 설명한 뒤 사용자 확인을 받는다. 테스트 통과나 AI의 검토만으로 사용자 검토 완료를 표시하지 않는다.

## 검토 완료 기록하기

- 사용자가 검토 완료를 명시한 범위만 해당 디렉터리의 README.md에 기록한다.
- 기존 README는 보존하고 검토 상태를 추가하거나 갱신한다. README가 없으면 역할을 짧게 설명하고 구현 링크와 검토 상태를 기록한다.
- 검토 상태는 체크된 항목에 `사용자 검토 완료`와 실제 확인 날짜를 적는다.
- 일부만 확인했다면 완료된 항목을 명시한다. 폴더 전체가 완료된 것으로 표시하지 않는다.
- 기록 후 남은 검토 단위를 짧게 안내하고 다음 진행을 기다린다.

## 완료 상태 유지하기

- 검토 완료 이후 동작이나 공개 계약을 변경하면 영향을 받는 항목을 재검토 대상으로 표시한다.
- 표현·주석·포맷만 바뀐 경우에는 기존 검토 완료 상태를 유지한다.
