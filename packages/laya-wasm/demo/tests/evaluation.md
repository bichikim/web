# 영문·다국어 WASM 비교

2026-10-15, 실제 Chromium의 Web Worker에서 `onnxruntime-web/wasm`으로 측정했다. 두 모델 모두 새로 불러온 초기 가중치에서 시작했다.

| 모델                  | 학습 전       | 90개 학습 후  |
| --------------------- | ------------- | ------------- |
| 영문 ModernBERT-large | 23/30 (76.7%) | 23/30 (76.7%) |
| 다국어 mmBERT-base    | 27/30 (90.0%) | 27/30 (90.0%) |

모델 교체로 4개, 약 13.3%p 개선됐다. 이번 조건의 학습 자체로 추가로 맞힌 문장은 없다. 평가가 30개뿐이므로 다른 문의나 전체 BANKING77에서 같은 성능을 보장하지 않는다.

## 학습 정체 원인 확인과 개선

같은 날 추가 진단했다. 학습률이 무시되거나 가중치가 적용되지 않는 오류는 발견하지 못했다. 실제 모델 크기에서 ONNX의 한 단계 SGD 갱신을 PyTorch autograd와 비교했으며 최대 파라미터 차이는 다국어 한국어에서 `3.73e-9`였다. 학습률 0.01·5회에서는 가중치의 L2 변화가 약 0.447이었고, 학습 90개의 평균 손실은 0.2787 → 0.2677로 줄었지만 정답 수는 77/90으로 같았다. 즉 기존 조건에서는 갱신이 있었어도 1위 답을 바꾸기에는 부족했다.

고정 인코더 표현을 반복마다 다시 계산하던 부분을 수정했다. 한 번의 학습 실행 안에서 같은 토큰·마커·질문 유형의 표현을 최대 32 MiB까지 재사용한다. 점수 계산층의 SGD 순서·단계 수·수식은 유지한다. 취소 후 다시 학습하면 새 캐시를 사용한다. UI에는 **한국어 90개 실험 설정 · 0.1 / 100회** 버튼과 평가 데이터의 전후 평균 교차 엔트로피 손실을 추가했다. 서로 다른 첫 예제와 마지막 예제 손실을 개선량처럼 표시하던 화살표도 제거했다.

다음 결과는 수정한 데모의 인앱 브라우저 UI에서 직접 실행했다. 각각 새 탭의 초기 가중치에서 시작했고, 학습 90개와 별도 평가 30개는 이전과 같은 문장·라벨·순서다. 영어 비교는 동일한 BANKING77 행의 번역 전 원문과 영어 지시문·선택지를 사용했다.

| 모델 / 데이터    | 학습률 / 반복 | 학습 전 → 후      | 평가 평균 손실 전 → 후 |
| ---------------- | ------------- | ----------------- | ---------------------- |
| 다국어 / 한국어  | 0.1 / 100회   | 27/30 → **30/30** | 0.2160 → **0.0647**    |
| 영문 / 영어 원문 | 0.01 / 5회    | 30/30 → **30/30** | 0.1763 → **0.0060**    |

한국어는 9,000단계를 완료했고 기존 오답 3개가 모두 정답으로 바뀌었다. “돈을 이체하려고 했는데 되지 않았어요.”의 송금 실패 확률은 약 30.3% → **80.9%**였다. 영어는 450단계를 완료했으며 이미 모두 맞히고 있었으므로 정확도 증가 여지가 없었지만, 평균 손실은 감소했다. 두 결과 모두 화면의 문장별 예측 30개를 실제 JSONL 정답과 독립적으로 대조했다. [한국어 UI 기록](./results/multilingual-rate0.1-epochs100.json), [영어 UI 기록](./results/english-data-rate0.01-epochs5.json), [한국어 화면](./results/training-korean.jpg), [영어 화면](./results/training-english.jpg).

언어와 모델의 영향을 분리하는 내부 대조 실험도 했다. 네 조건 모두 원본 ONNX에서 추출한 고정 표현과 같은 scorer 수식을 사용해 PyTorch에서 학습률 0.01·5회를 실행했다. 이 표는 브라우저 실행 결과와 구별한다.

| 모델   | 한국어 평가 전 → 후 | 영어 원문 평가 전 → 후 |
| ------ | ------------------- | ---------------------- |
| 다국어 | 27/30 → 27/30       | 30/30 → 30/30          |
| 영문   | 23/30 → 23/30       | 30/30 → 30/30          |

다국어 모델 자체가 학습 불가능한 것은 아니며, 이번 세트에서는 한국어가 영어보다 초기 오답이 많았다. Adam으로 바꾸기만 해서는 5회 조건의 한국어 오답이 줄지 않아 optimizer 변경은 적용하지 않았다. [진단 원시 기록](./results/training-diagnosis.json)에 네 조건의 학습·평가 평균 손실, 가중치 변화, autograd 대조 결과와 데이터 해시를 기록했다.

0.1·100회는 이 데이터에서 효과를 확인한 실험 설정이며 모든 데이터의 권장 기본값은 아니다. 기존 평가 30개를 여러 설정 비교에 사용했으므로 **새 테스트 문장에 대한 100% 정확도를 뜻하지 않는다**. 일반화 성능을 확인하려면 별도의 새 평가 세트가 필요하다. 위 수치는 전체 인코더의 미세 조정 결과가 아니라 고정 인코더 위 점수 계산층의 학습 결과다.

## 새 한국어 평가 30개

2026-10-15, 기존 학습·평가 파일과 문맥 예제에 없는 한국어 문장 30개를 새로 작성했다. 세 분류를 각 10개씩 포함하며 직접적인 표현과 문맥형 표현을 섞었다. 실제 고객 문의에서 무작위 추출한 자료가 아니라 AI가 작성한 합성 평가 자료다. [데이터와 작성 기준](../public/datasets/generalization/README.md).

모델 실행 전에 문장·정답을 확정하고 SHA-256 `4b3e7702efe7ad7358f2f09736598357bee8461116ad7fdb6bf944c64de30487`을 기록했다. 실행 후에도 해시가 같음을 확인했다. 새 탭에서 다국어 모델의 초기 가중치를 불러와 기존 한국어 학습 90개만 학습했다. 학습률 **0.1**, **100회**, **9,000단계**이며 새 평가 결과를 보고 설정을 다시 조정하거나 평가 문장을 학습에 넣지 않았다. 기존 문맥 예제 60개도 학습하지 않았다.

| 지표           | 학습 전       | 학습 후           |
| -------------- | ------------- | ----------------- |
| 전체 정확도    | 21/30 (70.0%) | **22/30 (73.3%)** |
| 카드 분실·도난 | 9/10          | 9/10              |
| 송금 실패      | 3/10          | **4/10**          |
| 개인정보 변경  | 9/10          | 9/10              |
| 평가 평균 손실 | 1.1423        | **1.5144**        |

인앱 브라우저 UI에서 직접 실행했다. 화면의 문장별 결과 30개를 새 JSONL의 문장·정답과 대조하고, 전후 맞힌 수와 분류별 합계를 독립적으로 다시 계산했다. “해외에 있는 가족에게 보낸 금액이 계속 되돌아옵니다. 정상적으로 전달하고 싶어요.” 한 문장만 오답에서 정답으로 바뀌었고 새로 틀린 문장은 없었다. 학습 후에도 송금 실패 6개, 카드 분실·도난 1개, 개인정보 변경 1개가 오답으로 남았다.

정확도는 3.3%p 올랐지만 평균 손실은 증가했다. 이 조건에서 새 표현에 대한 개선은 제한적이며, 기존 평가 30개의 100%를 일반화 성능으로 해석할 수 없다. 이 추가 세트도 합성 문장 30개뿐이므로 실제 고객 문의 전체의 정확도를 나타내지 않는다. [문장별 원시 결과](./results/generalization.json), [실제 UI 화면](./results/generalization.jpg).

정답 예제 영역에는 접을 수 있는 **학습 방법**을 추가했다. 예제 추가와 실제 학습의 차이, 직접 정답 지정, JSONL 일괄 가져오기, 한국어 90개 실험 설정, 평가 데이터 분리와 초기 가중치 복원 순서를 안내한다. **새 평가 30개 불러오기** 버튼과 JSONL 다운로드 링크도 제공한다.

## 다국어 모델 반복 횟수 비교

같은 날 인앱 브라우저의 데모 UI에서 학습률 0.001로 3회·5회 조건을 추가 실행했다. 3회는 새로 불러온 초기 가중치에서 시작했고, 5회는 **초기 가중치 복원** 후 누적 0단계를 확인하고 시작했다. 각 실험의 학습 전 정확도는 모두 27/30이었다.

| 반복 횟수 | 학습 단계 | 학습 후 정확도 |
| --------- | --------- | -------------- |
| 1회       | 90        | 27/30 (90.0%)  |
| 3회       | 270       | 27/30 (90.0%)  |
| 5회       | 450       | 27/30 (90.0%)  |

이번 범위에서는 반복 횟수를 늘려도 정확도가 오르지 않았다. 세 조건 모두 아래의 같은 송금 실패 문장 3개를 틀렸다. “돈을 이체하려고 했는데 되지 않았어요.”의 송금 실패 확률은 초기 약 30.3%에서 3회 약 31.6%, 5회 약 31.9%로 바뀌었지만 1위는 카드 분실·도난이었다.

[3회 UI 결과](./results/multilingual-epochs3.json)와 [5회 UI 결과](./results/multilingual-epochs5.json)에 문장별 결과·데이터 SHA-256·단계 수를 기록했다. 화면의 정답 수를 실제 30개 문장의 예측과 정답으로 다시 계산해 일치를 확인했다. 3회 체크포인트에서도 같은 모델 fingerprint와 누적 270단계를 확인했다. UI의 모델 선택은 다국어·영문 토글이며 내부 모델 경로와 패키지 API는 유지했다.

## 학습률 0.01 비교

이어서 같은 다국어 모델·학습 90개·평가 30개로 학습률만 0.01로 올려 인앱 브라우저 UI에서 실행했다. 3회는 새 모델 연결 후 누적 0단계에서 시작했고, 5회는 **초기 가중치 복원** 후 누적 0단계를 확인하고 시작했다. 학습 전 정확도는 모두 27/30이었다.

| 학습률 | 3회 학습 후   | 5회 학습 후   |
| ------ | ------------- | ------------- |
| 0.001  | 27/30 (90.0%) | 27/30 (90.0%) |
| 0.01   | 27/30 (90.0%) | 27/30 (90.0%) |

0.01 조건도 각각 270·450단계를 완료했으며, 문장별 예측은 같은 반복 횟수의 0.001 조건과 모두 같았다. 이 실험에서는 학습률을 올려도 정답 수가 늘지 않았다. “돈을 이체하려고 했는데 되지 않았어요.”의 송금 실패 확률은 0.01·3회에서 약 30.6%, 0.01·5회에서 약 33.4%였다. 두 조건 모두 카드 분실·도난이 1위라 오답으로 남았다.

[0.01·3회 UI 결과](./results/multilingual-rate0.01-epochs3.json)와 [0.01·5회 UI 결과](./results/multilingual-rate0.01-epochs5.json)에 문장별 결과·모델 fingerprint·데이터 SHA-256·단계 수를 기록했다. 화면의 정답 수를 30개 예측과 정답으로 다시 계산해 확인했다. 이 결과만으로 다른 학습률이나 전체 인코더 학습의 효과를 판단하지 않는다.

## 비교 조건

- 같은 [한글 학습 90개](../public/datasets/banking77/train.jsonl)와 [평가 30개](../public/datasets/banking77/evaluation.jsonl)를 같은 순서로 사용했다. 문맥 예제 60개는 추가하지 않았다.
- 학습률 0.001, 1회 반복, scorer SGD 90단계. 인코더와 앞쪽 Transformer는 고정했다.
- 평가 예제는 학습에 넣지 않았고, 각 평가 문장의 가장 높은 확률 선택지를 정답과 비교했다.
- 기존 학습 파일의 의심 라벨 2개도 수정하지 않았다. 모델만 변경한 비교다.
- 영문 ONNX: `receptron/laya-onnx@68f27dfe5a27a54fb2b1fefc432f43f972e90868`.
- 다국어 원본: `convaiinnovations/laya-multilingual@1720e3e3357cfe1e281542e223f8273b0890ca34`, FP32 ONNX 변환 후 브라우저용으로 분할했다.

원시 결과의 모델 fingerprint, 데이터 SHA-256, 가중치 갱신 단계와 문장별 결과는 [영문](./results/english.json), [다국어](./results/multilingual.json)에 있다. 재현 명령은 [데모 README](../README.md#검증)에 있다.

## 남은 오답

다국어 모델은 다음 송금 실패 문장 3개를 학습 전후 모두 카드 분실·도난으로 분류했다.

- 돈을 이체하려고 했는데 되지 않았어요.
- 무슨 상황인지 알아보는 걸 도와주실 수 있나요? 친구에게 돈을 보내려는데 계속 반송돼요. 제가 뭘 잘못하고 있는지 모르겠어요.
- 제 송금이 되지 않았어요.

첫 문장은 원본 PyTorch와 일치 검증을 통과한 ONNX에서도 카드 분실·도난 69.6271%, 송금 실패 30.2850%, 개인정보 변경 0.0879%였다. 브라우저 WASM에서도 같은 확률을 확인했다. 이 문장의 초기 오답은 변환 과정에서 새로 생긴 차이가 아니다. 다국어 모델은 초기 temperature가 모두 1이며 이 실험에서 확률 보정은 하지 않았다.

## 변환 검증

- 원본 PyTorch ↔ ONNX: 한국어, 배치 크기 1·2·3, 패딩, 길이 변화, 세 질문 유형을 포함한 3개 입력 묶음. 최대 logits 차이 약 `1.12e-5`. [기록](./results/conversion.json)
- 원본 ONNX ↔ frozen features + scorer: 최대 logits 차이 약 `9.54e-7`.
- Python ↔ 브라우저용 토크나이저: 학습·평가 120문장, 지시문과 선택지 4개, 총 124개 텍스트의 토큰 ID가 모두 일치했다.
- 실제 브라우저 평가에서 데이터 중복 거부, 90단계 체크포인트, 화면에 표시한 정확도와 문장별 합계, 375px 가로 넘침 검사도 통과했다.

학습률이나 반복 횟수를 선택하기 위해 이 평가 데이터를 반복 사용한다면, 최종 성능은 별도의 새 테스트 데이터로 확인해야 한다.
