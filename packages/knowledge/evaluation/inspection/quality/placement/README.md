# 근거 위치 대조

같은 의미의 질문인 ‘R7의 보존 기간과 삭제 조건은 무엇인가?’를 두고 정의 문장의 위치만 비교한다. 기존 합성 보존 사례를 사용한 통제 실험이며 새 미사용 사례나 사용자 승인 정답이 아니다. 모델이 질문을 표현하는 문구 자체를 고정하거나 강제로 주입하지 않는다. v27 전체 분류·검색 경로가 해당 의미의 미확인 조건을 어떻게 처리하는지 평가한다.

## 사전 기준

- original: 정의가 규칙 A 본문에 있다. duplicate, 검색 0회.
- supplemental: 동일한 정의가 별도 문서에만 있다. 검색 후 정의를 실제 인용하고 duplicate.
- missing: 정의가 어디에도 없다. R7의 뜻을 추정하지 않고 미확인 조건을 남긴 uncertain. 실제 검색을 사용하며 빈 결과를 모의로 반환하지 않는다.

조건별 별도 임시 Git 저장소와 Qdrant 컬렉션을 사용해 다른 조건의 정의가 검색되지 않게 한다. 사례·코드·문서·실행기 해시와 모델 digest를 고정하고 각각 세 번 실제 실행한다. 정의 문장 외의 A·B 요구는 같다. 답변 위치에 따라 전체 문서량이 달라지는 것은 이 실험의 조작 조건이다. 판정명·질문 내용·인용·검색과 호출 수·오류를 구분한다. 검색 상한 6회, 모델 호출 검증 상한 14회, 선택 문맥 12,000자 기준을 유지한다.

[문맥 충분성 조사](../holdout/README.md)와 [질문 보존 대조](../project/README.md)의 후속 실험으로 기존 방법론 조사를 재사용한다. 제품 프롬프트·코드·기대값은 변경하지 않는다. 실험 중 결과에 맞춰 기준을 바꾸지 않는다.

## 결과

v27로 조건별 세 번씩 실제 실행했다. missing은 서비스 복구 후 재실행해 검증을 마쳤다. 제품 코드는 변경하지 않았다.

| 조건         | 실제 결과     | 실행당 검색 / 모델 호출 | 판정 근거                                                                                      |
| ------------ | ------------- | ----------------------- | ---------------------------------------------------------------------------------------------- |
| original     | 3/3 duplicate | 0 / 3                   | 원문의 R7 정의와 B의 7일 보존·즉시 삭제 요구가 같다.                                           |
| supplemental | 3/3 duplicate | 1 / 7                   | 세 번 모두 정의 문서를 인용해 보존 기간과 삭제 조건을 확인했다.                                |
| missing      | 3/3 uncertain | 2 / 6                   | R7의 보존 기간과 삭제 조건을 미확인 사항으로 남겼다. 정의를 추정하거나 근거를 인용하지 않았다. |

[original 기록](runs/01-original/summary.json)과 [supplemental 기록](runs/01-supplemental/summary.json)은 실행 전후 코드·입력·색인·모델 불변 검사를 통과했다. 두 조건의 6개 결과는 기록된 응답으로 전체 요청·검색·최종 결과를 재현했다([original 재현](runs/01-original/verified.json), [supplemental 재현](runs/01-supplemental/verified.json)). 이 재현은 추가 실제 모델 실행이 아니다. supplemental의 세 결과 모두 질문에 연결된 인용문이 실제 R7 정의임을 확인했다.

세 조건의 모델 digest가 같고, supplemental과 missing의 A·B 문서가 동일하며, original에는 supplemental의 정의 문장만 추가되어 있음을 별도로 확인했다. 이 결과는 기존 합성 사례 하나의 통제 실험이며 일반적인 판정 품질 향상의 증거로 확대하지 않는다.

## 재시도 기록

[missing 첫 기록](runs/01-missing/1-retention.json)은 첫 검색에서 현재 조건의 문서를 반환했지만 두 번째 검색에서 연결 오류가 발생했다. 다음 두 실행도 연결 오류로 끝났고, 마지막 색인 재조회도 실패해 summary는 생성되지 않았다. 별도 상태 조회에서도 `127.0.0.1:6333` 연결 실패와 Docker 엔진 소켓 부재를 확인했다. 서비스가 중단된 원인은 이 기록만으로 판단할 수 없다.

첫 재시도인 `runs/02-missing`은 모델 응답 실패 기록 두 건만 남아 있으며 완료된 실행으로 세지 않는다. 기존 오류 기록은 보존한다.

Docker와 기존 Qdrant 컨테이너를 시작하고 동일 모델의 실제 응답을 확인한 뒤 [새 실행](runs/03-missing/summary.json)을 완료했다. 세 번 모두 실제 검색 2회 후 `no-new-evidence`로 종료했다. 각 질문의 확인된 답과 인용 근거는 비어 있고, R7의 보존 기간·삭제 조건이 미확인 사항으로 남았다. 실행 전후 입력·코드·색인·모델 불변 검사를 통과했으며, 앞선 supplemental 실행과 제품 코드 해시 및 모델 digest가 동일함도 확인했다.

[기록 재현](runs/03-missing/verified.json)에서도 세 실행의 전체 요청·검색·최종 결과가 일치했다. 따라서 이번 통제 사례에서는 세 조건의 사전 기준을 모두 충족했다. 서비스·모델 오류로 끝난 실행은 성공률에서 제외한 별도 실패 기록이며, 이 결과가 서비스 가용성이나 일반적인 판정 품질을 보장하지는 않는다.
