# 판정 품질 개선 실험

## 판정 기준

- [승인된 확장 16쌍](../expanded/golden.json)의 정답을 고정하고 같은 모델 digest·원문 hash·검색 예산으로 비교한다. 각 실행은 질문 이력과 연결을 재사용하지 않는다.
- 오답 감소와 사례별 회귀를 함께 본다. 오류는 정답으로 세지 않는다. 질문이 줄거나 uncertain이 다른 답으로 바뀌었다는 것만으로 개선이라 하지 않는다.
- 모델의 최초 분류, 질문, 검색, 재판정 응답을 보존해 오류가 발생한 단계를 구분한다. 모델에 평가 정답은 전달하지 않는다.
- 개발에 사용한 자료에서 얻은 개선과 별도 자료에 대한 일반화는 구분한다. 승인 해석이나 추가 근거가 필요하면 A ↔ B 원문과 제안 정답을 사용자에게 제시하고 멈춘다.

## 진행 기록

- `baseline/`: 최초 실행은 16쌍 중 3쌍만 기록된 뒤 세션이 중단됐다. 완료된 기준선이 아니며 전체 정확도로 집계하지 않는다. 이후 임시 저장소가 없고 Docker/Qdrant가 중지된 것을 확인해 별도 임시 저장소와 평가 컬렉션으로 재개했다.
- `opposite-concurrency`: 최초 분류는 conflict였으나 질문 단계가 이미 원문에 정의된 동시성 조건과 가상의 예외를 질문했다. 이어 관련 없는 정책 R을 찾다가 동일 검색어 3개를 반환해 `invalid-inquiry-queries`로 끝났다.
- `audit-pilot/`: 기존 질문 지침을 재실행해 같은 불필요한 질문을 2회 확인했다. 첫 후보는 빈 배열 대신 문자열 `"[]"`를 반환해 제외했다. 두 번째 후보는 빈 배열 객체를 명시했고 2회 모두 질문이 없었다. 이 결과는 질문 생성만 검증한 것이며 전체 판정 개선은 별도다.
- `comparison-01/`: 복구한 환경에서 전체 검색 경로로 기존·후보 지침을 비교한다. 제품 프롬프트는 그대로 두고, [평가 실행기](compare.mjs)가 질문 생성 요청의 지침 부분만 교체한다. 입력·요청·응답·결과를 파일로 기록하며 기존 파일은 덮어쓰지 않는다.

## 반복 결과

- [첫 전체 비교](comparison-01/summary.json): 기존 6/16, 질문 지침 후보 14/16. 오류 0, 기존 정답이 오답으로 바뀐 사례 0. 남은 오답은 한글·영문 동시성 충돌과 영문 감사 로그의 독립성이다.
- [두 번째 후보](comparison-02/summary.json): 명시적 모순을 미확인 조건으로 보지 않는 질문 지침과 독립 속성의 최초 분류 지침을 함께 적용했다. 15/16이지만 `staging-undefined-policy`가 uncertain에서 unrelated로 회귀해 이 조합은 제외했다.
- 최초 분류를 우선순위 문장·짧은 정의·범위 조건으로 바꾸는 추가 실험도 `audit-pilot/`에 보존했다. 감사 로그의 독립성과 미정의 참조 규칙을 모두 맞히지 못해 제품 코드에 적용하지 않았다.
- [세 번째 후보](comparison-03/summary.json): 최초 분류를 유지하고 질문 단계만 변경해 14/16이었다. 감사 로그 사례는 오답, 미정의 정책 사례는 같은 인용 ID를 반복해 오류로 처리됐다.
- [운영 자료 검증](operations-check/summary.json): 질문 지침 후보는 승인 2쌍 모두 unrelated로 오판했고 추가 검색도 하지 않았다. 미승인 12쌍은 제외했다. 판정 지침 후보는 모두 채택하지 않았다.
- 제품에 반영한 v13 변경은 알려진 인용 ID 중복 제거뿐이다. 알 수 없는 인용과 최대 개수 초과는 계속 거부한다. 패키지 테스트 417개가 통과했다. 두 평가를 함께 개선하는 판정 변경은 확인하지 못했다.
- 다음은 모델 변경에 앞서 [보조 자료 제공 방식 비교](context/README.md)를 수행한다. 기존 운영 문서 전체와 SolidJS 공식 자료 기반 실험을 분리해 자료 부족·검색 누락·판정 오류를 확인한다.
- [보조 자료 비교 결과](context/runs/checks.json): 32조건 실행 완료. SolidJS 공식 설명에 실제 실행값을 추가하자 검색 조건의 예상 판정 일치는 0/4에서 3/4로 올랐다. 직접 제공은 0/4를 유지했고, 답한 질문을 닫도록 한 지침 후보도 개선이 없었다. 운영 승인 두 쌍은 허용 정답을 유지했다. 소규모 자료 보강 효과와 제품 전체의 판정 품질은 구분한다.
- [승인된 큰 모델 비교](context/runs/04/comparison.json): SolidJS 직접 제공 4/4·검색 4/4, 근거 없는 발췌는 네 쌍 모두 uncertain이었다. 운영 자동 정리 범위의 직접 제공 한 조건이 기존 승인 기준에서 벗어나 전체는 17/18이었다. 모델 전면 교체는 보류하며 제품 설정과 승인 정답은 유지한다.

평가 실행기는 저장소, 승인 자료, 새 결과 디렉터리, 후보 지침이 담긴 파일, 실행 방식을 인자로 받는다. 방식은 기존·후보 비교인 `compare`(기본값), 후보만 실행하는 `candidate`, 요청을 교체하지 않는 실제 제품 경로 `production`이다. 후보 교체 횟수를 검사하며, 원래 지침을 찾지 못하면 검증을 통과시키지 않는다. 평가용 컬렉션은 환경변수로 분리한다. 원본·기존 운영 색인·승인 상태는 변경하지 않는다. 기록에는 원문과 모델 응답이 포함된다.
