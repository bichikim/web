# 판정 전제 감사 실험

새 조사 규칙에 따라 문맥 충분성·추가 질문 효용·과검색 연구를 확인한 뒤 진행한다. 핵심 가설은 **초기 판정에 필요한 전제가 원문에 없을 때만 질문한다**이다. 단어가 생소하다는 이유나 가상의 포함 관계만으로 질문하지 않는다.

제품 변경 전 기존 네 문서 쌍의 질문 요청을 사용하여 비교한다. 원문·초기 판정·모델·스키마는 유지하고 질문 지시만 바꾼다. 초기 판정은 신뢰할 근거가 아니라 감사 대상이다. 기존 사례의 기대값은 사용자 승인 정답이 아닌 실험 가설이며 변경하지 않는다.

사전 기준: 재검증·유효 기간·아카이브에는 필요한 정의 또는 적용 조건 질문이 있고, 저장 동작에는 추가 질문이 없어야 한다. 이후 전체 경로에서는 실제 근거 인용과 최종 판정, 빈 검색 결과에서 uncertain 유지, 호출·검색 상한을 함께 확인한다. 질문 단계 비교만으로 판정 품질 개선을 선언하지 않는다.

## 질문 단계 결과

[저장한 네 요청](runs/01.json)은 재검증의 지시 의미, 유효 기간의 우선순위, 아카이브의 자동 실행 여부를 질문했고 저장 동작에는 빈 질문 목록을 반환했다. 첫 실행도 같은 네 응답을 받았으나 출력 폴더 누락으로 저장에 실패했다. 실행 도구가 폴더를 먼저 준비하도록 고친 후 다시 실행하여 기록했다. 이 저장 실패를 제품 오류나 판정 오류로 집계하지 않는다.

질문 프롬프트만 연구 모드 v25에 적용했다. 기본 contextual 프롬프트, 스키마, 검색어 생성, 검색·호출 상한은 바꾸지 않았다. 일반 모드와 연구 모드가 서로 다른 지시를 쓰면서 모두 초기 판정을 보존하는 계약을 테스트한다. 기존 v21도 이 네 사례의 전체 판정은 12/12회 일치했으므로, 질문 단계 결과만으로 v21 대비 정확도 개선을 주장할 수 없다.

조사에 참고한 자료: [Google 문맥 충분성 연구](https://arxiv.org/html/2411.06037v3), [Google의 2026년 적용 설명](https://research.google/blog/unlocking-dependable-responses-with-gemini-enterprise-agent-platforms-agentic-rag/), [Clarify When Necessary](https://aclanthology.org/anthology-files/anthology-files/pdf/naacl/2025.naacl-findings.306.pdf), [Over-Searching](https://machinelearning.apple.com/research/search-augmented). 문맥의 충분성을 판정별로 확인하고, 질문의 효용과 과검색 비용을 함께 검증하는 관점만 참고했다.

## 정의 유무 대조의 사전 기준

`controls.mjs`는 재검증 원문을 복사해 두 실험 입력을 만든다. 하나는 원문에 없는 정의를 초기 판정만 단정하고, 다른 하나는 같은 정의를 원문에 명시한다. 기존 corpus와 기대값 파일은 수정하지 않는다. 전자에는 질문, 후자에는 빈 질문 목록을 기대한다. v21과 v25의 질문 단계만 각각 세 번 실행하고 모델 digest를 실행 전후 확인한다. 이 합성 입력은 사용자 승인 정답이나 전체 검색 평가가 아니다.

[정의 유무 대조 결과](runs/02.json)는 두 버전 모두 6/6회 기준을 만족했다. 따라서 이 대조에서는 v25의 우위를 확인하지 못했다. [v25 빈 검색 결과 대조](../transfer/runs/07-withheld/summary.json)는 3/3회 두 번의 검색 요청 뒤 uncertain을 유지했다. 실제 검색 백엔드는 호출하지 않고 빈 결과를 반환한 조건이며, [기록 재생](../transfer/runs/07-withheld/verified.json)도 세 건 일치했다.

두 합성 입력에서 v25 질문 요청의 `prompt_eval_count`는 v21보다 각각 5토큰 많았다. 입력 토큰 수와 질문 필요성 판정을 함께 남기며, 지시를 구체화했다는 이유만으로 비용 개선을 주장하지 않는다.

## 실제 검색 12회 결과

[v25 결과](../transfer/runs/07-live/summary.json)는 네 사례를 세 번씩 실행해 12/12회 기존 기대값과 일치했다. 재검증은 정의 문서를 인용해 conflict, 유효 기간은 우선순위 문서를 인용해 duplicate, 서로 다른 저장 동작은 질문·검색 없이 unrelated, 자동 여부 미정인 아카이브는 uncertain이었다. [기록 재생](../transfer/runs/07-live/verified.json)에서 모델 요청, 검색 요청, 판정과 연구 기록 12건이 현재 코드와 일치했다.

| 전체 12회 합계   |    v21 |    v25 |
| ---------------- | -----: | -----: |
| 기대 판정 일치   |     12 |     12 |
| 처리 오류        |      0 |      0 |
| 실제 검색        |     15 |     12 |
| 모델 호출        |     78 |     69 |
| 보고된 입력 토큰 | 63,159 | 49,665 |
| 보고된 출력 토큰 |  8,451 |  7,092 |

[비교 검증 기록](runs/03.json)은 원문·사례·색인 point·모델이 같은지 확인하고 완료된 응답 기록에서 합계를 계산한다. 유효 기간은 매회 검색 2→1회, 모델 호출 9→7회였고, 아카이브는 검색 2회를 유지하면서 모델 호출 7→6회였다. 재검증의 출력 토큰은 늘었으므로 모든 사례가 저렴해졌다는 뜻은 아니다. 실행 시간이나 실제 요금 절감은 검증하지 않았다.

이 결과는 이미 개선에 사용한 네 사례의 반복 평가다. 일반 정확도 향상이나 미사용 자료에서의 성능을 입증하지 않는다. 조사에서 가져온 전제 감사 관점을 적용하여, 이 평가 범위에서 판정을 유지하면서 검색·호출 수를 줄였다.

## v25 회귀 실패와 v26 보완

v25를 기존 여섯 사례에 실제 검색으로 적용한 [34차 결과](../context/runs/34/verified.json)는 5/6건만 일치했다. 정리 정책의 초기 unrelated가 질문 없이 통과해 승인 기준 uncertain을 위반했다. 처리 오류가 아니라 판정 퇴행이다. HTTP 비용 감소만으로 v25를 채택하지 않았다. 저장소 선택 사례는 판정을 유지했지만 모델 호출이 6→7회로 늘었다.

원 논문의 NLI 모호성 평가와 적용 범위 한계를 다시 확인하고, 초기 판정의 대상 구분을 곧바로 문서 근거로 인정하지 않도록 보완했다. 초기 unrelated는 두 문서가 독립적이라는 제안이므로, 그 분기에서만 기존의 행위·실행 조건 감사 지침을 더한다. 특정 문서 이름이나 기대 정답으로 분기하지 않는다. [두 질문 비교](runs/04.json)에서는 정리 정책의 적용 범위 질문이 회복됐고 저장 동작에는 질문이 없었다.

v26 검증은 변경 분기와 미변경 분기를 구분한다. `replay.mjs`는 버전 번호가 달라도 모든 모델 요청·검색 요청·최종 결과가 정확히 같을 때만 이전 기록을 사용할 수 있다. 변경된 저장 동작을 v25 기록으로 재생하면 거부되는지 확인한 대조는 의도대로 실패했고 성공 기록을 만들지 않았다. 이는 실제 모델 실패가 아니다.

- [HTTP 미변경 9건](runs/05.json), [기존 사례 미변경 5건](runs/06.json), [빈 결과 대조 3건](runs/07.json): 네트워크 호출 없이 v26 코드에서 정확한 요청·결과 재생을 확인했다. 신규 모델 실행으로 집계하지 않는다.
- [저장 동작 실제 재실행 3회](../transfer/runs/08-live/summary.json): 모두 질문·검색 없이 unrelated였고, [v26 기록 재생](../transfer/runs/08-live/verified.json)도 일치했다.
- [정리 정책 실제 재검증](../context/runs/35/verified.json)은 검색 2회 뒤 uncertain으로 승인 기준을 회복했다. 동일한 원문 point·사례·모델·첫 요청과 기록 재생을 확인했다. 평가 실행기에 선택적 사례 인자를 추가해 변경된 경로만 실행하고, 실행 범위를 input에 기록한다.

## 최종 반영과 한계

v26을 유지한다. 변경 분기 실제 실행은 저장 동작 3회와 정리 정책 1회이며, 미변경 경로 17건은 신규 모델 실행이 아닌 정확한 기록 재생이다. 이 근거를 합치면 HTTP 12건·기존 6건·빈 결과 대조 3건의 기준을 모두 만족한다. 전체 21건을 v26으로 새로 실시간 실행했다고 해석하면 안 된다.

HTTP의 신규 실행과 재생을 합친 검증 근거에서 검색 12회·모델 호출 69회로 v25의 감소를 유지한다. 미변경 9건의 토큰 기록과 변경 3건의 신규 토큰 기록 합계는 입력 49,761·출력 7,092토큰이다. 기존 6개 사례는 검색 8회·모델 호출 41회로 v21과 합계가 같다. 저장소 선택은 호출 6→7회, 정리 정책은 7→6회였다. 서로 다른 반복 횟수의 두 평가를 합쳐 일반 비용 절감률을 만들지 않는다.

Wallaby 대상 46개, 전체 Vitest 54파일·482개, 타입 검사를 통과했다. 새 지침의 일반 정확도 향상은 아직 입증하지 않았으며, 다음 검증은 개선에 사용하지 않은 문서 쌍에서 진행해야 한다.
