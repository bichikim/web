# 태그 비교 응답 거부 원인

후속 [버전 5 지침 보완 실험](../runs/prompt-5/README.md)에서도 비연속 인용이 재현됐다. 후보는 채택하지 않았고 버전 3을 유지한다.

프롬프트 버전 3과 기존 실행의 모델 digest·캐시 키·원문을 맞춘 뒤 실제 분류 어댑터로 한 쌍을 재현했다. HTTP 응답을 변경하지 않고 복사해 [요청·원시 응답](response.json)에 저장했다. 호출 전후 모델 digest도 같았다. 프로덕션 코드·프롬프트·정답·분류 캐시는 변경하지 않았다.

모델은 `duplicate`로 분류했지만 `rightQuote`를 다음과 같이 반환했다.

> 태그는 배포 트리거가 아니라 해당 npm 버전의 소스를 보존하는 기록이다. ... 태그는 이동, 재사용 또는 강제 push하지 않는다.

원문에는 `...`가 없다. 모델이 중간의 GitHub Release 설명 문장을 생략하고 양쪽 문장을 연결했다. 왼쪽 인용은 원문에 포함되지만 오른쪽 인용 전체는 원문에 연속된 문자열로 존재하지 않는다. 따라서 [실제 검증기](../../../../src/inspection/pairs.ts)의 원문 포함 조건이 `invalid-inspection-response`를 반환했다.

[통제 실험](validation.json)에서는 기록된 응답의 다른 필드를 유지하고 `rightQuote`만 원문 문단 전체로 바꿔 같은 검증기에 전달했다. 원래 응답은 거부되고 교체한 입력은 수락됐다. 이는 거부 원인을 분리하기 위한 오프라인 실험이며 수정된 응답을 실제 모델 결과나 정상 평가로 저장한 것이 아니다.

앞선 여섯 진단은 동일 캐시 키에서 같은 오류가 났지만 원시 응답이 없으므로 모두 동일한 생략 부호를 반환했다고 확정하지 않는다. 이번 재현에서의 직접 원인은 비연속 인용이다.

다음 개선 후보는 인용을 하나의 연속된 원문 문자열로 복사하고 생략 부호·요약·문장 이어 붙이기를 하지 않도록 지침을 구체화하는 것이다. 변경한다면 사용하지 않은 프롬프트 버전 5를 부여하고, 이 쌍과 업무 문서 전체·기존 합성 정답을 재평가한다. 검증기를 완화하거나 응답의 `...`를 자동 제거하는 처리는 하지 않는다.
