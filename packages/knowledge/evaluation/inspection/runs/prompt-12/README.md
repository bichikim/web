# 다른 검색어로 제한된 재시도

v12는 질문당 최초 검색과 대안 검색 1회를 허용한다. 이후에는 새 인용 단서가 필요하며 질문당 총 6회, 실행당 2라운드 한도를 유지한다. 최초 검색이 비어도 남은 라운드를 사용할 수 있다.

## 통제된 재현

[질문 이력 테스트](../../../../src/inspection/__tests__/inquiry.spec.ts)에서 실제 검색 루프에 통제된 검색·판정 응답을 전달했다. 첫 검색은 빈 결과, 두 번째 검색은 인용 가능한 원문을 반환하도록 했다. 수정 전에는 첫 검색에서 멈췄지만 수정 후 같은 실행에서 다른 검색어를 시도해 해결됐다. 이는 루프 동작 검증이며 실제 모델의 검색어나 판정 정확도를 입증하지 않는다.

두 번 빈 검색 후에는 재실행해도 추가 검색하지 않는 것, 한 번 검색한 이력에서는 남은 재시도를 사용하는 것, 같은 검색어 제외와 기존 6회 한도를 테스트했다. 전체 51개 파일·414개 테스트와 타입 검사가 통과했다. Wallaby CLI는 테스트 0건을 반환해 Vitest를 사용했다.

## 실제 로컬 모델

v11 입력의 승인 사례 두 쌍에 실제 `classifyResearchPair`와 Qdrant 검색을 사용했다. 모델은 `gemma4:latest`이며 이전 입력의 모델 digest와 현재 11개 unit 전체가 일치함을 확인했다. 재실행에는 직전 질문 이력과 인용된 unit을 메모리로 전달했다. 이번 실험은 CLI 프로세스나 연결 파일 저장 경로의 검증이 아니다.

| 사례           | 첫 실행 검색 | 재실행 검색 | 첫 실행 시간 | 재실행 시간 | 결과           |
| -------------- | -----------: | ----------: | -----------: | ----------: | -------------- |
| 저장 수단      |          3회 |         3회 |      55.25초 |     68.50초 | 모두 uncertain |
| 자동 정리 범위 |          6회 |         1회 |      51.58초 |     41.71초 | 모두 uncertain |

- 저장 수단: [첫 실행](storage-backend/cold.json), [재실행](storage-backend/warm.json).
- 자동 정리 범위: [첫 실행](cleanup-scope/cold.json), [재실행](cleanup-scope/warm.json).
- [무결성 확인](integrity.json): 색인과 승인 자료가 실험 전후 동일했다. 외부 요청은 차단하고 로컬 Ollama·Qdrant만 사용했다.

저장 수단은 첫 실행에서 유효한 새 검색어가 없어 멈췄지만 재실행에서는 다른 문자열의 검색어를 시도했다. 자동 정리 범위는 첫 실행에서 두 라운드를 사용했다. 인용 단서가 있으면 최초 두 번을 넘어 검색할 수 있으므로 모든 질문의 총 시도가 두 번으로 제한되는 것은 아니다.

네 실행 모두 확인 내용은 비어 있고 질문은 미해결로 남았다. 검색어에는 기존 질문의 단어 순서나 표현만 달라진 것도 있다. 문자열 중복 제외가 의미 중복을 제거하거나 더 좋은 검색어를 보장하지 않는다. 인용이 남았다는 사실만으로 유용한 단서를 찾았다고 볼 수도 없다. 재시도 동작은 확인했지만 판정 품질 개선은 확인하지 못했다.

각 조건을 한 번씩 실행했고 모델 예열이나 다른 로컬 부하를 통제하지 않았다. 시간은 실행 기록이며 v11 대비 성능 개선·악화의 근거로 사용하지 않는다. 승인 두 사례 외의 미승인 자료는 채점하지 않았다.
