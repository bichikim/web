# 미해결 조건 검색 검증

로컬 gemma4:latest와 Qdrant의 실제 hybrid 검색으로 실행했다. [기존 승인 자료](../../operations/reviewed.json)의 1·2번과 동일한 11개 발췌 색인을 사용했다. 원본·색인·정답을 변경하지 않았으며 주변 문서를 실험용으로 따로 주입하지 않았다. 입력에 전체 snapshot과 모델 digest를 보존했다. 외부 전송 위험으로 첫 실행 요청이 거부된 뒤 실제 설정이 127.0.0.1임을 확인했고, 검증 과정에서는 그 두 로컬 포트 외 요청을 거부했다.

| 사례             | 라운드 | 검색어 수 | 새 unit | 추가 본문 | 중단 이유   | 최종 결과 |
| ---------------- | ------ | --------- | ------- | --------- | ----------- | --------- |
| 1 저장 수단      | 2      | 6         | 5       | 1,334자   | round-limit | uncertain |
| 2 자동 정리 범위 | 2      | 6         | 3       | 1,031자   | round-limit | uncertain |

1번은 구조화 데이터 저장소의 공통 계약, 앱인토스 Storage 계약, localStorage와 웹 구조화 저장의 적용 범위를 검색했다. 2번은 자동 정리 정책의 대상 데이터, 피드 저장소 범위, 정책 우선순위를 검색했다. 검색어당 결과는 3개 이하였으며 원래 쌍과 중복 구간을 제외했다. 두 번째 라운드에서 각각 2개·1개의 새 unit을 읽었지만 미해결 조건이 남아 한도에서 종료했다.

- 1번: [입력](storage-backend/input.json), [검색 기록과 결과](storage-backend/result.json).
- 2번: [입력](cleanup-scope/input.json), [검색 기록과 결과](cleanup-scope/result.json).

둘 다 승인된 정답에 포함되지만 표본 2개이며, 검색이 조건을 해결하거나 전반적인 정확도를 높였다는 증거는 아니다. 일부 검색 결과는 배포·원격 함수 문서처럼 직접 관련성이 낮았다. 검색 결과 수는 근거의 적절성을 보장하지 않는다.

[실제 CLI 진입점 실행](cli.json)은 research 모드·limit 1에서 exit 0, healthy, semantic complete, 오류 0, promptVersion 9, cached 0이었다. 선택된 쌍은 새 근거가 없어 `no-new-evidence`로 종료했다. 위 두 특정 사례의 어댑터 실행과 CLI 경로 검증은 구분한다.

Wallaby 전체 375개 테스트가 통과했다. 검색 한도, 다음 라운드의 질문 전달, 반복·동일 본문 제외, 비활성 결과 제외, scope·본문 변경 거부, 오류 구분, 인용 검증, 기존 모드 호환성을 확인했다. 타입 검사·oxlint·포맷도 수행했다.
