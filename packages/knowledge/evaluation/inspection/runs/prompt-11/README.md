# 질문별 조사 이력 반복 실행

승인 사례 1·2번을 실제 Ollama `gemma4:latest`와 Qdrant로 각각 두 번 실행했다. 실제 판정 어댑터·검색·연결 파일 읽기/쓰기·잠금을 사용했다. 전체 CLI 프로세스를 실행한 실험은 아니다.

| 사례             | 첫 검색 | 재실행 검색 | 첫 실행 시간 | 재실행 시간 | 최종 결과      |
| ---------------- | ------: | ----------: | -----------: | ----------: | -------------- |
| 1 저장 수단      |     3회 |         0회 |      32.02초 |      7.69초 | 모두 uncertain |
| 2 자동 정리 범위 |     3회 |         0회 |      24.55초 |      7.30초 | 모두 uncertain |

- 1번: [입력](storage-backend/input.json), [첫 실행](storage-backend/cold.json), [재실행](storage-backend/warm.json).
- 2번: [입력](cleanup-scope/input.json), [첫 실행](cleanup-scope/cold.json), [재실행](cleanup-scope/warm.json).
- [무결성 확인](integrity.json): 전체 색인과 승인 자료가 실험 전후 같았다.

네 실행 모두 미해결 질문 3개와 `no-new-queries`로 종료했다. 이번에는 질문에 연결된 인용이 없었고, 재실행은 질문별 검색 이력을 이용해 추가 검색을 생략했다. 근거 재사용 성공이나 충돌 판정 정확도 개선을 확인한 결과는 아니다. 부족한 조건을 확정된 사실로 바꾸지 않고 `uncertain`을 유지했다.

[v10](../prompt-10/README.md)에서는 같은 승인 사례의 첫 실행·재실행 모두 검색 6회였다. 이번 비교는 같은 모델 digest와 11개 unit의 색인을 사용했지만 프롬프트와 중단 정책이 다르다. 각 조건을 한 번씩 실행했으며 모델 예열 등을 통제하지 않았으므로 시간 차이를 일반적인 성능 수치로 보지 않는다. 미승인 12개 사례는 채점하지 않았다.

현재 정책은 새 인용 단서나 색인 변경 없이 같은 질문을 더 탐색하지 않는다. 따라서 첫 검색어가 부적절했다면 다른 표현으로 검색할 기회도 줄어든다. 검색 감소와 조사 충분성은 별도로 평가해야 한다.
