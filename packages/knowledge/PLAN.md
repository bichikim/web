# Knowledge 구현 상태

2026-09-13 기준. 구현된 기능과 품질 검증을 구분한다. 사용법은 [README](README.md), 초기 설계와 과거 진행 기록은 이력 (로컬 보관: `.local/history-2026-09-13.md`)에 있다.

| ----------- | ------------------------------------------------------------------- | ------------------------------------------------- |

패키지는 private이며 CLI 명령은 `know`다. 기본 진단 모드는 combined이며 research는 명시적으로 선택한다. 평면 근거 확인은 [어댑터 선택형 후보](src/adapters/experimental/flat.md)이고 조건표 추출은 평가용 실행기다. 두 후보를 기본 동작으로 승격한 상태가 아니다.

## 검증 범위

- 검색: 승인 데모 문서 2개·질문 4개의 [저장 기준선](evaluation/demo/baseline.json)은 Recall@2·MRR@2가 각각 1이다. 전체 업무 문서의 검색 품질을 보증하지 않는다.
- 추가 조사: 질문 이력·근거 재사용·검색 및 생성 한도 계약은 구현돼 있다. 검색 완료나 인용문 존재가 근거의 의미상 충분성을 증명하지는 않는다.
- 최신 판정 후보: 조건표 검증 (로컬 보관: `.local/evaluation/inspection/quality/project/rows.md`) 8회는 JSON 형식을 통과했지만 값 비교 오류·적용 범위 단정·정의 근거 인용 누락이 남았다. 제품에 반영하지 않았다.
- 과거 테스트 수와 평가 점수는 각 기록의 코드·모델·자료 범위에만 해당한다. 이번 문서 정리는 전체 테스트나 실제 모델 재실행 결과가 아니다.

## 남은 범위

초기 계획에 있지만 완료로 표시하지 않는 항목이다.

- 같은 조건의 값 비교, 적용 범위와 근거 충분성을 포함한 판정 품질 확보
- unit별 Git 변경 이력과 의미상 최신성 추적
- exact duplicate 그룹·검색 결과 다양화와 status/freshness 순위 보정
- 대규모 corpus의 후보 선정·일반화 검증과 추가 검색 품질 지표
- 코드 심볼 색인, watcher, 저장소 간 관계, 원격 HTTP MCP

자동 원본 수정·자동 정답 승인·채팅 UI는 현재 제공 범위가 아니다. 생성 모델의 결론은 검토 제안으로 유지한다.
