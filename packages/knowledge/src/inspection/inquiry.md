# 질문별 조사 이력

[구현](inquiry.ts)은 기존 [검색 루프](research.ts)에 질문별 기록을 추가한다. 모델이 만든 확인 내용은 검증된 사실이나 사용자 승인으로 취급하지 않는다.

- 최초 질문에 고정 ID를 부여한다. 같은 색인 상태에서는 다음 실행의 질문 표현이 달라져도 기존 질문을 이어 사용한다.
- 질문마다 `confirmed`(모델이 확인했다고 제안한 내용), `remaining`(아직 필요한 조건), `evidence`(실제 원문 구간), `attempts`(실행한 검색어와 당시 단서)를 저장한다.
- 검색 결과가 비어 있어도 시도는 기록한다. 최초 검색 뒤에는 새 근거 없이도 다른 검색어로 한 번 더 시도할 수 있다. 두 번 시도한 뒤에는 새 인용 구간이 있어야 추가 검색하며, 이미 시도한 검색어는 제외한다. 같은 색인 상태에서 질문당 최대 6회다. 재실행해도 사용한 횟수는 초기화하지 않는다.
- 후속 조사에서 드러난 조건은 기존 질문의 `remaining`에 적는다. 질문을 새 이름으로 바꿔 한도를 우회하지 않는다. 최초 질문들 사이의 의미 중복까지 판별하지는 않는다.
- 원문 인용 없이 질문이 해결됐다는 응답은 거부한다. 남은 조건이 있으면 모델이 충돌을 제안해도 최종 결과는 `uncertain`이다. 검색을 멈췄다는 뜻과 질문이 해결됐다는 뜻을 구분한다.
- 같은 repo/workspace의 색인에 문서가 추가·변경·삭제되면 질문 이력을 다시 만든다. 파일 변경은 먼저 색인에 반영해야 감지된다. CLI는 모델·프롬프트가 바뀐 경우에도 이력을 재사용하지 않는다.

질문 ID·인용 구간·시도 횟수는 코드로 검사하지만, 인용이 질문에 실제로 답하는지는 모델 해석과 사람의 검토가 필요하다. 검색 실패는 완료 기록으로 저장하지 않는다. 파일 저장과 이전 버전 호환성은 [연결 저장 계약](../cli/links.md)을 따른다.

`auditor`를 제공한 소비자는 형식 검사를 통과하고 미해결 조건을 모두 비운 재판정을 별도로 검토한다. 거부한 질문의 확인 내용만 비우고 검토자가 제시한 미해결 조건을 남긴다. 질문 ID·근거·기존 검색 시도는 유지한다. 검토 결과는 해당 `decision.audits`에 기록하며, 검토 실패에는 성공한 질문 이력을 반환하지 않는다. 두 단계 `checks`가 있으면 각각의 질문·인용 ID를 검증하고 둘 다 승인한 답변만 유지한다. 실제 research 어댑터의 검토 입력·횟수 한도는 [사용법](../adapters/experimental/research.md#근거와-답변의-검토)을 따른다. 코어 API를 직접 호출하는 소비자는 모델·지침 변경 시 자기 저장소의 이력을 별도로 무효화해야 한다.

v12에서는 첫 라운드에 새 근거가 없어도 남은 라운드 안에서 다른 검색어를 요청한다. 모델이 같은 검색어만 반환하거나 유용한 검색어를 제안하지 않으면 검색을 더 실행하지 않는다. 한도 내 재시도는 조사 완결성을 보장하지 않는다.
