# 보조 문맥 진단

미해결 조건으로 지식 베이스 전체를 검색하려면 [research 모드](research.md)를 사용한다. 아래 contextual 모드는 같은 문서·직접 연결 문서의 문맥에 한정한다.

`know doctor <저장소> --model <모델> --inspection-mode contextual --json`으로 사용한다. 먼저 `know index <저장소>`로 주변·연결 문서까지 색인해야 한다. 발췌만 별도 문서로 저장하면 원본의 앞뒤 내용은 자동으로 찾아오지 못한다.

## 판정 순서

1. 기존 v7로 두 발췌를 비교하고 분류와 근거를 보존한다.
2. 모델이 비교에 필요한 미확인 조건을 최대 3개 질문으로 정리한다. 질문이 없으면 초기 판정을 유지한다.
3. 질문이 있으면 같은 문서의 다른 unit과 직접 연결된 문서의 active unit을 조회한다. 동일 repo/workspace의 색인 스냅샷만 사용하며 외부 웹·구현 코드·재귀 관계 탐색은 하지 않는다.
4. 질문에 포함된 단어와 제목·본문의 일치 수로 순서를 정하고 최대 6개 unit을 읽는다. unit당 앞부분 4,000자, 합계 12,000자(UTF-16 기준)까지이며 생략 여부를 표시한다.
5. 추가 근거로 원래 두 발췌를 재판정한다. 미해결 질문이 남으면 모델의 제안과 무관하게 최종 분류는 uncertain이다. 보조 문맥이 없으면 질문을 모두 미해결로 남긴다.

문서에 예외 설명이 없다는 사실을 충돌의 증거로 삼지 않는다. 다만 질문이 충분한지, 인용이 실제 설명을 뒷받침하는지는 모델 판단이므로 이 기능만으로 정확성을 보장하지 않는다.

## 결과 읽기

JSON의 `semantic.assessments[].assessment`는 최종 결과이며 `review`에 다음을 남긴다.

- `initial`: 발췌만 비교한 v7 판정.
- `questions`: 추가로 확인하려 한 조건.
- `selection`: 읽은 출처의 문서·unit ID, 경로·원본 unit 행 범위, 내용 hash, 발췌 본문, 조회 후보 수와 생략 여부. 행 범위는 잘린 본문만이 아니라 원본 unit 전체의 위치다.
- `proposed`: 보조 문맥을 읽은 모델의 원래 제안. 재판정 요청이 없으면 생략한다. 미해결 조건 때문에 최종 결과가 uncertain으로 보정됐는지 여기서 구분한다.
- `citations`: 보조 근거 구간 ID. `context-N-left-M`은 selection의 N번째 출처를 최대 800자씩 나눈 M번째 구간이다. 인용은 해당 발췌의 원문과 일치해야 하지만 인용의 논리적 적절성까지 검증하지는 않는다.
- `unresolved`: 보조 문맥을 읽어도 해결하지 못한 질문.

정상 실행에는 쌍당 3~4회의 생성 요청이 필요하다(v7의 분류·근거 2회 포함). 모델 digest를 재확인하고 기존 v3·v7과 다른 캐시 키를 사용한다. 읽을 수 있는 보조 문맥 전체의 변경도 캐시를 무효화한다. 캐시를 읽을 때 출처·인용·미해결 조건 처리 규칙을 다시 검증한다. 실패를 기존 방식의 결과로 숨기지 않는다.

원본·status·관계·검색 순위·색인은 변경하지 않는다. JSON과 캐시에는 추가 원문이 포함되므로 공유 전 내용을 확인한다. 구현은 [문맥 선택과 검증](../../inspection/context.ts), [모델 요청](contextual.ts), [CLI와 캐시](../../cli/inspection.ts)에 있다. [Ollama 공식 구조화 출력 안내](https://docs.ollama.com/capabilities/structured-outputs)에 맞춰 JSON 스키마 요청과 응답 검증을 사용한다.
