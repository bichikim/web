# 판정 근거 연결

`research` 진단의 파생 기록이다. A·B를 판단할 때 C를 인용했다는 뜻이며, C가 사실이거나 B가 A의 예외라는 승인은 아니다. 인용 구간의 원문 일치는 검사하지만 결론을 논리적으로 뒷받침하는지는 사람이 검토해야 한다.

- 저장 범위: 비교 쌍의 원문 버전·repo/workspace별 최신 연결. 쌍 순서와 생성 모델은 키에서 제외한다. 모델이 바뀌어도 원문은 다시 읽고 새로 판정한다.
- 각 연결은 원문 경로·unit·hash·읽은 본문·인용 구간과 마지막 모델 판정의 이유를 담는다. 모델명·digest·프롬프트 버전도 기록한다. 모델 판정 이유는 문서별로 검증된 관계 설명이 아니다.
- 다음 실행에는 검증된 현재 색인의 unit만 반환한다. 저장된 이유·결론은 모델 입력으로 재사용하지 않는다. 변경·삭제·비활성화된 unit은 제외하고 나머지 연결은 유지한다.
- 성공한 재판정의 마지막 인용 목록으로 교체한다. 앞선 라운드에서만 인용한 근거는 제외하며, 새 인용이 없으면 기존 목록을 비운다. 실패한 진단은 기존 기록을 덮어쓰지 않는다.
- 저장 스키마·연결 수·인용 수·본문 길이는 [구현](links.ts)에서 제한한다. 손상되거나 지원하지 않는 버전의 기록은 진단 오류다.
- CLI의 inspection 디렉터리 잠금 안에서 임시 파일을 작성한 뒤 [Node.js rename](https://nodejs.org/docs/latest-v24.x/api/fs.html#fspromisesrenameoldpath-newpath)으로 교체한다. 파일 권한은 사용자 읽기·쓰기 전용이며 암호화 저장은 아니다.

`links/`는 삭제 후 검색으로 다시 만들 수 있다. 원문 변경으로 생긴 이전 쌍 키의 파일을 자동 정리하는 기능은 없다. 원본 Git 문서·Qdrant 관계·평가 승인 데이터와는 별개이며 다른 쌍으로 연결을 자동 전파하지 않는다.

## 질문 이력

v2 저장 형식은 기존 연결에 `journal`을 추가한다. [질문별 조사 이력](../inspection/inquiry.md)에 확인 내용·남은 조건·인용·검색 시도를 보관한다. 인용한 문서가 없어도 빈 검색의 반복을 막기 위해 이력을 저장한다. v1 연결 파일도 읽을 수 있지만 질문 이력은 없다.

질문 이력은 같은 모델명·digest·프롬프트에서만 전달하며, 검색 루프가 현재 scope의 전체 색인 fingerprint를 대조한다. 색인 내용이 바뀌면 검색을 다시 시작한다. 이력 무효화와 유효한 연결 원문의 재사용은 별개다. 과거의 확인 내용과 최종 판정은 모델의 사실 근거로 전달하지 않는다.
