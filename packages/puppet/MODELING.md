# Puppet 캐릭터 모델링 가이드

얼굴 방향이 바뀔 때 귀·머리카락·장식이 같은 머리에 붙어 있으면서 서로 다른 깊이를 보이도록 만드는 방법을 정리한다. 대상은 레이어로 분리한 2D 일러스트를 정점 키폼과 디포머로 움직이는 모델이다. 원화에 없는 뒷면을 복원하는 완전한 3D 재구성을 목표로 하지 않는다.

자료 확인일: **2026-09-21**. 외부 근거는 Live2D Cubism 공식 매뉴얼·튜토리얼, PixiJS 8 공식 문서, OpenCV 공식 투영 설명이다. Puppet 동작은 아래에 연결한 현재 소스로 확인했다.

## 근거를 읽는 방법

- **[A 공식 근거]**: 링크한 제품 문서가 직접 설명하는 내용이다. Cubism 기능을 Puppet이 그대로 구현한다는 뜻은 아니다.
- **[B Puppet 적용]**: 현재 코드로 확인한 계약 또는 공식 개념을 이 프로젝트에 적용한 설계다. 둘은 문장 안에서 구분한다.
- **[C 조정 기준]**: 처음 시도할 수치와 시각적 판단 기준이다. 공식 표준이나 모든 모델에 통하는 합격선이 아니다.

핵심은 세 가지를 분리하는 것이다. **그리는 순서**는 무엇이 무엇을 가리는지, **머리의 공통 변환**은 부품이 어디에 붙어 있는지, **국소 깊이**는 그 부품 안에서 어떤 면이 더 앞에 있는지를 결정한다. 같은 화면 위치에 보인다는 이유로 세 관계를 같게 취급하지 않는다.

## 1. 편집 전에 정할 것

### 사전 확인표

- [ ] 원본 모델과 중앙 자세를 보존하고, 이번 작업에서 바꿀 파트·키폼·속성을 적는다.
- [ ] 파라미터의 최소·기본·최대값, 축 부호, 모델 좌표와 화면 배율을 확인한다. 값 `30`을 실제 회전각 `30°`로 단정하지 않는다.
- [ ] 움직이는 파트의 알파 경계와, 움직일 때 드러날 뒤쪽 그림이 준비되어 있는지 확인한다.
- [ ] 실제 그리기 순서를 뒤→앞으로 기록한다. 레이어 이름만으로 앞뒤를 판단하지 않는다.
- [ ] 머리의 기준점과 각 부품의 부착 영역을 정한다. 뿌리 한 점뿐 아니라 좌우 폭을 가진 영역을 측정한다.
- [ ] 해당 부품이 따라갈 머리 변환, 자체 형태 변화, 물리 흔들림을 각각 구분한다.
- [ ] 키폼, 디포머, 글루, 물리 출력 중 같은 이동을 중복 적용하는 곳이 없는지 확인한다.
- [ ] 기본 자세·네 축 끝·네 모서리와 그 사이의 검사 방법을 정한다.
- [ ] 브라우저에서 저장된 모델을 다시 불러오는 경로와 동일 배율의 전후 비교 화면을 준비한다.

[A 공식 근거] 움직임으로 새로 드러날 부분은 소재 분리 단계에서 미리 그려야 한다. 자세히 나눈 레이어가 필요하더라도, 이 가이드에서는 독립된 움직임·가림·깊이가 필요한 경계를 우선한다. [Live2D 소재 분리](https://docs.live2d.com/en/cubism-editor-manual/divide-the-material/)

| 기준 | 기록할 내용                                                  | 잘못 잡았을 때 생기는 문제                 |
| ---- | ------------------------------------------------------------ | ------------------------------------------ |
| 형태 | 중앙 실루엣, 테두리 두께, 텍스처의 불투명 경계               | 메시는 이어져도 그림에는 틈이 생긴다.      |
| 부착 | 관자놀이·두피의 기준점, 부착 영역의 폭, 뒤에 받치는 머리카락 | 귀나 장식이 머리 위를 미끄러진다.          |
| 깊이 | 공통 뿌리 깊이와 내부 면의 상대 깊이, 앞에서 가리는 레이어   | 안쪽과 테두리가 한 장의 종이처럼 움직인다. |

## 2. 레이어 분리와 깊이 관계

[A 공식 근거] Cubism은 ArtMesh의 그리기 순서를 별도로 관리하며 이를 파라미터에 연결할 수 있다. PixiJS의 기본 장면 트리는 자식을 추가한 순서대로 그리므로 뒤에 추가한 자식이 앞에 겹친다. 두 제품의 설정 방법을 혼용하지 않는다. [Cubism Draw Order](https://docs.live2d.com/en/cubism-editor-manual/draworder/), [PixiJS Scene Graph](https://pixijs.com/8.x/guides/concepts/scene-graph)

[B Puppet 적용] Puppet은 [scene.ts의 `flattenNodes`·`getScenePartStates`](src/player/scene.ts)와 [create-player.ts의 `applyDocumentScene`](src/player/create-player.ts)을 통해 장면 순서대로 그린다. [parse-document.ts의 `isPartRenderProperties`](src/player/parse-document.ts)는 `drawOrder` 속성을 허용하지 않는다. Cubism의 숫자 그리기 순서나 렌더러의 별도 순서값을 JSON에 추가하지 않는다. 현재 장면 계층과 마스크를 기준으로 가림을 설계한다.

### 깊이 띠는 부위 이름이 아니라 겹침으로 정한다

아래는 [B Puppet 적용]을 위한 설계표다. 숫자로 고정된 해부학적 깊이표가 아니다.

| 부위             | 공통 움직임의 기준              | 깊이와 가림을 정하는 방법                                             |
| ---------------- | ------------------------------- | --------------------------------------------------------------------- |
| 두개골·얼굴 윤곽 | 머리의 기준 좌표계              | 머리 회전의 기준으로 삼되 표정으로 움직이는 점은 분리한다.            |
| 뒤통수·뒷머리    | 두피                            | 얼굴·귀 뒤에 받치는 면과 바깥 실루엣을 구분한다.                      |
| 옆머리           | 관자놀이·두피                   | 귀 뒤쪽 띠와 귀를 덮는 앞쪽 띠가 같은 이름일 수 있다.                 |
| 귀 뿌리          | 인접 두피의 부착 영역           | 뒤쪽 옆머리보다 조금 앞일 수 있다. 공통 깊이를 작게 둔다.             |
| 귀 안쪽·테두리   | 같은 귀 뿌리                    | 안쪽의 오목함과 테두리의 돌출을 별도로 만들되 접합부에서는 합친다.    |
| 앞머리           | 두피                            | 얼굴·귀를 가리는 구간을 유지하고 끝부분의 흔들림을 분리한다.          |
| 리본·꽃·핀·고리  | 실제로 부착된 머리카락이나 뼈대 | 장식 자체의 중심보다 고정점이 먼저다. 늘어진 끝만 별도 자유도를 준다. |

귀 안쪽이 테두리보다 뒤에 있어도 주변 머리카락보다 반드시 뒤라는 뜻은 아니다. 한 부품 내부의 깊이와 서로 다른 부품의 그리기 순서는 별개다. 단순 깊이값만으로 픽셀 단위 가림이 자동 해결되지는 않는다.

## 3. 얼굴 X/Y 키폼과 부착 계층

[A 공식 근거] Cubism의 얼굴 XY 튜토리얼은 부위별 디포머로 시차를 조절하고, X와 Y를 만든 뒤 대각선 형태도 확인하도록 안내한다. 가까운 쪽과 먼 쪽의 폭 차이를 고려하고, 정지한 끝 자세뿐 아니라 파라미터를 움직이는 과정도 확인한다. [얼굴 XY 튜토리얼](https://docs.live2d.com/en/cubism-editor-tutorials/xy/)

### 먼저 공통 머리 움직임을 만든다

[B Puppet 적용] 다음 순서로 작업한다.

1. 중앙 자세를 기준으로 좌·우·상·하에서 두피와 얼굴 윤곽이 어떻게 변하는지 정한다.
2. 코·관자놀이·귀 부착 영역처럼 역할이 다른 기준점을 구분한다. 눈썹이나 머리카락 끝처럼 독립적으로 움직이는 점만으로 두피를 추정하지 않는다.
3. 기준 부위를 따라 귀·옆머리·장식의 부착점을 이동시킨다.
4. 그 상태에서 내부 면의 깊이와 곡률을 추가한다.
5. 네 모서리 키폼을 만들고, 축과 모서리 사이를 왕복하며 수정한다.

[A 공식 근거] Cubism의 부모 디포머 변화는 자식에 전달되지만 자식 변화가 부모를 바꾸지는 않는다. 머리 전체 움직임과 국소 움직임을 다른 단계에 두는 근거다. [부모·자식 계층](https://docs.live2d.com/en/cubism-editor-manual/system-of-parent-child-relation/)

[B Puppet 적용] 장면의 그룹에 넣었다는 사실만으로 필요한 얼굴 파라미터 변형이 생기는 것은 아니다. 대상 바인딩·디포머 연결을 확인한다. 현재 예제는 얼굴 XY의 파트별 정점 배열을 저장하며, 장면 노드는 그룹과 파트로 구성되어 있다. 이 경우 공통 머리 변환을 각 파트 키폼에 같은 규칙으로 반영한다. 나중에 부모 디포머를 도입하면 이미 정점에 반영한 변환을 다시 적용하지 않는다.

### 3×3 키폼은 출발점이다

[A 공식 근거] Cubism의 네 모서리 자동 생성은 축 방향 형태를 바탕으로 대각선 형태를 만든다. 생성 뒤의 시각 조정까지 생략해도 된다는 기능은 아니다. [네 모서리 자동 생성](https://docs.live2d.com/en/cubism-editor-manual/synthesize-corners/)

[B Puppet 적용] [parameter-keyforms.ts의 `addTwoDimensionalParameter`](src/editor/internal/parameter-keyforms.ts)는 최소·기본·최대값의 조합으로 9개 키폼을 만든다. `insertParameterKeyform`은 현재 보간 결과에서 새 키폼을 만들며, 자체적으로 더 나은 입체 형태를 추정하지 않는다. 새 키를 추가한 뒤 목적에 맞게 형태를 수정해야 한다.

현재 [parameter.ts의 `sampleTwoDimensionalVertices`](src/deformation/parameter.ts)는 키폼 위치를 Delaunay 삼각분할하고, 해당 삼각형의 세 키폼을 무게중심 가중치로 보간한다. 정확한 키 위치에서는 그 키폼을 반환하고, 볼록껍질 밖에서는 가까운 외곽 선분을 사용한다. **3×3 배치여도 사각 셀의 쌍선형 보간이 아니다.**

```text
p(q) = λ₀(q)p₀ + λ₁(q)p₁ + λ₂(q)p₂
λ₀ + λ₁ + λ₂ = 1
```

파라미터 공간의 이 삼각형과 그림을 구성하는 메시 삼각형은 서로 다르다. 키를 추가하면 파라미터 공간의 삼각분할도 달라질 수 있으므로 인접 구간을 다시 검사한다. 조각별 선형 보간은 위치가 이어져도 삼각형 경계에서 움직임의 기울기가 달라질 수 있다. [B: `getTriangulation`·`getBarycentricWeights`·`sampleParameterVertices`](src/deformation/parameter.ts)

## 4. 머리 움직임과 깊이 시차를 계산하는 방법

### 좌표와 단위를 먼저 고정한다

[A 공식 근거] PixiJS의 `pivot`은 로컬 픽셀 좌표이고 Sprite의 `anchor`는 정규화된 기준점이다. 아래의 해부학적 부착점 `a`는 이 렌더러 속성들과 구분한다. 렌더러의 기준점만 바꾼다고 두피를 따라가는 변형이 자동으로 만들어지지는 않는다. [PixiJS Scene Objects](https://pixijs.com/8.x/guides/components/scene-objects)

[B Puppet 적용] 이 절의 식은 키폼을 설계하기 위한 모델이며, Puppet 런타임에 새 3D 엔진이 있다고 가정하지 않는다.

- `p=(x,y)`: 중앙 자세의 모델 좌표. 픽셀 수치는 모델 좌표의 px이며 CSS 화면 px와 다르다.
- `q=(u,v)`: 기본값을 0으로 정규화한 얼굴 입력. 최소·최대가 비대칭이면 양쪽 구간을 따로 정규화한다.
- `a`: 해당 부품의 머리 공간 부착점.
- `Hq(p)`: 입력 `q`에서 두피·머리 기준면이 `p`를 옮기는 공통 변환.
- `z₀`: 주변 기준면보다 부품 뿌리가 앞이나 뒤에 있는 공통 깊이.
- `zᵢ`: 뿌리를 기준으로 한 내부 면의 추가 깊이.
- `θ=θmax·u`, `φ=φmax·v`: 설계한 yaw·pitch 각도. 라디안을 사용한다.

여기서는 화면 오른쪽을 `+x`, 아래쪽을 `+y`, 화면 앞쪽을 `+z`로 두고 아래 식의 회전 부호를 정의한다. 입력 장치나 원화의 방향이 다르면 부호를 대응시킨다.

[A 공식 근거] Cubism의 3D 회전 보조 기능도 회전 중심, 회전 전 Z 오프셋, 원근 강도, 회전 범위를 별도로 다룬다. 원근 강도 0은 평행 투영이며, 회전 순서는 모서리 형태에 영향을 준다. 이것은 개념적 근거이고 아래 계수의 출처는 아니다. [3D 회전 설정](https://docs.live2d.com/en/cubism-editor-manual/apply-3d-rotation-expression-settings/)

### 단계 1: 머리 변환 H를 정한다

[B Puppet 적용] 디포머가 권위 있는 머리 변환을 제공하면 그것을 사용한다. 기존 정점 키폼만 있다면 인접 두피·옆머리의 대응점으로 근사한다.

```text
Hq(p) = p + B(p)cq
cq = argmin_c Σⱼ wⱼ ‖pⱼ + B(pⱼ)c − p'ⱼ(q)‖²
```

`B`는 정규화한 좌표의 기저다. 이동·회전·크기를 설명할 수 있는 작은 모델부터 시작한다. 단순 유사변환이나 아핀변환으로 오차가 충분히 작다면 고차 다항식으로 바꾸지 않는다. 표본이 많은 레이어 하나가 추정을 독점하지 않도록 레이어별 가중치를 맞추고, 적합에 사용하지 않은 기준점에서도 오차를 확인한다. 굽은 두피를 표현하기 위해 차수를 높일 때는 외삽 영역과 국소 왜곡을 함께 검사한다. 이 선택은 모델별 설계 판단이며 공식 Cubism 알고리즘의 재현이 아니다.

### 단계 2: 평면 회전과 깊이 차이를 중복 적용하지 않는다

평행 투영에서 yaw 후 pitch를 적용하는 다음 좌표 모델을 사용한다고 하자.

```text
X = x cosθ + z sinθ
Z = −x sinθ + z cosθ
Y = y cosφ − Z sinφ
```

같은 `(x,y)`의 깊이 0인 점과 깊이 `z`인 점의 차이는 다음과 같다.

```text
Δ(q,z) = (z sinθ, −z sinφ cosθ)
```

[B Puppet 적용] 이는 위 회전식에서 직접 도출한 **깊이 차이의 평행 투영**이다. 이미 `Hq`가 머리의 이동·압축·기울기를 포함한다면 `Hq(p)`에 전체 회전식을 다시 적용하지 않고 `Δ`만 더한다. 공통 변환과 국소 깊이의 역할을 섞으면 뿌리가 미끄러지거나 머리 움직임이 두 번 적용된다.

실제 원근 투영이 필요한 경우에는 카메라 공간으로 옮긴 뒤 `u=fx·Xc/Zc+cx`, `v=fy·Yc/Zc+cy`로 투영하는 별도 모델을 선택한다. 이 경우 카메라의 깊이축·거리·단위를 새로 정의해야 한다. `Hq` 위에 근거 없는 원근 배율을 추가하지 않는다. [A: OpenCV의 카메라 투영식](https://docs.opencv.org/4.13.0/d9/d0c/group__calib3d.html)

### 단계 3: 부착점과 내부 깊이를 분리한다

```text
r(q) = Hq(a) + Δ(q,z₀)
p'ᵢ(q) = r(q) + [Hq(pᵢ) − Hq(a)] + wᵢ Δ(q,zᵢ)
```

[B Puppet 적용] 모든 하위 파트는 같은 `a`, `Hq`, `z₀`를 공유한다. 뿌리에서 `w=0`으로 두면 안쪽과 테두리는 같은 기준점을 따르면서 위쪽에서만 다른 깊이를 보인다. 머리보다 조금 앞에 붙은 귀라면 `z₀>0`일 수 있다. 따라서 뿌리와 옆머리의 상대 이동을 무조건 0으로 만드는 것이 목표는 아니다. **의도한 `Δ(q,z₀)`를 뺀 잔차**가 작아야 한다.

```text
t = clamp(부착 영역에서 떨어진 거리 / 전이 폭, 0, 1)
w(t) = t²(3−2t)
```

[B Puppet 적용] 이 가중치는 양 끝에서 기울기가 0이므로 부착 영역에서 국소 변형을 점진적으로 켜는 데 쓸 수 있다. 복잡한 뿌리는 단순한 y 좌표 대신 부착 곡선까지의 거리나 메시 가중치로 정의한다. 특정 정점 하나만 고정하고 바로 옆 정점을 크게 움직이는 형태는 피한다.

### 단계 4: 볼륨은 위치마다 다른 깊이로 만든다

[B Puppet 적용] 안쪽 전체를 일정량 이동하는 것만으로 오목함이 생기지는 않는다. 예를 들어 폭 방향 정규 좌표 `s∈[−1,1]`, 길이 방향 `t∈[0,1]`에서 다음을 출발점으로 삼을 수 있다.

```text
안쪽: zinner(s,t) = −dinner · (max(0,1−s²))² · sin(πt)
테두리: zrim(s,t) = +drim · b(s,t)
```

`b`는 실제 말린 테두리 주변에서만 값을 갖는 부드러운 함수다. 텍스처의 접합 경계에서는 두 면의 투영 위치가 맞도록 깊이·가중치를 함께 조정한다. 오목면의 중앙과 테두리에 서로 다른 변위를 주면 곡률과 상대 압축이 생긴다. 그림자·명암이 이미 그려진 원화에서는 그 단서와 변형 방향도 맞아야 한다.

[A 공식 근거] Cubism의 3D 회전 보조 기능은 평면 회전 형태와 깊이를 추정한 형태를 구분하며, 기본 자세가 아닌 키폼에서 깊이를 추정한다. 자동 생성은 기존 키폼을 덮어쓸 수 있으므로 기존 작업의 보존 범위를 먼저 확인한다. [3D 회전 표현 적용](https://docs.live2d.com/en/cubism-editor-manual/apply-3d-rotation-expression/)

### 단계 5: 키폼으로 저장하고 실제 보간으로 다시 평가한다

[B Puppet 적용] 계산식은 각 키폼을 만드는 데 사용하고, 그 사이의 결과는 [Puppet의 `sampleParameterVertices`](src/deformation/parameter.ts)로 검사한다. 키폼 생성식의 `sin` 값을 중간 자세마다 직접 계산한 결과와 런타임의 삼각형 보간 결과는 같다고 보장되지 않는다. 둘의 차이가 눈에 보이면 키폼 형태·위치를 조정한다.

## 5. 시작 수치와 확대·축소 기준

이 절은 모두 **[C 조정 기준]**이다. Live2D·PixiJS 공식 권장 수치가 아니다. `L`은 부품의 긴 변 길이, `W`는 폭, `m`은 모든 검사 자세에서 남는 실제 불투명 겹침 여유다. 변환된 화면에서 비교할 때는 세 값 모두 같은 배율로 환산한다.

| 항목                                | 처음 시도할 범위                    | `L=600px` 예시                             |
| ----------------------------------- | ----------------------------------- | ------------------------------------------ |
| 뿌리의 최대 공통 시차               | `0.002L…0.006L`, 동시에 `m/4` 이하  | 1.2…3.6px                                  |
| 내부 면·테두리의 상대 시차          | `0.01L…0.05L`에서 시작              | 6…30px                                     |
| 국소 변형을 켜는 전이 폭            | `0.15L…0.5L`                        | 90…300px                                   |
| 의도한 깊이 이동을 제외한 부착 잔차 | 우선 `0.002L` 이하, 화면에서 재판단 | 약 1.2px 이하                              |
| yaw·pitch 설계 범위                 | 원화가 허용하면 약 10…25°부터       | 모델 크기와 무관하며 실제 입력 범위와 별도 |

시차 목표 `d`를 정한 뒤 `z≈d/|sinθmax|`로 깊이를 역산하면 과도한 값을 피하기 쉽다. `θmax`가 0에 가까울 때 이 역산을 쓰지 않는다. 좌우·상하가 동시에 최대일 때의 벡터 길이도 계산한다.

폭이 좁은 고리·핀·테두리는 `L` 기준보다 `W`와 겹침 여유가 먼저 제한한다. 테두리의 최소 폭이 중앙 자세의 절반 아래로 줄어들면 우선 점검하되, 의도한 강한 측면 자세인지 확인한 뒤 판단한다. 크기를 바꾸면 깊이와 허용 잔차도 함께 바꾸고, 축소된 실제 표시 크기에서 효과가 보이는지 확인한다.

## 6. 메시·디포머·글루를 선택하는 기준

[A 공식 근거] ArtMesh는 정점을 움직여 텍스처를 변형한다. PixiJS `MeshGeometry`도 위치·UV·인덱스를 별도로 다룬다. 정점 수만 늘리면 형태가 좋아진다고 보장할 수 없다. [Cubism ArtMesh](https://docs.live2d.com/en/cubism-editor-manual/concept-of-artmesh/), [PixiJS Mesh](https://pixijs.com/8.x/guides/components/scene-objects/mesh)

[B Puppet 적용] 부착선, 접힘선, 실루엣, 테두리의 양쪽 경계에 변형을 설명할 정점이 있는지 먼저 본다. 긴 삼각형 하나가 뿌리와 끝부분의 서로 다른 변형을 가로지르면 그 사이를 조절하기 어렵다. 국소 깊이 함수를 적용하기 전에 메시가 그 곡률을 표현할 수 있는지 확인한다. 형태만 바꾸는 작업에서는 UV·인덱스·정점 순서를 유지하고 키폼 정점을 수정한다. 토폴로지를 바꾸면 모든 키폼·스키닝·글루 참조를 다시 검증한다.

[A 공식 근거] 큰 회전을 정점의 선형 이동으로 보간하면 중간 형태가 줄어들 수 있다. Cubism은 형태를 유지하는 회전에 회전 디포머를 쓰도록 설명한다. [디포머와 선형 보간](https://docs.live2d.com/en/cubism-editor-manual/deformer/)

[B Puppet 적용] 단단한 장식의 큰 회전은 회전 디포머를 검토하고, 휘거나 찌그러지는 귀·머리카락은 메시 또는 워프 변형을 검토한다. 귀 전체의 공통 변환과 안쪽의 오목함을 하나의 무분별한 정점 이동으로 해결하지 않는다. 부모 변형과 파트 정점에 같은 회전이 중복되지 않도록 한다.

### 글루는 접합을 위한 제약이다

[A 공식 근거] Cubism 글루는 두 ArtMesh의 겹치는 정점을 연결한다. 문서상 가중치는 정점별로, 접합 효과의 강도는 키폼별로 조절한다. [Cubism Glue](https://docs.live2d.com/en/cubism-editor-manual/glue/)

[B Puppet 적용] [parameter-glue.ts의 `sampleParameterGlue`·`composeParameterGlue`](src/deformation/parameter-glue.ts)는 첫 번째 파트에 저장한 글루 키폼에서 `weight`와 `strength`를 샘플링한다. 이는 Cubism 설정과 동일한 계약이 아니다. [glue.ts의 `applyGlue`](src/deformation/glue.ts)는 정점 쌍 또는 정점과 간선의 접합을 처리하며, 플레이어에서는 [장면 디포머 적용 후 글루를 적용](src/player/internal/scene-deformation.ts)한다.

연결되어야 하는 테두리의 위치를 맞추는 데 글루를 쓴다. 앞뒤로 떨어진 표면의 시차까지 모두 없애거나 잘못된 머리 기준점을 강제로 감추는 데 쓰지 않는다. 글루 적용 전후의 메시를 모두 검사해야 접합 강도가 주변 삼각형을 뒤집는지 알 수 있다. 현재 예제에는 글루 데이터가 없으므로, 같은 머리 변환과 공통 깊이를 공유하는 방식으로 접합을 유지한다.

## 7. 가림·클리핑·물리 흔들림

### 가림은 최종 텍스처로 확인한다

[A 공식 근거] Cubism 클리핑은 마스크로 사용할 ArtMesh를 지정해 다른 ArtMesh의 표시 영역을 제한한다. PixiJS도 마스크를 통해 표시 영역을 제한한다. [Cubism 클리핑](https://docs.live2d.com/en/cubism-editor-manual/clipping-mask/), [PixiJS 마스크](https://pixijs.com/8.x/guides/components/scene-objects#masking-scene-objects)

[B Puppet 적용] [create-player.ts의 `createRuntimePartMask`](src/player/create-player.ts)는 소스 파트의 텍스처·UV·변형 정점을 사용하고 알파 채널로 마스킹한다. [render-plan.ts의 `createPartMaskPlan`](src/player/internal/render-plan.ts)에서 중첩 관계도 확인한다. 투명한 픽셀이 포함된 삼각형 내부에 있다는 이유만으로 가림이 유지된다고 판단하지 않는다.

접촉 영역의 표본을 최종 변형 좌표로 옮기고, 그 위치를 가리는 파트의 UV로 역변환해 알파를 확인한다. CPU의 최근접 픽셀 검사와 GPU의 필터링·안티앨리어싱은 다를 수 있으므로 브라우저 확대 화면을 마지막 근거로 삼는다. 한 파트가 자세에 따라 다른 파트의 앞뒤를 오가야 한다면 고정 순서로 표현 가능한지 먼저 판단한다. 불가능한 경우 파트 분리·마스크·별도 모델 상태가 필요한 설계 문제로 남긴다.

### 물리 흔들림으로 자세 오류를 가리지 않는다

[A 공식 근거] Cubism 물리는 입력 파라미터, 진자 모델, 출력 파라미터를 구분하며 얼굴 움직임에 따른 머리카락 흔들림을 만든다. 계산 주기와 설정에 따라 결과가 달라진다. [Cubism Physics](https://docs.live2d.com/en/cubism-editor-manual/physics-operation/)

[B Puppet 적용] 먼저 물리를 끈 정적인 얼굴 XY 형태를 완성한다. 이후 머리카락 끝·귀 끝·늘어진 장식에 지연과 흔들림을 추가하되 고정점을 공유한다. [create-player.ts의 `applyRuntimeFrame`](src/player/create-player.ts)은 모션 파라미터와 물리를 평가한 뒤 정점·디포머·글루를 적용한다. 같은 출력 파라미터에 자세와 흔들림을 겹칠 경우 합성 계약을 확인한다. 현재 예제에 물리 데이터가 없다는 사실과 Puppet 런타임이 물리를 지원한다는 사실을 구분한다.

## 8. 좌우 대칭과 의도한 비대칭

[B Puppet 적용] 중앙선 `x=c`의 반사 `M(x,y)=(2c−x,y)`를 정하고, 좌측 `q=(u,v)`와 우측 `q*=(-u,v)`를 비교한다. 메시 정점 수가 다르면 같은 인덱스를 비교하지 말고 대응하는 위치를 면 안에서 보간한다.

```text
전체 형태 비교: p'R(q*, M(p)) ≈ M(p'L(q,p))
추가 보정 비교: δR,x(q*) ≈ −δL,x(q),  δR,y(q*) ≈ δL,y(q)
```

원화·머리 변환에 이미 비대칭이 있으면 두 번째 비교로 보정 규칙의 대칭을 먼저 검증한다. 전체 형태의 차이는 원본 차이와 새로 생긴 차이로 나눠 보고한다. 장식 위치·가르마·표정처럼 의도한 비대칭을 억지로 지우지 않는다. 공식 도구에도 깊이 추정을 대칭화하는 선택지가 있지만, 이 모델의 어느 비대칭을 보존할지는 작업자가 정해야 한다. [A: Cubism 깊이 대칭 설정](https://docs.live2d.com/en/cubism-editor-manual/apply-3d-rotation-expression-settings/)

## 9. 귀에 적용하는 계산 예

이 예는 현재 모델에서 사용한 접근을 일반화한 **[B Puppet 적용]**이며, 각도·깊이·감쇠 범위는 **[C 조정 기준]**이다. 다른 모델에 숫자를 그대로 복사하지 않는다.

1. 길이 약 `L=600px`인 귀를 안쪽·테두리·뿌리로 분리한다. 세 파트의 중앙 형태와 텍스처는 유지한다.
2. 귀 뒤의 두피·옆머리에서 `Hq`를 정하고, 귀 뿌리의 안쪽 영역에 기준점 `a`를 잡는다. 앞으로 가리는 머리카락의 경계도 따로 기록한다.
3. 머리 변환 위에 더할 각도를 `θmax=0.42rad`, `φmax=0.30rad`로 가정한다. 이 각도는 깊이 시차 계산용이며 `±30` 파라미터가 물리적으로 30도를 뜻한다는 주장이 아니다.
4. 뿌리 공통 깊이를 `z₀=6px`로 두면 yaw 끝에서 약 `±2.45px`, pitch 끝에서 약 `±1.77px`, 두 축 끝의 조합에서 약 `2.93px`의 시차가 생긴다.
5. 안쪽은 오목한 깊이, 테두리는 볼록한 깊이를 부여한다. 예를 들어 최대 계수 `dinner=80px`, `drim=30px`를 감쇠 함수와 곱하되, 접합 영역에서는 추가 깊이를 0으로 만든다. 최대 계수와 실제 정점 이동량은 다르므로 투영 결과를 측정한다.
6. 공통 `Δ(q,z₀)`는 세 파트에 똑같이 더한다. 공통 시차를 늘리는 것과 귀 내부의 곡률을 바꾸는 작업을 분리한다.
7. 9개 키폼을 만든 뒤 실제 삼각형 보간, 최종 합성, 알파 겹침, 브라우저 동작 순서로 확인한다. 문제가 생기면 뿌리의 공통 깊이부터 줄일지, 내부 깊이·전이 폭을 바꿀지 원인별로 결정한다.

현재 [예제 파일](examples/development-model.json)의 귀 길이는 596 모델 px이며, 얼굴 XY는 9개 키폼으로 저장되어 있다. `H`·깊이 함수·위 계수가 별도 런타임 속성으로 저장된 것은 아니다. JSON의 권위 있는 결과는 키폼 정점 배열이다. 예제를 재생성한다면 계산에 사용한 모델별 좌표와 설정을 별도로 남겨야 한다.

문서 작성 시 실제 [샘플러](src/deformation/parameter.ts)를 직접 호출해 현재 귀 여섯 파트를 21×21 자세로 검사했다. 삼각형 339,570회에서 뒤집힘은 0회였고, 최소 면적 비율은 약 0.4569였다. 이 결과는 정점 보간과 메시 방향 검사에 한정된다. 최종 픽셀 겹침, 전체 실루엣, 브라우저에서의 자연스러움까지 통과했다는 뜻은 아니다. 예전에 다른 보간식으로 얻은 수치를 런타임 검증 결과로 옮겨 적지 않는다.

## 10. 검증 행렬과 판정

### 수치의 의미

[B Puppet 적용] 중앙 자세의 삼각형 정점을 `a,b,c`, 변형 후를 `a',b',c'`라 하면 방향과 면적 비율을 다음처럼 계산한다.

```text
A₀ = cross(b−a, c−a)
Aq = cross(b'−a', c'−a')
면적 비율 = Aq / A₀
부착 잔차 e(q) = ‖관측한 뿌리(q) − 기준 머리점(q) − 의도한 깊이 시차(q)‖
```

`A₀=0`인 원본 삼각형은 별도 결함으로 보고한다. `Aq/A₀≤0`이면 퇴화 또는 뒤집힘이다. 같은 삼각형끼리 비교하므로 면적의 1/2 계수는 생략해도 된다. 단순 깊이 차이 자체를 부착 오류로 집계하지 말고, 의도한 시차와 잔차를 함께 보고한다.

### 검사 조합

| 검사      | 자세·조건                                     | 기록할 증거                                                        |
| --------- | --------------------------------------------- | ------------------------------------------------------------------ |
| 저장 범위 | 변경 전후 JSON                                | 바뀐 파트·배열·키폼, 중앙 보존, 정점 수, 유한 좌표, UV·인덱스 보존 |
| 보간      | 실제 샘플러의 21×21 격자부터 시작             | 각 파트의 뒤집힘 수, 최소 면적 비율, 최악의 입력값                 |
| 경계      | 파라미터 삼각형의 경계 양쪽·중심·축 끝·모서리 | 위치 연속성, 속도 변화, 좌우 반전, 국소 압축                       |

21×21은 [C 조정 기준]인 초기 표본 수다. 모든 연속 입력에 대한 수학적 보장이 아니다. 여유가 작거나 기울기가 급한 구간은 표본을 촘촘히 늘리고, 필요하면 파라미터 삼각형 내부의 면적 함수 최솟값을 별도로 분석한다. 키폼만 정상이라고 중간 자세도 정상인 것은 아니다.

### 완료 기준

| 구분                 | 판정 기준                                                                                                              |
| -------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| 데이터 필수 조건 [B] | 허용한 범위만 변경. 중앙 보존이 요구되면 정확히 보존. 유한 좌표·정점 대응·참조가 유효함                                |

| 기하 여유 [C]        | 면적 비율이 0.2 아래이면 우선 재검토. 양수라는 사실만으로 자연스러움을 판정하지 않음                                   |

수치가 통과해도 브라우저에서 종이처럼 보이면 완료가 아니다. 반대로 의도한 얇은 측면 표현을 면적 비율 하나만으로 결함으로 단정하지 않는다. 같은 배율·같은 입력·같은 물리 상태에서 전후를 비교한다.

## 13. 근거의 범위와 남은 판단

공식 문서는 부위별 시차, 회전 중심, 깊이, 디포머 계층, 글루, 마스크, 물리를 설명한다. 어떤 캐릭터의 귀 뿌리를 몇 px 앞에 놓아야 하는지, 면적 비율이 얼마여야 자연스러운지까지 정해 주지는 않는다. 이 문서의 깊이 함수·적합법·검사 임계값은 Puppet용 설계와 조정 기준이다.

Cubism의 숫자 그리기 순서, 글루 가중치 제약, 3D 회전 보조 기능은 Puppet과 다르다. 서로 모순된 지침이라기보다 제품별 기능 계약의 차이다. 원화 한 장만으로 실제 깊이는 유일하게 결정되지 않으며, 큰 회전에서 드러나는 면이 없으면 메시 변형만으로 해결할 수 없는 구간도 있다. 해당 구간은 추가 그림이나 다른 표현 설계가 필요하다고 기록한다.

문서나 수치 검사로 확인한 것과 실제 브라우저에서 확인한 것을 결과 보고에서 분리한다. 검증 기록에는 모델 식별값, 샘플러, 자세 범위, 카메라 배율, 물리 상태, 수치 결과, 전후 화면을 함께 남긴다.
