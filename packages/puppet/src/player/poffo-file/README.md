# Poffo v1 파일 규격

웹과 외부 SDK가 공유하는 `.poffo` 컨테이너다. 문서 모델은 기존 `PuppetDocument`이며 컨테이너 버전과 문서의 `version`은 독립적이다. 기존 SDK의 `POFO` 형식과 `.json.br`는 이 규격에 포함하지 않는다. 일반 JSON 입출력은 유지한다.

## 컨테이너

모든 정수와 IEEE 754 부동소수점 값은 little endian이다. MIME은 `application/vnd.poffo`다. 정렬 패딩은 없다.

| 바이트 오프셋 | 형식     | 내용                                        |
| ------------- | -------- | ------------------------------------------- |
| 0             | 8 bytes  | `50 4f 46 46 4f 0d 0a 1a` (`POFFO\r\n\x1a`) |
| 8             | u16      | 컨테이너 버전 `1`                           |
| 10            | u16      | 플래그 `0`                                  |
| 12            | u32      | 인덱스 바이트 길이                          |
| 16            | u32      | 메타데이터 코덱                             |
| 20            | u32      | 저장된 메타데이터 길이                      |
| 24            | u32      | 해제된 메타데이터 길이                      |
| 28            | u32      | 자산 수                                     |
| 32            | 32 bytes | 저장된 인덱스의 SHA-256 원시 바이트         |

64바이트 헤더 뒤에 **인덱스 → 메타데이터 → 인덱스 순서의 자산**을 연속 저장한다. 각 길이는 바이트 단위이며 u32 범위다. 파일 전체 길이는 헤더와 모든 구간 길이의 합과 정확히 같아야 한다.

인덱스는 UTF-8 JSON이다. 키 순서·공백은 의미가 없으며 체크섬은 파싱·재직렬화한 결과가 아닌 저장된 바이트로 계산한다.

```json
{
  "assets": [
    {
      "codec": 0,
      "decodedLength": 4,
      "encodedLength": 4,
      "prefix": "data:audio/wav;base64,",
      "sha256": "소문자 16진수 SHA-256 64자리"
    }
  ],
  "metadataSha256": "소문자 16진수 SHA-256 64자리"
}
```

코덱 `0`은 원시 바이트, `1`은 독립된 Brotli 스트림이다. 코덱 0은 저장 길이와 해제 길이가 같다. 메타데이터와 각 자산을 각각 압축하며, 현 인코더는 품질 9로 압축한 결과가 더 작을 때만 코덱 1을 선택한다. 압축 품질과 출력 바이트 일치는 상호 운용 조건이 아니다. 디코더는 두 코덱을 모두 지원해야 한다.

`metadataSha256`과 자산의 `sha256`은 각각 **저장된 구간 바이트**의 SHA-256이다. 알 수 없는 버전·플래그·코덱, 잘못된 인덱스, 자산 수 불일치, 체크섬 불일치, 해제 길이 불일치, 부족하거나 남는 바이트를 거부한다. 체크섬은 손상 검출용이며 작성자를 인증하지 않는다.

## 메타데이터 값

해제된 메타데이터는 아래 값 하나다. 각 값은 1바이트 태그로 시작한다. `length`와 모든 참조는 u32이며 숫자 배열 길이는 원소 수다.

| 태그 | 형식                                                                           |
| ---- | ------------------------------------------------------------------------------ |
| 0    | null                                                                           |
| 1    | false                                                                          |
| 2    | true                                                                           |
| 3    | UTF-8 바이트 길이 + 문자열 바이트; 문자열 사전에 추가                          |
| 4    | 문자열 사전 인덱스; 사전에 추가하지 않음                                       |
| 5    | f64 스칼라                                                                     |
| 6    | length + f64 배열                                                              |
| 7    | length + u32 배열                                                              |
| 8    | length + f32 배열                                                              |
| 9    | length + 재귀적 값 배열                                                        |
| 10   | 자산 인덱스; 복원한 data URL을 문자열 사전에 추가                              |
| 11   | 쌍 수 + (문자열 키 값, 내용 값) 반복                                           |
| 12   | UTF-8 바이트 길이 + JSON 문자열 리터럴 바이트; JSON 해석 후 문자열 사전에 추가 |
| 13   | length + u8 배열                                                               |
| 14   | length + u16 배열                                                              |
| 15   | length + i32 배열                                                              |

문자열 사전은 비어 있는 상태에서 시작하며 키와 값이 공유한다. 태그 3·10·12를 만날 때마다 그 문자열을 순서대로 추가한다. 사전이나 자산의 아직 존재하지 않는 인덱스는 오류다. 태그 12는 단독 UTF-16 서로게이트를 손실 없이 표현한다. UTF-8은 엄격하게 검증하며 문자열 첫 U+FEFF도 값으로 보존한다.

객체 키는 문자열이어야 하며 중복 키는 오류다. `__proto__`도 일반적인 자체 키로 취급한다. NaN·Infinity는 허용하지 않는다. 음수 0, 서브노멀, f64 정밀도를 보존한다. 인코더는 숫자 배열을 정확하게 왕복할 수 있는 가장 작은 표현으로 저장한다. 디코더는 태그에 명시된 표현을 그대로 해석하며 임의 반올림하지 않는다. 빈 배열은 태그 9다.

루트 깊이는 0이며 최대 깊이는 256이다. 메타데이터 마지막 값 이후 남는 바이트도 오류다. 인덱스나 배열 길이만 믿고 메모리를 할당하지 말고 실제 남은 바이트와 해제된 길이를 검증해야 한다.

## 자산과 문서 보존

정규 base64 data URL을 자산으로 추출하며 원래 prefix와 해제한 원본 바이트를 저장한다. 읽을 때 `prefix + 표준 패딩 포함 base64`로 복원한다. 정규 base64로 재인코딩했을 때 문자열이 달라지는 URL은 일반 문자열로 유지한다. 같은 문자열의 반복은 문자열 참조로 표현한다. 이미지·오디오를 재인코딩하거나 손실 압축하지 않는다.

문서는 기존 JSON 내보내기와 같은 [정규화](../get-export-document.ts)를 거친다. 메시·장면 정리와 텍스처 중복 제거 후의 문서를 보존하며 입력 객체를 수정하지 않는다. 알 수 없는 문서 필드도 값으로 보존한다. JSON과 마찬가지로 객체의 undefined 필드는 생략하고 배열의 undefined·빈 슬롯은 null로 저장한다. 함수·BigInt·순환 참조는 거부한다.

공개 API는 [serializePoffoDocument](../serialize-poffo-document.ts)와 [parseDocumentBlob](../parse-document-blob.ts)이다. 브라우저 내보내기는 Worker를 사용하며 완료·실패·취소 때 Worker와 리스너를 정리한다. 취소된 결과는 다운로드하지 않는다. 불러오기는 기존 문서 준비 Worker 경로를 사용한다.

## SDK 상호 운용 예제

[fixtures](./__tests__/fixtures/)의 `document.json`은 기대 문서다. `raw.poffo`는 모든 구간이 원시 바이트이며 `compressed.poffo`는 압축 메타데이터와 원시 자산을 포함한다. 두 파일은 같은 문서로 복원되어야 한다. JSON에서 `authoring.float32[1]`은 표기상 0이지만 바이너리의 기대 값은 **음수 0**이다. 단독 서로게이트·BOM·정수 경계·서브노멀·최대 f64·반복 문자열·이미지·오디오를 포함한다.

다른 SDK에서는 두 예제의 읽기부터 검증한 뒤, 같은 문서를 저장하여 웹에서 다시 읽는다. 압축 결과나 객체 키 순서가 달라도 문서 값과 자산 바이트가 같으면 호환된다.
