# 프레임 선계산

`createPlayer({buffering: true, randomSeed: 42, ...})`로 선택한다. 기본값은 `false`다. Poffo Viewer의 기본값·설정 저장·UI는 앱이 소유한다.

```ts
await configurePlayerBuffering(player, {enabled: true})
player.patchParameterValues(values)
const result = await flushPlayerInputs(player)
if (result === 'applied') {
  const displayed = player.getParameterValues()
}
```

설정 완료는 첫 화면 제출 완료와 다르다. `getPlayerBufferingInfo` 또는
`onBufferingChange`로 실제 상태를 확인한다. `enabled`는 요청한 설정이며 `framesAhead`는
최대 용량으로, 현재 대기 중인 프레임 수가 아니다. 겹친 설정은 마지막 요청이 우선한다.
다른 `Player` 구현에 대한 설정·입력 대기는 `unavailable`을 반환한다.

## 입력과 조회

버퍼가 꺼져 있으면 기존 동기 계산을 유지한다. 켜져 있으면 명령의 검증·접수 결과와 예외는
동기로 반환하고, 수치 계산은 Worker에서 진행한다. 파라미터·블렌드·시선·입 모양뿐 아니라
표정·투명도·파트 속성·물리 설정·타임라인·문서 변경·추가 모션 핸들도 같은 입력 경로를 사용한다.

메인은 마지막으로 제출한 체크포인트와 아직 반영하지 않은 제어 값만 보관한다. Worker가
효과·물리·포즈·디포머·Glue·표시 계획을 계산하며, 메인은 같은 프레임을 다시 계산하지 않는다.
GPU 리소스·텍스처·카메라·화면 제출은 메인에 남는다. 원본 리그를 굽거나 수정하지 않는다.

메인은 템플릿과 색상 값이 같은 파트의 표시 속성을 재사용해 필터를 불필요하게 다시 지정하지
않는다. 수치 값은 프레임별로 보관하며, 값이나 템플릿이 바뀌면 새 속성을 만들어 대기 중인
이전 프레임을 유지한다.

조회값·표정·hitTest는 마지막으로 제출한 프레임을 기준으로 한다. 명령 직후에 새 계산 결과가
필요하면 `flushPlayerInputs`를 기다린다. 반환값 `applied`는 호출 시점까지 접수한 제어 값이
화면 제출에 반영됐다는 뜻이며 GPU 표시 완료를 뜻하지 않는다. 더 최신 입력이 앞선 값을
대체할 수 있으므로 모든 중간 입력이 각각 표시된다는 보장은 없다. 문서 교체는 기존 대기를
`superseded`, 종료는 `destroyed`로 끝낸다. 숨겨진 탭의 대기는 다시 표시될 때까지 유지한다.

## 큐와 수명

입력이 없으면 최대 세 프레임을 앞서 계산한다. 화면 주기로 다음 시각을 예측하고, 계산이 늦으면
실제 경과 시간을 반영한다. 과거 응답 지연을 이후 프레임 간격으로 유지하지 않는다. 큐 보충은
화면 제출과 겹쳐 실행하며, 새 입력은 제출한 체크포인트를 기준으로 계산한다.
입력이 들어오면 대기 중인 예측은 해제하고, 이미 계산 중인 유효한 프레임은
활용한다. 완료한 입력은 더 최신 입력이 와도 제출하여 연속 입력 중 표시가 멈추지 않게 한다.
제출 후 최신 제어 값과 원래 물리 체크포인트로 다음 프레임을 계산한다. 기존 제어 필드는
최신 값 하나만 보관한다. 추가 모션은 ID별 상태를 보관하며, 정지한 ID의 대기 정보는 수신
확인 후 해제한다. 정지 중 입력은 시간 증가 없이 한 번
계산하며, 세 프레임 재충전을 기다리지 않는다.

모션 오디오·이벤트·완료 콜백·자동 눈 깜박임·독립 추가 모션을 사용해도 Worker를 유지한다.
오디오 파일이 문서에 있다는 이유로 계산 경로를 바꾸지 않는다. `unsupported`는 Worker 또는
화면 갱신 API가 없는 실행 환경에만 해당한다. Worker 생성·실행 실패는 `error`로 알리고
미반영 입력을 로컬 경로에 반영한다. 명시적으로 다시 켜면 재시도한다.

## 난수·오디오·알림

함수를 받던 `random` 옵션은 제거했다. `randomSeed`에 유한한 수를 주면 난수 상태를
체크포인트와 함께 전달한다. 같은 seed·입력·시간 간격으로 재현할 수 있다. 생략하면 생성 시
seed를 한 번 선택한다. 예측을 취소해도 난수 상태를 해당 체크포인트로 되돌린다.

WAV 로딩·실제 오디오 출력은 호스트가 소유한다. 디코딩한 수치 샘플을 Worker에 전달하고,
Worker에서 해당 모션 시각의 RMS·입 모양을 분석한다. 실제 소리는 제출한 프레임의 모션 시각에
맞춰 메인에서 재생·정지한다. 선계산 시점에 AudioNode나 사용자 콜백을 실행하지 않는다.

이벤트와 완료 알림은 순번을 가진 데이터로 전달한다. 메인이 수신을 확인할 때까지 Worker가
보관하므로 예측 큐를 해제해도 누락하지 않고, 같은 알림을 두 번 실행하지 않는다. 모션 이벤트·완료·프레임
콜백의 예외는 일반 호스트 예외로 전달하며 Worker 장애로 처리하지 않는다.

추가 모션 핸들의 숫자 `id`는 해당 Player 내에서 유지한다. 핸들의 정지·탐색·가중치·배속도
버전별 입력으로 전달한다. `getState()`는 최근 수신한 계산 시각과 접수한 제어 값을 반환한다.
화면 반영까지 기다리려면 동일하게 `flushPlayerInputs`를 사용한다.

숨겨진 탭은 큐를 해제하고 `idle`이 되며, 표시되면 재개한다. 끄기·문서 교체·종료는 Worker를
해제하고 늦은 응답을 무시한다. 끄기는 아직 반영되지 않은 제어 값도 기존 경로에 적용한다.
