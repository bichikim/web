# Playback Wasm

By default, the library's [JavaScript Worker](../../buffering/worker.ts) runs playback, effects, audio analysis, physics, Glue, render planning and checkpoints through the JavaScript buffer engine. It loads the [deformation kernel](./deformation/README.md) for numeric geometry work. Unsupported geometry or unavailable Wasm retains the JavaScript evaluator inside the Worker.

The boundary passes numeric buffers and interpolation descriptors to Wasm; it does not serialize a complete frame and checkpoint through JSON on every step. Both implementations retain the existing host/Worker message contract, including transferred vertex buffers, generation/revision handling and notice acknowledgements.

The [full-runtime adapter](./create-worker.ts) and [native Rust runtime](../../../../native/README.md) run when `CreatePlayerOptions.workerRuntime` is `'rust'`. Wallpaper selects this runtime by default for its characters and Poffo backgrounds. The [Rust Worker entry](../../buffering/rust-worker.ts) retains the same generation/revision, audio, transferable-buffer and checkpoint contract, so the existing three-frame session and input handling remain in use. See [web renderer options](../../rendering-options.ts) for the separate drawing configuration.

Rust initialization or processing failures reach the existing buffering error boundary. `getPlayerBufferingInfo` reports `workerRuntime: 'rust'` only while the selected Worker owns active or idle playback; synchronous fallback does not report that ownership. The full-runtime adapter retains JSON for checkpoints and changed structural templates. Rust writes render numbers into reusable f64 buffers; the host copies those numbers and vertices through linear memory before transferring them. Unchanged render structures are not serialized again. `processPacked` serves the Worker packet directly, while `process` reconstructs the ordinary lazy frame representation. A consumer uses one representation until initialization resets the stream. Older standalone performance records do not describe the complete app path.
