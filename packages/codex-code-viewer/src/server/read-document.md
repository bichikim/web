# 큰 텍스트 파일 읽기 검증

2026-10-16, macOS 로컬 생산 번들·MCP stdio·Codex 인앱 브라우저 기준.

## 변경 이유와 범위

기존에는 편집과 읽기에 같은 한도를 사용해 큰 파일을 거부했다. 읽기 한도는 [reading-limits.ts](../shared/reading-limits.ts), 편집 한도는 [editing-limits.ts](../shared/editing-limits.ts)에서 각각 관리한다. 큰 파일은 전체 서버 구문 강조를 생략하고 기존 CodeMirror의 가상 뷰포트와 점진적 파서를 사용한다. 편집과 저장은 계속 제한한다.

큰 원문 전체를 한 RPC 응답에 넣으면 설치된 MCP SDK의 10 MiB 수신 버퍼 제한으로 연결이 끊겼다. [tool-result.ts](tool-result.ts)는 먼저 문서 메타데이터를 보내고, [create-server.ts](create-server.ts)의 `code.source`와 [load-document-source.ts](../viewer/load-document-source.ts)가 리비전에 묶인 조각을 최대 4개씩 받아 원문을 조립한다. 조각 경계의 UTF-16 문자와 줄바꿈도 보존한다. 새 파일 요청·연결 종료 시 오래된 응답을 적용하지 않으며, 전송 실패 시 이전 문서 세션을 유지한다.

[create-document-reader.ts](create-document-reader.ts)는 큰 원문을 별도 바이트 예산으로 캐시한다. 검색 강조도 화면에 보이는 일치 항목만 생성한다. 큰 Markdown·CSV는 원문으로 열고 SVG는 이미지 미리보기와 원문 전환을 유지한다. 큰 코드 파일에서 정의·사용처를 클릭하면 서버 토큰화가 필요할 수 있다. 이번 변경은 의미 분석 자체의 속도 개선을 주장하지 않는다.

## 실행 결과

[원시 결과와 화면](../../benchmarks/large-files/results/2026-10-16/)에 측정·검증 증거를 보관했다. 기존 버전은 큰 파일 열기를 거부했으므로 열기 시간의 전후 비교는 없다.

| 파일                     | 서버 읽기·문서 구성 중앙값, 5회 | 실제 MCP 원문 수신·조립 중앙값, 3회 |
| ------------------------ | ------------------------------: | ----------------------------------: |
| 1 MiB 텍스트             |                          1.1 ms |                              6.5 ms |
| 4 MiB 텍스트             |                          3.9 ms |                             21.2 ms |
| 16 MiB 텍스트            |                         15.8 ms |                             73.4 ms |
| 32 MiB 텍스트            |                         32.4 ms |                            134.6 ms |
| 13,741,868바이트 생성 JS |                         35.7 ms |                            104.7 ms |

MCP 측정은 연결된 서버에서 순차 실행했으며 세션 생성·분할 수신·조립을 포함한다. 모든 15회 원문 SHA-256이 원본과 일치했고 연결 오류는 없었다. 화면 그리기 시간이나 운영 호스트 전체 지연을 측정한 값은 아니다.

실제 브라우저에서 32 MiB·559,243줄 문서의 첫 화면 DOM은 36줄이었다. 끝으로 이동한 뒤 입력해도 원문은 바뀌지 않았다. 559,240개 검색 결과의 처음·끝 이동을 확인했다. 실제 생성 JS도 36줄만 렌더링하며 구문 강조가 표시됐다. 큰 TS 파일의 별칭에서 정의 `core.ts:1:14`로 이동했고 사용처 6개가 큰 파일 3개·외부 파일 3개와 정확히 일치했다. 결과를 눌러 `large.ts:2:1`로 돌아가는 동작과 큰 SVG의 이미지·원문 구문 강조도 확인했다.

관련 단위 테스트 252개, 통합 테스트 157개가 통과했다. 통합 검증에는 읽기 경계·한도 초과, 읽기 전용 파일 저장 거부, 원문 캐시 무효화·바이트 예산, 분할 전송·리비전 변경·세션 검증, 별칭·외부 파일 이동과 배포 번들이 포함된다. 단위 검증에는 파일 전환·연결 해제 중 전송, 실패 시 세션 유지, 줄바꿈 오프셋과 뷰포트 검색 강조가 포함된다.

실제 화면의 첫 표시·스크롤·검색 후속 측정과 원문 재사용 개선은 [큰 파일 화면 표시 측정](../../benchmarks/large-files/README.md)에 기록했다.
