# Python·Rust·Ruby 별칭 누락 수정 검증

Ruby 순차 재할당·정적 로드 순서·외부 Solargraph 경로는 이후 구현했다. 현재 결과는 [Ruby 후속 검증](../ruby-reassignment/README.md)에 기록했으며 아래는 이 작업 당시의 기록이다.

2026-10-13. 이전 검토에서 재현한 Python 2건, Rust 1건, Ruby 1건의 누락·실패를 수정했다. TypeScript 프로젝트 분할은 적용하지 않았다. 구현 원인, 회귀 사례와 남은 검증 범위는 [검토 보고서](review.md)에 정리했다.

## 수정 후 속도

언어별 48개 소비자 파일로 구성한 fixture의 독립 프로세스 3회 중앙값이다. 첫 결과는 서버 스트림의 첫 비어 있지 않은 결과이며 브라우저 paint는 포함하지 않는다. 재조회는 완료 직후 같은 프로세스·workspace에서 반복한 검색이다.

| 대상                    | 첫 결과 (초) | 전체 완료 (초) | 재조회 완료 (ms) | 결과 위치 수 |
| ----------------------- | -----------: | -------------: | ---------------: | -----------: |
| Python 원본·스텁 사용처 |        0.586 |          0.623 |            3.875 |          144 |
| Python 중첩 설정 사용처 |        0.730 |          1.816 |            0.526 |          144 |
| Rust 독립 Cargo 사용처  |        0.470 |          1.203 |            0.497 |          144 |
| Ruby 상수 별칭 사용처   |        0.443 |          0.547 |            0.488 |          241 |
| Python 일반 검색 대조군 |        0.384 |          0.415 |            0.446 |          144 |
| Python 소비자 정의      |        0.325 |          0.326 |            0.671 |            1 |
| Rust 소비자 정의        |        0.241 |          0.242 |            0.492 |            1 |

Python과 Rust의 사용처는 각 144개 위치, Ruby는 두 단계 별칭의 바인딩·참조·호출 및 직접 사용을 포함한 241개 위치다. [검증 코드](results/2026-10-13/validate.py.txt)가 모든 수정 후 기록의 전체 위치 집합을 독립 기대값과 비교했다. 다른 메서드·다른 설정의 동명 함수·다른 Cargo 프로젝트·다른 Ruby 네임스페이스·인스턴스 대입의 호출을 잘못 포함하지 않았다. 최초·재조회·3개 프로세스 사이의 집합도 같았다.

## 수정 전후 비교

각 칸은 전 → 후다. 결과가 0개거나 오류였던 조회는 정상 검색의 성능 기준으로 사용할 수 없다. 전체 완료 열의 수정 전 값은 불완전하거나 실패한 요청이 종료된 시간이다.

| 대상                    | 결과 위치 수 |  첫 결과 (초) | 종료/전체 완료 (초) | 재조회 종료/완료 (ms) |
| ----------------------- | -----------: | ------------: | ------------------: | --------------------: |
| Python 원본·스텁 사용처 |      0 → 144 |     — → 0.586 |       0.379 → 0.623 |         0.429 → 3.875 |
| Python 중첩 설정 사용처 |      0 → 144 |     — → 0.730 |       0.383 → 1.816 |         0.411 → 0.526 |
| Rust 독립 Cargo 사용처  |   오류 → 144 |     — → 0.470 |       0.266 → 1.203 |         8.811 → 0.497 |
| Ruby 상수 별칭 사용처   |     49 → 241 | 0.431 → 0.443 |       0.447 → 0.547 |         0.400 → 0.488 |
| Python 일반 검색 대조군 |    144 → 144 | 0.379 → 0.384 |       0.414 → 0.415 |         0.437 → 0.446 |
| Python 소비자 정의      |        0 → 1 |     — → 0.325 |       0.211 → 0.326 |         0.467 → 0.671 |
| Rust 소비자 정의        |        1 → 1 | 0.241 → 0.241 |       0.241 → 0.242 |         0.484 → 0.492 |

일반 Python 대조군은 동일한 144개 결과에서 전체 완료 0.414 → 0.415초로 유지됐다. 작업 중 추가 정의 조회 때문에 중앙값 0.641초까지 느려지는 것을 측정했고, 단일 설정이며 workspace 안에 스텁이 없는 경우 기존 직접 검색 경로를 사용하도록 수정했다. 해당 중간 결과는 [중간 검증 기록](results/2026-10-13/intermediate-validation.txt)이며 최종 표에는 포함하지 않았다.

Ruby는 49개에서 241개로 결과를 보완하면서 전체 완료가 약 0.101초 늘었다. 첫 결과는 약 0.012초 늘었고 재조회는 0.088ms 늘었다. 정확도 수정 뒤 모든 지표가 빨라졌다고 해석하지 않는다. 3회 표본과 실제 데스크톱 부하가 있는 환경이므로 작은 차이를 확정적인 회귀나 향상으로 일반화하지 않는다. 개별 범위는 [요약 JSON](results/2026-10-13/summary.json)에 보존했다.

## 수정 방법

- [Python 목표 연결](../../src/server/read-python-reference-targets.ts#L64): 대응하는 스텁의 이름은 후보로만 사용하고 Pyright의 구현 정의가 같은 경우에 연결한다. 현재 구현과 스텁의 선언 위치는 사용처에서 제외한다.
- [Python 설정과 수집](../../src/server/collect-python-references.ts#L105): 소비자의 설정으로 후보 정의를 검증하고, 설정별 분석기를 재사용해 참조·재별칭 결과를 합친다. 관련 문서 조회에서는 편집 중인 원본을 유지한다.
- [Rust 후보 컨텍스트](../../src/server/create-rust-navigation.ts#L61): 라이브러리가 속한 분석기만 사용하던 경로를 후보 Cargo 프로젝트의 분석기로 바꿨다. 정의 위치를 비교해 동명 심볼을 제외한다.
- [Ruby 상수 별칭](../../src/server/ruby/reference-handler.ts#L25): 상수 참조 AST와 의미 정의로 확인한 관계를 따라 별칭을 확장한다. 인스턴스 생성 결과, 다른 네임스페이스, 다른 클래스로의 재할당을 하나의 별칭으로 합치지 않는다.
