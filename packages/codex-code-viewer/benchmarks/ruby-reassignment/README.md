# Ruby 재할당·외부 Solargraph 검증

2026-10-13. 순차 상수 재할당, 재할당 전 값의 복사, 정적 `require`/`require_relative` 로드 순서와 별칭을 수신자로 한 메서드 조회를 보완했다. `SOLARGRAPH_BINARY`로 지정한 실행 파일도 같은 확장을 사용한다.

## 수정 전후 비교

각 칸은 전 → 후다. 수정 전 결과에는 누락·오탐이 있으므로 모든 행을 같은 작업량의 속도 비교로 해석할 수는 없다. 0개 조회의 수정 전 완료는 빈 결과가 종료된 시간이다.

| 검색 대상          | 경로 | 결과 위치 |  첫 결과 (초) | 전체 완료 (초) | 재조회 완료 (ms) |
| ------------------ | ---- | --------: | ------------: | -------------: | ---------------: |
| 재할당·복사 별칭   | 기본 |  97 → 433 | 0.382 → 0.392 |  0.408 → 0.553 |    0.390 → 2.581 |
| 재할당·복사 별칭   | 외부 |  97 → 433 | 0.372 → 0.386 |  0.375 → 0.549 |    0.309 → 2.383 |
| 재할당 없는 대조군 | 기본 | 241 → 241 | 0.366 → 0.364 |  0.451 → 0.450 |    0.411 → 0.404 |
| 재할당 없는 대조군 | 외부 |  49 → 241 | 0.356 → 0.371 |  0.359 → 0.459 |    0.378 → 0.395 |

- 재할당 사용처는 97 → 433개로 보완됐고, 완료 시간은 기본 약 0.145초·외부 약 0.174초 늘었다. 재조회도 각각 약 2.19ms·2.07ms 늘었다. 모든 지표가 개선됐다는 결과는 아니다.
- 기존 클래스 메서드의 192개에는 새 클래스 호출 48개가 잘못 포함돼 있었다. 144개로 바로잡았고 새 클래스 호출은 0 → 48개로 복구했다. 정확도 확인을 위한 수신자 검증 비용이 완료 시간에 포함된다.
- 기존에 정확했던 기본 경로의 대조군은 241개를 유지했고 전체 완료 중앙값은 0.451 → 0.450초였다. 외부 대조군은 별칭 확장이 빠져 있던 49개를 241개로 보완했다.

## 변경과 검증

- [대입 상태와 로드 순서](../../src/server/ruby/constant-references.ts#L7): Solargraph가 파싱한 상수 대입과 리터럴 import를 순서대로 반영한다. 프로젝트 코드를 실행하지 않는다. 복사 대입은 그 시점의 값을 보존하며, 재할당·자기 참조·관련 없는 순환 이름을 전역 별칭 하나로 합치지 않는다.
- [메서드 수신자 검증](../../src/server/ruby/constant-references.ts#L45): `Alias.method`와 기본 생성자의 `Alias.new.method`는 호출 시점의 클래스에서 메서드 스택을 확인한다. 별도의 `new` 구현이 있으면 기존 분석기의 추론 경로를 사용한다.
- [외부 로드](../../src/server/ruby/create-preload.ts#L14): 설정된 실행 파일을 그대로 실행하고, 그 프로세스가 선택한 Solargraph를 로드할 때 확장을 설치한다. 기존 `RUBYOPT`·`RUBYLIB`를 보존한다. 로드 검사가 자동 로드로 재진입할 때 중복 설치되지 않도록 막았다.
- [정리](../../src/server/ruby/create-preload.ts#L27): 로드를 마치면 임시 파일과 추가한 환경 옵션을 제거한다. 생성 실패·프로세스 시작 실패·서비스 종료에도 정리한다. 측정 전후 추가로 남은 preload 디렉터리는 0개였다.
- [새 통합 사례](../../src/server/__tests__/create-workspace.ruby-flow.integration.ts#L27): 기본·외부 각각 4개, 총 8개다. 한 파일의 재할당·복사·복귀 대입, 파일 간 복사, namespace·인스턴스 제외, 두 파일의 require 순서, 수신자 메서드를 검증한다. 변경 후 참조 갱신과 스트림 위치 집합도 확인했다. 외부 실행 파일 경로·임시 디렉터리에 공백이 있고 기존 `RUBYOPT`가 있는 경우도 실행했다.
- [수정 전 재현](results/2026-10-13/before-tests.txt) 네 테스트가 모두 실패했다. [수신자 오탐 재현](results/2026-10-13/method-tests-before.txt)에서도 기존 클래스에 새 클래스 호출이 섞이는 것을 확인했다.
- [전체 통합 테스트](results/2026-10-13/integration.txt) 385/385, [Ruby 단위 테스트](results/2026-10-13/unit.txt) 19/19 통과. oxlint, typecheck, build, `pnpm format`도 실행했다.

## 측정 방법

[기존 측정 CLI](../language-aliases/measure.ts)를 사용했다. workspace 파일 읽기가 끝난 뒤 검색 요청부터 타이머를 시작하고 스트림 종료까지 측정했다. 최종 결과 확인과 캐시 완료 처리도 포함한다. 각 프로세스의 `CODEX_HOME`은 새로 만들었고, 전후 순서를 번갈아 실행했다. 빌드·테스트와 측정을 겹치지 않았다. OS 파일 캐시는 지우지 않았다. 프로세스 재시작 후 디스크 캐시 조회나 취소 후 재조회 실험은 아니다.

Node 24.15.0, Ruby 4.0.6, Solargraph 0.60.4 환경에서 실행했다. 외부 경로는 설치된 gem의 실제 실행 파일이며, 통합 테스트에서는 해당 실행 파일을 공백이 있는 경로로 복사해서도 실행했다. 원시 값과 범위는 [요약 JSON](results/2026-10-13/summary.json)과 [96개 원시 기록](results/2026-10-13/measurements.jsonl)에 있다. [fixture 생성](results/2026-10-13/fixtures.py.txt), [기대 위치](results/2026-10-13/fixtures.json), [실행 코드](results/2026-10-13/run.py.txt), [위치 검증](results/2026-10-13/validate.py.txt), [번들 생성](results/2026-10-13/bundle.mts.txt)을 보존했다. 전후 번들 SHA-256도 요약 JSON에 있다. 실행 당시 번들은 `/tmp/code-viewer-ruby-flow`에 보존했으며 저장소에는 중복 첨부하지 않았다.

## 검토와 검증 공백

동작, 구조·테스트 가능성, 명명·배치를 검토했다. 전체 위험도는 보통이다. P0/P1은 발견하지 않았다. 재할당의 사용처 누락·외부 확장 우회·수신자 메서드 오탐의 P2 세 문제를 수정했으며 위 재현 범위에 남은 실패는 없다. 상태 계산·참조 핸들러·외부 bootstrap을 역할별로 분리했고 파일은 모두 600줄 미만이다. 별도 P3/P4 제안은 추가하지 않는다.

1. 검증한 것은 위 정적 순차 대입·리터럴 로드·복사·수신자 사례와 48개 소비자 fixture다. 모든 실제 Ruby 저장소의 독립적인 완전 정답 집합을 구축한 것은 아니다.
2. 임의 조건 분기·반복문·실행 중 `const_set`·동적 require·autoload·메타프로그래밍의 실행 결과를 시뮬레이션하지 않는다. 조건에 따라 달라지는 런타임 순서는 이번 검증 범위에 포함하지 않았다.
3. 외부 경로는 Solargraph 0.60.4와 일반 Ruby 환경 옵션을 사용하는 실행 파일에서 확인했다. 다른 Solargraph 버전, Ruby 환경 옵션을 제거하는 별도 실행 래퍼, 다른 Ruby parser backend는 별도 호환성 검증이 필요하다.
4. 첫 결과는 서버 스트림 기준이다. 브라우저의 실제 표시 시간과 대규모 저장소의 최대 메모리 사용량은 측정하지 않았다.

TypeScript 프로젝트 분할과 다른 언어 분석기의 추가 변경은 범위 밖이다.

조건 분기와 정적으로 계산 가능한 동적 require는 [2026-10-14 후속 검증](../ruby-branches/README.md)에서 보완했다. 위 날짜의 측정값과 검증 공백은 당시 기록으로 유지한다.
