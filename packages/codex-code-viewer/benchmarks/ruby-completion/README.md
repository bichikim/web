# Ruby 전체 완료 병목 개선

2026-10-14. [분기·동적 require 누락 수정](../ruby-branches/README.md)을 포함한 번들을 기준으로 성능을 비교했다. 누락 수정 이전의 불완전한 결과와 비교하지 않는다.

## 병목과 변경

- 동적 require fixture에서 이름별 후보 추출을 14,406번 호출해 약 180ms가 들었다. 각 파일의 parsed AST에 실제 있는 Symbol 이름만 골라 기존 Solargraph 위치 추출기를 호출하도록 바꿨다. 후보 축소 단계의 호출은 389번·약 29ms로 감소했다. 다른 parser backend에서는 기존 후보 수집 경로를 사용한다.
- 위치별 정의 확인 캐시를 별칭 그래프·호출 수신자·후보 검증이 공유한다. 후보 축소 단계에서 실제 정의 확인은 634→488회로 줄었다. 캐시는 검색 요청마다 새로 만들어 파일 변경 이후에 재사용하지 않는다.
- 메서드 fixture에서는 파일별 후보를 이미 검증한 뒤 기본 Solargraph가 같은 파일·이름을 다시 순회해 약 75ms를 사용했다. 클래스·상수·일반 메서드는 이 두 번째 검색을 생략했다. 생성자·변수·다른 pin 유형은 기본 검색을 유지한다. 메서드 계측에서 기본 전체 검색 호출은 1회→호출 없음, 정의 확인은 630→484회, 위치 추출은 100→49회로 감소했다.
- [후보 선택](../../src/server/ruby/reference-candidates.ts#L4), [정의 캐시](../../src/server/ruby/constant-references.ts#L33), [기본 검색 유지 조건](../../src/server/ruby/reference-handler.ts#L67)이 구현이다. 분기 상태·동적 require·require-once·복사 별칭 분석은 유지한다.
- 추가 회귀 검증에서 기존 setter 선언의 정의 확인 실패와 setter 호출 범위의 차이를 발견했다. 정확한 선언 위치의 Method pin과 호출 시점 수신자 클래스로 보완했다. 같은 이름의 다른 클래스 setter는 제외한다.

프로파일은 원인 확인을 위한 단일 실행이며 계측 오버헤드를 포함한다. 위 프로파일 시간을 최종 제품 속도로 사용하지 않았다. [초기 프로파일](results/2026-10-14/profile-before.json), [후보 축소 후](results/2026-10-14/profile-after.json), [중복 검색 포함 메서드](results/2026-10-14/profile-method.json), [최종 메서드](results/2026-10-14/profile-final-method.json)를 보존했다.

## 대조군 추가 확인

## 측정 범위

Node 24.15.0, Ruby 4.0.6, Solargraph 0.60.4. 첫 결과는 파일을 읽은 뒤 검색 요청부터 서버 스트림의 첫 비어 있지 않은 결과까지이며 브라우저 페인트 시간은 아니다. 전체 완료에는 최종 결과와 캐시 처리가 포함된다. OS 파일 캐시는 지우지 않았으며 사용자 데스크톱을 격리하지 않았다. 원인 계측·테스트·빌드와 최종 성능 측정을 겹치지 않았다. 취소 후 재조회·프로세스 재시작 뒤 디스크 캐시 조회 실험은 아니다. 측정용 번들은 /tmp/code-viewer-ruby-completion에 보존했다.

임의 런타임 함수로만 결정되는 require 경로, autoload, const_set, 메타프로그래밍, 반복문·예외 흐름·조건 간 상관관계, 다른 Solargraph 버전/parser backend와 최대 메모리 사용량은 별도 검증 범위다. 이전 누락 수정의 분석 범위를 임의로 축소하지 않았으며, 모든 Ruby 저장소의 완전성을 입증한 것은 아니다.
