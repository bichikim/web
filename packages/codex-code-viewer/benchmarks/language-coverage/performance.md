## 측정 조건

Node 24.15.0 / TypeScript 런타임 6.0.3 (패키지 메타데이터 6.0.2) / Pyright 1.1.414 / rust-analyzer 배포 2026-10-05 (실행 파일 0.3.3073, 2026-10-04) / Ruby 4.0.6 / Solargraph 0.60.4. 전후에 같은 TypeScript 기본 라이브러리·Python·Rust 분석기 파일을 사용했다. Ruby는 기본 실행 경로다.

각 조회를 독립 프로세스 3쌍에서 교대로 실행했고, 각 프로세스에 빈 CODEX_HOME을 사용했다. 별도 warmup을 호출하지 않았다. 파일 읽기가 끝난 뒤 `scanNavigation()`부터 측정한다. 첫 결과는 첫 비어 있지 않은 서버 배치, 전체 완료는 캐시 검증까지 끝난 스트림 종료, 재조회는 같은 프로세스와 workspace에서 완료한 요청을 다시 실행한 시간이다. OS 파일 캐시를 지우거나 데스크톱을 격리하지 않았다. 측정 중 테스트·빌드·소스 수정은 하지 않았다.

13개 조회 × 전후 × 3회 × 최초/재조회 = **156개 기록**이다. 표는 ms 단위의 3회 중앙값이며 전→후다. 재조회 첫 결과도 [원시 기록](results/2026-10-14/speed-measurements.jsonl)과 [요약·범위](results/2026-10-14/speed-summary.json)에 있다. 재조회 첫 결과와 완료의 차이는 모든 기록에서 0.1ms 미만이었다.

## 차이가 큰 항목의 추가 5쌍 확인

처음 3쌍에서 JavaScript 재조회가 33.591→45.346ms, Ruby 대조군 전체 완료가 711.667→499.891ms로 달라져 두 조회만 별도 5쌍을 추가했다. 추가 기록 40개도 기존 검증 위치 집합과 모두 일치했다. 처음 측정을 삭제하거나 추가 측정으로 대체하지 않는다.
