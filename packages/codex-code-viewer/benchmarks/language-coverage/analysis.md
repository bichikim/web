# TypeScript 전체 분석과 탐색 결과 캐시 비교

2026-10-14. 이전 누락 수정과 Rust 반복 빌드 수정을 포함한 소스를 기준으로 비교했다. **이번 변경으로 TypeScript 최초 전체 분석이 유의미하게 빨라졌다는 증거는 얻지 못했다.** 전체 완료 시간은 여전히 7초대다. 같은 식별자 내부 위치 차이 때문에 완료 결과 캐시를 놓치는 문제는 수정했고, 변경되지 않은 결과 재조회와 파일 수정 후 갱신을 검증했다.

## 적용한 변경

- [캐시 키](../../src/server/navigation-cache/create-navigation-cache.ts#L64)를 식별자 시작 위치로 정규화했다. 서로 다른 식별자·조회 종류·문서 revision·편집 중 원문은 구분한다. 기존 인덱스와 관련 입력의 변경 검증을 유지했다. 취소되거나 완료되지 않은 결과를 완료 캐시로 승격하지 않는다.
- [검색 순서 점수](../../src/server/scan-typescript-references.ts#L68)는 정렬 비교 때마다 원문을 읽지 않고 파일별 한 번 계산한다. 최종 전체 의미 검색과 별칭 병합은 유지한다.
- [컴파일러 원문 읽기](../../src/server/read-compiler-source.ts#L5)는 Node의 UTF-8 문자열 읽기를 사용한다. BOM을 제거하고 UTF-16은 기존 TypeScript 읽기에 위임한다. 실제 인코딩과 실패 경계 검증을 추가했다.
- [파일시스템 메타데이터](../../src/server/create-navigation-file-system.ts#L19)를 같은 작업의 스냅샷 버전·존재 확인에 공유한다. 비동기 사전 읽기가 얻은 stat도 공유한다. 기존 조회 시작·종료 무효화와 dispose 세대 검사를 유지한다. 디렉터리·설정 파일까지 BigInt stat으로 읽는 중간 시도는 제외했다.

프로젝트를 분할하거나 후보 루트를 줄이지 않았다. 프로젝트별 별칭, 패키지 밖 소비자, `.d.ts` 연결, 네이티브 전체 검색과 불변 모듈 바인딩 병합을 유지했다. I/O 변경은 중복 경계 작업을 줄이지만, 아래 결과처럼 TypeScript 전체 완료 개선으로 이어졌다고 주장할 수 없다. 워커 young heap 64/128/256/512MB 조정과 재귀 의존성 사전 읽기는 최종 코드에 넣지 않았다. Node 24 기본 워커 heap을 유지한다.

## 측정 조건

동일한 현재 저장소를 전후 번들로 검색했다. 전후 번들은 `/tmp/code-viewer-typescript-next/{before,after}`에 있으며 [해시와 환경](results/2026-10-14/analysis-metadata.json)을 보존했다. 주요 TypeScript 두 조회는 독립 프로세스 5쌍, 나머지는 3쌍을 교대로 실행했다. 매 프로세스의 CODEX_HOME은 비어 있고 별도 warmup을 호출하지 않았다. 완료 후 같은 workspace에서 한 번 더 요청했다. OS 파일 캐시는 지우지 않았고 호스트를 독점하지 않았다. 측정 동안 소스 수정·빌드·테스트는 하지 않았다.

시간은 ms 중앙값이다. 첫 결과는 비어 있지 않은 첫 서버 배치, 전체 완료는 최종 검증을 포함한 스트림 종료다. 최초 document 읽기 이후부터 계측하며 브라우저 paint 시간은 아니다. 172개 기록의 결과 위치·반복 안정성과 fixture 정답 집합을 검증했다. [원시 기록](results/2026-10-14/analysis-measurements.jsonl), [중앙값·최소·최대·위치 검증](results/2026-10-14/analysis-summary.json).

## 정의 → 사용처 → 재방문

같은 실제 저장소에서 정의로 이동한 후 그 정의의 사용처를 조회하고, 원래 호출·정의를 다시 조회했다. 독립 프로세스 3쌍, 총 72개 기록이다. 각 단계의 결과 위치는 최초 정의 또는 대응하는 독립 사용처 조회와 일치했다. [원시 기록](results/2026-10-14/analysis-roundtrip.jsonl), [요약](results/2026-10-14/analysis-roundtrip-summary.json).

일반 읽기 UI는 이미 토큰 시작 위치를 전송하므로, 동일 위치 재방문은 수정 전에도 완료 캐시를 사용했다. 내부 다른 위치의 개선을 일반 UI 전체가 새로 빨라진 것으로 해석하지 않는다. 정의 조회가 알려 준 한 위치는 전체 사용처 목록이 아니다. 정의로 한 번 이동했어도 전체 사용처를 아직 완료하지 않았다면 첫 사용처 검색은 필요하다. 이미 완료한 사용처는 관련 입력의 변경 검증 후 재사용한다.

최종 배포 빌드의 브라우저에서 별칭 hello→정의 greet→사용처 6개→호출로 복귀→정의→사용처 6개를 확인했다. 닫힌 second.ts의 호출을 1개에서 3개로 바꾼 뒤 재조회하자 8개로 갱신됐으며, 무관한 패키지의 동명 greet는 포함되지 않았다. 이 검증은 기능과 무효화 증거이며 브라우저 표시 시간 계측은 아니다. [변경 후 화면](results/2026-10-14/analysis-browser-usages-final.png).
