# Ruby 조건 분기·동적 require 검증

2026-10-14. 기본 Solargraph와 외부 `SOLARGRAPH_BINARY`에 같은 분석을 적용했다. 이전 순차 재할당 수정은 유지한다.

## 결과

- 조건 분기에서 앞쪽 별칭이 뒤쪽 분기에 덮이던 누락을 수정했다. 분기 안에서는 그 분기의 상태를, 분기 뒤에서는 가능한 대상의 합집합을 사용한다.
- 문자열 변수·상수·보간·이어 붙이기·`File.join`으로 계산한 require 경로를 작업 폴더의 실제 파일에 연결한다. 패키지 밖 소비 파일도 검사한다.
- 분기에 따라 달라지는 require-once 상태는 별도로 보존한다. 메서드 안의 deferred require를 최상위 실행에 적용하지 않으며 class/module의 지역 변수를 분리한다.
- 상수 별칭 이름은 역방향 연결 그래프로 찾고, 실제 후보는 호출 위치의 상태와 Solargraph 정의로 다시 검사한다. 검색 전에 모든 파일의 최종 상태를 계산하지 않는다.
- 수정 후 84개 기록(14조회 × 3실행 × 최초/재조회)의 파일·행·열이 독립적으로 작성한 기대 위치와 모두 일치했다. 검증 범위 내 누락·오탐은 0개다. 전후 합계는 168개 기록이다.

## 방법과 한계

Node 24.15.0, Ruby 4.0.6, Solargraph 0.60.4. 첫 결과는 파일을 읽은 뒤 검색 요청부터 서버 스트림의 첫 비어 있지 않은 결과까지이고, 완료는 최종 검증과 캐시 처리가 끝나는 스트림 종료까지다. 브라우저 페인트 시간은 아니다. 각 실행은 새 CODEX_HOME을 사용하고 전후 순서를 교대로 실행했다. OS 파일 캐시는 지우지 않았다. 빌드·테스트와 성능 측정을 겹치지 않았다. 취소 후 재조회나 디스크 캐시 재시작 실험은 아니다. preload 디렉터리가 추가로 남은 것은 0개다.

조건이 실행 시점에만 정해지면 가능한 양쪽 대상을 포함한다. 분기 안의 코드는 소스 참조로 유지하되, 정적으로 선택되지 않은 분기의 대입은 분기 뒤 상태에 적용하지 않는다. 임의 프로젝트 함수, ENV 값만으로 정해지는 경로, autoload, const_set, 메타프로그래밍의 실행 결과는 확정하지 않는다. 프로젝트 코드를 실행하거나 파일 이름만 비슷한 경로를 추측하지 않는다.

반복문·예외 흐름·임의 블록 호출, 반복되는 조건 사이의 상관관계, 외부 래퍼가 Ruby 환경 옵션을 제거하는 경우, 다른 Solargraph 버전/parser backend, 대규모 분기 조합의 최대 메모리는 별도 검증이 필요하다. 검증한 fixture를 넘어 모든 Ruby 저장소의 완전성을 입증한 것은 아니다.

이 누락 수정을 유지한 전체 완료 시간 개선은 [후속 성능 검증](../ruby-completion/README.md)에 기록했다. 위 측정값은 개선 전 기록으로 유지한다.
