# Claude Code hooks

The default [register.js](register.js) keeps the original Browser viewer behind explicit user actions: a project file link, the composer footer's open button, or the open command. Session startup does not open a pane or call the viewer MCP server. Click handling runs in `ui.press`, rather than an element closure, so its tool calls retain the hook origin used by the limited permission handler. Read/Edit/Write tracking updates an already opened page without reloading it. The open button resumes the viewer’s last file rather than replaying a tracked tool location. Authenticated app location updates retain that file, while session-scoped local view snapshots recover the cursor and viewport alongside unsaved drafts. Explicit file links still take precedence over a saved position. For opened viewers, `prompt.submit` reads user-selected snapshots through `code.attachments` and adds them to the composer message’s context without consuming them. Reads share the viewer operation queue; the limited permission phase covers only this Mod’s empty-argument attachment read and preserves explicit restrictions. A failed read drops the message with an error, preventing silent attachment loss. Unopened sessions do not connect for this hook.

On macOS, explicit file-link and open-button presses also invoke the existing native helper to reveal Browser. The helper resolves the CLI session to its Desktop identity from non-secret session records, verifies the matching Claude window, and presses only an unchecked Browser toggle. It confirms both the checked toggle and exact viewer URL without typing, pasting or reloading the page. Startup and automatic following never invoke this operation. Other hosts keep the manual Browser-toggle fallback.

The archived [register-pane.js](register-pane.js) retains the native Pane implementation and its independent draft store. The build bundles both entrypoints, while `hooks.json` registers only the Browser bridge. The archive is not a migration path for Pane drafts.

Stage the bundled `register.js` with `register.browser.test.ts` for the Browser SDK tests. To run the retained Pane tests, stage bundled `register-pane.js` as `register.js` with the previous `register*.test.ts` files, excluding `register.browser.test.ts`.

## Retained Mods Pane

The native Pane consumes a captured view model and emits declarative commands. Its views have no filesystem, network, DOM, Solid or Mods API dependencies. The controller owns I/O and session persistence; the server owns workspace boundaries, revisions and file operations.

Search, path parsing, tree calculations, attachment formatting, patches, positions and table ordering reuse the common headless operations. CSV parsing stays on the server because its browser dependency modifies typed-array prototypes and cannot load in the Mods environment.

Hooks must be bundled before loading or running the official Mods tests. The loader refuses imports outside the plugin root, and API calls must resolve inside the compiled entrypoint. Package builds bundle the hooks into one `register.js`; source files are not a directly loadable plugin. Run SDK tests against a staged plugin containing the compiled hooks and the matching test files.

The source, tree and action controls use the original UnoCSS palette, fonts and icons in scriptless SVG, with `Client` surfaces capturing input. CodeMirror document and selection state stays in the hooks; only bounded visual rows and ordered input events cross the surface boundary. Native buttons remain beneath painted controls for their accessible roles and keyboard actions. Editing a path uses the host's native input. Browser remains available for renderers that have not been ported.

## Interaction mapping

The [toolbar and workspace](pane-view.js) retain the file tree beside the document on wide panes and above it on narrow panes. Settings can force either arrangement. The [tree](pane-files.js) keeps matching ancestors, reveals the active file, marks drafts and opens actions for a selected entry. The [document](pane-document.js) exposes search, location, selection and draft actions only when requested. Selection fields accept one-based columns; the end column is excluded.

Display preferences and the follow toggle persist beside the existing session draft store. Pausing following affects this Pane; explicit file opening remains available. Refresh keeps drafts and exposes revision conflicts. Discard requires a separate confirmation, and attachment snapshots remain independent of later edits or saves.

The macOS plugin explicitly enables the local text clipboard adapter. Cmd/Ctrl+C/X/V and an explicit copy menu action invoke it; it is not exposed to the model and does not read at startup. Both clipboard processes use UTF-8 independently of the Desktop launch locale. Tree shortcuts reuse revision-checked entry operations; Delete retains the existing confirmation. Shift+F10 and Ctrl+Shift+. request code or tree actions without a pointer. Full IME composition remains unverified: `Client` exposes keys rather than composition events, and the installed SVG scrubber removes HTML input elements.

Each painted tree row owns a native one-row input surface inside the same keyed Box and hover group. This aligns clicks; hover does not open a file. Keyboard navigation shares one tree cursor across the row surfaces. SVG styles retain only referenced UnoCSS rules and palette variables, avoiding repeated document-wide styles in each row. An earlier Desktop capture showed row hover with no file open; the final wheel-based computer-use pass did not reproduce idle row hover consistently, so final native hover verification remains open. File opening was exercised in Desktop. The previous shared surface was also checked with upper, middle and last files, folder expansion and scrolling.

Hover messages retain the owning row on leave, so a delayed leave from one Client cannot clear another row's highlight. An unheld pointer move also clears a pressed state left behind when activation redraws the host before pointer release reaches the old input region. Unit tests cover both event sequences; the SDK exercises crossing between independent row Clients while keeping the open document unchanged.

The installed Desktop scroll bridge omits the wheel pointer and requires scrollable content. The root exposes the combined code/tree scroll extent and positions its workspace at the host window offset, keeping the toolbar and footer visible. `Client` entry events retain the last pointed region when the wheel pointer is absent. Code and tree retain independent offsets.

The internal divider and Browser share the original 200 px sidebar minimum, 240 px content minimum, 6 px separator and 16 px keyboard step. The Pane stores a preferred pixel width and converts legacy percentage settings on the first measured render; resizing the outer panel preserves that preferred width. Client pointer capture retains a held drag across leave/enter events until release; it does not add an overlay that could steal the gesture. Dragging, Home/End bounds and outer-panel resizing were exercised in Desktop. Source gestures are collected until release or leaving the source, preventing redraws from replaying a held selection. Reopening a document obtains a host-clock generation so pending events from an earlier module reload are rejected. Transparent input rows contain one nonbreaking space to avoid the host painting selections over their full width. Desktop can emit leave/enter while redrawing a pressed control; activation validates the release coordinates instead of treating that transition as cancellation.

Divider motion invalidates layout outside the document I/O queue. Only pointer release or keyboard resizing writes the preference store; fine coordinates are used when supplied. SDK tests assert that width changes before release without a store write. Desktop confirms the completed drag and hover appearance; the computer-use driver serializes actions and captures, so it did not establish frame-by-frame drag latency. The current public `Box` and `Client` props expose no pointer-cursor setting, and no OS resize cursor is claimed.

The [official redraw limits](https://code.claude.com/docs/en/plugins/mods/reference#limits) cap Desktop `ui.render` invalidation at 10 redraws per second. Removing I/O from the pointer path does not remove that host limit; no claim of 60-frame-per-second layout tracking is made.

The source input keeps its allocated row count separate from measured painting rows. Its local Box uses the allocated height, preventing an initial one-row measurement from shrinking the next measurement again. The role-specific row, resize and source input modules keep the previous module paths bundled for already-running drawings.

## Verification boundaries

Desktop 2.1.295 was exercised with synthetic project files: a new Code session automatically unfolded the Pane, a successful Read followed its file, declaration clicks opened grouped references, reference clicks and definition clicks changed file/line, new-file submission opened the created file, editing and Save changed disk contents, and Claude received an unsaved attachment snapshot in its next prompt. These observations do not establish complete Codex UI parity. Reference preview settings and the compact reference popup were also exercised in Desktop. Function-key menu delivery remains unverified; Ctrl+Shift+. was exercised for both source and tree in Desktop. Cmd+Shift+M was removed because it opens the host permission-mode menu.

The viewer's right-click menu renders and its actions execute, but the Desktop/macOS default Copy/Select All menu can also appear above it. The current `ClientPointerEvent` exposes no context-menu cancellation method. Keyboard context actions and the document's more button remain available. The native input's focused appearance is host-controlled; the painted search outline and icon do not make that inner input identical to Codex. Search fields place the native Input after their SVG background in the same absolute layer so the background cannot intercept clicks.

Language selection reuses the original translations and is persisted independently of project text. Complete IME composition, full Office layout, PDF text selection/search and audio/video rendering and remaining visual details are not complete. Absence of Desktop `Image`/`Raster` elements alone does not rule out a vector or server-rendered fallback. Each fallback needs its own runtime experiment before being called impossible.

Raster images use a revision-checked `code.media` read and an SVG data URI. PNG display was exercised in Desktop; the current implementation caps input at 90 KiB to stay below the SVG document limit. PNG/GIF header dimensions enable the shared Browser/Pane image camera: numeric zoom, fit without upscaling, zoom keys, bounded arrow movement and release-time drag movement. PNG numeric zoom, arrow movement, dragging and Home fit were exercised in Desktop. JPEG/WebP/AVIF/BMP/ICO natural-size discovery, wheel/pinch input and larger-image conversion remain unimplemented. This experiment proves that the absence of a native Image element does not prevent every raster preview.

Office previews use the app-only `code.documentPreview` operation with the connected workspace and current media revision. The server reuses the XLSX parser and sanitized DOCX node conversion. Native Excel sheets reuse table filtering, sorting and pagination; Word nodes use bounded Markdown pages and separate embedded-image pages. These paths preserve text and do not evaluate spreadsheet formulas or fetch external document resources. Complete Word layout, advanced formatting and image conversion are not parity claims. Office parsing and workspace boundaries are integration-tested; Excel sheet selection and filtering, Word headings, tables and page navigation were exercised in a fresh Desktop Code session.

PDF previews use the app-only `code.pdfPreview` operation with workspace, revision and page checks. PDF.js's public Node `canvasFactory` renders one page into a bounded JPEG data URI; its already-installed optional Canvas runtime, worker, CMaps, fonts and WASM assets are copied into the installation ZIP. No direct Canvas dependency was added. Previous/next, page input, zoom, fit and recent page/camera retention are implemented. First/second pages, numeric 200% zoom and direct page entry were exercised in Desktop; an extracted ZIP rendered both pages with its bundled Node outside the repository. Text selection/search and PDFs above 16 MiB remain unimplemented.

The [official element reference](https://code.claude.com/docs/en/plugins/mods/reference#elements) lists Desktop elements separately from terminal elements: Desktop has no `Image` or `Raster`, and its button/input props do not expose arbitrary CSS. The [official declarations](https://github.com/anthropics/claude-code/blob/main/mods/types/claude-code.d.ts) describe `Client` key events without a composition event and a scriptless SVG frame. These boundaries do not prove every alternative renderer impossible; they prevent claiming that the original HTML editor or full UI has been embedded here.
